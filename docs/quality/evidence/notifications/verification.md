## 2. 核心场景

测试通过真实业务写入产生以下通知，再经实际 Outbox 和持久任务投递：任务分配／改派、审批步骤及申请退回／批准、明确策略下的生效合同到期、订阅账期提醒、文件副本失败／受控重试恢复、多服务事件及恢复、秘书终态结果。各模块仍检查自身当前权限，没有通过伪造通知行代替业务生产者。

专项检查包括：

- 本人列表和计数只包含当前可查阅资料；猜测他人 ID、资料撤权和失效负责人不会暴露旧标题。
- 标记已读只确认员工实际看到的投递序号，旧确认不能读掉新通知，未来序号被拒绝；已读不完成任务。
- 提醒和通知没有创建实际付款；订阅提醒在真实投递后更新为 delivered。
- 无效租约、终态重跑及失败事务不会留下半条投递；通知事实和结果不能修改。
- 未知事件版本进入实际拒绝记录，普通员工不能读取异常队列；获授权人员看到的异常不含事件正文。
- 副本恢复和服务事件解决后，原通知显示当前结果，并停止显示仍需处理。
- 客户端拒绝外部地址和错配业务 ID；相关资料页继续执行自身授权。

## 3. 尝试记录与清理

[部分旧来源后端批次](attempts/backend-before-browser-fixture-correction.json)保留了浏览器夹具修正前的 4 个批次。期间变更了仅供浏览器使用的 MFA 夹具初始化，全量检查检测到来源变化后拒绝继续拼接；本增量重新执行完整回归。

[Web 早期检查](attempts/web-before-inbox-count-correction.json)将实际两条本人通知误断言为一条，已改成与真实本人 API 列表逐一比对；[Taro 早期检查](attempts/mobile-before-title-selector-correction.json)未包含通用页面标题附带的品牌句点，已修正选择器。两次页面尝试均记录所属浏览器关闭、隔离数据库清理及临时服务停止；最终成功记录独立保存。

两组最终页面记录均要求源码运行前后不变。Taro 还单独核对夹具启动前、H5 构建后与浏览器执行时的相同源码。私有登录资料仅存在忽略的临时夹具，结束后删除，未写入交付报告。

本机 5178 Web、18080 开发 API 和 notification worker 作为继续开发的入口保留；5189 页面验收服务及所属浏览器／上下文在结束后关闭。最终开发库检查在全部隔离测试结束后执行。
