## 3. 主要风险与处理

| 风险 | 严重度 | 具体触发条件 | 处理与责任 |
| --- | --- | --- | --- |
| 官方 Codex/OpenAI 资格不适用 | 高，可能阻塞原路线 | 香港使用、境内服务器与官方地区政策不匹配 | 产品负责人/账号所有者确认；未满足前不承诺该 AI 路线生产可用 |
| 境内到 TG/模型/R2 链路不可用或不稳定 | 高 | 既有网络无可靠授权连接，长传输频繁失败 | 运维做真实路径验证；合规接入或独立网关须另作架构决策，不将换出口等同资格解决 |
| 120 GB 上传被错误按普通附件实现 | 高 | 一次读内存、整文件过业务网关、过期重传 | 后端/移动工程师做真文件、断点、重启与内存验收 |
| 2 TB 首迁时间和出口费用超预期 | 高 | 低有效带宽、重复校验、路径双重出流量 | 先测样本账单和实际吞吐，分批迁移、限速、保留来源 |
| 小程序发布主体/类目不适用 | 高 | 公司主体、内用登录或服务类别不满足平台要求 | 产品负责人在 P0 核实资格、测试账号和提审说明；平台审核时间外部依赖 |
| Android 后台上传不稳定 | 高 | 文件权限丢失、系统杀进程、网络切换 | 原生上传任务模块和持久化权限；验收恢复能力而非无限后台存活 |
| AI 越权或受文档提示操纵 | 高 | 使用管理员共用凭据、工具信任模型身份、共享上下文 | 工具网关重鉴权、OS 限制、上下文隔离、恶意样本验证 |
| 并发/重试重复修改 | 高 | 多端同时更新、模型重复调用、网络超时 | 基础版本检查、幂等 Key、提交记录与短事务 |
| 云端有副本但无法恢复 | 高 | 仅附件备份、数据库引用不匹配、密钥遗失 | 双云 DB 备份、恢复清单、实际恢复演练与独立密钥保管 |
| 复制延迟被误认为没有数据风险 | 高 | 最新 120 GB 文件未复制，界面却显示全部已备份 | 逐版本显示可用/复制/已校验；重要归档等待副本确认 |
| 费用重复、汇率口径混乱 | 高 | 同笔扣款关联多个模块、年费与摊销混算 | 统一实际台账、账期唯一、价格和汇率历史快照 |
| app-server/运行时升级不兼容 | 中高 | 实验协议、事件或工具权限行为变化 | 冻结版本、适配接口、回归样本、回滚、候选运行时替换 |
| 单应用节点故障 | 中高 | 服务器或磁盘失效，监控也在同机 | 外部探测、状态外置、自动重启与重建手册；高可用另付成本 |
| 文件/版本增长快于估计 | 中高 | 120 GB 二进制重复版本、保留无上限 | 按版本统计、保留规则、恢复窗口协调，定期看费用 |
| 模型输出事实或金额错误 | 中高 | 合同提取、票据 OCR、摘要推断被当正式事实 | 附原件/来源、校验金额币种、人工核实关键字段 |
| AI 长任务费用失控 | 中 | 全量文件入上下文、重复失败重试 | 元数据优先、任务预算、并发与循环上限、逐任务计量 |
| 范围持续膨胀 | 中高 | 将“完整 OA/项目管理”扩展成通用财务/ERP | 当前闭环逐项验收，新需求登记、重新评估排期 |

官方地区依据见 [支持地区](https://developers.openai.com/api/docs/supported-countries)。本表提出技术和运营控制，不作公司具体法律资格结论。

## 4. 待确认问题

### 立项/P0 必须确认

1. 服务器云厂商、境内区域、OS、CPU/RAM、磁盘、出口带宽/流量计费，以及是否已有独立 PG、域名/证书和 OSS。
2. 你司核准的 Codex/模型账号使用资格；若官方路线不可用，是否接受另行评估可用模型与运行时，还是将其作为首发阻塞。
3. 微信和抖音开发者主体、现有 AppID、适用发布类别、员工专用登录的审核材料；Android 采用签名 APK 内部分发还是应用商店。
4. 合同、报销、采购各由谁提交/审批/经办，金额阈值、退回/撤回/本人审批规则；三人组织下可否兼任。
5. 项目“完整闭环”是否接受需求文档定义，是否还要求甘特编辑、复杂资源排程、外部客户验收入口等。
6. 120 GB 文件的实际类型、数量分布与当前来源；是否存在加密压缩包、镜像、视频或备份档；2 TB 文件的当前权限与归属。
7. 公司的记账币种、涉及原币、月报按实际支付还是发生额，年费是否需要摊销；付款执行是否仅人工记录。
8. 可接受的开发投入、每月运行预算、期望首发日期和项目负责人。

### 设计冻结前确认

9. 主存储优先考虑香港访问速度还是境内运维/网络成本；是否要求具体地理区域证明，哪些资料允许进入 R2/模型/TG。
10. 回收站、合同签署件、版本、会话、费用和审计的实际保留周期；是否需要额外独立管理域备份。
11. 对跨云数据库 RPO ≤ 8 小时、大文件按实际复制完成时间暴露风险的接受程度；更低指标所需投入。
12. 股东 TG 群/话题的共同披露范围、成员变更负责人，是否需要群定时简报。
13. 服务与服务器清单、已有监控、告警接收人和维护窗口。
14. 首发需支持的 PDF/Office/票据样本、OCR 语言和格式保留要求；项目博客是否只用于内部。
15. 普通写入、批量整理、归档和通知的预授权规则，以及哪些操作必须固定计划后由指定人确认。

## 6. 试点与正式首发的质量门

内部试点可以使用受限测试数据、部分业务和开发版本，目的是发现问题。正式首发需：核心业务规则由负责人确认；资格/平台发布门槛明确；所有阻塞级验收通过；2 TB 迁移核验完成；120 GB 续传/复制实测通过；恢复演练成功；费用与告警可见；运维与签名密钥有负责人。

若某项条件未满足，准确标记对应功能与影响，不用“基础上可用”代替用户要求的全端首发验收。
