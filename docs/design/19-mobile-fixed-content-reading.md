# 固定版本阅读页风格与交互约束

日期：2026-10-24。对应[官网风格总规范](00-style-design-specification.md)的 VC-01—09、[组件契约](07-design-handoff-and-component-contracts.md)及[移动内容协议](../development/46-mobile-fixed-content-reading.md)。本页将官网的颜色和秩序用于真实附件核对，不另设文件模块主题。

## 1. 风格继承

官网暖灰白画布、墨色文字、蓝色强调和双主题 Logo 属于已核实来源 O；下表的阅读页面组合及预算属于内部设计 D。最近官网资源复核见[来源记录](evidence/website-source-refresh.json)，本次未改动官网色值或现有语义令牌。

| 页面元素 | 浅色 / 深色令牌 | 设计约束 |
| --- | --- | --- |
| 画布 | bg.canvas：#F6F6F4 / #0F131A | 稳定实色，避免阅读时背景动画 |
| 内容与资料面板 | bg.surface：#FFFFFF / #171D29 | 同一版本一组资料，不逐字段套卡片 |
| 正文与版本 | fg.default：#15171A / #E8EDF8 | 正文正常对比，长文件名可以完整换行 |
| 时间、大小与说明 | fg.muted：#5D636D / #A0ACC2 | 辅助文字保持可辨识，不隐藏关键差异 |
| 主要读取动作 | action.fill / action.on | 浅色墨底浅字，深色反转；同一状态只保留一个最强动作 |
| 链接、焦点与来源 | accent.fg：#1F5EFF / #79A2FF | 蓝色表达当前位置与访问，不代表审批通过 |
| 完整性提示／错误 | status.success / status.danger 的 fg/bg 配对 | 必须同时写出实际事实，不能只显示绿点或红点 |

文字使用既有 UI 字体栈；内容原文使用 mono 字体栈及中文回退。业务阅读页不使用展示性衬线大标题替代可读正文。面板、按钮、间距、边框和安全区沿用全局规范；没有新增孤立色板。

## 2. 页面结构

页面标题固定“固定版本阅读”，顶部保持公司标识和“我的”。主体顺序为：固定对象与版本 → 扫描／可用性 → 完整摘要 → 读取说明与动作 → 错误或已核对内容 → 清除 → 返回文件资料。返回优先回到上一页，直接进入页面的情形才回退到准确版本资料。

```text
copypaste.                                      我的
COPYPASTE / FILES
固定版本阅读.

这个固定版本
  文件名称 / 原文件名
  版本 N · 当前版本或历史版本 · 大小
  扫描结果 / 可用状态
  SHA-256：完整值，可选择与换行

读取说明
[读取这个版本的内容 →]

固定版本内容
  完整内容摘要已核对
  文本原文 / 图片 / 本机文档打开入口
[清除已读取内容 →]
[返回文件资料 →]
```

历史版本不能借用当前版本的正文、原名或摘要。当前逻辑文件名可作为上下文，版本原名独立显示。任何“当前”字样必须明确指向当前版本，不能将历史依据着色成当前业务事实。

## 3. 状态与动作矩阵

| 状态 | 必须呈现 | 可用动作 |
| --- | --- | --- |
| 元信息读取中 | 常规读取提示，尚无内容 | 等待／返回 |
| 可以阅读 | 固定版本、大小、扫描、摘要 | “读取这个版本的内容” |
| 正在读取 | 实际已处理字节 / 固定总大小 | “取消读取”；不并列再次读取 |
| 完整校验通过 | “完整内容摘要已核对”及对应内容 | 重新读取、清除、返回 |
| 内容截断／摘要或格式不符 | 准确失败说明，不出现完整性成功标识 | 重新读取或返回资料 |
| 未支持格式／超过预算 | 明确本页能力边界与 Web 原件下载说明 | 保留资料访问，不创建虚假预览 |
| 扫描未通过／豁免 | 区分未通过和正式豁免，禁止称豁免为 clean | 查看资料；不在本页预览 |
| 权限或登录变化 | 清除本页暂存，按当前鉴权结果处理 | 重新登录／刷新可访问资料 |
| 隐藏后返回 | 固定元信息重新读取，正文不恢复 | 重新主动读取 |

进度用真实已校验／暂存字节，达到总大小后仍须通过完整摘要才能展示正文。不能以进度 100% 代表人工已核实。取消后的迟到响应不得恢复内容或显示成功。

## 4. 内容呈现

文本保持原有换行，长行自然折行，可选择内容；HTML／脚本标签作为文字出现。Markdown、CSV 和 JSON 本轮均显示原文，不自动执行、联机加载图片或生成外部链接。空文本有明确空内容说明。

图片保持原比例、宽度不超过内容区；解码失败有可见提示。图片像素内容属于文件，不为了深色主题改色或加滤镜；外围画布、说明和操作同步换主题。

PDF／Office 仅在完整验证后交由本机查看器打开。打开前说明系统查看器可能保存自己的副本；打开失败有可操作的 Web 下载说明。系统查看器的字体、工具栏与颜色由平台控制，不能伪称完全符合品牌皮肤。H5 本地审阅页明确提供文档格式降级，不嵌入 PDF／Office；此处的真实传输与摘要通过不等于文档渲染通过。

“完整内容摘要已核对”仅表达传输完整性；不能使用“已阅读”“已验收”“审批依据已核实”等字样代替员工判断。原审批和交付验收的独立核实声明保持默认未勾选。

## 5. 窄屏、主题和可访问性

本地布局基线覆盖 320、390、768 CSS px 与明／暗主题。窄屏保持单列，摘要允许任意字符换行，原文长行不撑宽页面；按钮和链接命中区至少 44 CSS px。焦点采用既有蓝色可见描边，错误不依赖颜色。

阅读大图／长文本时只在内容本身允许正常滚动，不把所有操作堆在图上。读取／取消／错误文案保持稳定名称。切换主题会触发页面隐藏，内容按隐私规则清除；返回后重新主动读取，不能为了截图自动恢复正文。

截图须记录是页首还是滚动后的可见区域。Taro H5 内部滚动可能使 fullPage 截图仅包含当前视区，不能仅凭一张截图声称长文所有部分都经过视觉检查。

## 6. 验收与证据边界

TC-MULTI-06 本地证据包括：准确历史文本与当前正文、真实 PNG、双段 PDF 完整性、未支持格式与预算降级、截断、取消、内容清除、成员撤销及存储检查。内容读取前后不替换实际 API 响应；本地受控对象端保留真实上传和正式提交的字节。

最终记录应包含源代码摘要、构建与 UI 来源一致性、截图及其人工检查结果、浏览器上下文／标签页关闭、本地数据库与审阅服务释放。失败尝试单独保留。记录入口为[移动内容证据](../quality/evidence/mobile-content/result.json)。

微信／抖音真机、Android、原生临时目录清理与查看器行为仍需独立记录。本文不以 H5 或两端编译替代这些结论，也不将当前 1／32 MiB 阅读预算写成 120 GB 文件能力已验收。

## 7. 本次实际检查

2026-10-24最终[真实 UI 记录](../quality/evidence/mobile-content/result.json)通过10条链、5组页面各6种主题／宽度组合，共30组布局；保留10张390px截图。明暗画布计算值、无横向撑宽及44px触控边界均经过实际页面检查。

[四张最终截图复核](../quality/evidence/mobile-content/visual-review.json)覆盖浅色历史原文、深色图片、浅色超预算及深色截断错误；完整摘要和原文标签可读，错误区不出现成功标识，图片未因主题改写颜色。开放P3：1048577字节被格式化为1.0MiB，预算提示可补充精确大小／上限解释边界；没有将该问题登记为正式发布豁免。原有全局长标题装饰点问题也未因此关闭。

本地 H5 不再嵌入 PDF／Office，使用明确格式降级；PDF 的两段真实字节和完整摘要仍已通过。被浏览器拦截的早期 PDF 嵌入保留为[失败尝试](../quality/evidence/mobile-content/browser-pdf-embedding-attempt.json)，不是最终通过证据。
