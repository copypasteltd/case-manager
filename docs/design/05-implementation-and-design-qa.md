# 设计实现、验收与维护约束

版本：v1.0.0-draft；日期：2026-10-23。适用于产品/设计/React/Taro/Android/测试；与 [工程规范](../development/01-system-and-engineering.md)、[页面矩阵](../development/06-clients-and-pages.md) 和 [发布门禁](../quality/02-traceability-and-release.md) 配套。

## 1. 令牌与代码的唯一来源

tokens.json 是本项目自定义、可机器读取的设计令牌格式，包含两个主题各39个同名语义值、字体、排版、间距、圆角、尺寸、断点、动效与层级。它不是已声明兼容某个外部令牌交换标准的文件，不应直接承诺任意设计工具无损导入。

修改顺序为 JSON 源→生成 CSS→同步文档/组件→检查组合对比度→检查样板/实际页面。禁止只改生成文件。原生生成命令在仓库根目录执行：

~~~powershell
python -X utf8 app/scripts/check_website_design_sources.py
python docs/design/build_tokens.py
python docs/design/verify_design.py
node docs/design/review_styleguide.cjs
~~~

前三项仅依赖原生Python标准库；来源复核需要HTTPS网络，只读取官网5项公开资源并比较原取证与本地标识，不自动更新令牌或Logo。浏览器复核脚本使用本机现有Playwright与Edge，默认路径见脚本；换机器需配置其环境变量或修改本机路径，不能假定所有开发者都有当前用户目录。它使用file://打开本地样板，不需要本地Web服务或虚拟化。

本目录的脚本只生成设计CSS、检查文档/颜色、采集官网或审阅样板，不实现产品接口。不能把这些命令通过当作业务测试通过。

## 2. React/Vite落地

建议依赖方向：业务页面→业务组合组件→基础UI组件→主题/令牌。禁止基础按钮组件直接调用审批API，禁止页面自行复制一套颜色/焦点处理。组件库可选用成熟库，但先确认版本、授权、可访问性和React兼容性；选定后统一theme adapter，不因默认主题方便就更换品牌主色。

在未来工程公共styles层导入生成CSS，以CSS变量构建基础组件。业务代码使用语义token，不硬编码色值；文件类型插画等确需局部色彩时登记用途/主题/对比度，不直接增加无语义颜色常量。设计稿色板、前端变量、图表和状态文案按同一版本维护。

主题初始化放在首次绘制前或等效入口，读取显式外观偏好，否则跟随系统；监听系统切换只对「跟随系统」生效。偏好读取失败回退浅色，不阻塞登录。内容权限与主题无关，禁止把token/主题中的配置当安全授权。

表单、可访问名称、键盘处理、浮层焦点、日期/金额、状态组件统一封装。业务按钮显隐只能改善体验，最终权限由后端执行。文档/消息/文件预览遵守消毒与隔离，CSS主题不能放宽CSP或执行上传内容。

使用当前浏览器支持范围内的CSS；断点媒体查询由tokens.json生成适配或在构建时注入，不能把CSS自定义属性直接放入原生媒体查询条件而假定浏览器支持。字体/间距可按适配器转rem并支持用户字号，不将字体缩放锁死。

## 3. Taro/Android适配层

共享的是语义值、状态映射、字段格式与设计原则。微信/抖音以编译结果和真机为准，是否可直接使用CSS变量、选择器和字体需要逐端验证；不支持时构建期解析JSON输出静态主题样式。Android原生样式读取JSON映射到实际支持的样式属性，不把CSS阴影字符串、font-family串或z-index直接作为原生属性。

单位适配独立处理：Web设计px、小程序rpx/px、Android dp/sp。只转换适合缩放的尺寸，最小触控、文字放大、细线与原生导航分别验证。深色主题、键盘、系统返回、安全区、文件预览、后台上传不能仅靠共用JS组件宣称一致。

图标统一资源集，品牌Logo使用核验过的PNG双版本；不能用名称相同但未核验的SVG悄悄替代。字体内置需要授权/包体/加载和中文覆盖记录；无字体包时显示回退是允许状态，截图验收注明实际字体。

## 4. 组件/页面完成清单

| 交付项 | 就绪标准 |
| --- | --- |
| 页面说明 | PG编号、角色/capability、数据来源/精确DTO、核心动作及风险 |
| 布局 | 桌面/移动主要断点、长文本、空/加载/失败/失权/过期/冲突/离线 |
| 视觉 | 双主题、JSON语义token、密度与图标、金额和版本完整显示 |
| 可访问性 | 名称/标签、键盘顺序/焦点、错误关联、读屏、放大/重排 |
| 业务事实 | 审批/付款、传输/正式版/副本、计划/执行等严格分层 |
| 测试证据 | 截图/录屏、运行版本、浏览器或真机信息、输入数据与结果 |
| 隐私 | 使用合成/脱敏数据；源文件、票据、合同不被设计工具或截图外泄 |

设计规范发布不要求当前立即选择Figma或新增付费工具。未来采用设计工具时保持组件命名与令牌语义一致；设计源、评审记录和资产索引仍在docs/可追溯。

## 6. 与工作包/门禁的衔接

WP-02建设令牌和基础组件；WP-03—10在各领域交付页面/状态/业务组件；WP-11落实Android与多端尺寸适配，WP-12分别做微信/抖音真机；WP-14执行设计验收与业务回归。

G1：该工作包页面/关键状态与精确接口已定义，令牌/风险文案可评审；G2：Web完整闭环含错误、焦点和事实状态；G4：四端真机、响应式、可访问性与实际平台限制有证据；G5：影响权限、金额/审批解释、关键操作或内容可读性的设计缺陷全部关闭。单纯像素偏差按影响分级，不新增无依据的停工审批。

## 7. 版本、责任与变更

产品负责人维护术语/旅程/权限含义；设计负责人维护视觉和组件；前端维护适配器/样板；测试负责人维护用例与证据。同一人可兼任，需指定实际责任人后再排期，不虚构当前团队已有岗位。

语义删除/改名或交互事实变化按破坏性变更处理；新增兼容token/组件可次版本；色值/布局修复用修订版本并记录影响页。当前draft只是设计基线，版本号不等于产品发版。

官网变化不能自动覆盖内部已验收组件：先重新取证→差异表→对比度与回归→更新设计基线。必要无障碍修正可在品牌基因内派生，不为了「官网一致」保留已发现的低对比组合。

## 8. 工具环境与资源释放

所有文档、资产和验证证据在docs/；已有设计支持脚本保留在本目录，后续新增开发脚本与产品代码放在app/。禁止为本地审图和开发测试启动Docker、WSL、虚拟机或Android模拟器。浏览器只创建本任务拥有的上下文，不连接用户现有配置；结束后关闭全部本任务不再使用页面/上下文/进程，并记录关闭结果。不得为了释放内存杀掉用户原有浏览器进程。

## 9. 可复现的来源与样板检查

在仓库根目录使用原生环境执行：

```powershell
python -X utf8 app/scripts/check_website_design_sources.py
python -X utf8 docs/design/verify_design.py
node docs/design/review_styleguide.cjs
```

来源脚本读取原始取证中的5项当前使用资源，核对HTTPS响应、字节哈希与本地PNG，更新来源复核JSON；不启动浏览器，也不自动覆盖设计资产。资源变化或本地Logo不符会返回非零，需要重新比较视觉基线。样板脚本使用独立无头Edge上下文，检查结束在finally关闭所有所属上下文和浏览器；结果记录到docs/design/evidence，不能推定真实业务页面或各原生端已通过。
