# 项目结项核查与归档复盘设计

日期：2026-10-24。状态：本地 Web 实现、实际操作与四张截图复核已完成；完整移动流程、辅助技术及生产验收仍未完成。证据与范围见本页第 8 节及交付台账。遵守[总体风格](00-style-design-specification.md)、[组件规范](03-components-and-patterns.md)、[项目需求](../requirements/03-projects-and-knowledge.md)及[结项开发协议](../development/44-project-closeout-and-archive.md)。本页只细化产品与视觉行为，不另定合同、付款或审批规则。

## 1. 风格与信息层级

沿用官网的暖白画布、黑白主按钮、蓝色链接／焦点和克制边框；深色主题使用既有令牌。页面不引入新品牌色、渐变、插画或营销式大标题。业务内容采用现有无衬线字体，长项目名、任务名、中文和连续英文均须换行。

项目页增加“结项与归档”页签。项目概览内的“发起结项核查”和“归档项目”进入该页；普通通用状态对话框不能直接归档。页首依次展示用途、重新核查、总体核查状态、项目版本与香港时间，随后为十三类清单和归档历史。

版面使用现有 surface／border／muted 令牌和 16 px 圆角容器；每个类别为可展开清单。摘要显示类别、文字状态及有权查看的数量。预算是参考版本，类别与条目均用中性徽标，并显示真实预算修订号，不能用批准色暗示已经发生费用。颜色只辅助表达，不能独立表示通过或受限。

## 2. 核查清单

| 状态 | 必须展示 | 可用动作 |
|---|---|---|
| 读取中 | 正在核对项目与财务事项 | 等待读取；不提前显示零 |
| 已知有阻塞 | 具体类别、待处置数量和授权对象；优先展开 | 打开原记录处理；closing 时说明须先恢复进行 |
| 当前规则未发现阻塞 | 完整可见范围、实际数量、项目版本和时间 | 仍须人工核对实际情况，进入结项阶段或填写复盘 |
| 权限受限 | “尚未核实”，明确没有完整核查权限 | 安排有相应权限的人员处理；不展示条目、数量、指纹或归档动作 |
| 读取失败 | 错误、可用重试及请求编号 | 隐藏旧成功数据，不把缓存当作最新核查 |

各类展开后先说明判断口径，再给真实记录链接、版本、中文状态和是否阻塞。普通任务、里程碑、交付、风险和问题回到对应项目视图；合同、采购、报销、费用、资金、订阅和变更进入各自对象页。新链接不得通过标题、数量、金额、隐藏 DOM 或游标泄漏未授权数据。

## 3. 两步人工动作

进入结项阶段的对话框说明内容将变为只读，要求填写原因，提交前服务端重新检查全部事项。该动作不产生归档记录，也不替代复盘。之后归档表单按以下顺序展示：

1. 准确项目名称／版本和本次操作影响。
2. 错误或过期依据提示、保留填写内容的重新核查入口。
3. 本次采用的十三类核查清单。
4. 成果与交付总结、经验与复盘、后续跟进三段文本。
5. 可选正式文件版本，展示文件名／版本／字节数，最多 20 个，不把文件名相同当作同一版本。
6. 归档原因。
7. 两项初始未选的核实：业务闭环；合同／采购／报销／费用／资金／退款／订阅处置。
8. 真实近期 MFA 状态或验证入口，以及明确的确认归档按钮。

“后续跟进”无待办时也须明确说明。该字段不得当作忽略阻塞的入口。复盘附件按正式版本固定，移除选择不删除源文件。验证成功后不自动归档，按钮只在权限、阶段、完整依据、填写内容和两项核实满足时可用。

## 4. 错误、并发和键盘

服务端字段错误显示摘要和可聚焦到对应输入的链接；保留标签与控件的同一稳定 ID，不由基础组件重写显式 ID。错误摘要可接受焦点，嵌套文件选择器关闭后焦点留在当前归档对话框内，关闭归档对话框后回到合理入口。

409／412／失权提示必须保留复盘、原因和附件。旧依据不能再次提交；人员明确重新读取后，展示新项目版本与核查结果，两项核实清空，待重新核实后再提交。重新读取失败仍保留输入，不自动视为更新成功。未知网络结果提示保留窗口并重试原内容或核对项目状态，不编造成功。

所有表单有标签、中文动作和文字状态；复盘输入使用自然换行。复选框为 24 px，整行标签至少 44 px 高；按钮／链接采用既有触控和焦点规则。页签保留方向键导航，Dialog 保留 Tab 限制和 Escape／关闭的忙碌保护。不能仅靠红／绿状态、鼠标悬停或桌面布局表达结项信息。

## 5. 历史与受控重开

历史卡按时间倒序，摘要显示归档时项目名、归档项目版本与日期。展开显示不可改写的三段复盘、原因、操作者当前姓名、记录时间、固定附件，以及当时清单。原始嵌套财务载荷不放入客户端 DOM。

当项目仍与该次归档版本和事实一致时显示当前依据一致；受控重开或其他来源变化时说明此记录保留当时情况，当前情况请看最新核查。不得覆盖旧复盘、把旧状态改成最新状态、或把旧归档删掉。再次归档保留独立新记录。姓名属于当前用户资料，不宣称历史姓名已经固定。

权限不足时整份历史隐藏，说明当前无法完整查阅；不展示“0 次归档”、历史标题、复盘、条目数量或分页游标。当前授权失效也不得继续展示上一次缓存的成功内容。

## 6. 跨端和验收

320／390 px 采用单列，清单项状态放到标题下方，摘要可换行，对话框不得超出屏幕；768／1024／1440 px 保留同一顺序和状态语义。双主题都使用既有品牌与语义令牌，不把通过状态换成大面积品牌蓝。长项目名和连续英文名必须在实际页面验证。

小程序和 Android 应复用十三类口径、精确版本、权限结果、复盘字段和人工确认语义，但须另做原生表单、存草稿、身份核验、导航和真机测试。当前 Web 浏览器五档宽度通过不代表微信、抖音或 Android 通过。真实 Web/API、截图、人工视觉复核和浏览器清理证据应与对应源代码版本一起归档；仅有样板或编译不构成业务页面验收。
