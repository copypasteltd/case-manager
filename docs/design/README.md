# CopyPaste 内部平台风格与设计规范

版本：v1.0.0-draft；更新：2026-10-24；适用：React/Vite 管理端、Taro 微信/抖音小程序、Android。状态：依据当前官网形成的设计基线，供评审、原型和开发执行；实际产品实现与验收另见[实施台账](../delivery/02-implementation-ledger.md)。

## 1. 设计结论

内部平台延续官网的「暖灰白画布、墨色内容、克制蓝色、衬线品牌标题、细描边圆角面板」。主操作沿用官网黑白按钮，品牌蓝承担链接、选中、焦点和来源标记。深色主题采用官网蓝灰黑背景与浅蓝强调色。工作页面以清晰的信息层级和稳定的数据布局为中心。

官网的宣传性大标题、轨道动画和大段留白只适合品牌介绍。内部平台将这些元素收敛为工作台标题、品牌标识和局部强调；表格、金额、审批、文件及秘书会话使用易读的无衬线字体与紧凑但可操作的尺寸。

### 1.1 核心色系速查

以下色值来自官网；产品通过语义令牌使用，具体前景/背景搭配见[视觉基础](02-visual-foundations.md)，不能任意互配。

| 角色 | 浅色主题 | 深色主题 | 内部平台用途 |
| --- | --- | --- | --- |
| 画布 | #F6F6F4 | #0F131A | 页面底色 |
| 面板 | #FFFFFF | #171D29 | 表格、表单、详情和会话 |
| 主要文字 | #15171A | #E8EDF8 | 正文、标题；亦为主按钮填色 |
| 主按钮文字 | #F6F6F4 | #0F131A | 随主题反转，与 action.fill 成对使用 |
| 次级文字 | #5D636D | #A0ACC2 | 时间、版本、来源与辅助说明 |
| 强调蓝 | #1F5EFF | #79A2FF | 链接、焦点、来源标记；选中文字另用专用令牌 |
| 轻描边 | #D8D9DE | #2A3344 | 面板与内容分隔；输入边界另用专用令牌 |

字体采用「少量衬线品牌标题 + 无衬线工作内容 + 等宽版本/代码」。形态采用细描边、16px面板圆角和胶囊主按钮；完整字体回退、交互尺寸和跨端单位分别由第02、04份规范约束。

## 3. 约束等级与冲突处理

首次阅读可按「风格设计总规范 → 官网实证 → 视觉基础 → 品牌应用与文案 → 组件与页面 → 设计交接与验收」的顺序；实现时直接引用令牌与组件契约，不从截图手工猜色。

**O（Observed，官网实证）**表示本次实际读取/看到的官网内容。**D（Derived，产品扩展）**表示为后台、多端和可读性新增的设计决定。D 不应被写成官网原有官方品牌规范。两类都以本目录说明为当前设计草案。

用户确认的业务范围与 [治理基线](../governance/01-baseline-and-rules.md) 优先；权限、金额、版本、上传与副本等真实状态以需求和接口契约为准。设计只能表达这些事实，不另建简化业务状态机。视觉数值以 tokens.json 为准，tokens.css 由生成器产生；发现文字与令牌不一致时先修正文档与源，不允许各端自行选一个。

本文的「必须/禁止」是实施约束，「建议」允许在记录理由、验证可用性后调整。修改颜色、密度或交互不得降低权限提示、事实完整性和无障碍标准；无需为遵守既有范围内的日常 UI 修正逐次请求用户许可。

## 4. 五条实施原则

1. 品牌一致：保留真实官网配色与黑白主按钮；禁止自动套用另一套模板主色或渐变。
2. 内容优先：先给待办、对象、金额/币种、版本和时间，再给装饰；首页不做营销 Hero。
3. 状态可信：审批通过不等于已付款，上传完成不等于双云备份完成，未知不等于正常。
4. 多端同义：四端共享术语、字段和授权结果，布局及原生能力分别适配。
5. 操作可恢复：保留草稿、展示冲突和逐项结果，秘书执行有范围、来源和证据。

## 5. 交付边界

本套交付包含官网风格实证、可执行视觉规则、组件/页面约束、跨端规范、令牌和可查看样板。样板用于检查风格与布局，不是运行中的 OA、上传器、模型、TG 或监控系统；也不替代后续各业务页面的线框稿、真实接口联调与真机测试。

全部文档、设计资产与证据放在 docs/；本目录保留早期设计支持脚本，产品实现和后续新增开发脚本放在 app/。本次使用 Windows 原生 Python/Node/Edge 取证与检查，不调用 Docker、WSL、虚拟机或模拟器；浏览器仅创建独立临时上下文，并在完成后关闭。
