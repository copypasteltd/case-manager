# 采购差异重审与执行基线页面设计

日期：2026-10-24。适用采购详情和独立差异申请，属于产品派生规则 D。继承[总规范](00-style-design-specification.md)、[组件契约](07-design-handoff-and-component-contracts.md)与[采购实施协议](../development/40-purchase-variance-approval-and-execution-baselines.md)。当前实现与实际验证范围分别以实施记录和证据为准。

## 1. 视觉和业务表达

沿用官网的暖灰白画布、蓝灰黑深色画布、细描边面板、墨色主按钮和品牌蓝链接／焦点。界面新增业务信息层级，颜色继续使用现有语义令牌，不为“采购差异”另设模块主色。

必须分别展示原商业批准、当前执行总额、完整差异申请和明确启用事实。审批状态用既有审批徽标；执行依据用中性徽标和具体文字。提案“已批准”旁必须说明是否启用，不能仅凭绿色徽标表示新额度可以使用。历史启用基线被后续基线替代时，写明“历史已启用基线”，不能继续标为当前。

金额始终携带原币，使用可复制的准确十进制文字；不以进度环、柱状条或百分比代替数量和金额事实。数量、价格、订单占用、验收和真实费用各有名称，不统称“完成率”。

## 2. 入口与当前事实

采购详情在原商业批准之后、订购验收之前，增加“执行基线与差异重审”分区。按原批准金额、当前执行总额、来源、启用时间、提案列表排序。原批准内容继续展示原始商业事实。

独立差异详情仍归属“采购管理”：侧栏保持采购入口选中，顶栏显示采购管理，返回入口指向准确父采购。审批申请页面沿用“业务申请”归属，并提供准确提案链接，避免同一申请被误认为另一个模块的对象。

具备服务器返回的创建能力时，展示“起草采购差异提案”；必须先取得当前执行依据，读取失败不能用旧批准内容静默兜底。列表项目显示编号、名称、拟执行金额、审批状态、固定采购版本、更新时间和是否为当前基线。分页只展示当前获授权的条目，不能先获取全部标题后由浏览器隐藏。

订购验收区将上限明确标为“当前执行数量／额度”，将占用标为“执行额度占用”。订单详情保留登记时固定依据、供应商和价格，不能随着最新基线重新计算历史金额。

## 3. 起草与明确修订

表单打开时固定当前采购版本与执行基线。创建时从当前完整执行内容起草；修订保留提案内容，并明确告知这次保存将固定当前采购版本作为新的审批依据。用户可以展开查阅当前完整执行依据。

| 内容 | 表达和约束 |
| --- | --- |
| 原币、计价、舍入 | 显示固定值；原币只读，规则不可修改 |
| 全部原行身份 | 保留；描述与单位只读，不显示增删行入口 |
| 数量、单价、税额、折扣 | 按行填写拟执行值，服务端精确计算金额 |
| 供应商、报价 | 通过有权选择器引用准确修订和正式版本 |
| 目的、交付、预算、备注 | 提供完整拟执行说明，不能只提交自由文本差额 |
| 创建／修改原因 | 明确填写；不自动代替员工确认 |

版本或权限冲突时保留全部输入，显示核对提示，阻止继续用旧依据保存。不自动换成最新版本提交，也不把“重新加载”实现为覆盖当前编辑内容。

## 4. 提案与审批详情

详情先显示提案名称、编号、分类、审批状态及是否启用，再显示动作和完整内容。顺序为固定采购版本／来源、原执行金额／拟执行金额、送审时的履行集合、送审时完整执行依据、完整拟执行内容。两份内容均包含全部行、供应商与准确报价版本。

“送审时的履行集合”逐行列出当时执行数量、占用数量、净验收数量、待收数量、占用金额、税额和折扣。它是固定的审阅依据，不随新订单刷新。当前采购已变化时在上方提示须重新核对、修订并重审。

独立申请页面、送审预览和历史均复用完整前后对照，制度名称必须为实际选中的采购差异制度。不存在制度、证据不可用或审批权限不足时显示服务器原因，不能转用普通采购制度。小程序申请详情也展示这两份内容和履行集合，审批操作沿用固定修订与顺序步骤。

## 5. 明确启用

“核对并启用执行基线”只依服务器能力展示。对话框包含原执行总额、拟启用总额、固定采购版本及完整前后内容，随后填写启用原因、勾选初始未选中的核对声明，并完成近期两步验证。主操作为“确认启用此执行基线”，沿用墨色按钮；验证身份不会提交启用动作。

```mermaid
flowchart LR
  A[当前执行依据] --> B[完整差异提案]
  B --> C[独立顺序审批]
  C --> D[获批待启用]
  D --> E[人工核对与近期 MFA]
  E --> F[后续订单使用新基线]
  E --> G[依据已变：保留输入并重审]
```

启用不生成实际订单、费用、银行付款或采购完成事实。新额度不得低于有效订单承诺和当前有效费用；无法完整核对关联费用时显示无法核对的原因，不能把不可见费用当作零。

## 6. 响应式、权限与验收

双主题检查宽度为 320、390、768、1024、1440px。事实区域沿用响应式定义列表，行项纵向排列，长名称和金额可换行。对话框限制在视口内并允许纵向滚动；键盘焦点始终留在最上层对话框，选择报价后回到原表单。交互目标遵循既有 24px 下限及移动端整行点击规范。

仅查阅人员不显示编辑、启用和商业修订历史入口。任何历史读取、旧链接和幂等重放都重新核对当前父采购及提案权限。无权读取时清除旧响应，不以旧缓存继续显示金额或附件。

验收至少覆盖完整 Web 起草／送审／指定人员审批／启用／后续订单、批准未启用、旧订单保留、当前基线来源、陈旧表单输入保留、只读分支以及双主题布局。受控小文件、隔离业务和桌面浏览器通过，不等同于真实云、真实采购、微信／抖音平台或 Android 真机验收。
