# 合同完成与终止页面设计

日期：2026-10-24。适用合同详情 PG-11，属于产品派生规则 D。继承[风格总规范](00-style-design-specification.md)、[组件契约](07-design-handoff-and-component-contracts.md)和[合同财务设计](11-contract-financial-reconciliation.md)。业务、权限及事务约束以[合同关闭实施协议](../development/39-contract-completion-and-termination.md)为准。

## 1. 入口与信息层级

合同详情在“合同财务归属”之后增加“完成与终止”分区。标题右侧展示当前法律阶段，正文先解释“依据实际条款和凭证人工登记法律阶段。未结事项和真实收付款继续保留，后续财务更正可单独登记。”

沿用暖灰白／蓝灰黑背景、细边框面板、墨色主按钮、品牌蓝链接与焦点。完成记录不使用整块绿色或庆祝图形；终止不是系统故障，不使用整块红色。警示色只用于未结事项、来源变化和冲突提示，颜色均取自语义令牌。

分区按以下顺序组织：当前未结事项、固定计划与归属净收付、相关费用结算、补充协议、允许的人工动作或既有结束记录。财务和法律阶段保持各自名称，不用“关闭”一个词代替多个不同状态。

## 2. 当前事实和权限

| 情况 | 界面与动作 |
| --- | --- |
| 无权查阅完整依据 | 显示“未结情况未知”；不展示旧金额、指纹或结束按钮 |
| 计划未知 | 明确说明收付款计划尚未明确，不显示为零或无义务 |
| 节点差额、未核对、条件未满足、退款未归属 | 分项列出；不能登记完成 |
| 关联费用未结清 | 展示准确费用入口、原币发生额和有效结算额 |
| 仍生效补充协议 | 提示先分别处理，父合同两个结束动作均不展示 |
| 其他未结束补充协议 | 列出准确入口及阶段；不能完成，终止须说明后续处理 |
| 当前完整依据满足完成条件 | 展示“登记合同完成”；仍须人工核实条款和真实凭证 |
| 合同已完成或终止 | 展示固定记录；后续财务仍有独立入口，不展示重复结束按钮 |

节点以纵向卡片呈现计划／净收付、当前核对／条件、未归属退款。币种与准确十进制金额同组展示。费用和补充协议使用可展开明细，链接带可理解的操作文字；员工不需要输入 UUID、指纹或数据库版本。

## 3. 人工登记表单

动作分别命名“登记合同完成”“登记合同终止”。对话框固定打开时的合同、节点、结算与补充协议依据；先展示合同名及本次依据，再填写以下内容：

1. 实际完成或终止日期：初始为空，按香港日期校验，不预填为今天。
2. 当时完整未结事项：只在确有事项时展开；终止须勾选“本人确认上述未结事项在终止后仍须处理。”并填写后续处理说明。
3. 条款与材料核实：复选框初始不勾选，另填核实说明，不能由系统自动确认。
4. 准确结束凭证：选择1—20项正式文件版本，展示文件名和版本号；删除选择不删除原件。
5. 登记原因、当前 MFA 和明确的业务提交按钮。

完成条件由服务端核对。按钮初始禁用，不用一项“确认全部”覆盖条款、差额、结算与未结事项。身份验证结束后仍由操作者点击业务提交，不自动执行。

## 4. 冲突、历史与后续财务

来源变化、第二设备操作或准确版本失效返回409/412时，保留日期、文字、凭证和复选项，停止继续提交，提示重新核对后打开新表单。不能静默刷新指纹、自动重试或将旧输入绑定新依据。

结束记录展示实际发生日期、登记人、香港登记时间、原因、核实说明、未结事项处理、固定凭证，以及“查阅登记时的固定依据”。历史金额标明当时依据，当前事实仍在上方。真实后续资金或结算变化时显示“登记后的财务、结算或补充协议依据已变化，须继续跟进”，原法律阶段继续保留。

固定凭证按准确版本读取，不能跳转到当前最新版。历史来源权限变化时重新鉴权；受限读取不能继续展示旧缓存中的金额或凭证。

## 5. 布局、主题与可达性

Web验证320／390／768／1024／1440五档宽度、明暗两个主题。节点、金额和动作自然换行，页面无横向滚动；长修订号可断行。对话框独立滚动，错误和提交动作均可达。复选框至少24px，整行点击至少44px；沿用已有可见焦点、模态焦点约束和嵌套文件选择器，关闭子选择器后焦点回到父表单。

移动端沿用同一事实语义、默认不勾选及冲突保留规则；原生微信、抖音、Android分别实现和验收，不以Web窄屏截图代替。Web实际验证及代表截图在[设计验证](06-design-verification.md)单独登记，未完成项在[实施台账](../delivery/02-implementation-ledger.md)持续跟踪。
