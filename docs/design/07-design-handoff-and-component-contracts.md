# 设计交接、组件目录与状态契约

版本：v1.0.0-draft；日期：2026-10-23。本文把已有风格规范落实为设计稿、组件和页面的交接约束；全部属于产品扩展 D，不代表官网已有完整组件库。它定义交付要求，不表示已创建 Figma 文件或已实现以下组件。

## 1. 交付物之间的关系

[官网实证](01-website-style-audit.md)解释品牌依据，[视觉基础](02-visual-foundations.md)定义颜色和尺寸，[组件规范](03-components-and-patterns.md)解释交互，[页面蓝图](04-page-and-cross-platform-design.md)定义页面范围。本文统一命名、属性、状态和评审记录；[关键页面展开](08-page-layouts-and-flows.md)用于页面设计和联调检查。

`tokens.json`是数值源，`tokens.css`是生成结果。设计工具中的变量、代码中的语义变量与截图上的数值必须对应同一版本。样板只证明样板自身的效果，产品页面的证据单独保存。

设计稿与开发交接最少包含：页面编号、组件引用、主题、尺寸与重排、数据字段、实际可用操作、状态分支、文案、焦点顺序、校验反馈和证据位置。不能只提供一张正常态图片。

## 2. 设计源的组织与命名

采用何种设计工具由团队选择；以下结构可用于设计工具页面、Markdown 或其他可维护设计源：

| 设计源区 | 必须包含 | 对应仓库依据 |
| --- | --- | --- |
| Brand | 当前 PNG 双主题标识、官网截图、来源与更新时间 | 官网实证与 assets/ |
| Foundations | 浅/深语义颜色、字体回退、字号、间距、圆角、层级 | tokens.json 与视觉基础 |
| Components | 基础组件、变体、状态、交互与可访问名称 | 本文 CP-01—28 |
| Patterns | 审批快照、文件保护、固定计划、财务口径等业务组合 | 组件与交互规范 |
| Pages | PG-01—19 页面、代表性宽度和适用状态 | 页面蓝图与关键页面展开 |
| Review | 对照结果、问题编号、修改原因、版本与验证证据 | 实现与设计验收 |

组件命名采用「CP / 类别 / 名称」，如「CP / Action / Button」「CP / File / ReplicaSummary」；页面命名采用「PG-10 / 审批详情 / 待处理 / 浅色 / 桌面」。状态用可理解的名称，禁止只有「方案2」「最终版」「新新版本」。

宽度标签对应实际检查值：320、390、768、1024、1440 CSS px。Android 设计标注逻辑 dp 与字体 sp；小程序另外标注设计基准、rpx/px 转换规则及实际编译结果，不能给不同单位使用一个未标单位的数值。

如选用 Figma 等工具，先人工或通过已验证的适配器建立变量映射。当前令牌是项目自定义格式，不承诺任意插件直接导入，亦不要求为完成本规范采购工具。

## 4. 交互状态契约

| 状态 | 主按钮 | 输入/选择 | 列表/详情 |
| --- | --- | --- | --- |
| 默认 | action.fill/on，动作名称具体 | surface 底、control 边、可见标签 | 正常正文，实际业务状态 |
| 悬停 | action.hover；不改变几何尺寸 | 可轻微加强边界 | bg.hover；行不跳动 |
| 键盘焦点 | focus.ring 2px、外偏移2px | 同样有可见环；错误边框不替代焦点 | 可聚焦动作/滚动区显示焦点 |
| 按下 | action.pressed；不触发双重提交 | 保留输入位置 | 选中对象与普通 hover 区分 |
| 处理中 | 固定名称/宽度，显示「正在提交」等事实 | 保留已有值，防止误改本次提交快照 | 旧内容可保留并标注刷新中 |
| 禁用 | subtle 底，disabled 字，提供可理解原因 | 禁止编辑但不让必要文字整体低透明 | 不把无权对象以禁用形式留在页面 |
| 只读 | 展示详情和有权导航；没有写入动作 | 使用正常正文色，可按需复制 | 明确只读原因，如「项目已归档」 |
| 失败 | 恢复可执行动作，保留失败信息 | 字段旁问题与错误汇总关联 | 局部错误不抹掉其他成功区块 |
| 结果未知 | 提供「查询处理结果」 | 保留本次内容与提交标识 | 显示待确认，不伪造成功或失败 |
| 版本冲突 | 提供比较/重新读取 | 保留未提交草稿，不静默重试覆盖 | 显示受影响版本和可恢复入口 |

禁用不是授权。失权应停止呈现受限内容、清理受限缓存并显示统一安全提示；不保留受限文件名、金额、正文片段作为灰色占位。

成功反馈要对应真实操作：「已保存草稿」「已发布修订」「已生成正式版本」。点击、收到请求或传输100%均不足以显示业务最终成功。

## 5. 尺寸与变体

| 变体 | 尺寸来源 | 使用限制 |
| --- | --- | --- |
| Compact | controlHeights.compact=32，tableRows.compact=44 | 精细指针工具栏；不能作为移动默认 |
| Default | controlHeights.default=40，tableRows.default=52 | 桌面常规；触屏通过外层命中区满足至少44 |
| Comfortable | controlHeights.comfortable=44，tableRows.comfortable=64 | 可触摸 Web、大量换行内容 |
| Mobile | controlHeights.mobile=48，mobileBody=16/26 | Web 窄屏/移动逻辑设计；各原生单位另适配 |

输入与工具按钮使用 control 圆角10，面板使用 panel 圆角16，主操作使用 pill 圆角999。多行按钮、辅助说明和200%字号应允许高度增长，不能为了维持指定行高裁掉文字。

状态标签本身不是按钮；需要可点击时必须给真实动作语义及符合尺寸的点击区域。表格行不能兼作包含一组不可分辨交互的单一大按钮，行内「打开」「更多」分别可聚焦。

## 6. 权限分支与数据属性

每个详情页应明确哪些字段可见、哪些操作可用，以及后端给出的限制原因。接口尚未提供操作能力字段时，设计交接须把该缺口列入 API 工作，不以「系统管理员」或某个前端角色判断代替对象权限。

| 使用情境 | 界面约束 |
| --- | --- |
| 仅有系统管理权限 | 可以配置获准事项；不自动展示全部项目、合同和文件 |
| 项目只读成员 | 可读范围内正常展示；隐藏编辑/状态变更入口，读操作不使用灰字 |
| 可编辑但不可发布 | 可以保存草稿；不能将「保存」写成「发布」 |
| 普通已发布文章读者 | 只见已发布标题/正文/来源与相应讨论，不提前看到新草稿 |
| 审批人 | 只呈现本次有权节点及准确修订，不以名单中存在名字等同可审批 |
| 秘书会话参与人 | 来源、工具、执行结果按当前身份与渠道披露；历史可见不代表当前仍有权 |
| 列表批量选择 | 先固定选择范围；提交时与结果返回时均考虑权限变化和逐项失败 |

设计示例中的角色、审批阈值、默认币种和默认分类不得冒充已确认配置。跨端展示同一个对象时，不因入口不同改变审批版本、账期或文件版本。

## 7. 内容与长数据压力样本

交接至少准备以下合成样本，并分别检查浅/深主题及窄屏；不能用真实合同、客户身份或凭证填充设计工具。

| 样本 | 应验证的行为 |
| --- | --- |
| 超过40个汉字的项目名、含空格和扩展名的长文件名 | 可换行/展开，完整名称有可访问入口，操作不被挤出 |
| 简体、繁体、英文混排 | 字体回退稳定，预留文本增长，动作术语保持一致 |
| HKD、CNY、USD 原币金额并列 | 明确原币，缺汇率不合并成一个伪总额；币种仅为样本 |
| 金额为0、缺失、冲销负值 | 三者含义不同；不能用「—」替代所有情况 |
| 120 GB 文件、主副本状态不同 | 字节进度、正式版与两份保护事实分别成立 |
| 已批准但未付款的采购 | 批准状态与结算状态同时可见 |
| 未知/过期观测、维护期间中断 | 不能用「正常」或维护图标遮盖真实观测 |
| 正文带代码、长链接和引用失权 | 正文可读、局部滚动、安全占位不泄露来源 |
| 只成功3/5项的秘书任务 | 成功、失败、未执行与可重试范围清楚，不统一提示全部成功 |

## 8. 页面交接记录模板

以下字段直接用于页面说明或评审记录；不要求额外审批工具：

~~~text
页面：PG-xx / 名称 / 设计版本
目标：本页帮助谁完成什么操作
入口与返回：来源页面、深链接、返回位置
数据：接口、DTO字段、日期/金额/版本口径
授权：对象可见性、可用动作、限制原因、撤权刷新
组件：CP编号、主题、尺寸变体、必要扩展
布局：1440 / 1024 / 768 / 390 / 320及重排规则
状态：正常、加载、空、无结果、失败、过期、离线、冲突、失权
动作：按钮文案、提交条件、成功事实、结果未知时的处理
辅助：标签、焦点顺序、键盘、读屏、字号放大、减少动态效果
证据：截图/录屏路径、环境、版本、已测与未测范围
问题：缺口、影响、负责角色、处理结果
~~~

可按适用性标记「不适用」，须写明原因；例如纯只读详情没有编辑冲突，但仍有刷新失败、失权和过期数据。不得把未实现或未测试标成不适用。

## 9. 验收与变更约束

页面交付首先满足事实和可操作性：正确对象/金额/版本、有效授权、可恢复操作、完整关键文字。随后核对主题、组件、间距与视觉一致性。具体执行 [VD-01—14](05-implementation-and-design-qa.md)；本文不新增与既有治理无关的停工审批。

新增组件先检查能否由现有基础组件组合。确需新增语义颜色、尺寸或状态时，补齐用途、双主题、数值来源、可访问性和影响范围，再更新令牌与文档；禁止在单页里私建品牌色或一套互不一致的审批含义。

所有文档、设计说明、资产与评审证据保存在 docs/；产品开发与后续新增开发脚本放在 app/。浏览器审阅结束关闭本任务的页面/上下文，不启动 Docker、WSL、虚拟机或模拟器。
