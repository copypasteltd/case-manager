# 项目范围变更与预算修订设计

版本：v1.0.0-draft；日期：2026-10-24。状态：本地Web/API及合成数据浏览器检查已执行，原生端完整业务仍待验收。沿用[官网风格总规范](00-style-design-specification.md)、[视觉基础](02-visual-foundations.md)和[组件契约](07-design-handoff-and-component-contracts.md)。业务依据为[项目需求](../requirements/03-projects-and-knowledge.md)和[变更实施协议](../development/43-project-changes-and-budget-revisions.md)；已执行范围和证据见[设计验证第24节](06-design-verification.md)，未执行项仍为设计要求。

## 1. 页面任务与品牌应用

员工需要看清项目原有范围、时间及预算，准确提出修改，交给独立审批人核对，并在批准后明确实施。页面应让人随时知道“当前正在执行什么”“本次建议改什么”“批准了什么”“是否已经实施”。

继续采用暖灰白／蓝灰黑画布、细描边面板、无衬线工作文字、等宽版本和原币金额。品牌蓝用于变更标题链接、选中页签、焦点和固定依据标记。黑白主按钮表达当前最主要的行动；预算增加不能仅因数字上升而用绿色表达。衬线仅用于工作台或品牌标题，不用于逐行预算与审批对照。

## 2. 入口、导航与内容顺序

项目详情增加“变更”和“预算”页签，保持项目名称、阶段及返回入口。申请中心能够按项目和变更类型找到同一份审批资料，不复制出独立且可能过期的业务文本。点击审批来源返回准确变更详情；无权限时清理已加载的标题、范围和金额。

| 页面区域 | 必须呈现 | 有权动作 |
| --- | --- | --- |
| 变更列表 | 标题、申请人、项目、当前修订、审批阶段、是否实施、更新时间 | 新建、查看、继续草稿；按权限显示 |
| 变更详情页首 | 项目与变更名称、修订号、审批状态、实施事实 | 草稿编辑／准备申请／进入审批／明确实施，依真实状态选择 |
| 固定依据 | 基线项目版本、范围、起止日期、分类、币种和预算版本 | 查看可读依据；提示基线是否仍与当前一致 |
| 变更对照 | 原值、建议值、范围说明、时间影响和理由 | 查看完整内容，不用摘要取代原始提案 |
| 预算对照 | 原明细、建议明细、净变化、审批金额及其口径 | 按类别／期间核对，明确空值含义 |
| 固定资料 | 文件名称、准确版本、大小、可用状态 | 读取当前仍有权访问的正式版本 |
| 流程与历史 | 修订、申请、独立审批与实施记录 | 打开准确历史；历史不可直接编辑 |

列表用准确阶段词，不用单一“完成”标签覆盖审批和实施。初期记录少也保留分页与独立加载／空／失败状态，不预设只有三条记录。

## 3. 范围与日期对照

桌面中同一字段按“原项目基线 → 本次提案”排列；窄屏改为先原值后提案的纵向字段组，两个标签重复保留。范围长文允许换行和展开，不截去决定所需内容。日期使用明确年月日；未设置与清空分别表达，不能把空字符串显示成今天。

对照包含完整拟实施范围与日期，并另列申请人填写的影响说明。项目名称、负责人或当前版本变化后，应明确提示基线过期；重新生成依据和审批不能沿用旧批准。页面中的“当前项目”与“本次固定基线”要有独立标题和版本，不因自动刷新而悄悄覆盖提案依据。

活动项目的日常编辑区域应将受变更控制的范围和日期设为正常对比度的只读值，并提供“提出项目变更”入口。保存其他信息时不夹带修改这些字段。任务和里程碑日期不随项目日期自动变化，是否另外修改由实际业务流程表达。

## 4. 预算明细和金额层级

预算按原币独立显示，每项包含类别、期间开始、期间结束及准确金额。不同币种不得直接相加。独立宽内容区可使用带表头的明细表；双栏对照和模态内采用带字段标签的明细组，避免把两张窄表并排后依赖横向滚动。窄屏始终保留明细字段标签；编辑组连续编号，行操作置于本行末尾。

| 预算输入／事实 | 必须显示的文字含义 | 禁止的表现 |
| --- | --- | --- |
| 不修改预算 | “保持该币种当前预算” | 把未提供明细误当成清零 |
| 替换为零项 | “本次将该币种预算明细清空”并显示原预算 | 用普通空状态掩盖清空影响 |
| 新增或调整明细 | 原明细与完整建议明细，类别和期间一并对照 | 只显示最终总额，省略挪动与期间变化 |
| 预算净变化 | 明确币种、正负方向和计算前后金额 | 用颜色或加减图标作为唯一含义 |
| 审批金额 | 单独显示各明细正向增加合计及口径说明 | 用净增加抵消其他明细的增加后误选审批规则 |
| 实际费用 | 保持独立来源和当前确认状态 | 将预算批准／实施显示为已发生费用或实际付款 |

例如，原“设备／10月”为HKD 100.00，提案将该项降至HKD 60.00，并新增“服务／10月”HKD 40.00。净变化为HKD 0.00；审批金额仍为HKD 40.00。页面在两个数字旁分别写清“预算净变化”和“用于选择审批规则的增加合计”，不把二者都命名为“总额”。示例仅说明口径，不预设公司的审批金额门槛。

类别与期间的重叠错误关联到具体行和字段，顶部错误汇总可跳转。删除一行后保留其余输入与稳定的键盘焦点。金额使用十进制字符串和币种允许的小数位，前端不通过浮点四舍五入替用户修改输入。

## 5. 草稿、准备申请与独立审批

草稿编辑表单同时呈现固定基线、完整提案、理由及固定附件。选择文件时显示准确版本；只读详情不能默认跳到文件最新版。草稿允许暂时缺资料，送审前再展示缺项，并将焦点引到可处理位置。

“准备申请”和“正式送审”按后端真实流程区分：准备完成只显示已生成申请，不显示已经交给审批人。正式送审前展示固定修订、金额口径、匹配规则和审批人。规则未配置、审批人不可用或资料失权时解释具体原因，保留草稿。

审批页沿用现有申请布局，顶部明确“项目变更”，正文包含固定项目基线、完整前后对照、原币预算、固定附件及申请理由。独立审批与申请人身份限制由后端执行；界面同步展示可用动作。批准后首先显示“已批准，待明确实施”，不刷新项目范围和当前预算来制造已实施观感。

## 6. 明确实施与实际结果

“实施已批准变更”只对当前有权、当前会话满足要求且基线仍有效的人工操作显示。进入实施界面时，重新读取变更、批准修订、项目版本和固定资料可用性；不能复用旧列表缓存作最终确认依据。

实施界面使用普通宽度的详情区或可滚动模态，重复显示项目、批准修订、完整范围／日期对照及预算变化。两项人工核实默认均不选中：

1. “我已核对本次项目范围和日期调整。”
2. “我已核对本次预算调整及其影响。”

同时要求明确实施理由与近期真实MFA。标签应表达人的核实行为，不写成系统已验证的事实。按钮处理中防止重复点击；成功后显示实施人、时间、变更修订及项目前后版本，并更新有权读取的当前项目与预算。批准记录和原预算历史继续保留。

若请求超时而结果未知，显示“正在确认本次实施结果”，先按同一操作标识查询结果。禁止直接提示“失败，请重新实施”或生成第二次操作。取消查看界面不等于撤销已经提交的实施；已实施变更不提供伪装为编辑的回滚按钮。

## 7. 预算视图与历史

预算页按币种展示当前已实施预算，标明预算修订、来源变更和实施记录，再提供历史入口。草稿预算在提案详情中显示，并明确标成“拟议预算”；不能与当前已批准实施预算合并成一张无标签的总表。

历史预算标明“已被后续修订替代”，同时保留当时的准确明细。打开历史时不将后来增加的资料或当前项目范围覆盖进去。实际费用与预算对比尚未完成时，不提供缺少来源的已用率、剩余额度或“未超支”判断；无可读明细也不等于零支出。

## 8. 异常、权限与多端约束

| 场景 | 页面响应与恢复路径 |
| --- | --- |
| 基线项目或预算版本已变化 | 显示当前与固定版本差异，保留提案输入，另建或重新修订后重新审批 |
| 409版本冲突 | 保留本地输入及操作标识，读取最新事实后由人核对；不自动覆盖或二次实施 |
| 固定文件撤权／不再可用 | 停止相应流程，清理敏感标题及片段；说明需重新选择有权正式版本 |
| MFA已过期 | 保留核实内容，完成真实MFA后重新校验全部依据；不借旧成功状态继续 |
| 项目关闭、归档或取消 | 显示有权只读历史与限制原因，不呈现可写假入口 |
| 预算权限不足 | 隐去明细和金额；不得从摘要、提示、导出或统计泄露 |
| 查询失败与旧数据 | 显示最后成功读取时刻和“待重新确认”，不把空响应表示成无预算 |

Web沿用双主题与320／390／768／1024／1440代表宽度；长标题、连续字符、长金额和模态内部内容均可重排。键盘顺序跟随阅读顺序，表头和明细标签有程序关联，错误汇总可聚焦；关键值与只读内容保持正文对比度。

微信、抖音小程序及Android共享术语、字段和状态。移动先展示本次行动与固定依据，再展开对照和历史；不可把明细横向缩成无法点按的小字。当前本文是四端设计目标，不将Web布局、H5检查或编译成功记为任何原生端验收。

## 9. 交接与验收要求

本模块复用已有页签、列表、表单、金额、固定文件选择、前后对照、审批轨迹、MFA及模态组件。开发交接应提供准确接口、能力名称、DTO空值语义、状态和版本来源；视觉数值仅引用既有令牌，不为预算页面另加一套主题。

验收至少包含：仅改范围、不改预算；创建首版预算；同币种减少与新增相抵；空明细与不修改的区别；期间重叠与金额精度错误；独立审批但未实施；明确人工实施；审批后基线过期；权限撤销；MFA过期；冲突保留输入；结果未知及重复请求；历史预算不可变。每项分别记录后端、实际Web页面及各原生端证据，未执行的检查保留为待验收。
