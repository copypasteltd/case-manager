# 组件、交互与业务表达规范

版本：v1.0.0-draft；日期：2026-10-23。以下均为基于官网视觉语言的产品扩展（D），遵守 [视觉基础](02-visual-foundations.md) 与现有业务契约。

## 1. 组件交付通则

每个组件必须提供适用范围、属性/事件、双主题、尺寸、键盘/读屏行为和状态示例。组件状态至少覆盖默认、悬停、键盘焦点、按下、禁用、只读；涉及请求时再覆盖加载、成功、失败、失权、过期和冲突。开发不能只交付正常空白截图。

系统状态与业务状态分层：页面加载失败用系统错误区；申请被拒绝用申请详情；文件复制失败用副本区。错误展示原始服务端错误码对应的用户文案与可复制 request_id，不暴露内部堆栈、签名URL、密钥和模型认证信息。

## 2. 操作与导航

| 组件 | 外观/结构 | 交互与约束 |
| --- | --- | --- |
| 主按钮 | action.fill/on，胶囊，默认40或舒适44 | 一处决策区一个主动作；文案用「提交报销」「创建项目」等动词+对象 |
| 次按钮 | surface底、control边、default字 | 保存草稿、预览、返回；不能与主按钮同样抢眼 |
| 文本/链接按钮 | accent字、必要时下划线 | 导航链接用链接语义；改变数据用button；键盘可见焦点 |
| 危险按钮 | danger.fill/on或危险描边 | 仅用于破坏性动作；审批拒绝有明确文案与原因字段 |
| 图标按钮 | 20px图标、符合命中区的外框 | 有aria-label/平台无障碍名称；hover提示不是唯一名称 |
| 加载按钮 | 保留原宽度、文字说明+进度 | 禁止重复激活；失败恢复可操作；查询既有提交结果，不能盲重发 |
| 标签页 | 底部细线、选中fg.selected | 标示当前项；键盘方向键移动、关联tabpanel；不以颜色独自表达 |
| 面包屑 | 主页/列表/当前对象 | 窄屏收敛为返回上级；不展示用户无权对象名 |
| 侧栏 | 中性底、选中浅蓝底+3px侧线 | 当前项aria-current；分组明确，不给每项加不同彩色块 |

主按钮不得默认改成品牌蓝。按钮组 Web 主动作在右，移动固定操作区主动作醒目且可单手触及；批准和拒绝保持独立空间，不并列做两个同色实心按钮。固定底栏为内容预留高度和安全区，键盘弹出时不遮输入。

登录/退出、打开面板与普通查询无需确认弹窗。已有明确授权范围内的可恢复普通写入直接执行并给结果；批量/不可恢复/敏感操作按业务规则展示具体范围和后果。禁止用统一「确定吗」覆盖所有风险。

## 3. 表单与校验

字段顺序为标签→输入→单位/帮助→错误。必填使用可读的「必填」或说明，不只放红星。输入支持清除/复制时保留可访问名称，密码显示按钮明确状态。placeholder不能代替标签。

| 场景 | 必需行为 |
| --- | --- |
| 金额 | 币种独立可见；定点字符串输入校验；不把前端浮点求和当最终账务结论 |
| 日期/时刻 | 业务日期不偏移；时刻明确时区；跨时区查看提供完整绝对时间 |
| 人/项目/文件选择 | 只查有权范围，异步搜索；选项含足够区分信息，不一次下发全量受限名单 |
| 长表单 | 分组、锚点/步骤、自动保存状态；草稿不等于已提交 |
| OCR/AI候选 | 标注「待核实」，用户核对原件；不直接当正式已确认值 |
| 本地格式错误 | 失焦或提交校验，输入时不过度打断；用户修正后同步清除已解决提示 |
| 服务端422 | 顶部可聚焦错误汇总，链接到字段；字段旁保留具体问题与修复建议 |
| 409冲突 | 保留本地草稿，展示当前版本与本次修改；提供重载/比较/另存，不静默覆盖 |
| 401/失权 | 登录恢复后先查提交结果；敏感数据立即停止展示，草稿按安全规则处理 |

提交失败保留合法输入；第一次提交错误后焦点移至错误汇总，不能只发即逝toast。读屏关联label、description和error，动态结果通过适当live区简要播报，不逐字播报所有流式消息。

## 4. 表格、列表、筛选与搜索

表格结构：标题/结果数→筛选→批量操作区→表头/行→分页/选择说明。表头、行选择、排序方向具备语义。名称左、金额右、时间/状态对齐一致。仅在确有必要时固定首列/操作列，不使窄屏可用宽度归零。

筛选区优先关键词、状态、项目、时间，更多条件折叠；有「清除筛选」及结果为空原因。加载保留列宽，刷新失败时旧数据必须标「更新失败，显示截至…的数据」。列表可局部横向滚动，页面整体不得横溢；移动优先卡片/详情，而非缩小桌面表格。

选择行后显示已选数量与范围，区分「当前页」与「全部筛选结果」。批量动作提交前固定对象清单/查询快照，并按权限逐项反馈；翻页不得默默扩展选择范围。分页采用接口稳定游标/既定页规则，不用前端重排破坏一致性。

搜索结果显示项目/目录、文件类型、匹配片段、版本、更新时间和授权引用入口。不可见内容不出现在数量、联想、摘要或失效提示里；无权结果的安全文案遵循权限规范。

## 5. 通用反馈、浮层与空状态

| 状态/组件 | 必需内容 | 用户动作 |
| --- | --- | --- |
| 首次加载 | 与实际结构相符的骨架或文字 | 可退出/返回，超时变明确错误 |
| 空列表 | 对应范围尚无内容 | 有权时提供创建；不能写「服务器错误」 |
| 筛选无结果 | 当前条件未匹配 | 清除筛选，不误导创建重复数据 |
| 接口失败 | 失败范围、已有数据是否过期、request_id | 重试查询，保留草稿 |
| 离线 | 离线标记、最后同步时间 | 只读缓存明确；不显示写入已成功 |
| 失权/不存在 | 统一安全提示 | 返回列表/联系有权负责人，不泄露资源标题 |
| toast | 简短非阻塞确认 | 对失败/待处理另有持久入口 |
| 全局公告 | 服务降级或维护及影响 | 不挡住正常手工流程 |

抽屉用于快速查看、轻量编辑；复杂合同/报销走完整页面。对话框用于有界决策，不把多步骤长表单塞入小弹窗。模态打开后焦点进入并限制在其中，关闭后返回触发点；背景不可操作。Escape通常关闭，未保存改动按实际风险提示，不无限阻止退出。tooltip可键盘触发，内容短且可关闭。

## 6. 文件、上传与副本专用组件

文件行/卡片至少包含：名称、格式、大小、所属项目/目录、当前版本、修改时间、授权操作；必要时展示分类/扫描限制。分类和「不可预览/不可扫描」不能被文件类型图标遮盖。

上传器结构：文件/目标→会话状态→字节进度/速率/估计剩余→暂停/恢复/取消→校验→正式版本→副本。速率和剩余时间标「估计」，断网时冻结为重连状态，不继续伪造倒计时。进度条是分片字节进度，不是全流程进度。

Web 当前实现区分“本次分片回执”和“云端已确认分片”，只对已返回分片计字节；没有可用吞吐采样时不展示速率/剩余时间。“暂停本机传输”只停止本机请求，不能伪造服务端暂停；刷新后明确要求重选原文件。接入未配置时按钮禁用并提供持久原因。扫描/制度窗口的 MFA 再验证保留表单且不自动确认业务操作，滚动窗口必须能到达验证说明和最终按钮。实现和验收边界见[上传队列文档](../development/18-upload-queue-and-review-clients.md)。

界面分别显示：

1. 传输：未开始、传输中、暂停、待恢复、已传输、失败/取消。
2. 校验/提交：校验中、失败、已生成正式版本等实际阶段。
3. 保护：OSS状态、R2状态、最后校验时间、待复制/失败原因与重试入口。

上述为展示分组，接口枚举和状态跳转遵循 [存储协议](../development/03-storage-protocol.md)，不能创建一个与后端无关的新枚举替代它。

**「已传输120 GB」不能配「双云已备份」图标，除非复制/校验事实已经成立。** 副本失败仍保留已成功生成的正式版本事实；恢复历史版本显示「生成新版本」及来源，不覆盖旧版本。

waived使用警示语义，明确「经扫描例外审核放行，尚未取得完整安全扫描通过的结论」；不能复用clean的成功标记。副本手动重试对话框固定具体内容版本/副本版本并填写原因，提交成功只表达已排队；来源不可用或版本冲突保留输入，等待重试时不得重复发起平行任务。

下载入口固定具体内容版本。版本不可用、扫描/放行条件不满足或没有已校验副本时，禁用动作并说明原因；服务端仍在申请时再次核对。下载弹窗先说明大小、版本、waived风险与访问方式，再选择本机保存位置。受控流显示实际已写字节与取消入口；只在保存流成功提交后显示完成，长度校验不能表述为浏览器整文件摘要已通过。普通短签的撤权时效与浏览器/切页限制按[下载协议](../development/17-download-authorization-and-streaming.md)可见说明；不在界面暴露签名地址。

120GB任务在Web/Android有独立可恢复队列和全局入口，切页不会假装任务消失；浏览器关闭/Android被系统终止的限制如实提示。小程序提供受支持的普通附件上传与资料访问，不展示120GB上传承诺。

## 7. 审批、合同、采购与财务组件

审批详情上方显示对象、申请人、金额/币种、项目、提交修订号和当前节点；中间为固定审批快照/附件；侧栏或下方为时间线。处理人需先看到本次批准的确切版本；审批期间变更触发版本失效规则，旧页面按钮不能仍可提交成功。

时间线每项含动作、操作者、绝对时间/时区、理由、修订号。退回/拒绝理由必填按业务契约执行；撤回提示影响范围。本人不能审批等原因就地说明，不让用户点后才发现。

合同组件把「审批」「签署/生效」「履约」「结算」分段；采购把申请、订单、收货、差异、结算分段；报销把明细、票据、核实、批准、付款分段。批准不得显示「已付款」，取消订阅不得显示「未来一定不扣费」。

费用总览固定区分预计/已发生/现金支付，带账期/币种/汇率/口径；汇率缺失显示「无法汇总」及缺项，不能显示0。原币、折算额和分摊有来源。票据重复提示说明匹配依据与人工处理入口，不让AI判断自动拒绝。导出含字段范围和生成状态，导出文件仍受权限与有效期限制。

## 8. 秘书会话、固定计划与结果证据

会话界面由会话列表、消息流、引用/上下文选择、输入区、任务状态组成。用户消息、秘书文本、工具执行与系统事件结构区分；不使用头像/颜色假扮员工或审批人。

| 内容 | 视觉/语义规则 |
| --- | --- |
| 来源卡 | 左3px蓝线，文件名/项目/版本/引用片段/读取时间；按点击时权限访问 |
| 执行阶段 | 显示已受理、读取、整理、等待授权、提交、结果等公开阶段；不展示模型私有推理 |
| 草稿/差异 | 可读的增删/字段比较、基础版、目标范围；不仅用红绿颜色 |
| L0/L1普通授权动作 | 在既有范围内执行，结果列证据；不无理由反复弹批准 |
| L2固定计划 | 对象/数量/范围、基础版本、变更、可见性、外发接收范围、预计费用、有效期与可恢复方法 |
| 批准按钮 | 绑定准确plan_hash及授权版本；对象/内容/版本变化显示「计划已失效，需更新」 |
| 结果 | 成功/失败/未执行逐项列出，含资源ID/新版本/审计引用；副本仍单独显示 |
| 取消/中断 | 清楚区分停止请求、确认已停止、提交结果待确认；不能承诺已回滚 |
| 引用失权 | 按安全规则移除可泄露片段；不得继续用旧摘要回答受限事实 |

待授权卡是业务控制点，不是隐藏在聊天文字里的一个「好」字。界面显示只代表已批准/任务状态，正式执行仍由后端鉴权和工具契约约束。禁止在样板或真实界面呈现「秘书拥有服务器无限权限」。

流式消息支持中断后恢复查看，保持滚动位置；用户输入中的换行与发送快捷键有说明。重复点击/断线恢复沿用已有run，不自动新建同一任务。Telegram采用短文本摘要+安全入口，同一状态与权限含义沿用；不把Web颜色/复杂表格照搬到群消息。

## 9. 状态服务与通知

状态卡显示服务、真实观测状态、最近观测时间、观测来源、事件/维护。operational为正常、degraded为降级、down为中断、unknown为未知；maintenance为维护展示层，保留原始观测。过期观测显式提示，不能用旧绿灯表达目前健康。维护中仍显示真实down等观测，不得用维护图标掩盖它。

事件时间线显示影响范围、进展、恢复及复盘入口；服务页不能承诺修复时间，除非有负责人确认。监控查看权限不自动带来生产配置/SSH动作。

通知分「未读」与「待处理」，读过不等于处理完成。角标只计用户有权范围；点击重新检查目标权限。通知中心保留失败/过期状态的可理解说明，不在锁屏、TG和推送中泄露合同金额或敏感文件名。

## 10. 文案规范

优先「已保存草稿」「已提交，等待财务审批」「主存储可用，R2待复制」「提交结果待确认」等可核实表达。避免泛泛「操作成功」涵盖所有阶段。错误写清发生什么、影响什么、下一步；不责备用户。

文件/项目/人名长文本可折行或适度截断；金额、币种、审批版本和关键风险不得截断成无法区分的省略号。演示数据必须标记，不将示例服务状态或金额当作公司真实数据。

### 文件历史恢复的实际交互约束

历史内容采用独立候选与明确提交，回收站还原保持独立。文件详情按实际对象能力提供“恢复为新版本”，并列出本人任务；展示来源/基础内容序号、复制确认量与目标摘要进度。ready显示“待确认提交”，不显示为当前版。确认弹窗固定基础版本与SHA-256，冲突保留输入，不自动重定基础版；取消保留全部历史。两主题、五宽度与移动取消的实际记录见[历史恢复协议](../development/19-history-restoration.md)。

## 文件保留与评估页面

文件详情的保留摘要沿用面板、语义徽标和品牌强调色；普通读者只见约束数量，管理人可查依据及释放历史。有效保留用语义警示色，释放历史用中性色；评估结论不能渲染为“允许删除”。MFA 保留在原表单内，确认由用户另行提交。香港时间显示日期和时分，长原因换行；320px 模态框内部可滚动，保留底部操作可达。制度按四种用途分卡，不以装饰色混淆启用、未发布或执行能力。实际协议见[保留与引用保护](../development/20-retention-and-reference-protection.md)。

## 审批制度页面

规则卡片同时呈现业务类型、修订、类别、币种与准确金额边界；下界标“含”，上界标“不含”，空上界标“不设上限”。启用/停用用现有语义徽标，不能把启用制度表达为已有申请获批。顺序列表显示步骤号、职责名称、指定成员和身份验证要求；成员停用须有文字警示。历史制度固定 ID 与顺序，当前姓名及账号状态须说明来源。

编辑器沿用原生模态框和表单组件，小屏单列、长表单内部滚动，排序按钮须有含步骤号的无障碍名称。本人审批和撤回政策须明确选择；允许本人审批时显示对应说明。取消不发布，MFA 不触发业务提交，版本冲突保留填写内容。实际页面及检查范围见[审批协议](../development/21-oa-approval-and-business-revisions.md)。

## 往来资料页面

列表以机构/个人图标、名称、关系、分类和状态组织信息；搜索与关系/状态筛选在小屏单列重排。当前资料与修订历史分别标识，修订号、修改依据和原联系内容可辨。归档保留历史并停止内容编辑，不能使用删除成功的文案。冲突保留未保存字段，长名称、电话、邮箱和说明可换行；关系不能仅用图标或颜色表达。实际协议见[往来资料](../development/22-business-parties.md)。

## 合同与固定依据选择

合同阶段与审批状态使用独立徽标，未知金额写“未填写”，不能渲染为零或已付款。往来方和正文显示固定修订依据；无权限或不可用分别说明，不泄露隐藏名称。选择器按本项目/公司范围分页搜索，文件先选择记录再选具体正式版本；不可选项写明缺少正式版、不可用或分类原因。所有选择通过真实资料完成，不要求用户输入内部标识。

草稿长表单沿用品牌令牌和共享模态框，小屏单列并内部滚动，正文历史与往来方选择为独立模态层。提交冲突保留条款；回收保留历史，补充协议继承主合同安全范围。固定正文下载重新校验文件权限，扫描例外同时显示文字风险。能力及验证边界见[合同草稿协议](../development/23-contract-drafts-and-fixed-evidence.md)。

## 申请快照与人工审批页面

准备申请、更新申请和正式送审分为三个明确动作。详情显示准确固定内容与审批顺序；合同更新后提示重新核对，不能自动替换送审依据。预览同时展示条款、制度修订、指定人及本人/撤回政策；制度或权限变化后的重新读取由用户操作，保留已填原因。决定弹窗固定申请和步骤，MFA 内嵌且不自动提交。退回、拒绝、撤回采用准确文案，历史只读保留各次决定；批准提示合同仍需签署和生效。

品牌强调色与语义状态继承现有双主题令牌，禁止用绿色把草稿或送审表达为已完成业务。长原因折行，小屏模态内部滚动，失权资料不残留名称。[实际记录](../quality/evidence/requests/result.json)覆盖双主题五种宽度，代表截图已人工复核；完整正向审批 UI 与移动端仍需相应证据。页面路由独立分块，加载失败提供可理解的重载入口，不改变全局上传状态。

## 签署登记与生效确认

批准、签署、生效分别表达。签署区列出实际签署日、固定批准生效日、登记依据和条款核对说明；签署件绑定准确正式版本，可用与例外风险均沿用文件语义。没有当前文件权限时隐藏名称，保留“已固定签署件，当前不可用或无权查阅”的说明。

登记弹窗不预填尚未知晓的签署日期，不要求人工输入文件标识；使用独立签署件选择器。本人近期 MFA 保留在原表单中，不自动提交。生效采用独立确认，显示实际签署日和已批准日期；未来日期及尚未生效的主合同阻断操作。并发冲突保留核对说明、原因和已选版本，禁用旧依据的确认，关闭后重新核对。业务阶段进入履行不显示为已付款、已结算或履约完成。

签署区的[受控真实页面检查](../quality/evidence/business-execution/result.json)已覆盖双主题五宽度、准确版本选择、独立操作与冲突保留。嵌套模态关闭后恢复仍可操作的原触发控件焦点；触发控件因状态推进移除、但仍有父模态打开时，焦点恢复至该父模态的关闭控件。全部模态关闭后才回主要内容，恢复时不触发页面滚动。移动表单以实际视口截图复核，详情先回到页首再采集完整页面，避免固定侧栏截图位置失真。


## 合同收付款计划

计划编辑使用原生字段组，每个节点有明确序号、名称、金额、日期和条件，移除操作须有文字名称；更改条件保留节点身份。未知计划、明确无义务和已列计划分开选择。计划合计错误保留输入，金额与总额同一修订原子保存。合同、历史和申请共享同一计划内容，生效详情另列应收/应付节点；没有实际付款证据时不得显示已付或逾期未付。双主题沿用品牌令牌，长条款换行，小屏内部滚动，原生字段焦点可见。[实际协议与受控证据](../development/26-contract-payment-schedules.md)记录6条浏览器链和代表截图。
