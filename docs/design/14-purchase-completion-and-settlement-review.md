# 采购完成与结算核对页面设计

日期：2026-10-24。适用：采购详情、采购完成核对对话框及不可变完成记录。规则类别为产品派生 D，继承[官网风格总规范](00-style-design-specification.md)、[视觉基础](02-visual-foundations.md)、[组件契约](07-design-handoff-and-component-contracts.md)和[采购完成实施协议](../development/41-purchase-completion-and-settlement-review.md)。实现与验收状态见实施协议，不将本页设计要求作为测试通过记录。

## 1. 品牌和事实层级

沿用暖灰白／蓝灰黑画布、细描边面板、墨色主操作、品牌蓝链接与焦点。全部颜色来自既有语义令牌，不为采购完成新增主题色。“已登记采购完成”使用中性徽标；后续依据变化使用带文字的警示提示，不将完成阶段等同于当前没有未结事项。

页面按原商业批准、执行基线、订单与验收、完成与结算核对排序。批准金额、执行额度、订单金额、净验收数量、实际费用和有效付款分别命名。金额显示原币及十进制值，数量保留精度，不用百分比或进度环替代完整核对集合。

## 2. 当前核对区

“完成与结算核对”放在采购详情订购验收之后。未获批准时不展示登记入口；已获批准时读取服务器给出的完整性和操作能力，不能仅凭前端角色名称推算权限。

| 内容组 | 必须可查阅的内容 | 默认展开 |
| --- | --- | --- |
| 原批准和执行来源 | 原批准修订／内容指纹、当前执行基线修订、原币执行总额 | 是 |
| 交付与额度 | 每行执行数量、占用、净验收、有效订单待收、额度、占用金额／税额／折扣 | 是 |
| 固定订单 | 订单号、日期、取消余量状态、供应商准确修订、采购版本、登记时基线、完整固定行和价格 | 否 |
| 验收和来源退货 | 日期、固定订单、采购版本、通过／拒收／退货结果、数量、原因及原验收来源 | 否 |
| 差异提案 | 标题和准确链接、版本／修订／指纹、审批状态、是否已启用及依据采购版本 | 否 |
| 实际费用 | 来源链接、费用／冲销性质、状态、原币金额、有效已结金额、准确修订和版本 | 是 |
| 资金及分配 | 付款／退款／冲销、状态、原币金额、未归属退款、原付款、准确修订及全部费用分配 | 否 |

折叠使用原生`details/summary`语义，标题保留集合数量，展开后可以读取完整集合。展开控件高度至少44px。长修订号、文件名、金额和说明允许换行；金额使用等宽数字，禁止横向裁切。集合超过一次人工核对上限时由服务器拒绝，不能隐藏尾页后允许确认。

待处理事项在核对区上方用完整文字列出：没有合格交付、有效订单待收、差异审批未结束、费用未确认／未结、退款未归属或币种不一致。没有费用时写“此集合未归集实际费用，仍需经办人核实是否存在应付义务”，不能写成“已结算”。

## 3. 明确登记对话框

入口“核对并登记采购完成”只在服务器返回可操作时展示。打开后固定当前采购版本、完整核对集合和指纹。先显示标题、固定版本和全部事实，再填写实际完成日期、结算核实方式、完整费用归集与结算核实说明、差异处置、登记依据及1至20个准确文件版本。

结算方式初始为空，由用户明确选择“按已归集实际费用核对”或“经人工核实无应付义务”；可选项服从服务器实际集合。存在未使用额度、取消余量、未启用提案或费用差异时，差异处置为必填。无应付声明须说明实际核实方法和非零订单承诺如何处理，不能由秘书或空列表替用户确认。

未使用额度包含金额和数量两个维度。例如原订单10件、每件HKD2，全部验收且HKD20实际费用已结；后续经独立审批启用每件HKD3的执行基线时，当前额度为HKD30，旧订单仍为HKD20。页面分别展示两种金额，要求明确说明剩余HKD10的处置；数量全部交付不能自动消除金额差异，也不能把旧订单或费用改成HKD30。

三项独立复选声明分别为核实交付与订单余量、核实完整实际费用／付款／退款义务、核实全部差异及未用额度。初始全部未选，复选命中区至少24px，标签整行可操作。近期两步验证单独执行，验证成功只更新身份凭据，不提交采购完成。

主操作“确认登记采购完成”沿用墨色按钮。缺少必填说明、准确凭证、明确方式、任一声明或近期验证时不可提交；提交中防重复并保留可理解的状态。

## 4. 完成后的固定记录

显示实际完成日期、登记人／时间、明确核实方式、完成对应采购版本和集合指纹，随后显示完整人工说明、差异处置、登记依据、完成时的固定集合和凭证版本。来源链接可指向当前对象，但固定值不能被当前详情覆盖。

当前依据与历史指纹相同时，说明已保存当时的完整核实依据。后续退货、实际费用、付款或退款改变依据时，在历史上方显示“完成时依据已变化”，并另列当前核对集合和待处理事项。历史仍保留原完成日期、声明和金额，不自动改为今天的结算结论。

已完成后隐藏新订单、新验收、取消履行、差异编辑及启用入口。具备权限时，既有合格验收仍可登记准确来源退货；入口必须指向原验收行，并明确追加记录的性质。

## 5. 权限、失败与恢复

无法完整读取交付、差异、费用、付款或准确凭证时，展示完整性未知的中性说明，不输出部分金额／数量、不将受限集合显示为空。历史读取失败时移除此前缓存内容；不因按钮不可见就假设后台已禁止操作。

提交遇到版本、关联财务、依据或授权变化时，保留日期、方式、说明、文件和三项声明，把键盘焦点移到对话框内的错误说明。旧依据不得再次提交；用户关闭后核对新的完整集合，不自动换指纹重试。网络结果不明时保留请求和输入，按幂等协议核对，不杜撰成功状态。

## 6. 多端与设计验收

Web沿用采购导航归属；窄屏单列排布，主操作和来源链接可换行。微信／抖音／Android沿用相同术语、完整性、人工声明和固定依据语义，分别适配原生选择器和安全会话；本页不表示完整移动采购页面已经实现或真机验收。

验收至少覆盖正常完成、数量已交付但存在未使用金额、无应付人工确认、未结阻断、只读未知、来源退货后的依据变化及打开表单后的外部财务变化；分别检查双主题、320／390／768／1024／1440px、无溢出、控件尺寸、嵌套文件选择、焦点和输入保留。记录必须来自最终源码和实际Web/API操作，执行后关闭自有浏览器上下文及所有不用的标签。
