# 关键页面布局、任务流与设计检查

版本：v1.0.0-draft；日期：2026-10-23。本文展开 [19组页面蓝图](04-page-and-cross-platform-design.md)，用于原型、开发和测试交接。布局属于产品扩展 D；示例文字与数值不代表公司真实业务数据。此处是设计规格，不表示各页面已经实现。

## 1. 统一页面结构

桌面沿用240/72侧栏、64顶栏、最大1600工作区及32页边距；移动页边距16，沿用 [视觉基础](02-visual-foundations.md)。常见页面分为页标题、筛选/决策区、主内容、补充信息和反馈区，不把工具按钮分散在不可预测的位置。

| 结构 | 桌面 | 窄屏/移动 |
| --- | --- | --- |
| 列表页 | 页标题及主操作→筛选→表格/列表→分页 | 页标题→常用筛选→卡片→加载更多；高级筛选单独面板 |
| 对象详情 | 标题/当前状态→子导航→主体与摘要并排 | 标题→关键事实→主体→摘要；必要动作独立底栏 |
| 编辑页 | 页标题→分组字段→附件/核对→保存/提交 | 业务分段单列；可返回修改，键盘不遮正在编辑字段 |
| 阅读页 | 标题/修订→受控行长正文→关联资料→讨论/历史 | 同一语义顺序；图片/代码局部适配，根不横溢 |
| 工作会话 | 会话列表→消息与输入→来源/计划辅助区 | 列表与会话分开，计划完整页或可展开面板 |

只有桌面宽度足够且字段值得同时比较时才使用双栏；不要为保留左右布局压缩金额、版本和审批理由。正文与表格使用无衬线，品牌衬线仅出现在工作台欢迎/登录等有限展示位置。

## 2. 工作台：PG-02

页面的首要任务是让员工找到当前需要处理的事项。首屏顺序为简洁欢迎区、当前待办/到期/异常提示、待处理列表及近期项目。汇总指标应紧凑，不能把主要待办推到多屏之后。

| 区块 | 内容 | 行为与约束 |
| --- | --- | --- |
| 欢迎/主操作 | 品牌衬线短标题、业务日期、本人常用入口 | 主操作随用户实际能力提供；没有创建权限则不显示创建 |
| 汇总 | 待处理、进行中项目、费用口径、文件保护异常 | 只统计有权范围；更新时间及统计口径可查看 |
| 主要工作区 | 审批、本人任务、需确认的秘书计划 | 类型/对象/截止或修订清楚；点击进入真实详情 |
| 项目进展 | 项目名、当前阶段、下一里程碑/交付 | 不用一个无依据百分比代替项目验收 |
| 辅助区 | 秘书入口、文件异常、服务观测 | 不在首页嵌入复杂编辑器或持续装饰动画 |

桌面主要工作区优先宽度，辅助区可在右侧；小屏把辅助区移至主任务之后。无待办显示「当前没有待处理事项」，查询失败显示「待处理事项未能更新」；两者不能使用同一个空状态。

## 3. 项目列表、项目详情与任务：PG-03—05

项目列表保留名称、负责人、状态、下一关键节点、截止信息与实际可用动作。创建入口与筛选区分开；筛选条件进入详情再返回时尽量保留。不存在明确业务排序时沿用接口顺序，不在前端重排已分页结果。

项目详情页头展示完整名称、状态、负责人和关键时间，其下为项目子导航。任务、里程碑、风险/问题、变更、交付、成本、文件、知识与合同是同一项目的关联视图，引用同一对象，不能重复复制一份单据或文件。

| 详情视图 | 必须首先看到 | 关键限制/下一步 |
| --- | --- | --- |
| 概览 | 项目目的、负责人、关键日期、下一里程碑 | 关闭项目时给阻塞清单，不只提示失败 |
| 任务 | 名称、状态、责任人、截止、依赖阻塞 | 任务详情展示验收标准、父子任务、评论和历史 |
| 里程碑 | 目标、关联任务/交付、计划与实际日期 | 达成依据可展开；不能仅点按钮变绿 |
| 风险/问题 | 严重性、责任人、应对/解决、关联关系 | 风险发生转问题后能追踪同一事件 |
| 变更/交付 | 范围、基础版本、影响、验收依据 | 接受交付与文件上传完成分开 |
| 成本 | 预算、承诺/发生/现金的实际口径 | 无权限时不以隐藏列残留金额 |
| 资料 | 目录/文件版本、知识发布状态、合同关联 | 分类、来源与授权范围保持一致 |

任务轻量查看可用抽屉，复杂编辑和移动任务操作用完整页。任务状态动作放在标题附近或明确动作区；依赖未满足时给具体可公开原因，不让用户反复试点。

项目归档后的只读说明置于标题之后，写入动作一致收敛。只读成员看到正常文字和允许的读取入口；不能在评论区、任务弹层或快捷按钮中残留写入入口。

## 4. 文件中心、版本与上传：PG-06/07

桌面文件中心由目录区、文件列表、详情/版本信息及可返回的上传队列组成。目录区与应用导航层级区分；当空间不够，目录切换为选择面板，文件列表保持可读宽度。移动目录使用明确的上级入口与目录选择，不缩成一条无法操作的树。

列表默认只放识别和操作所需信息；完整元数据进入详情：

| 位置 | 内容 |
| --- | --- |
| 列表/卡片 | 文件名、格式/大小、修改时间、版本、必要的保护/扫描提醒 |
| 详情标题 | 文件名、版本、分类、有权的预览/下载 |
| 预览区 | 安全预览；不支持时说明原因及可用替代 |
| 版本区 | 修订、来源、操作者、时间、恢复生成新版本 |
| 保护区 | 正式版本是否可用、OSS/R2各自状态、最后校验、错误与修复入口 |
| 上传队列 | 当前源文件、目标、真实阶段、传输量、估计速率/剩余、暂停/恢复 |

上传流程按存储契约连接，以下是界面分区而非新增 API 状态机：

~~~mermaid
flowchart LR
    A["选择文件与目标"] --> B["分片传输 / 可暂停恢复"]
    B --> C["校验与正式提交"]
    C --> D["正式版本与可用性"]
    D --> E["OSS / R2 独立复制和校验"]
    B --> F["传输异常 / 等待恢复"]
    F --> B
    E --> G["保护完成或明确待修复项"]
~~~

120 GB 的字节进度到100%只表示传输事实。校验、扫描例外、正式提交、主副本保护分别展示；单个步骤失败不得抹掉已经成立的其他事实。提交结果未知时先查询同一任务结果，不能点击重试就创建另一份正式文件。

Web/Android提供大文件任务入口、切页返回及恢复说明；小程序提供查阅、审批和平台支持的普通附件流程，不承诺120 GB上传。Android系统终止/源文件权限变化时明确说明需要恢复或重选源文件。

## 5. 知识、项目博客与修订：PG-08

列表显示当前用户可见的标题、类型、摘要、项目、发布时间/更新时间和草稿或发布状态。阅读页的标题、正文、标签和来源必须来自同一可见修订，不能将草稿标题与已发布正文拼在一起。

| 模式 | 布局 | 操作 |
| --- | --- | --- |
| 阅读 | 标题/类型/项目→修订信息→正文→来源→讨论 | 按权限开放编辑、历史、发布；普通读者不看到新草稿提示或片段 |
| 编辑 | 标题/摘要/标签→正文→预览→保存状态 | 保存草稿与发布独立；保留基础修订和冲突草稿 |
| 历史 | 修订列表→选中修订→正文/字段差异→恢复说明 | 恢复生成新草稿或新修订，不修改历史 |
| 讨论 | 所属对象/可见修订→评论→编辑记录 | 草稿讨论与已发布讨论不能混淆或提前泄露 |

Markdown和外部内容保持隔离/安全渲染；外链有可识别名称与安全打开策略。文件引用显示用户可读文件名和版本，失权后采用安全不可用提示，不继续保留可泄露标题或正文。

正文默认16/26阅读尺度，受控行长；编辑、代码区可有局部横滚。移动保留编辑草稿和预览切换，不能通过缩小到12px维持桌面双栏。

## 6. OA、合同、采购与报销：PG-09—13

OA中心先区分「我的申请」「待我审批」「已处理」，再区分业务类型。页面只出现合同、采购、报销等已纳入范围的入口，不增加考勤、人事或请假。

编辑与提交页面保持同一对象标识；审批详情读取固定提交快照。相同业务从项目页、OA中心或秘书进入时，不能形成不同的审批版本。

| 页面 | 主体内容 | 与主动作一起可见的关键事实 |
| --- | --- | --- |
| OA中心 | 类型、申请人、项目、金额/币种、状态、时间 | 当前用户是否需要处理，按当前节点进入 |
| 审批详情 | 快照摘要、申请内容、附件、审批时间线 | 对象、修订、金额/币种、节点、处理身份 |
| 合同 | 对方、主题、条款/版本、签署、履约、结算 | 本次审批的合同版本，审批/签署/收付分别表示 |
| 采购 | 申请明细、项目、供应商、订单、收货/差异、结算 | 批准采购不等于已收货或已付款 |
| 报销 | 明细、票据/原件、核实提示、分摊、付款 | OCR候选待核实，重复票据处理，批准不等于报销已到账 |

审批处理区在桌面详情末尾或稳定侧区，移动可固定底部；正文和最后一条附件必须能完整滚到不被按钮遮挡的位置。批准使用主动作，拒绝/退回独立并有明确后果，不能把两者做成难以区分的两个同色实心按钮。

~~~mermaid
flowchart LR
    A["编辑草稿"] --> B["检查字段与附件"]
    B --> C["提交固定修订"]
    C --> D["查看快照 / 当前有权节点"]
    D --> E["按配置批准、退回或拒绝"]
    E --> F["履约 / 收货 / 付款等后续流程"]
    D --> G["版本过期或权限变化"]
    G --> H["保留操作说明 / 重新读取当前状态"]
~~~

图中为界面旅程，实际可选动作及状态转移严格来自 OA 业务规范。批准前后切换修订、本人不得审批、节点变化均须即时核对；旧页面不能继续提交成功。失败时保留已填理由，结果未知时先查单据现状。

## 7. 费用与订阅：PG-14/15

费用总览从账期、币种、项目和汇率口径开始。汇总固定区分预计、已发生和现金支付，图表在明细之前或旁侧提供趋势，明细能解释合计。缺汇率时显示缺项和无法汇总，不能填0或把不同币种直接相加。

订阅详情按「服务/当前价格→价格历史→账期与实际账单→提醒与取消」展开。开始日、续费锚点、价格生效日、取消生效日分别有标签；取消动作不能把已发生费用或后续异常扣费从列表移除。

| 情境 | 展示 |
| --- | --- |
| 预算/预计尚无实际账单 | 「预计」标签及来源，不显示为已支付 |
| 实际发生但未付款 | 已发生与应付清楚；现金支付金额不随审批通过增加 |
| 取消后继续扣费 | 保留账单，标记异常与核对入口 |
| 分摊/冲销 | 显示来源与关联，避免多入口重复计入 |
| 导出生成中/失效 | 异步状态与授权下载；导出失效不给可复用公开链接 |

金额优先完整显示，币种不可截断；图表颜色只用于区分序列，财务结论仍由文字、口径和明细表达。移动保留必要查询、申请/审批和账单查看，复杂配置按能力矩阵提供正确入口。

## 8. 公司秘书与固定计划：PG-16

桌面以消息/输入为主体，会话列表在一侧，来源和计划根据空间作为辅助区或展开面板；小屏先进入会话列表，再进入单个会话。输入区保留上下文选择、附件/对象引用、发送/停止和当前执行状态，避免多个相同外观的主按钮。

| 消息/面板 | 必须显示 | 不应误导的含义 |
| --- | --- | --- |
| 普通答复 | 答复、适当来源、读取时间/版本 | 有答案不等于已执行文件修改 |
| 执行进展 | 可公开的受理、读取、整理、提交、完成阶段 | 不呈现模型私有推理或伪造执行日志 |
| 固定计划 | 目标清单/数量、版本、差异、权限影响、有效期、费用与恢复方式 | 批准绑定准确计划，不能只批准一段可变聊天文字 |
| 失效计划 | 失效原因、需更新的范围、重新生成入口 | 旧批准不能复用 |
| 结果证据 | 每项成功/失败/未执行、对象/新版本、审计引用 | 部分成功不得显示全部完成 |
| 中断 | 已请求停止、已停止或提交结果待确认 | 停止请求不保证已经回滚 |

来源卡沿用3px蓝线，展示名称、版本和可公开片段；点击重新鉴权。已有授权范围内的普通可恢复操作按规则执行，不增加无依据的反复确认。敏感固定计划依业务权限执行，界面不能赋予秘书服务器无限权限。

用户向上阅读时保持滚动位置，有新内容显示返回底部入口；流式增量不重复全文读屏播报。断线恢复回到已有任务，不自动新建同一执行。

TG采用简短安全摘要、对象/任务标识和登录入口，沿用同一授权和披露规则。群内不照搬复杂Web表格，不默认发送合同金额、文件内容或签名下载地址。

## 9. 服务状态、设置与通知：PG-17—19

服务页按「影响/更新时间→服务观测→事件与维护→时间线/复盘」组织。正常、降级、中断、未知都有文字；过期时间明显可见；维护作为叠加信息，仍保留真实观测。页面不向有监控查看权的人自动提供生产控制动作。

设置页将身份/权限、工作流、分类/保留、渠道、系统配置按授权分组。当前配置与生效版本先于编辑，提交后显示变更证据。系统管理员不自动获得业务内容全读；敏感二次认证按既有权限规范触发。

通知页独立表示「未读/已读」与「待处理/已处理」。点击后重新检查目标权限，目标不可用时显示安全提示；不能以通知历史绕过当前访问限制。

## 10. 登录与绑定：PG-01

单个紧凑面板包含真实Logo、平台名称、当前步骤及表单。初始凭证、MFA、账号激活/绑定各步骤保持清晰，不用营销大图压缩输入空间。

错误采用不枚举账户的安全文案，同时给可采取的下一步。密码显示、恢复码、二次认证、失效链接和重新登录分别有状态；邀请激活完成不等于已获得业务角色。主题切换不会清空凭证输入，但敏感凭证不得跨账户缓存。

## 11. 四端检查与页面交接清单

Web、小程序和Android共享语义与品牌，不要求相同像素布局。小程序/Android从工作台、项目、待办、秘书、我的等适合移动的入口连接相同对象，实际导航形式遵循平台能力与工程方案。

| 页面组 | 必须准备的异常/边界示例 | 对应重点 |
| --- | --- | --- |
| PG-01 | 凭证错误、MFA失败、链接过期、激活后无业务权限 | 安全提示、焦点、账号状态 |
| PG-02 | 待办为空、局部刷新失败、费用/监控过期 | 空与错误不同，真实统计口径 |
| PG-03/04/05 | 长名称、依赖阻塞、归档、只读、并发修改 | 完整关键文字、写入入口一致 |
| PG-06/07 | 断线、校验失败、扫描受限、R2失败、来源失效 | 三阶段独立、大文件恢复 |
| PG-08 | 新草稿与已发布并存、冲突、来源失权 | 同一可见修订、保留草稿 |
| PG-09/10 | 审批版本过期、本人申请、节点/权限变化 | 快照与动作绑定 |
| PG-11/12/13 | 未签署、收货差异、票据待核实、批准未付款 | 多维业务事实 |
| PG-14/15 | 缺汇率、零与无数据、取消后扣费、冲销 | 金额完整、口径不混合 |
| PG-16 | 引用失权、计划失效、部分成功、中断结果未知 | 授权范围与逐项证据 |
| PG-17 | unknown、观测过期、维护时down | 不误报正常 |
| PG-18 | 无权限、配置冲突、二次认证过期 | 当前版本、明确变更 |
| PG-19 | 已读但未完成、目标失权、链接失效 | 阅读与处理分开 |

每组均补充适用的加载、失败、离线和无权状态。320/390/768/1024/1440宽度、双主题、200%字号、键盘和减少动态效果按 [设计验收](05-implementation-and-design-qa.md)逐项验证；真机、安全区、系统返回、软键盘与后台上传另记设备证据。
