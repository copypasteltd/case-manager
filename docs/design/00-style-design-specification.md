# CopyPaste 内部平台风格设计总规范

版本：v1.0.0-draft；整理日期：2026-10-24。适用范围：React/Vite 管理端、Taro 微信小程序、抖音小程序及 Android。本文是统一设计说明；各项数值以 [tokens.json](tokens.json) 为源，业务事实以需求与接口契约为准。官网来源已于2026-10-24重新复核，最近执行时间以[来源记录](evidence/website-source-refresh.json)的 `checked_at` 为准。

## 1. 设计定位与使用方式

内部平台以「温和的画布、清楚的文字、安静的面板、明确的行动」为设计方向。延续 [CopyPaste 官网](https://copypaste.hk/) 的暖灰白、墨色、蓝色、衬线品牌标题和细线圆角面板，将它们用于每天查资料、处理审批、管理项目及与秘书协作的工作界面。

主要使用者是首期3名香港员工，服务器位于境内。界面优先帮助使用者确认对象、版本、金额、当前事实和下一步；为跨境请求的等待、失败及结果未确认保留清楚的反馈。网络等待不以装饰动画掩盖，不在消息尚未返回时显示成功。

本规范中的 **O** 表示已由官网资源或浏览器快照验证的表现；**D** 表示内部系统的设计决定。D 形成可执行的产品规则，但不能反向称为公司既有官方 VI。

### 1.1 约束的执行方式

本文的「必须／禁止」作为设计与开发检查项；「建议／通常」是可按内容调整的基准，调整需说明任务原因；「待确认／待验证」保留为未决事项，不能在交接时写成已批准或已通过。涉及平台原生界面的差异，应记录受影响的页面、可用替代及验证结果。

新页面先确定用户任务和当前业务事实，再套用本规范的布局、令牌与组件。视觉差异不得改变权限结果、审批含义、原币金额、文件版本或执行状态。设计稿、样板和运行页面分别记录自己的验证范围。

## 2. 官网到内部平台的继承规则

| 官网特征 O | 内部平台规则 D | 应用位置 |
| --- | --- | --- |
| 暖灰白底、白色面板 | 画布与内容表面分层，主要靠留白及细描边区分 | 全部工作页面 |
| 深色为蓝灰黑与浅蓝强调 | 提供真正成对的深色令牌，文字、边界、状态和品牌标识同步切换 | 全部受控业务页面 |
| 墨色主按钮，深色主题反转 | 主按钮固定使用 action.fill/on 配对 | 创建、保存、提交、批准等主要动作 |
| 克制蓝色与左侧蓝色细线 | 链接、焦点、当前位置、来源和选中状态 | 导航、引用、选择器和秘书来源 |
| 衬线大标题、无衬线正文 | 品牌展示用少量衬线，工作内容采用无衬线 | 登录、工作台欢迎；业务内容另设层级 |
| 16px面板圆角、胶囊按钮 | 面板16、控件10、弹窗20、主要按钮胶囊 | 组件层统一处理 |
| 首页轨道、网格、较大留白 | 登录可局部使用静态细线；工作区保持稳定密度 | 登录或品牌介绍区域 |

品牌辨识由标识、画布、黑白按钮、少量蓝色和排版共同建立。业务模块共享同一套品牌色，不按合同、文件、秘书分别另设主题色。

官网画布包含很淡的蓝灰渐变，顶栏使用半透明模糊，品牌图形含细网格和轨道；这些是官网展示层的处理。内部工作区采用稳定的实色画布与面板，登录或品牌介绍区可局部引用静态细线和网格。保留官网的颜色与秩序感，具体取舍以工作内容的可读性、加载成本及减少动态效果偏好为依据。

### 2.1 官网特征到产品的可执行映射

以下编号用于页面交接和问题记录。官网实证仍以[原始取证](01-website-style-audit.md)为准，表中后台尺寸、业务含义与组件组合属于产品设计 D；CP、PG 的完整定义见[组件契约](07-design-handoff-and-component-contracts.md)和[页面矩阵](04-page-and-cross-platform-design.md)。

| 编号 | 官网特征与产品约束 | 令牌／组件 | 应用及检查方法 |
| --- | --- | --- | --- |
| VC-01 | 暖白／蓝灰黑画布与面板分层；内容区域用实色 | bg.canvas、bg.surface、bg.subtle；CP-02 | 全局骨架；分别检查双主题计算样式，正文不能与底图混叠 |
| VC-02 | 主按钮继承墨底浅字／浅底深字；同一决策区一个最强主动作 | action.fill/on/hover/pressed；CP-04 | 创建、保存、送审；核对默认、处理中、焦点与禁用状态 |
| VC-03 | 蓝色承担链接、焦点和当前位置；选中底色必须搭配专用文字色 | accent.fg、focus.ring、bg.selected、fg.selected；CP-06/09 | 全局导航、选择器；键盘可识别当前项，不能只凭颜色表达选择 |
| VC-04 | 衬线保留品牌气质，无衬线承载工作内容 | display、ui、mono 字体栈及排版尺度；CP-03/13/23 | 登录、工作台、知识与金额；核对实际回退字体、长标题与数字对齐 |
| VC-05 | 细描边、圆角与克制阴影延续官网形态；控件边界另满足可辨识要求 | border.subtle/control、圆角与阴影令牌；CP-05/08/12 | 列表、表单、浮层；不把浅分隔线当输入边框，不逐字段堆叠卡片 |
| VC-06 | 使用当前双主题 PNG 标识，保持比例及净空 | 官方 Logo 资产；CP-01 | 顶栏、侧栏、登录；切换主题无错配，不以未核验 SVG 或生成图替代 |
| VC-07 | 官网蓝色细线转为来源和上下文标记，文字承担实际事实 | accent.fg、3px 来源线；CP-15/18/24/25 | 文件、知识、秘书；引用可见对象及版本，蓝线不表示已批准或已执行 |
| VC-08 | 品牌网格与轨道只在介绍区有限使用；工作内容直接出现 | 动效时长、减少动态效果；CP-02/11 | 登录、工作台及反馈；无循环工作区装饰，减少动效时取消位移 |
| VC-09 | 四端使用相同语义颜色和业务文案，尺寸经各端适配 | 同一 tokens.json；跨端单位适配 | Web、微信、抖音、Android；分别核对字号、命中区、安全区和系统控件 |

业务状态色是产品扩展，应在上述中性色与品牌蓝体系内配合准确文字使用。合同、费用、项目、文件和秘书共享品牌规则；模块之间靠信息结构与术语区分。

## 3. 色彩体系与使用规则

### 3.1 基础色与常用组合

以下取自同一令牌源。前景与背景应按规定组合使用；完整状态色和对比度见 [视觉基础](02-visual-foundations.md) 及 [对比度记录](evidence/contrast-report.json)。

| 语义 | 浅色 | 深色 | 用法 |
| --- | --- | --- | --- |
| bg.canvas | #F6F6F4 | #0F131A | 页面大底，继承官网 O |
| bg.surface | #FFFFFF | #171D29 | 表格、输入、详情与会话面板，O |
| bg.subtle | #EFEFEB | #141A24 | 次级背景与轻量分组，O |
| fg.default | #15171A | #E8EDF8 | 正文、标题、关键数值，O |
| fg.muted | #5D636D | #A0ACC2 | 辅助说明、时间和版本，O |
| accent.fg | #1F5EFF | #79A2FF | 画布/面板上的链接、焦点和品牌强调，O色值 |
| action.fill / action.on | #15171A / #F6F6F4 | #E8EDF8 / #0F131A | 主按钮，保留官网配对关系 O |
| bg.selected / fg.selected | #EBF0FF / #204FC1 | #1C2C4F / #A5BFFF | 导航或候选选中，D |
| border.subtle | #D8D9DE | #2A3344 | 内容分隔和面板边，O |
| border.control | #7D8593 | #687A96 | 必须能辨认的输入、复选框与选择器边界，D |

一屏先以中性色组织内容，再以黑白主按钮指出当前行动，最后使用蓝色或状态色强调事实。同一决策区通常只保留一个最强主动作；正文链接具备颜色之外的识别线索。

浅色 accent.fg 直接置于 bg.selected 上约为4.494:1，低于普通文字4.5:1目标；选中项必须使用 fg.selected。此修正属于产品扩展，不为了逐字照搬官网保留已知不合格组合。

### 3.2 状态色与含义

以下状态配色均为内部平台扩展 D，采用 `status.{语义}.fg` 与 `status.{语义}.bg` 成对使用。

| 语义 | 浅色前景 / 背景 | 深色前景 / 背景 | 适用表达与要求 |
| --- | --- | --- | --- |
| success | #17633D / #EAF5EE | #8EDDB0 / #163326 | 明确检查通过、实际完成；具体文字与完成依据可追踪 |
| warning | #8A4B08 / #FFF3DD | #F2C078 / #3B2C16 | 待处理、到期、降级、需核对；说明事项及有权动作 |
| danger | #B32636 / #FCEDEF | #FFA3AD / #3A1C25 | 系统失败、复制失败、明确异常；保留原因和恢复入口 |
| info | #204FC1 / #EBF0FF | #A5BFFF / #1C2C4F | 当前、处理中、可继续；使用准确的阶段文字 |
| neutral | #5D636D / #EFEFEB | #A0ACC2 / #141A24 | 草稿、归档、未知；必须标出具体状态 |

颜色不定义业务状态。审批通过、签署、生效、费用发生、实际收付款、合同履约分别表达；标签不能把它们合并成一个模糊的「完成」。

### 3.3 常用元素的配色决定

| 元素 | 配色与形态 | 状态及使用约束 |
| --- | --- | --- |
| 主操作 | action.fill / action.on，胶囊圆角 | 悬停为 action.hover，按下为 action.pressed；焦点环独立保留 |
| 次操作 | bg.surface、fg.default、border.control，10px圆角 | 同一决策区保持与主操作的清楚层级 |
| 正文链接 | accent.fg，正文中保留下划线 | 默认搭配画布或面板；换背景后重新检查对比度 |
| 当前导航或选中项 | bg.selected / fg.selected | 同时标出当前项或选择状态，不能只画一条蓝线 |
| 输入与选择器 | bg.surface、fg.default、border.control | 焦点用 focus.ring；错误增加明确文字及相应语义，标签持续可见 |
| 状态标签 | 对应 status 前景 / 背景，带文字 | 标签本身为信息；需要操作时另给动作与可访问名称 |
| 秘书来源与固定引用 | 中性面板、蓝色来源线、正常文字 | 保留对象、准确版本及有权入口，引用色不代表内容已获批准 |
| 图表 | chart.1—6，配文字图例及线型 | 多序列色仅用于数据区分，金额口径与缺失数据另行说明 |

以上规则从同一语义令牌生成。业务页面引用令牌名；设计工具中的颜色变量对应同名语义，禁止为单个页面私建近似蓝色、灰色或状态色。

### 3.4 组合状态的视觉优先级

同一控件可能同时处于选中、聚焦、校验失败或处理中。以下规则属于产品扩展 D，用于避免状态互相覆盖；不增加新的业务状态或颜色。

| 同时出现的情况 | 呈现方式 | 不合格表现 |
| --- | --- | --- |
| 输入错误且获得焦点 | 保留错误文字及错误标识，外侧继续显示 focus.ring；错误与焦点分别可辨 | 获得焦点后错误消失，或为保留红框而移除键盘焦点 |
| 选中行包含失败或未知状态 | 行使用 selected 配对；状态以自己的文字和语义标签独立呈现 | 选中蓝底覆盖异常文字；整行变绿并暗示所有字段均正常 |
| 操作处理中 | 保持动作名称，补充处理中反馈；在原位置阻止重复操作 | 按钮消失引起布局跳动；未收到结果即改成成功 |
| 操作结果尚未确认 | 中性或警示信息说明“结果待确认”，保留查询本次操作的入口 | 将超时直接写成业务失败并诱导再次提交 |
| 只读且仍有重要内容 | 正文、金额、依据采用正常可读文字；清楚标明只读及原因 | 对整张表单应用透明度，导致已填写内容无法阅读 |
| 动作不可用但仍需解释 | 仅处理对应动作的不可用样式；在相邻位置给出可读原因 | 将说明和恢复入口一同禁用，或仅在悬停时解释 |
| 有旧的正常记录，但当前观测过期 | 当前状态显示未知／待重新确认；旧记录保留时间并明确标为历史 | 用旧绿色状态充当当前状态，或以维护标签掩盖观测异常 |

权限收回属于数据可见性变化：应清理不可见内容并显示相应提示，不能以低透明度继续保留标题、金额或文件片段。聚焦、选择、校验和业务状态的组合需在双主题下分别检查，不能只交付默认态。

## 4. 字体、数字与文案

| 角色 | 字体与尺度 | 使用边界 |
| --- | --- | --- |
| 品牌展示 | Fraunces / Iowan Old Style / Noto Serif SC / Songti SC / serif；桌面40/52、移动28/40 | 登录品牌标题、工作台欢迎；有限使用 |
| 业务页标题 | 无衬线28/40、600；窄屏24/34 | 对象或任务名称，不加入无意义英文眉题 |
| 分段标题 | 无衬线20/30、600 | 合同依据、文件版本、费用明细等 |
| 桌面工作正文 | 无衬线14/22、400 | 表格、字段、菜单、会话 |
| 移动主要正文 | 无衬线16/26、400 | 移动输入、主要内容和长篇阅读 |
| 辅助信息 | 无衬线12/18 | 时间、来源、版本；不承载主要审批正文 |
| 金额与版本 | 金额用无衬线及等宽数字；代码/摘要用等宽字体 | 金额保留币种与方向；代码字体不用于整张账单 |

无衬线栈为 Manrope / Avenir Next / Segoe UI / Noto Sans SC / PingFang SC / Microsoft YaHei / sans-serif。官网声明字体与设备实际使用字体分别记录；不假定所有设备已安装或下载同一品牌字体。字体完整定义见令牌源。

采用动词加对象的动作名，例如「创建项目」「保存草稿」「提交报销」「登记付款」。反馈沿用相同词义。业务日期与事件时刻区分，时刻提供完整时区；简繁及英文偏好待业务确认，设计预留文本增长空间。

金额为0、尚未登记、无权查看、无法汇总分别表达。不同币种没有已确认汇率时分开显示。HKD/CNY/USD只用作设计压力样本，不擅自确定组织默认币种。

## 5. 布局、尺度与形态

| 规则 | 桌面基准 | 移动及适配 |
| --- | --- | --- |
| 页面框架 | 240px侧栏，收起72px；64px顶栏 | 导航按宽度重排；平台原生导航服从实际能力 |
| 工作区 | 最大1600px、左右32px | 左右16px；阅读正文控制行长 |
| 面板 | 内距20—24px、间距24px、16px圆角 | 内距通常16px；内容可增长 |
| 字段 | 标签至输入8px、字段组间24px | 单列；输入法不遮正在编辑字段 |
| 控件 | 默认40px，舒适44px；紧凑32px限精细指针工具栏 | Web触屏目标至少44 CSS px；移动设计48，按平台单位适配 |
| 表格 | 默认行52px，紧凑44px，舒适64px | 优先卡片与详情；必要表格局部横滚 |
| 形态 | 输入/工具10px，嵌套12px，面板16px，弹窗20px | 保持层级，复杂表单使用完整页面 |
| 强调 | 分隔1px、焦点2px并外偏移2px、来源线3px | 不能用细装饰线代替输入边界 |

间距采用4px基线；不为凑布局随意出现17、19、23px等孤立数值。页标题、筛选、主内容、辅助信息及反馈有稳定位置，避免多层卡片机械嵌套。

响应式按实际内容宽度：≥1180完整侧栏；900—1179收起侧栏；640—899菜单抽屉与单列主体；<640移动布局。最低检查320px，另查390、768、1024、1440；具体重排见 [跨端规则](04-page-and-cross-platform-design.md)。

### 5.1 标准页面骨架与密度选择

页面先选择适合任务的骨架，再放置组件。以下是阅读顺序，非强制固定高度；遇到长名称、多币种、错误和权限提示时，容器应自然增长。

| 页面类型 | 桌面阅读顺序 | 移动重排 | 密度约束 |
| --- | --- | --- | --- |
| 列表与检索 | 标题／当前范围 → 搜索筛选 → 结果数量与状态 → 数据列表 → 分页 | 筛选收敛为可展开区域，记录优先卡片化，保留范围与分页 | 默认密度；触屏不采用仅适合鼠标的紧凑工具栏 |
| 对象详情 | 名称／当前事实 → 下一步动作 → 正文与依据 → 关联记录／历史 | 先给关键事实，再按任务顺序单列；次级资料可独立进入 | 名称、金额、版本和状态不靠悬停才能看全 |
| 编辑与审批 | 标题／对象版本 → 分段字段／明细 → 固定附件 → 预览／错误 → 操作与回执 | 长表单使用完整页面；键盘打开时仍可定位错误和当前字段 | 字段组之间留白，组内紧凑；不为每个字段额外套一层卡片 |
| 会话与资料协作 | 会话列表 → 消息与输入 → 来源／计划／执行结果辅助区 | 会话列表、消息、来源分层进入；复杂计划使用完整页面 | 消息保持稳定行长；输入区不遮最后内容或系统安全区 |
| 状态与事件 | 当前状态／观测时间 → 影响范围 → 观测依据／维护 → 事件时间线 | 先状态与时间，再逐项展开服务和事件 | 状态信息不堆成彩色仪表盘；历史与当前有明确边界 |

首屏保留“我在哪里、查看什么、目前怎样、下一步做什么”。固定操作栏必须为内容预留空间；错误摘要定位字段后，目标不能被顶栏、底栏或输入法遮住。帮助、秘书及主题入口在同类页面中保持相对稳定的位置。

不按首期3人把工作台固定为三列，也不把2TB或120GB作为装饰性大数字。容量只在文件、上传或资源配额等与当前任务有关的位置出现。完整页面字段与路径由[页面蓝图](04-page-and-cross-platform-design.md)及[页面展开](08-page-layouts-and-flows.md)约束。

## 6. 关键页面的视觉组织

### 6.1 工作台、项目和知识

工作台依次展示简洁欢迎、待办/到期/异常、待处理事项和近期项目。汇总占紧凑区域，不能将实际任务挤到多屏之后；不按首期员工数量固定三列布局。秘书入口可作为辅助区，品牌展示只占少量空间。

项目详情先给名称、阶段、责任人、关键日期和下一节点，再进入任务、里程碑、风险、交付、费用与资料视图。验收依据和阻塞条件可读，不用没有依据的完成百分比。

结项页面分别组织核查事项、人工复盘与归档历史。无权核查的区域显示「无法核查」，预算参考显示为中性信息；「未发现阻塞」与用户实际归档是不同阶段。具体页面规则见[项目结项与归档复盘](17-project-closeout-and-archive.md)，避免用整片绿色或自动勾选的声明代替人工确认。

知识与项目博客采用受控行长，标题、摘要、正文和来源来自同一可见修订。阅读、编辑、预览、发布与历史清楚区分；品牌衬线可用于文章标题，长篇正文保持无衬线。

### 6.2 OA、合同、采购、报销与费用

列表按对象名称、申请人、项目、原币金额、业务状态及时间排列。详情先给单据和准确修订，再给正文/明细、固定附件、审批记录和后续执行事实。批准与拒绝分开组织；写清动作及处理对象。

合同审批、签署、生效、节点履行、财务归属和法律完成／终止各有明确区域。采购的批准、下单、验收、退货与付款分别表示；报销的批准与员工实际收款分别表示。已发生、现金和预计开支三种口径分别展示，订阅账期/变价/取消生效/实际扣费有独立字段。

需要对比当前和历史时，分别标出「当前事实」和「当时固定依据」。相关细节见 [订阅与财务](10-subscriptions-and-financial-views.md)、[合同节点财务归属](11-contract-financial-reconciliation.md)、[合同完成／终止](12-contract-completion-and-termination.md)、[采购差异与执行基线](13-purchase-variance-and-execution-baselines.md)及[采购完成核对](14-purchase-completion-and-settlement-review.md)。采购已完成后仍须明确显示后续依据变化，空费用列表也不能被设计成已结算结论。

### 6.3 文件与120 GB传输

文件页按目录、列表、详情/版本和上传队列组织；窄屏目录变为选择面板。完整文件名、版本、大小、分类和有权操作优先，格式图标不掩盖扫描与保护限制。

上传界面依次呈现传输字节、校验/扫描、正式版本以及OSS/R2各自副本。传输100%之后仍显示后续真实阶段；速率与剩余时间明确标为估计。Web/Android提供大文件任务入口，小程序提供查阅、审批及平台支持的普通附件操作。

### 6.4 公司秘书与TG

秘书以消息、来源、固定计划、差异及执行结果为主体。来源采用蓝色细线及文件/版本信息；普通答复、计划建议和已经执行的业务结果有各自标题与依据。批量结果逐项表达成功、失败、未执行，停止不冒充回滚。

桌面会话可带来源辅助区，移动先选择会话再进入消息；复杂计划转完整页面。输入区不遮最后消息，用户向上阅读时保持位置。TG摘要应在纯文本中独立可读，使用安全授权入口，不能依赖颜色或透露超出允许范围的内容。

### 6.5 服务状态

状态页首先展示观测状态、最后观测时间和是否过期，再给趋势、事件及维护。未知、数据过期与真实中断分别表达；维护不覆盖真实观测。时间线与图表提供文字或表格等价信息，不显示无依据的正常率。

以上为页面规格；19组页面的字段、布局与任务路径见 [页面矩阵](04-page-and-cross-platform-design.md) 和 [页面展开](08-page-layouts-and-flows.md)。范围不包含考勤、人事与请假入口。

## 7. 组件和交互状态约束

| 类别 | 统一要求 | 关键异常 |
| --- | --- | --- |
| 按钮 | 主/次/文字/危险层级，明确动作，可见焦点，处理中防重复 | 结果未知先查询本次操作，不能盲目重发 |
| 表单 | 持续标签、帮助、字段错误及顶部汇总；错误关联字段 | 提交失败保留合法输入；409保留草稿并提供比较 |
| 列表/选择器 | 有权候选、分页、选择范围、准确版本和查询状态 | 空列表、无匹配、失败、旧数据分别表达 |
| 状态/通知 | 颜色、文字及必要图形共同表达，重要失败持久可见 | 不以短暂toast作为唯一失败记录 |
| 弹窗/抽屉 | 明确标题、焦点进入/限制/返回，背景不可操作 | 嵌套选择器关闭后恢复到仍打开的父弹窗 |
| 引用/历史 | 显示当前可读的对象/版本与固定依据 | 失权后清理标题、金额、片段，不保留灰字泄露 |

至少准备默认、悬停、焦点、按下、禁用和只读；请求组件再补加载、空、失败、离线、过期、冲突、结果未知及部分成功。禁用不等于只读；只读正文仍保持正常对比度。

完整组件目录为 [CP-01—28](07-design-handoff-and-component-contracts.md)。优先组合已定义组件，业务页面不私建品牌色、金额格式或另一套审批含义。

## 8. 标识、图标、动效及四端

采用官网当前 [浅色PNG](assets/official-logo-light.png) / [深色PNG](assets/official-logo-dark.png)，保持1:1和contain，不重绘或重新生成标识。侧栏32—40px、登录48—56px，建议净空为标识宽度1/4；净空是产品扩展，待品牌审定。工作图标统一24网格、1.75—2px线性描边；图标动作具备可访问名称。

动效限于120/180/240ms的颜色、菜单及面板反馈。工作内容无需滚动揭示才能出现；表格悬停不跳动；减少动态效果偏好下取消位移和循环装饰。

| 端 | 共享规则 | 分别验证 |
| --- | --- | --- |
| Web | 同一语义令牌、术语、字段和状态 | CSS px、键盘、焦点、缩放、窄屏、主题初始绘制 |
| 微信/抖音 | 同一品牌颜色和业务事实 | rpx/px换算、原生导航、输入法、安全区、真实平台能力 |
| Android | 同一语义颜色、状态及对象版本 | dp/sp、字体放大、系统返回、文件选择与后台任务 |

不能将48rpx、48 CSS px和48dp视为同一个物理目标。两小程序与Android分别验收，编译或Web模拟表现不代表真机通过。使用原生开发环境与真机，不启动本地Docker、WSL、虚拟机或模拟器；浏览器检查结束关闭本任务不再使用的标签页与上下文。

### 8.1 主题与素材交付规则

主题偏好支持“跟随系统／浅色／深色”的产品设计，实际平台能力和实现进度另行记录。切换时同步替换画布、面板、文字、控件、状态和配对Logo；不以整页反色滤镜生成深色模式。Web初始绘制应按已选主题准备，避免先亮后暗；无法控制的原生导航、选择器和系统窗口单独记录实际表现。

业务上传图片、合同扫描件、截图与品牌Logo是不同素材类型。业务证据保留原有颜色，不为匹配深色主题反相或改色；透明图片可置于有边界的中性底上，并提供原图查看。官网轨道和网格仅用于品牌区域，业务表单、审批或秘书执行结果不以装饰插图替代事实。

| 资产 | 交付要求 | 核对项目 |
| --- | --- | --- |
| 官网Logo | 使用已核验的浅／深PNG，记录来源和文件摘要 | 图形、比例、清晰度、主题配对和净空；不直接将官网图认作各平台上架图标 |
| 工作图标 | 同一图标体系、统一网格及描边，必要动作具有文字或可访问名称 | 常态／选中／禁用下可辨；不能依靠emoji、图标颜色或工具提示承载唯一含义 |
| 项目封面／头像 | 可选，提供中性占位并保持稳定尺寸 | 缺失、加载失败、长名称和深色主题；封面不挤占项目任务 |
| 截图／扫描件／业务图片 | 保留原色、原比例及对应文件版本 | 缩略图不被误认为完整原件；无法预览时给出原因及有权替代入口 |
| 发布素材 | 微信、抖音与Android按各平台当期规范分别制作 | 图标、启动展示、裁切／安全区域和真机效果；不能把Web截图当作原生验收 |

字体交付说明必须区分“CSS声明”“设备实际回退”和“已打包字体”。在授权、字库覆盖与体积未经确认前，按既定回退栈实施；不新增依赖境外字体服务才能正常阅读的关键路径。

## 9. 开发交接与验收

每页交接包含：PG编号、任务目标、入口/返回、数据和状态来源、权限分支、CP组件、双主题、五组代表宽度、文案、焦点顺序、提交/恢复方式及证据位置。设计工具变量与代码令牌对应同一版本，不把截图手工取色作为新数值源。

普通正文目标≥4.5:1，必要控件边界与图形≥3:1。检查真实前景/背景、键盘焦点、200%字号、根页面重排、完整金额/名称、触控目标及固定栏遮挡。64组已声明实色组合的验证结果不能替代全部页面无障碍审查。

按 [VD-01—14](05-implementation-and-design-qa.md) 执行设计检查；先处理事实/权限、金额/版本、内容可读和动作可恢复，再核对视觉细节。样板验收、业务浏览器检查、真机与生产验收各有自己的范围及证据。

## 10. 文档、令牌和变更

所有文档、设计资产与审阅证据放在 `docs/`，开发代码与后续新增开发脚本放在 `app/`。设计数值修改顺序为 JSON源 → 生成CSS → 各端适配 → 文档/样板 → 对比度和受影响页面回归，不仅修改生成文件。

官网资源更新时，先比较当前来源与已有快照，再评估令牌、标识和产品页面的变化。当前基线、机器记录及维护命令分别见 [设计入口](README.md)、[验证记录](06-design-verification.md) 和 [实现与维护](05-implementation-and-design-qa.md)。风格规范是可执行设计约束，版本号不等于公司正式VI审定或完整产品上线。

项目交付与人工验收的页面细节见[交付设计](15-project-deliverables-and-acceptance.md)，包括准确文件版本、修订历史、独立验收与版本冲突保留。

项目范围变更与预算修订的页面约束见[变更与预算设计](16-project-changes-and-budget-revisions.md)，包含固定项目基线、完整前后对照、原币预算口径、独立审批、明确实施及不可变历史；本地Web/API检查与尚未验收的原生端范围分别记录于[实施协议](../development/43-project-changes-and-budget-revisions.md)。

以下项目需要在相应阶段落实，文档编写不替代实际选择。它们不阻塞已定义页面的布局、组件和品牌配色工作。

| 待定事项 | 当前可执行基准 | 后续落实时需要记录 |

## 12. 每页风格确认卡

以下确认卡供设计稿、开发交接及评审记录使用。页面交接的完整格式见[组件契约](07-design-handoff-and-component-contracts.md)，本卡专门检查官网风格是否实际落地。填写依据和结果；未执行项目标为“待验证”。

| 确认项 | 必须记录的内容 | 通过条件 |
| --- | --- | --- |
| 任务与骨架 | 页面编号、用户任务、列表／详情／编辑／会话／状态骨架 | 关键事实和下一步动作可在合理阅读顺序中找到 |
| 画布与主动作 | 明／暗主题实际令牌；主、次、危险动作名称 | 官网中性色、黑白主按钮与克制蓝色一致；不私设模块主色 |
| 字体与长内容 | 实际字体、标题层级、长中文／英文名称及金额样本 | 工作内容无衬线、重要信息完整；装饰点等品牌符号不孤立占行 |
| 组件与组合状态 | 所用CP组件、焦点／错误／选择／处理中等交叉状态 | 焦点、错误和业务事实同时可辨；无重叠遮挡或含义覆盖 |
| 事实与权限 | 状态来源、准确版本、金额币种、失权／过期表现 | 旧资料、未知、未提交、已批准和实际执行各有准确表达 |
| 四端适配 | Web、微信、抖音、Android各自布局及单位说明 | 适配有明确实现或待办；不以Web模拟替代真机结论 |
| 可用性与证据 | 检查宽度、键盘／触控／大字、对比度、截图及结果记录 | 每项结论有相应证据范围，未执行和已知问题保留可追踪状态 |

新增页面不需要重新选择风格。先复用现有令牌和组件；只有发现明确任务需求无法表达时，才记录扩展原因、受影响的两种主题与四端，并更新设计源、样板和验收记录。此流程用于维持统一风格，不替代用户已授权范围内的日常修正。
