# 订阅、对账与月度财务页面设计约束

版本：v1.0.0-draft；日期：2026-10-24。本文是 PG-14/15 的详细设计约束，属于内部产品派生规则 D。颜色、字体和基础形态沿用[官网实证](01-website-style-audit.md)与[视觉基础](02-visual-foundations.md)，业务事实以[订阅需求](../requirements/05-finance-and-subscriptions.md)和[实施协议](../development/37-subscriptions-billing-and-forecast.md)为准。设计规范存在不代表所有页面及四端已实现或验收。

## 1. 金额、状态与品牌表达

财务工作区使用同一暖灰白/蓝灰黑画布、中性描边面板、墨色主操作和蓝色链接。业务标题、金额、表单和账期全部采用 UI 无衬线字体；衬线限于品牌与工作台欢迎区。原币数字使用等宽数字特性，保留币种，可换行，不通过缩小字号塞进窄屏。

| 信息 | 必须显示 | 色彩和形态 |
| --- | --- | --- |
| 预计收费 | 预计金额、币种、账期、价格生效依据 | 正常文字与中性面板；不使用代表已支付的成功样式 |
| 真实发生 | 已关联且有效的费用金额、币种、费用入口；没有记录则写“尚未登记实际费用” | 普通数值；部分扣款、超扣和冲销另用文字及状态标签 |
| 实际资金 | 对应资金台账/现金报表入口、付款或退款事实 | 使用独立名称及期间，不由订阅金额推定已付 |
| 已人工核对 | 当前有效核对状态、核对依据与固定凭证 | success 标签；不表示供应方停订或现金结清 |
| 未知 | 明确写未知、待补或未核实，并给下一步入口 | neutral；已阻碍操作时使用 warning 说明原因 |
| 异常 | 具体异常、影响对象、可执行的处理入口 | warning/danger 的成对语义令牌；不把整页铺红 |

金额不能只用红绿区别方向；状态不能只用圆点区别。零金额必须有已知价格或真实记录依据。原币之间没有已确认换算依据时分列，不显示跨币种总额。此规则同样用于工作台摘要、秘书引用及移动审批。

## 2. 订阅列表

内容顺序为页面标题及“新建订阅” → 筛选 → 订阅列表 → 分页。筛选至少支持产品名称、生命周期、项目/公司范围、币种、类别；供应方和负责人按实际接口及选择能力逐步开放，不用裸 UUID 作为日常选择器。

每行优先显示产品名、内部状态、供应方、负责人、下次收费日期与时区、价格已知情况、项目范围和异常。下次价格未知时不能取历史价格冒充。供应方尚未核实停订与内部取消待生效可以同时出现；不要为每行堆满五种彩色标签。

桌面名称占剩余宽度，金额右对齐；窄屏改为一列对象列表，名称及状态在首行，其余事实按标签纵向展开。主入口使用有含义的产品名链接；次要操作置于详情，避免列表每行都放实心主按钮。

| 分支 | 表达与下一步 |
| --- | --- |
| 无订阅 | “尚无可见订阅”；有创建权限时提供创建入口 |
| 筛选无结果 | 保留筛选并提供清除；不提示“尚未创建” |
| 读取失败 | 保留已填写筛选，显示错误和重新查询入口；不呈现旧统计为当前结果 |
| 无业务权限 | 采用统一安全不可用表达，不泄露对象存在与名称 |

## 3. 订阅详情与编辑

详情按以下顺序展开，不给每个字段单独套卡片：

1. 产品名、内部生命周期、范围、当前修订和允许的操作。
2. 下次收费、原币价格及异常摘要；未知信息保持显式。
3. 固定供应方、负责人、计费日历、续费方式和安全的付款标签。
4. 价格时间线、供应方核实状态及固定凭证。
5. 账期列表、提醒排队记录、配置历史和操作历史。

开始日、试用截止、首次收费日、原始锚点、价格生效日、取消生效日分别命名。日期显示为自然日；实际核实或操作时间显示时分秒与时区。月末回退后的日期不覆盖原始锚点说明。价格区间写清“至某日前”，不让用户猜结束日是否包含。

草稿编辑允许未知；启用前在同一流程检查完整资料。已启用后的固定日历显示为只读并说明原因；调价使用单独入口，展示生效日、原币、金额、套餐及对已有账期的影响。未知价格不自动补零。

表单字段保持可见标签、明确必填项和字段说明。供应方及文件使用准确修订选择器；付款标签仅收集识别所需简称/尾号，不收集完整卡号。长表单按供应方与负责人、日历、价格、依据分组，按钮保留在可达的末尾。

## 4. 暂停、取消、核实与归档

| 动作 | 确认区必须展示 | 成功后准确文案 |
| --- | --- | --- |
| 启用 | 产品、范围、首次收费日、周期、已知价格与依据 | “已启用内部订阅管理” |
| 暂停 | 生效规则、保留历史的说明；供应方状态单独显示 | “已暂停后续正常预测” |
| 恢复 | 当前固定日历、恢复日、停用区间规则 | “已恢复后续正常预测” |
| 登记取消 | 取消生效日、内部操作影响、供应方核实情况 | “已登记内部取消”，需要时补充“尚未到生效日” |
| 核实供应方 | 实际核实状态、实际时间、固定证据及当前内部状态 | “已保存供应方核实依据” |
| 归档 | 当前取消、供应方证明和持久账期核对条件；服务端阻断原因 | “已归档订阅记录” |
| 恢复归档记录 | 说明恢复的是取消状态下的历史核对能力 | “已恢复历史核对入口” |

“恢复归档记录”不能写成“重新订阅”，也不能暗示恢复供应方服务。暂停和取消均不显示“供应方不会再扣费”，除非另有实际核实事实；核实事实仍只表示所记录的时点。

敏感操作复用近期 MFA 流程；完成身份确认后保留输入，仍由人再次点击业务动作。版本冲突保留理由、日期、附件选择与金额，提供核对最新状态入口；不得自动丢弃输入并以新版本重提。

## 5. 账期列表与对账详情

账期列表按收费日范围及状态筛选，日期依据每项订阅的计费时区。每项显示收费日、区间、币种、预计、真实发生、核对状态及异常。到期、部分扣款、超扣、发票待补、停订期间扣款和旧核对失效分别表达。

详情顶部保留订阅返回入口、准确账期和状态；金额区并排或纵排显示预计与真实发生，窄屏不强行保留双栏。随后展示固定价格依据、关联费用、固定核对凭证、价格修订历史与操作时间线。

关联费用时选择当前有权读取的规范费用，显示币种、供应方、发生日、金额、状态和准确修订供人工确认。一笔规范费用的其他业务关联仍然可见，不能因关联账期另造一笔费用。真实金额汇总由接口提供，前端不进行浮点相加。

人工核对区固定本次看到的费用集合及其版本，显示预计与实际是否有差异、是否缺发票、固定凭证及理由。差异确认必须由用户主动勾选，默认不勾选。费用在另一会话中冲销，即使账期头版本没变化，也必须阻断旧集合提交并保留输入。

“免付”“作废”“重新核对”分别解释后果。已有历史费用关联的账期不能通过免付或作废隐藏实际支出。停订后异常账期必须有准确日期和依据，创建成功只表示已登记账期。

## 6. 三种月报与预测覆盖

月度预测、月度发生支出、现金月报使用平行的页面入口与一致筛选布局。页面标题和金额卡片明确标明口径；从一个入口切换到另一个入口时重新按各自日期口径查询，不把同名月份当作相同财务事实。

| 视图 | 期间依据 | 主要数值与钻取 |
| --- | --- | --- |
| 月度预测 | 订阅计费本地自然日，显示所涉时区 | 每原币预计金额、账期数、待核对数、异常数；钻取持久账期 |
| 月度发生支出 | 已确认规范费用的发生日期及既定时区 | 每原币原费用、冲销减少、净额；钻取规范费用 |
| 现金月报 | 真实资金发生时间与报表时区 | 每原币付款、退款、冲销和净现金；钻取实际资金 |

预测页在合计附近持续显示覆盖情况：缺账期、缺价格、未补齐草稿、配置不完整或扫描达到上限。覆盖不完整时合计仍可表示已知持久预测，但标题需说明“已知预测”，不能宣称完整本月开支。空合计同时有覆盖缺项时不得显示“本月无需支出”。

初期以可核对的列表和原币金额卡为主。后续图表只能使用受控图表令牌，提供文本标签与明细；不能用有填充面积的图形暗示未计算的摊销、收入或汇率总额。

## 7. 提醒与历史

提醒配置显示提前自然日及计费当日。持久提醒的“已排队”只表示进入内部事件链路；只有实际投递回执才能显示“已送达”。通知链路尚未实现或不可用时明确说明当前边界，不能用绿色已完成图标代替未知投递结果。

时间线将人工动作与后台账期生成分开命名；后台任务不能显示成某员工确认付款。历史修订展示当时固定价格和凭证；当前费用发生变化时，旧记录仍是旧依据，同时标出当前需重新核对。

## 8. 四端与验收矩阵

Web支持完整维护和对账；微信、抖音与Android复用相同术语、状态与授权事实，具体页面开放范围以实际实现与端能力矩阵为准。移动不把桌面多栏表格整体缩小；必要的长凭证、套餐名、币种及小数金额应自然换行。

| 必验项 | 样例和判断 |
| --- | --- |
| 双主题 | 正文、表单边界、状态、选中与焦点使用已验证令牌组合 |
| 五档Web视口 | 320/390/768/1024/1440；无根页面横向溢出，弹窗可独立滚动 |
| 真实状态 | 未知价格、已知零价、月底锚点、未来取消、停订后扣款、部分/超扣 |
| 金额与范围 | 长小数、多原币、项目/公司、缺汇率，合计与明细口径相符 |
| 冲突与权限 | 另一会话更新配置、费用冲销、授权撤销；输入保留及安全错误 |
| 键盘与触摸 | 对话框焦点约束、子选择器关闭后回到父表单；可见焦点和触摸命中区 |
| 当前证据 | 自动布局检查后人工复核代表截图；记录来源摘要、执行时间和未测平台 |

执行记录应放到 `docs/quality/evidence/` 并在[设计验证记录](06-design-verification.md)链接；在取得真实证据之前，本表只作为验收要求。原生平台需独立真机检查，不由Web结果推定。
