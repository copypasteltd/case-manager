# 页面蓝图与四端适配

版本：v1.0.0-draft；日期：2026-10-23。页面编号与能力边界以 [客户端页面矩阵](../development/06-clients-and-pages.md) 为准；本文件补充布局与风格，不能自行缩减四端首发。

## 1. 桌面应用骨架

左侧240px导航，上方64px顶栏，中间可伸缩主工作区；收起侧栏72px。内容左右32px，最大1600px居中；标题区之后是筛选/动作区，再进入内容。默认采用中性背景侧栏，当前项浅蓝底+蓝侧线，禁止整块饱和蓝导航。

建议导航分组：工作台；项目、文件、知识；审批、费用与订阅；秘书、服务状态；有权用户的系统设置。通知入口在顶栏，个人账户在侧栏底部/顶栏。项目详情内的「文件/日志/合同」属于项目子导航，不另复制一套同名全局对象。

顶栏只放面包屑/页名、搜索、通知和用户必要入口；业务主操作位于页标题旁。工作台可以有品牌衬线标题，详情和编辑页优先无衬线，以内容和任务操作为中心。

## 2. 响应式断点与重排

| 宽度（CSS px，Web设计） | 导航 | 内容与操作 |
| --- | --- | --- |
| ≥1180 | 完整侧栏 | 双栏详情/3—4列轻指标；表格按实际字段宽度 |
| 900—1179 | 默认收起侧栏，可展开 | 次要侧栏折叠；指标2列，必要表格局部横滚 |
| 640—899 | 顶栏菜单触发抽屉 | 单列主内容；筛选可折叠；详情辅助信息下移 |
| <640 | 紧凑顶栏+移动导航 | 16px页边距；卡片列表；固定操作区预留安全高度 |

断点继承官网，但以上导航/重排规则是D。不得只依设备UA选择布局。宽屏控制行长，小屏优先重排而非缩字。最低验证320px，常见390px，另验768/1024/1440；浏览器200%缩放仍可读、可操作。

局部复杂表格允许有标题说明的横向滚动区域，键盘可操作；根页面不得横溢。固定头/底栏不遮焦点和最后一行；弹窗内容可独立滚动，移动复杂编辑转完整页面。

## 3. 19组页面设计配方

| ID/页面 | 布局与内容顺序 | 关键交互/视觉要求 |
| --- | --- | --- |
| PG-01 登录/绑定 | Logo+紧凑标题→表单→MFA/绑定→帮助 | 无大营销Banner；焦点/错误可见，不枚举账户；深色Logo配对 |
| PG-02 工作台 | 衬线欢迎标题→待办/到期/异常→近期项目→秘书入口 | 用户有权范围；数值有截止时间，不把装饰统计放在待办前 |
| PG-03 项目列表 | 标题/创建→筛选→项目列表→分页 | 名称/负责人/状态/截止/里程碑；卡片与表格可按场景选择 |
| PG-04 项目详情 | 标题/状态/动作→项目子导航→主内容+摘要栏 | 子页任务、里程碑、风险、变更、交付、成本、文件/日志/合同；归档只读与关闭阻塞可见 |
| PG-05 任务 | 标题/状态→描述与验收标准→依赖/子任务→评论→历史 | 依赖阻塞有说明；移动用整页，不把关键操作埋在hover |
| PG-06 文件中心 | 目录树→面包屑/搜索/上传→文件表→上传队列 | 小屏树切为目录选择页；副本状态独立列/详情；不一屏展示所有元数据 |
| PG-07 文件详情 | 名称/版本/分类→安全预览→元信息/副本/历史 | 不支持预览有原因与有权下载入口；历史恢复说明生成新版本 |
| PG-08 项目博客/知识 | 标题/来源/版本→舒适宽度正文→关联资料→修订 | 编辑与阅读分开；草稿/已发布区分；冲突保留草稿 |
| PG-09 OA中心 | 我的申请/待审批/已处理→类型/时间筛选→列表 | 合同、采购、报销快捷创建；不出现考勤/人事入口 |
| PG-10 审批详情 | 固定修订摘要→申请内容/附件→时间线→处理区 | 金额/币种/版本先于批准动作；旧快照和本人禁止审批说明 |
| PG-11 合同 | 合同概要→修订/签署→履约节点→关联收付/附件 | 各阶段分开，不用一个「已完成」掩盖未履约/未结算 |
| PG-12 采购 | 申请→订单→收货/差异→结算 | 长行项支持分段编辑；手机可完成必要申请与审批 |
| PG-13 报销 | 草稿摘要→明细/票据→核对→分摊/结算 | OCR候选醒目标记；缺票原因/重复提示；币种口径清楚 |
| PG-14 费用总览 | 账期/币种/项目筛选→预测/发生/现金→趋势→明细 | 无汇率不可伪合计；表格与图表同口径；导出异步反馈 |
| PG-15 订阅 | 当前服务/费用→价格历史→账期→取消/提醒→实际账单 | 月底锚点和取消生效日期明确；取消后扣费异常突出 |
| PG-16 秘书 | 会话列表→消息/来源→计划/差异→输入→任务状态 | 小屏会话列表单独一页；授权卡和结果证据稳定，流式不抢滚动 |
| PG-17 状态/事件 | 总体影响/最后更新→服务观测→事件/维护→时间线 | unknown/down/维护分开；按权限给监控入口，不给生产控制捷径 |
| PG-18 设置 | 分类导航→当前配置/生效版本→编辑→变更证据 | 仅有权管理者可操作；管理身份不带来内容全读权；危险动作按业务二次认证 |
| PG-19 通知 | 未读/全部/待处理→筛选→通知列表→安全跳转 | 已读和已完成分开；失权目标统一安全文案 |

每页至少交付正常、加载、空、失败、失权、过期、冲突、离线的适用示例。产品尚未开发时这些是设计/测试要求，不能填为已通过。

## 4. 关键用户旅程的界面连接

新建项目：项目列表创建→选择模板/范围/成员→检查初始目录和任务→创建结果→项目详情；秘书创建同样给真实项目ID和初始化缺项。不可在创建结果写「所有资料已齐全」除非核对事实。

合同/采购/报销：草稿→必要字段/附件核对→提交修订快照→待审批→本人有权节点处理→业务后续履约/收货/付款。所有阶段沿用同一对象标识和修订关系，避免不同入口形成重复单据。

120GB文件：目标项目/目录→选本地原件→会话/分片传输→断线恢复→校验/生成版本→OSS/R2各自状态。工作台和文件页都能返回同一上传任务，不因切页生成新上传会话。

秘书更新资料：明确范围→来源读取→草稿/差异→按既有L1授权执行或L2固定计划→逐项结果/版本/副本。会话结果能打开真实业务详情，详情历史能追溯秘书动作；TG仅给披露范围内摘要或登录链接。

## 5. 微信与抖音小程序

建议底部5项：工作台、项目、待办、秘书、我的。文件/知识由工作台和项目入口进入；费用/订阅/状态通过工作台快捷入口。此为D的信息架构建议，不代表已经确定平台原生tabBar配置；需要真机验证平台允许的形式与数量。

小程序必须能查阅、完成必要合同/采购/报销申请、提交与审批；不能把所有编辑简化为「请去电脑」。复杂桌面配置可以按既定能力矩阵转Web。普通票据附件/拍照受实际平台限制，120GB不在小程序承诺中。

视觉沿用背景、文字、状态和主按钮关系；顶部原生导航及系统选择器按平台允许范围配置，不能承诺所有系统弹层完全同色。长表单按业务段落拆分，步骤内保存草稿，返回前说明未保存内容；账号绑定/权限说明明确。

设计稿以375逻辑宽度为标尺；在750rpx标尺且375 CSS px视口的前提下，32rpx对应16 CSS px，但该关系随视口改变。不能把所有CSS px无条件改成同数值rpx，也不能把48rpx当48px命中区。需要各端设计适配器、平台编译结果与真机共同验证。

## 6. Android

Taro Android运行路径和原生能力沿用工程PoC，不能把Web CSS直接当原生样式。共享语义令牌和状态文案，字体/阴影/点击反馈、导航/返回栈、文件选择和后台任务分别适配。48为移动设计目标，Android需在dp/字体sp体系下落实并实测，不把px、rpx、dp、sp混成一种单位。

原生上传队列提供前台/后台状态、暂停、恢复、重选源文件、系统权限修复、任务结果；应用被系统终止后恢复显示真实已传分片。不能在UI写「退出App也一定上传成功」。上传进度通知按平台实际可用路径实现并测试，图片缩略图不会通过读取整个120GB文件生成。

导航手势、系统返回、键盘与输入法、安全区、字体放大和深色主题分别验证。真机而非本地模拟器进行首发验收，遵守不启动本地虚拟化的约束。

## 7. 主题、偏好与语言

Web提供浅色/深色/跟随系统；默认跟随系统，用户显式选择优先。首次绘制前尽量确定主题，防止闪白；本地只存非敏感外观偏好。服务端不依设备主题改变业务含义，退出/换账户不得残留敏感页面缓存。

移动对受控业务页面保持双主题一致，系统原生控件遵循平台能力；不支持动态切换的页面必须在设计实现评审中列出具体降级。字号放大时按钮可长高、标签可折行，禁止截断金额/审批结论以维持固定高度。

当前中文文案只是草案语言口径；香港使用者的简繁/英文偏好待确认。日期/金额格式按组织/用户偏好显示，但数据口径仍由统一契约决定。

## 8. 原型到实现的交付包

每页交付：可编辑布局/组件引用、双主题、代表性宽度、完整状态、字段/接口映射、权限分支、键盘/读屏说明、文案、真机验证要求。工作包可先做已定义页面，不以整个产品高保真未完成阻塞独立开发。

[风格样板](styleguide.html) 仅展示骨架、关键组件和示例工作台，不能代替19组页面的业务高保真。后续页面必须在本体系内展开，确需新增模式则先补组件/令牌说明和适用边界。
