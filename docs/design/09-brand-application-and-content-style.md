# 品牌应用、业务界面与文案规范

版本：v1.0.0-draft；日期：2026-10-23。本文将官网视觉语言落实到内部平台的日常工作界面，供产品、设计、开发和测试共同使用。官网事实标记为 O；为内部产品制定的规则标记为 D。本文不构成公司既有完整 VI，也不改变业务权限与状态定义。

## 1. 整体设计方向

内部平台采用「温和的画布、清楚的文字、安静的面板、明确的行动」作为设计方向。员工进入系统后，首先能找到待办、项目、文件与下一步操作；品牌通过配色、排版和组件形态保持连续性。

| 设计特征 | 官网依据 O | 内部平台执行 D |
| --- | --- | --- |
| 温和 | 暖灰白画布，纯白面板；深色为蓝灰黑 | 页面使用 canvas，内容使用 surface；避免纯白大底与卡片没有层次 |
| 清楚 | 墨色正文、次级灰字、明确标题层级 | 正文和金额使用无衬线；标题、状态、操作、辅助信息按重要性排列 |
| 克制 | 少量蓝色、细线、较少装饰色 | 蓝色承担链接、焦点、选择和来源提示；状态色用于具体事实 |
| 有品牌识别 | 衬线展示标题、圆角标识、线条与节点 | 衬线限于欢迎和品牌展示；来源与摘要可使用3px蓝色强调线 |
| 可靠 | 稳定的内容区、面板和按钮结构 | 版本、金额、审批、保护状态分开表达，提交结果必须有实际依据 |

界面中的主要品牌识别组合固定为：当前官网 PNG 标识、暖灰白/蓝灰黑背景、黑白主按钮、少量蓝色强调、有限使用的衬线标题。颜色和形态的准确数值以 [视觉基础](02-visual-foundations.md) 与 [令牌源](tokens.json) 为准。

## 2. 色彩使用顺序

### 2.1 基础色速查

| 用途 | 浅色主题 | 深色主题 | 规则 |
| --- | --- | --- | --- |
| 页面画布 | #F6F6F4 | #0F131A | 覆盖工作区底层，保持大面积安静 |
| 内容面板 | #FFFFFF | #171D29 | 承载表格、详情、表单、会话等 |
| 主要文字 | #15171A | #E8EDF8 | 标题、正文、重要数值；同时为主按钮填色 |
| 次级文字 | #5D636D | #A0ACC2 | 说明、时间、来源信息；保持可读 |
| 品牌强调 | #1F5EFF | #79A2FF | 链接、焦点及少量强调，不能任意配所有底色 |
| 轻分隔线 | #D8D9DE | #2A3344 | 区分面板和内容，不代替必须辨识的控件边界 |

以上为官网基础色 O；状态、选中底、控件边界和图表是 D。不得从此速查表直接拼出未经验证的新前景/背景组合。尤其浅色选中背景必须搭配 fg.selected，不能使用对比度不足的原始品牌蓝作为普通选中文字。

### 2.2 一屏中的颜色关系

一屏先由中性色建立结构，再用黑白按钮指出当前主要动作，最后用蓝色和必要状态色补充信息。此处是设计优先级，不是对官网像素面积的统计，也不规定每个页面必须符合某个色彩百分比。

| 元素 | 推荐处理 | 使用边界 |
| --- | --- | --- |
| 当前导航 | selected 背景、selected 文字、当前项语义 | 不依赖单独一条蓝线表达当前位置 |
| 普通链接 | accent 前景，必要时保留下划线 | 与正文混排时应有颜色之外的可识别线索 |
| 主要操作 | action.fill / action.on，胶囊形态 | 同一局部决策区通常一个；不能每行都放一个最强按钮 |
| 次要操作 | surface 背景、control 边界和正常文字 | 与主要操作并排时保持明确层级 |
| 删除等危险动作 | danger 专用组合，并写清对象与影响 | 一般编辑、撤回、业务拒绝不因重要就全部使用危险填色 |
| 成功或异常 | 状态标签和具体事实文字 | 不给整张合同、项目或文件面板铺满红绿底 |
| 财务数据 | 正常文字、原币单位、对齐的数值 | 收入/支出用明确文字或符号，不只用红绿区分 |

## 3. 标题、内容与空间

工作台欢迎标题可使用品牌衬线，桌面 display 为40/52，移动为28/40；业务页面标题使用无衬线，默认28/40，窄屏24/34。普通表格、菜单、输入、审批和秘书正文统一无衬线。字体栈及加载边界沿用视觉基础，不能把 CSS 中出现的字体名称等同于实际已加载字体。

标题先写对象或任务，例如「合同」「收付款计划」「待我处理」，不添加没有业务作用的英文眉题和序号。确有顺序的审批步骤、修订历史和任务流程可以编号；平行模块不为了装饰编号。

桌面默认240px侧栏、64px顶栏、32px页边距、最大1600px工作区。面板内20—24px，面板间24px；移动页边距和面板内距通常16px。正文、名称和金额可使容器长高，不用固定高度截掉重要内容。完整尺寸、密度和断点见视觉基础及 [四端规范](04-page-and-cross-platform-design.md)。

## 4. 各业务模块的风格应用

以下是同一套品牌体系的不同内容组织方式，不为每个模块另建品牌色。

| 模块 | 首要视觉信息 | 品牌应用 | 应避免的问题 |
| --- | --- | --- | --- |
| 登录与身份 | 登录方式、当前步骤、错误、恢复入口 | 当前标识、简洁衬线品牌标题；可用局部淡网格 | 大型宣传图挤占表单；把验证码、恢复码当装饰内容 |
| 工作台 | 本人待办、到期事项、异常、近期项目 | 欢迎标题适度展示品牌；其余为稳定列表与描边面板 | 大量彩色指标卡把真实待办推到首屏之外 |
| 项目管理 | 名称、阶段、责任人、下一节点、阻塞 | 中性列表，蓝色表示当前选择或导航 | 无依据的完成百分比；用颜色代替验收条件 |
| 文件管理 | 名称、版本、分类、大小、上传及保护事实 | 清楚的目录层级；版本、来源可用蓝色细线 | 将上传100%、正式提交、OSS副本与R2副本合并成「完成」 |
| 项目博客与知识 | 已发布标题、正文、目录、来源、修订 | 适合阅读的窄内容区；文章标题可有限使用衬线 | 长篇正文整页横向铺开；普通读者看到未发布草稿 |
| 合同 | 对方、金额/方向、业务修订、批准、签署、生效与履约 | 主要事实稳定排列；使用独立状态和历史区 | 用一个绿色「已完成」同时代表审批、签署、付款和履约 |
| 采购与报销 | 申请内容、明细、附件、当前审批与结算 | 分段表单、可核对摘要、固定版本信息 | OCR候选当作已核实事实；金额和币种被省略 |
| 月开支与订阅 | 账期、原币、预计、已发生、现金、取消生效 | 无衬线数值、对齐金额、受控图表序列 | 缺汇率仍合计；取消申请直接显示「不会再扣费」 |
| 公司秘书 | 消息、可核对来源、范围、差异、执行结果 | 中性会话；引用使用蓝线；计划与结果独立成块 | 发光机器人、持续动画；把生成文字当作实际执行凭证 |
| 服务状态 | 真实观测、最后观测时间、事件、维护影响 | 列表优先，明确状态文字，必要图表辅助 | 无数据仍显示正常；维护状态遮盖服务实际中断 |
| 设置与权限 | 当前配置、适用范围、生效版本、变更影响 | 功能分组明确，危险动作与日常编辑区分 | 通过管理员身份推断可读全部业务内容 |
| 通知与TG摘要 | 对象、事项、时间、需要采取的动作 | 短句和安全链接；文字能独立表达状态 | 依赖卡片颜色才能理解；向群聊泄露附件或敏感金额 |

具体页面采用 [PG-01—19页面规则](04-page-and-cross-platform-design.md)、[页面布局与任务流](08-page-layouts-and-flows.md) 和 [CP-01—28组件契约](07-design-handoff-and-component-contracts.md)。本表不代表这些模块均已开发完成。

订阅维护、账期核对、三种月报及提醒的页面细节另见[订阅与财务页面设计](10-subscriptions-and-financial-views.md)，沿用本章品牌规则。

## 5. 四类页面的构图配方

| 页面类型 | 内容顺序 | 主次关系 | 窄屏处理 |
| --- | --- | --- | --- |
| 工作台 | 欢迎与常用入口 → 待办/异常 → 近期项目 → 辅助信息 | 待办占主要工作区；指标压缩为摘要 | 按同一重要性顺序单列，辅助内容置后 |
| 列表 | 页面标题/创建 → 筛选 → 对象列表 → 分页 | 可识别名称优先；状态、金额、时间有固定位置 | 卡片保留对象、事实、动作；高级筛选进入面板 |
| 业务详情/编辑 | 标题/状态 → 关键事实 → 分段正文 → 关联依据 → 历史/操作 | 主要决定与当前版本在同一区域核对 | 单列；底部操作须留安全区和内容避让 |
| 秘书会话 | 会话入口 → 消息与来源 → 差异/计划 → 输入 → 执行结果 | 消息、计划、执行结果各自明确，来源可展开 | 会话列表单独显示；复杂计划进入完整页面 |

面板不机械嵌套：一层用于主要内容区，下一层仅在确有独立对象或可展开区域时使用。表格行、字段和审批步骤通常用留白与分隔线组织，不给每个字段加独立卡片。

## 6. 文案、术语与数字规范

界面采用明确、平实的工作语言。动作名称写出结果，例如「保存草稿」「提交审批」「登记签署」「生成正式版本」「查询处理结果」。按钮与结果反馈使用同一动作概念，避免按钮写「保存」而提示写「已发布」。

| 情境 | 应使用的表达 | 应说明的事实 |
| --- | --- | --- |
| 草稿保存 | 已保存草稿 | 仅代表草稿保存成功，不代表批准或发布 |
| 合同批准 | 本次申请已批准 | 仍需依据流程判断签署、生效、履约和结算 |
| 正文更新冲突 | 内容已被更新，请比较当前版本 | 保留本次未提交输入，提供当前版本与比较入口 |
| 网络中断后的提交 | 暂未确认处理结果 | 提供同一次操作的结果查询，不能直接重建并重发 |
| 上传传输结束 | 传输完成，正在校验 | 后续正式版本与副本状态分别更新 |
| 缺少财务事实 | 尚未登记实际付款 | 不用0元或「已结清」替代缺失信息 |
| 观测失效 | 观测已过期，最后观测时间…… | 不推断当前可用性 |
| 秘书部分完成 | 已完成3项，2项未完成 | 逐项给出实际结果和允许公开的原因，数字须来自真实结果 |
| 统一安全不可用 | 当前无法访问此内容 | 不通过错误文案确认无权对象存在、标题或金额 |

字段标签持续可见，不能只靠 placeholder；错误写明问题和修正方式。多字段错误在表单顶部汇总并关联各字段，提交失败后焦点进入汇总；修正后的字段错误按验证结果更新。避免只弹出短暂toast后把原因清掉。

金额保留币种、方向与口径，未知和零分开；不同币种在缺少已确认换算依据时分别展示。业务日期与事件时间区分，时间有完整时区入口。香港员工的简体、繁体及英文偏好尚待确认，不能根据服务器所在地强行确定；词条须统一维护，并预留翻译后的长度。

## 7. 多端与非网页输出

Web、微信、抖音与Android继承同一语义色、术语、对象版本和状态事实。系统导航、键盘、选择器与安全区服从平台能力；设计稿分别标注 CSS px、rpx、dp、sp，不直接复制单位数值。Android触摸目标按48dp设计，小程序与Web触屏尺寸须依据实际布局转换和验证。

TG以简短文字为主，平台卡片、字体和颜色不能保证与Web一致；事件名称、当前状态和授权入口必须在纯文本中也能理解。只有业务明确授权的披露范围才能进入群消息；本规范不授权发送任何实际消息。

未来增加打印或PDF导出时，应使用独立输出样式：浅色纸面、明确标题、原币金额、准确业务修订及生成时间；不要打印侧栏、按钮、阴影或依赖背景色区分的状态。此处是设计要求，尚未实现或验收打印/导出能力。合同原件和签署件保持原始文件，不用后台样式改写。

## 8. 新页面交付前的快速核对

1. 去掉页面标题后，标识、画布、按钮和排版仍与官网品牌连续；未自行改成另一套主色。
2. 首屏能识别对象、当前状态和下一步操作；品牌展示没有挤掉实际任务。
3. 浅深主题分别核对正文、状态、控件和焦点；没有把语义色任意互配。
4. 金额、币种、修订、审批、上传与副本等事实没有被一个模糊状态替代。
5. 320px窄屏、长名称、键盘、触摸、大字及减少动态效果均有适用检查。
6. 页面正常、加载、空、失败、失权、过期、冲突和结果未知分支有明确文案与恢复动作。

完整验收沿用 [VD-01—14](05-implementation-and-design-qa.md)，不新增重复审批环节。以上为设计约束；实际检查结果须单独提供证据，不得将清单存在视为验收通过。
