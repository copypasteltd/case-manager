# 项目交付与人工验收页面设计

日期：2026-10-24。规则类别：产品派生 D。继承[风格总规范](00-style-design-specification.md)、[视觉基础](02-visual-foundations.md)、[组件契约](07-design-handoff-and-component-contracts.md)，业务约束见[交付实施协议](../development/42-project-deliverables-and-acceptance.md)。本页规定界面行为，实际完成情况与证据另见实施协议。

## 1. 风格与信息层级

交付位于项目详情的“交付”页签，与任务、里程碑、风险及成员共享导航。沿用暖灰白／蓝灰黑画布、中性面板、细描边、墨色主按钮和品牌蓝来源链接。使用既有语义令牌，不新增模块专属颜色。状态始终配完整文字：草稿、待人工验收、已退回待修订、已验收。

列表按交付名称、状态、负责人、更新时间和查看操作组织；支持名称搜索、状态筛选与逐页加载。空状态说明先明确准则再提交准确版本。无权对象不进入列表；读取失败显示错误，不将失败描述成暂无交付。

详情先展示当前名称、交付版本、状态及下次提交使用的准则，再展示修订历史和所选固定修订。明确区分“当前资料”与“当时提交资料”；退回后修改当前准则不能改写旧修订。时间、版本及负责人采用工作界面字体，正文不使用品牌展示衬线。

## 2. 草稿与准确提交

新建／编辑包含名称、验收准则、有效项目负责人、可选里程碑和操作依据。输入有持续可见标签；准则允许长段落及换行。里程碑选择只允许可修改的项目里程碑，分页不能被静默截断为完整集合。

“提交固定交付修订”先展示固定交付版本与本次准则，再填写说明、选择1—20项正式文件版本和操作依据。选择器明确文件名、版本、摘要及扫描状态；选择历史版本后保持该版本，不追随文件的当前版本指针。已选择项目可逐项移除，初始没有默认文件。

已验收后入口称“提交新交付修订”，说明原修订和验收保留，新修订重新等待验收。文件上传、任务完成或秘书整理不能直接改变交付验收状态。

## 3. 人工验收

验收对话框固定打开时的交付版本、准确修订ID及内容指纹，完整展示当时准则、说明、文件名／版本／大小／摘要、来源和扫描豁免风险。长摘要与文件名换行，不能把关键信息裁切为不可查阅的省略号。固定版本下载使用共享下载确认流程。

决定初始为空，由本人选择“通过此修订验收”或“退回修改”。通过验收要求另外两项初始未选的人工声明：已核实全部固定文件及完整内容、已逐项核对本次固定准则。退回填写明确说明；不由秘书预填通过意见或自动勾选。

提交人查看自己的修订时，禁用通过选项并说明需要另一名获授权人员核实；仍可明确退回。两步验证独立完成，验证成功保留输入，主操作仍须本人确认。界面操作能力服从服务器结果；只读成员没有创建、提交、编辑或验收入口。

## 4. 固定历史与异常

历史按钮同时标明修订序号及准确决定。所选修订显示固定名称、准则、说明、提交人／时间、项目版本、提交时交付版本、内容指纹、准确文件，以及决定人／时间／说明。没有决定时写“此修订尚未登记验收决定”，不能把其他修订的通过结果附给它。

业务或文件权限失效时移除对应缓存内容，保留可以理解的错误提示；不能因看不到文件就展示一个不完整但可验收的集合。旧协议记录标明来源待核实，并关闭普通新协议写入，不编造历史。

提交遇到404／409／412时保留名称、准则、说明、原因、文件及决定选择，将焦点移入错误说明，禁止再次提交旧依据。用户关闭后核对最新资料；不得自动替换版本、修订或指纹重试。网络结果不明时保留命令和输入，按幂等协议核对。

## 5. 多端与验收

桌面列表允许内部滚动，页面本身不横向溢出；窄屏对话框保持单列、可滚动、长文案自动增高。沿用统一焦点环与模态焦点管理，嵌套文件选择器关闭后焦点留在当前业务对话框。交互命中区至少24px，常用移动控件按既有48px规则实施；明暗主题分别核对文字、边界及错误状态。

验证覆盖新建、准确历史文件提交、独立退回／重提／验收、固定历史、新修订与旧验收并存、真实版本冲突保留、只读成员。代表页面在320、390、768、1024、1440五档宽度及双主题检查。Web实现和编译不能代替微信／抖音／Android真机交付验收；四端业务术语和固定依据语义必须一致。
