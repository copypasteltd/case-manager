# 移动合同、采购、报销草稿与送审设计

日期：2026-10-24。继承[官网风格总规范](00-style-design-specification.md)与[组件契约](07-design-handoff-and-component-contracts.md)，业务语义遵守[移动业务实施协议](../development/47-mobile-business-drafts-and-submission.md)。

## 1. 品牌落地与信息优先级

使用既有39个双主题颜色令牌、官方双主题标识、无衬线工作字体和少量蓝色强调。暖灰白/蓝灰黑画布承载细线面板；保存、建立申请及确认送审沿用墨底浅字/浅底墨字主按钮。业务类别不另设主题色。

顶部先说明正在起草、编辑或查阅的准确业务，再按基本资料、业务内容、明细/收付计划、保存依据分段。背景、文字、输入、禁用、错误、焦点与状态均从统一令牌取值；不能只切页面大底而保留浅色输入。

## 2. 页面和任务流

```text
工作台 → 合同／采购／报销列表 → 起草或当前业务
                                     │
                               保存业务草稿
                                     ↓
                             当前实际业务修订
                                     │
                               建立申请草稿
                                     ↓
                              固定申请与审批顺序
                                     │
                          打开完整预览 → 人工核对
                                     ↓
                                  确认送审
                                     │
                     指定人员独立处理／申请人明确撤回
                                     ↓
                       当前进展 + 不可变申请修订历史
```

每个步骤显示实际完成程度。保存业务草稿不显示「已送审」，批准不显示「已付款」，原合同批准不显示「已签署」。文字负责说明事实，颜色只作辅助。

## 3. 手机长表单

长表单使用单列、可滚动的分段面板。标题、项目范围、负责人、币种先出现；专业字段紧贴其业务说明，不把金额、计价和税额分散到无关联页面。未知可留空的字段必须明确说明，不自动填入0。

采购/报销明细和合同节点采用稳定编号摘要及单行展开编辑。添加或移除后其他行文字、金额、固定引用及焦点不串行；达到100项后明确禁用添加。合同节点与报销凭证的操作名称包含用途，不能只显示一组相同的「添加」。

可先保存不完整业务草稿。保存依据靠近最终按钮，按钮文字精确到「保存合同草稿」「保存为新的业务修订」。未提交输入超出共享恢复容量时，在表单前部明确提示，当前页面继续保留完整输入。

## 4. 候选与固定资料

项目、人员、供应商与文件从有权访问的真实候选选择，提供查找、继续加载、当前选择及返回表单。用户不需要手工复制 UUID。候选界面从表单状态进入，返回保留其他输入；改变创建范围须明确告知会清除既有引用。

文件先选对象，再选准确版本；每项呈现原文件名或名称未知、版本、可用性、扫描状态和完整摘要。扫描例外显示专用说明。固定文件引用不能悄悄跟随最新版。原依据当前不可读时说明保存停止及修复方式，不能将失权渲染成空列表再静默清除。

现有正式版本选择与本机普通附件上传是独立能力，不能用前者替代首发附件要求。

## 5. 送审和不可逆含义

准备申请说明「固定当前业务，尚不送审」。送审预览展示完整业务内容、固定文件、原币金额、制度名称/修订、实际审批人、自审政策及撤回规则。确认框初始未勾选，查看附件、返回页面或已通过MFA均不自动代表已核对。

只有明确核对并填写依据后才允许「确认以此内容送审」。预览失效、真实冲突或授权变化时停止本次提交，提示重新读取；不替换制度或自动换新摘要。

撤回展示准确申请和影响：已做决定保留，未完成步骤取消。历史视图明确写「该修订当时固定的审批顺序」，旧内容和旧决定不借用当前审批状态。

## 6. 错误、可访问性与多端

验证后显示可定位的错误摘要和字段下具体说明。金额错误说明格式或精度，不将输入自动改成另一金额。服务器没有指定某一行时定位到明细段，不编造行号。输入保留，成功提示只在真实回执验证后出现。

触摸区沿用公共组件的至少44逻辑像素基线，正文与输入字号沿用官网工作字体规范；不压缩长行及长金额来塞进小屏。检查浅/深主题、320/375/390/768宽度及横屏；原生键盘、安全区、系统大字和读屏须由两平台真机分别验证。按钮、输入、复选框使用对应平台可访问名称，不仅依靠颜色。

本地 H5 风格检查可以证明该审阅环境的实际布局，不能代替微信、抖音和Android。截图若只包含Taro内部滚动可见区域，不得声称覆盖整张长表单。
