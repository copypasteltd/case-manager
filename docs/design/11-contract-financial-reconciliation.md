# 合同节点与财务归属页面规范

版本：v1.0.0-draft；日期：2026-10-24。适用 PG-11 合同详情及关联财务操作，属于产品派生规则 D。继承[官网实证](01-website-style-audit.md)、[视觉基础](02-visual-foundations.md)和[财务公共规则](10-subscriptions-and-financial-views.md)，业务以[合同财务协议](../development/38-contract-financial-reconciliation.md)为准。Web 实现与原生移动端验收分别记录。

## 1. 页面结构与视觉关系

合同详情依次呈现合同身份与法律阶段、固定条款/正文、签署生效依据、固定履约计划、合同财务归属。财务操作保持在准确合同和节点上下文中，不将跨合同的资金总额放入某一个节点。

沿用暖灰白／蓝灰黑画布、细描边面板与黑白主按钮。正文、金额、标签均使用工作区无衬线字体；蓝色只用于链接、焦点和选中。不得通过新增渐变、财务专用主色或大面积绿色暗示合同已履行完毕。

财务面板标题为“合同财务归属”，辅助说明“固定计划与实际事实分别核对”。每个节点采用独立纵向分区，节点标题与核对徽标在首行，事实列表在中间，允许的动作在末尾。使用语义令牌，不在组件内另写色值。

## 2. 五类事实分别表达

| 事实 | 推荐标签与展示 | 禁止的推断 |
| --- | --- | --- |
| 批准计划 | “计划应付”或“计划应收”，原币和准确金额 | 不能随实际发生额自动改写 |
| 费用发生 | “已归属真实费用”；应收显示“应收节点不登记支出费用” | 不能将付款金额直接作为费用 |
| 实际资金 | “已归属净收付”，已扣本节点归属退回款 | 不能将尚未分类的退款默认为与本节点无关 |
| 金额差额 | “与计划尚差 / 超过计划”，两个金额分别显示币种 | 不能将超付改写为进度超过100%或隐藏差额 |
| 条件与核对 | “约定条件核实”与独立核对徽标 | 人工核对不等于条件均满足、结清或法律合同完成 |

金额来自后端的十进制字符串，前端不使用浮点累加。数字使用等宽数字排版，币种与金额同组；窄屏可在组之间换行。已知零显示准确零值，受限金额显示“当前不可查阅”，不得使用 `0`、绿色正常或空白代替未知。

## 3. 状态与提醒

| 接口事实 | 界面文案 | 视觉处理 |
| --- | --- | --- |
| 尚无人工核对 | 尚未人工核对 | 中性徽标 |
| 当前指纹与核对一致 | 当前依据已核对 | 中性徽标，保留差额和条件结果 |
| 来源变化 | 来源已变化，须重新核对 | 警示徽标，使用 warning 前景/背景令牌 |
| 核对依据不可读 | 核对情况不可查阅 | 中性，不展示旧指纹或旧条件 |
| 有未归属退款 | 原付款存在尚未归属的实际退款，请核实它对本节点的影响 | 节点内持续警示，不自动冲抵其他节点 |

旧核对曾确认条件满足、但来源已变化时，条件文字追加“须重新核对”。核对徽标不能写成“已结清”“已完成履约”。

## 4. 来源选择与归属操作

“归属真实费用”“归属实际收付款”“归属实际退回款”使用次操作按钮；“核对节点财务”作为该节点当前可用的主操作。只有具备对应授权时展示操作。只读用户保留可读的事实，不显示不可用的写入按钮制造误导。

来源选择器展示名称、币种、金额、发生日期和可核对的固定版本。费用须已确认并关联准确生效合同；收付款须已实际登记且符合范围、往来方与币种。空结果说明当前页无合格来源，保留搜索和下一页入口。不得要求员工手输 UUID、摘要或数据库版本号。

退回款先选择该节点的原正向资金归属，再选择匹配的实际资金。原归属显示操作序号、尚未解除金额、人员、时间和原因，避免仅凭相同金额认领。切换原归属后清空已选退款来源。

操作表单固定打开时的合同版本、财务版本、来源修订与摘要；显示本次原币金额、原因和近期 MFA。验证身份后仍由员工点击明确的业务动作。来源或余额冲突时保留输入，停止自动提交，提示重新核对最新事实。

## 5. 人工核对与解除

核对表单展示计划、净收付、尚差与超额；条件满足、金额差额、未归属退款影响分别用复选项确认。全部默认不勾选。有差额或未归属退款时，相应确认不可省略；不能用一个“确认全部”代替不同含义。

核对须引用具体文件版本。文件选择器与父表单使用原有嵌套对话框规范，关闭子选择器后焦点回到父表单。来源冲销即使未改变财务头版本，旧来源指纹也须被拒绝，理由、金额和附件选择保持可见。

解除操作从准确历史归属进入，展示原操作序号和尚未解除金额，允许部分解除。成功说明追加了解除历史；它不表示删除原费用、撤回银行付款或退回资金。已有退回款时，不能把正向归属释放到不足以解释退回款的金额。

## 6. 历史与关联付款

历史按实际操作时间倒序分页，显示动作、操作序号、金额、原因、人员及香港时间。来源费用／资金使用蓝色文字链接，跳转准确记录。归属金额、尚未解除金额和当前有效金额分别标注；冲销后历史金额仍在。

人工核对记录提供“查阅当时固定的财务依据”，展示当时来源状态、原币有效金额、剩余归属和固定修订，并列出固定凭证。历史状态使用“当时”限定，不能让旧 `recorded` 事实覆盖当前已冲销状态。

客户收款退回使用真实对外付款记录。付款详情新增“收款退回已预留”，与“有效费用分配”“有效实际退款”“当前未分配金额”并列，说明该部分不能重复结算费用。预留和解除须与服务端余额一致，不由界面自行减扣。

## 7. 响应式、主题与可达性

桌面保持清楚的事实列，窄屏自然堆叠；按钮允许换行，不截断完整动作名称。节点标题、徽标、币种与金额在320px宽度下仍可阅读。对话框独立滚动，错误和提交按钮均可达；历史长修订号允许换行。

使用现有24px分区间距、中性边框和控制圆角。复选控件至少24px，整行标签至少44px，标签点击可切换；键盘保留清晰焦点。双主题采用相同层级与状态含义，不以浅色截图代替深色验证。

Web验证320/390/768/1024/1440五档宽度；覆盖正常归属、差额核对、历史、旧依据冲突、应收退回和受限读取。原生微信、抖音、Android使用相同事实语义，须独立联调与真机验收。

## 8. 交接与完成条件

交接资料须包含状态矩阵、默认未勾选的确认项、来源与固定凭证、准确版本冲突行为、五档布局及代表截图。实现记录链接[合同财务协议](../development/38-contract-financial-reconciliation.md)与[实施台账](../delivery/02-implementation-ledger.md)，证据放 `docs/quality/evidence/`。

设计文档存在、截图通过或数据库测试通过均不能单独代表合同业务全部完成。法律完成／终止的独立分区与后续财务变化见[结束页面设计](12-contract-completion-and-termination.md)；真实银行核对、多端页面与上线门禁仍按各工作包验收。
