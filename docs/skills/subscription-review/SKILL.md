按指定账期核对订阅预测与实际扣费、重复及缺票情况，形成有来源的审阅草稿。

执行前遵守[共同业务边界](../execution-boundaries.md)。本技能当前为未发布源码包，实际可用工具与授权以服务端登记为准。

1. 使用 `read_finance_summary`，明确 `month`（YYYY-MM）与 `view`（forecast / actual / cash），可选三位大写 `currency`。范围由当前会话固定：项目会话读取该项目分摊，公司会话读取公司分摊；公司分摊不代表全部项目合计。不能传入其他项目、成员、付款指令或任意 SQL。不同币种分列，缺汇率不填零、不直接相加。

2. 需要逐笔审阅时，先用 `list_subscriptions` 的准确ID选择订阅；可按标题／状态查询，每页最多20项，有 `next_cursor` 必须继续分页。范围由会话固定，公司会话仅列公司订阅，不代表所有项目。不能猜测订阅ID，发现列表本身不证明审阅完成。

3. 使用 `read_subscription_review` 明确 `subscription_id`、本地自然日 `from` 及不含结束日的 `to`，最多366日。工具返回范围内全部已生成账期、固定价格／配置、关联费用原额与项目分摊、真实资金分配及未生成的应有账期。缺失账期不是零支出。最多100项账期、200项费用／分配及500项私有依赖；超限或正文超过90KB会拒绝，须缩小日期或读取准确单条原记录，不返回不完整前缀。逐笔审阅覆盖只针对所选订阅和日期，不能外推全司。

4. 使用 `read_finance_record` 读取真实关联原记录，必须同时提供订阅ID、账期ID、`kind`（cost／payment）和准确记录ID。后台核对实际链路与每名成员当前权限；不能用任意可见付款绕过本会话范围。原费用／付款可能涉及多个项目，原额、分摊、实际分配和全局退款余额分别核对。无分配的退款不自动归属于此账期。

5. 预测来自已存账期，核对 `coverage_complete`、缺失账期/价格、待核对及异常数量；实际支出来自确认及冲销费用，现金来自已登记收付及分摊。三种口径分别调用、分别说明，不能相减后声称净利润或真实余额。不因内部已取消就报告供应商退款或停止收费。部分扣费、超额、缺票及冲销是带来源的待核对信号；同名费用或超额本身不能证明重复扣费，供应商处理须有实际证据。

6. 输出有明确账期、`as_of` / `captured_at`、覆盖说明和 `agent_finance_report` 来源的审阅草稿。完成状态必须引用本次成功摘要、逐笔核对或原记录工具产生的准确快照；发现列表、一般项目读取和其他运行的回执不能证明审阅完成。只读取一条原记录时须明确这一范围，不声称完成了全部账期。快照保持原值，但读取会继续验证每名当前成员的 AI、渠道、财务、固定凭证、供应方、结算及关联资源权限。新增成员不能自动取得旧快照；候选异常不会自动生成已确认费用，不注册扣款、不代付；本技能未开放 Telegram。

源码版本 1.2.0 仍为 draft；受控环境测试不代表真实模型语义评估或上线验收通过。

输出符合随包 result Schema，附准确来源、业务对象和操作引用，明确待补信息与下一动作。
