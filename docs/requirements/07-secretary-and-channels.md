## 3. 预授权与计划

L0 授权内阅读自动执行；L1 明确指令下少量可恢复写入匹配既有授权后执行并给结果；L2 达批量阈值、跨项目或站外通知，必须先产生固定计划。既有明确的自动化授权可匹配后执行，未覆盖时由有权者批准。不得每次正常写入重复询问，也不得把一句泛泛的“帮我处理”视为无限范围授权。

AI-14：计划含 action_items、每项资源/基础版本/参数摘要、预期可见性影响、内容哈希、接收范围、失效时间、费用估算、补偿方法。批准绑定完整 plan_hash 与授权版本。内容、对象、版本、收件人变化使批准失效；不能批准 A 后执行 B。批处理可能部分成功，逐项给结果，补偿是新审计操作。

AI-15：首发秘书不开放修改权限、永久删除、资金执行、任意 SQL/SSH、任意 shell、任意 URL 抓取、生产配置改动。编辑临时文件仅受控目录/格式；不挂载对象存储为无限权限磁盘。若 Runtime 无法限制旁路工具，在该路线下不开放正式写入。

## 4. Telegram

AI-16：Bot 校验 webhook secret、输入大小/类型，持久化 inbox 后应答；以 `(bot_id,update_id)` 去重。portal 发起单用绑定，TG 私聊提供数字 user_id 证明，群里不暴露绑定秘密。相同 user_id 不得跨组织随意复用。

AI-17：只接白名单 chat/topic 的提及、命令、回复；保留隐私模式。读取所有群聊/定时主动群发不是默认授权。群结果取请求人权限与共同披露范围交集；Bot 不能可靠证明所有成员身份时，严格受限只给需登录链接。群迁移/异常成员变更暂停敏感播报并复核。

AI-18：受理、阶段、结果合并投递，不逐 token 发消息。发出前重新检查披露范围；去重键绑定 run+channel+阶段。Telegram 超时可能已送达，记录 delivery_unknown，不能声称恰好一次。不得为本轮写文档去注册 Bot、入群或实际发消息。

## 5. 预算、质量与降级

AI-19：记录每 run/用户/项目/Skill 的模型用量、调用次数、工具结果、估计/实际费用、耗时。接单预留预算、执行分段检查、完结结算；供应商延迟账单可能产生差额，设置保守安全余量。预算/限流/超时/服务不可用时中断或排队，OA、项目、文件手工流程继续。

AI-20：模型上下文仅含当前授权且允许 AI 处理的最少数据；文件/网页指令视作不可信资料。正式知识从业务来源获取，记忆摘要需来源与安全版本。原生线程状态筛选后加密归档或从业务会话重建；不得打包整个用户配置与认证缓存。

验收包含每个 Skill 正常/缺字段/越权/冲突/重复调用/取消/进程崩溃/提示注入；输出“成功”却无工具证据为失败。外发泄露、越权提交零容忍；自然语言质量使用真实脱敏样本与事先固定预期评审，不能只看演示。
