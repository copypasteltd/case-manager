# 身份、权限、分类与审计需求

实现补充（增量97）：小程序平台身份必须由既有员工本人确认绑定，不以匿名身份、昵称或UnionID自动建号；具体配置、MFA、会话失效及外部验收边界见[小程序身份方案](../development/97-mini-program-identity.md)。

版本：v1.0-draft；日期：2026-10-23；关联 U-04/07/10、R-01/02。

## 1. 身份生命周期

| ID | 必须行为 | 失败与边界 |
| --- | --- | --- |
| IAM-01 | 邀请制开户；组织内登录标识唯一；邀请随机单用且过期；员工状态 invited/active/disabled | 禁止公开注册；停用保留历史作者；删除身份不级联删业务 |
| IAM-02 | Web 使用安全 HttpOnly 会话；移动端使用短时访问令牌+旋转刷新；不同设备可单独撤销 | 令牌不入 URL/日志；Web Cookie 写操作校验 CSRF；重放刷新触发会话撤销 |
| IAM-03 | 管理员 MFA；密码采用审计认可的现代哈希参数；登录限速；找回单用令牌 | 不发回原密码；错误不枚举员工；恢复码摘要存储 |
| IAM-04 | 停用/撤角色/项目成员移除后，新请求与工具立即拒绝；重建相关 AI 上下文 | 不能仅等待 JWT 自然过期；已完成下载或外发不能虚称已撤回 |
| IAM-05 | 微信/抖音身份先由员工账号绑定，平台 openid 等只证明平台身份 | 不因首次微信/抖音登录自动创建特权账号；不同平台 subject 不混用 |
| IAM-06 | TG 数字身份单用绑定；重复绑定、解绑、账号停用有可追踪记录 | 不按昵称授权；匿名 sender_chat 不具备个人写权限 |

三人可兼任角色，但每个动作仍依据实际权限判断。系统管理员、业务管理员、项目负责人、成员、审批人、费用经办、运维、审计、股东是可组合的职责集合，不硬编码八个部门。

## 2. 权限表达

`允许 = 账号有效 ∩ 角色动作 ∩ 组织/资源范围 ∩ 分类 ∩ 渠道 ∩（AI 时）任务范围`。默认拒绝，任何限制项均不能被另一个宽泛角色绕过。

范围可取本组织、指定项目、指定对象、本人创建；“本人创建”不覆盖审批人、分类和归档限制。资源授权必须保存 action、scope、subject、grantor、valid_from/until、版本与理由。显式受限资源可以收紧父目录权限；首发不提供任意复杂 allow/deny 策略语言。

| 动作组 | 示例 | 约束 |
| --- | --- | --- |
| 组织配置 | user.invite/disable、role.assign、policy.manage | 与 file.read、finance.read 分开；敏感变更二次认证 |
| 项目 | project.create/read/update/manage_members/archive | 成员变更不能给超出操作者可授予范围的权限 |
| 任务/知识 | task.assign/transition、post.write/publish | 归档项目写入受限；发布仅内部 |
| 文件 | file.read/upload/update/move/trash/restore | 跨项目移动逐项检查源/目标及可见性变化 |
| OA | request.create/submit/withdraw、approval.decide | 审批只对分配给自己的有效步骤；不能传审批人 ID 冒充 |
| 费用 | cost.record/confirm/reverse、payment.record、report.read | 原始费用、付款与汇总可分别授权 |
| AI | agent.run、plan.approve、skill.release | skill.release 不自动得到业务修改权限 |
| 状态/审计 | service.read/manage、incident.update、audit.read/export | 日志中的内容与 Token 脱敏；审计导出需独立权限 |

## 3. 分类与渠道

| 分类 | 默认读范围 | AI/站外默认策略 |
| --- | --- | --- |
| internal 公司内部 | 获授组织内容权限的员工 | AI 另需 ai_allowed；TG 还需群 allowlist |
| project_restricted 项目受限 | 获授该项目/资源的人 | 不因股东个人可看就发到群；项目共享会话复核成员 |
| confidential 严格受限 | 明确对象授权 | 默认 AI 禁止、站外正文禁止；仅登录门户查阅 |

分类、`ai_processing_allowed`、渠道允许范围是独立属性。初值只收紧，业务确认后才能扩大。移动/复制/新版本/文章引用不得意外降低分类；复制继承更严格的来源与目标限制。变更分类需要专门权限和审计，不由普通重命名触发。

列表、分页总数、聚合统计、搜索词命中、自动补全、预览缩略图、文件名、引用标题、错误提示、缓存都受 ACL。后台索引保留资源/版本标识，查询必须过滤授权；无授权引用不得在先生成摘要后才删链接。

签名 URL 是短时 bearer 凭证，日志/聊天不能保存完整 URL。普通下载允许短 TTL，撤权后已签 URL 在有效期内的风险需可见；confidential 采用每次鉴权代理/受控流式读取。代理下载使用限速与 Range，120 GB 普通流量不默认经过应用机。

## 4. 权限变更与缓存

组织/用户/项目保存 `authorization_version`。权限变更与审计/outbox 同事务；请求鉴权比较当前版本，不把长时间缓存当唯一判据。权限缓存命中也需要确认会话未撤销和安全版本有效。无法取得授权状态时受限读取/写入 fail closed。

权限发生变化后：停止受影响尚未提交操作；已运行任务标记需重授权；旧生成计划失效；会话只保留有权可见业务消息视图，下一轮新建/重建模型上下文。不能继续原生线程并仅在提示词追加“不要提及”来撤权。

RLS 可作为补充，但不得替代 Go 鉴权。应用连接不得用 superuser/BYPASSRLS；涉及事务局部身份设置必须确保连接池复用清理，管理员维护路径单独审计。

## 5. 审计

IAM-07：正式业务写入必须与审计/outbox 在同一 DB 事务持久化；至少含组织、真实发起人、执行身份、会话/渠道、request_id、run_id、资源/修订/版本、动作、前后摘要、结果、原因、时间。登录失败与拒绝单独记录，避免在失败事务回滚时丢失。

审计追加、不可由普通业务接口修改；应用账号无删除历史权限。包含敏感字段的 old/new 只保存必要字段或摘要，禁止密码、访问令牌、全文合同和模型私有推理。导出清单校验与独立保管降低篡改风险，但不声称普通 DB 日志天然不可篡改。

验收：两个交叉项目账号尝试列表、搜索、引用、下载、审批、成本统计、撤权后继续会话，越权成功数必须为 0；系统管理员没有内容授权时也适用。
