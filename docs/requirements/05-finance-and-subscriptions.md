# 费用、订阅、付款与月报需求

增量116当前约束：受控实际双币核销按人工明确输入的费用原币、付款本金、实际汇率及凭证来源执行，部分释放／退款及全额冲销分别守恒两套余额；费用与批准垫付保持原币。手续费和汇差不自动归类，异币实收退款和公司财务制度采纳仍开放。见[详细约束](../development/116-cross-currency-settlement.md)。下文增量89／106的能力描述保留其原实现范围。

增量102已实现可由有权限员工明确发布的基础币种和人工区间汇率版本，以及发生／现金／预测的独立报表折算。实际公司的基础币种与报价内容仍需在使用时明确选择，示例不充当公司配置。增量106进一步提供人工选用的版本化摊销计划与独立报表；公司仍需明确选用财务制度。Q07中的跨币种核销、手续费／汇差及完整旅程仍待完成，不因新增能力而默认启用。见[增量102](../development/102-finance-fx-valuation.md)。

实现追踪（增量88）：[完整财务筛选、规范来源与限时异步导出](../development/88-financial-report-filters-and-exports.md)已在Web／Taro接通三种口径、期间／项目或公司／原币／类别／供应方／经办或负责人／关键词、签名明细与本人任务分页、独立导出授权、实际worker快照及24小时重新鉴权下载。增量87的当前预算对比继续保留。只代表授权记录；跨OA旅程、更多财务写入、汇率制度、实体设备及生产验收仍按GAP-03／18推进。 Implementation trace: complete authorized filters, canonical sources and owner-only asynchronous expiring CSV exports are implemented; currency policy, broader workflows and production acceptance remain open.

版本：v1.0-draft；日期：2026-10-23；关联 U-16、ADR-06、Q-07。系统提供经营台账，不实现会计总账或资金执行。

## 1. 费用模型与避免重复

| ID | 规则 |
| --- | --- |
| FIN-01 | 预测 expected_cost、实际费用 actual_cost、付款 payment 三种事实独立保存，不互相当作同义状态 |
| FIN-02 | 同一实际经济事项只有一个实际费用 ID；采购、报销、合同、订阅通过 cost_links 关联，不按各业务单重复求和 |
| FIN-03 | 实际费用含供应方、发生日、类别、原币金额、核实状态、来源唯一键、项目分摊、凭证和版本；draft/confirmed/reversed，entry_kind=expense/reversal；confirmed 不原位改金额 |
| FIN-04 | 一项费用允许多次付款，一笔付款可分配多个费用；分配总额不得超过有效付款金额；退款/冲销有明确反向关系 |
| FIN-05 | 项目成本按费用分摊归集，全部分摊之和等于费用金额；公司费用可占一部分，不因多项目关联重复统计 |
| FIN-06 | 支出、收入、转账分别表达。合同应收/客户回款不计作费用；内部转账不是新增成本 |

`source_key` 由规范化来源生成，例如 `subscription:{id}:period:{period_id}:charge:{external_ref}`。没有可靠外部参考号时，录入需要可持久化的人工确认标识；摘要相近只能提示疑似重复。数据库保存 `(org_id, source_key)` 唯一；幂等缓存过期后这个约束仍有效。

例：年费 HKD 12,000 同时关联采购、合同与一张报销，实际费用仍只有 HKD 12,000；员工垫付的报销付款是清偿对应费用，不创建第二项费用。分摊项目 A 7,200、项目 B 4,800，总额仍 12,000。公司已直接支付的同一费用再报销必须提示/阻止未经解释的重复结算。

## 2. 金额、币种与汇率

FIN-07：API 金额使用十进制字符串；数据库 `numeric(20,6)`，依据 currency_exponent 校验录入精度；不使用二进制浮点计算。原币总额由明细定点求和，税额、折扣、含税口径须显式；不自动假设特定税制。

折算保存 `base_currency / fx_rate / rate_date / rate_source / rounding_rule / base_amount`。汇率正数，候选存 `numeric(20,10)`；中间计算保留精度，汇总按记账币种精度舍入，舍入差异分配到明确的一行且留说明。修改汇率源不追改已确认快照。

基础币种、汇率日期与财务口径未确认时，各币种单独展示；缺汇率不填 0，也不把 HKD/USD/CNY 直接相加。费用发生日期是业务时区 date，付款实际时间保存 UTC 与业务日期快照。

## 3. 订阅台账

FIN-08：字段含供应商/产品/套餐、owner、项目或公司成本、开始日、计费周期 month/year/custom、锚点日、业务时区、原币、价格版本、试用截止、下次扣款日、续费方式、付款方式安全标识、通知提前量、取消时间/生效时间。不得存完整卡号/CVV。

生命周期 `draft → active ↔ paused → cancelled → archived`；past_due、即将续费、取消待生效为可计算信号，不挤入互斥主状态。paused 不代表供应商已停止收费，需记录供应商实际状态/证据。取消仅内部标记不能报告“供应商已取消成功”，除非有外部证据。

FIN-09：价格版本有 effective_from/to、套餐/币种/金额与原因，区间不得重叠；生成账期时锁定价格快照，后续变价不覆盖历史。周期用半开区间 `[period_start, period_end)`，`(subscription_id, period_start, period_end, charge_type)` 唯一。按月以原锚点计算，月底截到当月末，不能二月截短后永久漂移到 28 日。

FIN-10：账期状态 forecast/awaiting_confirmation/confirmed/waived/void；定时任务只生成预测和提醒，不直接凭预测制造实际已扣款事实。真实扣款需人工确认或后续核准对账适配器证据；部分扣款、超扣、缺票、重复扣款、取消后仍扣款形成异常待办。

暂停/取消后重新生成不得重复账期，取消生效区间外不再新建预测；已产生实际费用保留。时区与提前提醒规则以账期快照为准，不能服务重启后重新推迟扣款日。

## 4. 付款与更正

FIN-11：付款记录 `draft → recorded → reversed`，记录经办、付款人/收款方、方向 outgoing/incoming/refund、原币金额、业务日、外部参考、方式标识、凭证、分配。`recorded` 意味人工核实记录，不是系统向银行转账；批准申请也不能自动生成 recorded。

已确认费用纠错：新建反向冲销记录并关联原记录，必要时再建正确费用；退款不直接改原付款数。并发登记分配必须锁定有效余额，避免双设备各自看到可分配额度后超配。增量116开放人工明确核对本金、费用原币、实际汇率及凭证来源的受控跨币核销；手续费／汇差及异币实收退款不自动处理，Q-07公司财务制度仍待明确采纳。

冲销的统计约定必须统一：原记录改为 reversed 表示存在冲销，原事实仍按原发生日参与历史计算；新增 entry_kind=reversal 的正数字段按负号计入冲销生效日，不能一边排除原记录、一边再扣一次冲销。冲销继承原币、汇率和分摊，部分更正首发采用全额冲销+新正确记录。例如1月费用100、2月全额冲销后录正确120：1月发生100，2月净发生20，累计120。原记录与冲销行都不可重复冲销。

付款同样区分 record_kind=payment/reversal；普通退款是实际反向现金事实，冲销是纠错，不能同笔同时算退款和冲销。现金符号由 direction 与 record_kind 确定：支出为正、退款为负、冲销反转所引用记录的贡献；普通 incoming 不进入支出视图。冲销时同事务撤销/反向调整相关分配并保留历史，使有效余额与净付款一致。

## 5. 报表与预算

FIN-12：至少提供三个独立视图：预计开支（预测账期）、发生支出（已确认原费用与冲销的带符号净额）、现金支出（已登记现金事实与冲销的净额）。支持月份、项目/公司、类别、供应商、负责人、币种筛选；总额可钻取到规范费用/付款 ID；reversed 不意味着原记录从所有历史月份消失。

年费发生/支付全额与按月摊销不得相加为一个总计。摊销为独立可选视图，Q-07 确认后才启用；若启用，以起止期/分配规则生成版本化分摊表，不能修改付款事实。项目预算超限只形成控制/提醒，是否阻止采购提交由流程规则确定。

月报记录 as_of、业务时区、查询口径、基础币种、汇率覆盖率、未核实条数、源记录清单与导出权限。导出用异步 job，下载重新鉴权、限期保留；不把无权明细通过汇总金额泄露。

## 6. 验收数据集

至少包含：月付跨二月、1 月 31 日锚点、闰年年费、月中变价、取消待生效、暂停后仍扣款、缺汇率、多币种、采购/报销/订阅同费、部分付款/退款、并发分配、年费支付与摊销、项目两方分摊、冲销更正。每例固定预期的原币/折算/现金/发生额，人工算例与系统核对。

## 增量63财务秘书读取

现有报表口径已复用于秘书的月度只读汇总，明确公司／项目分摊及获授权记录覆盖，按原币种分别展示预测、发生支出和现金。固定来源不跟随新数据改写，读取时继续共同权限校验。逐笔异常核对、跨项目汇总、预算／汇率与真实模型评测继续开放；见[实现契约](../development/63-agent-finance-summary.md)。

## 增量71：秘书逐笔核对

在月度摘要和原人工财务流程上，增加会话范围内真实订阅分页、单订阅完整日期窗口及关联费用／资金原记录。预测、费用原额、项目份额、付款原额和实际分配保留各自口径；缺失账期不补零，未分配退款不猜测归属。生成不可变证据并逐成员核对当前权限，撤权后隐藏旧丰富快照。候选异常需人工判断，真实模型与财务写入不因此完成。见[实现与验收约束](../development/71-secretary-subscription-detail-review.md)。

## 增量89：移动财务操作约束

FIN-01—07／11—12的人工费用、付款、退款、员工结算与冲销接入共享Taro操作页。固定原币、范围、往来方／文件版本及香港时刻；费用来源不因回页改变，分摊精确核对，员工报销固定原申请员工／批准修订／准确垫付行／供应方。确认、资金登记、关联、分配、释放与全额冲销须实际人工核实及新鲜MFA；并发或未知结果阻止重复提交并保留文字。真实退款、费用冲销和资金冲销分别保留独立事实；原发生、现金、预测及授权覆盖不混算。

新实现不引入默认汇率、跨币结算或摊销制度。完整四端真实设备、跨模块业务和生产验收保持原标准；本地204项测试、9组实际UI与开发APK不代替正式验收。见[字段、流程、接口和回执](../development/89-mobile-financial-operations.md)及[准确证据](../quality/evidence/mobile-finance-operations/verification.md)。
