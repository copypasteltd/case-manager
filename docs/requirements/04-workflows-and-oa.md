# 审批引擎、合同、采购与报销需求

版本：v1.0-draft；日期：2026-10-23；关联 U-16、R-06。审批身份、阈值与本人审批制度见 Q-06；本设计不替公司默认批准。

## 1. 通用审批

OA-01：申请头保存类型、申请人、项目、标题、分类、当前修订、并发版本；修订包含完整业务内容、附件固定版本、原币总额、流程快照与内容摘要。模板发布后不可原位修改；新版本只影响之后提交。首发实现顺序审批、按金额/类别选用已发布模板；复杂会签、加签、转交、代理为后续范围。

申请状态统一：`draft → in_review → approved / returned / rejected`；`in_review → withdrawn` 按制度允许；`returned/withdrawn → draft → in_review` 重提必须新修订、新审批实例；rejected 终态需要新申请，不能编辑为 approved。提交动作内部原子创建实例，不对客户端暴露短暂 submitted 状态。

审批步骤状态 `pending/active/approved/returned/rejected/cancelled`。只当前 active 步骤可决策，同一步骤只可终结一次。返回会取消后续未执行步骤；批准最后一步才将申请 approved。已批准不支持简单撤回，需业务撤销/更正流程。流程缺失、审批人停用、无满足条件规则时拒绝提交或阻塞在明确异常队列，不自动跳步。

| ID | 动作 | 必须校验 |
| --- | --- | --- |
| OA-02 | 保存草稿 | 作者/编辑权限、字段类型、expected_version；缺少提交必填可暂存 |
| OA-03 | 提交 | 完整字段、金额、固定附件可用且范围匹配、已发布规则、有效审批人；同事务快照+步骤+审计+outbox |
| OA-04 | 同意/退回/拒绝 | 当前分配人身份、MFA/渠道策略、步骤/申请版本、本人审批策略；退回/拒绝必填理由 |
| OA-05 | 撤回/重提 | 当前状态与规则；重提不能复用旧批准；保留旧修订和决定 |
| OA-06 | 提醒与工作台 | 只提醒实际待办人；已完成不重复催办；推送不承担唯一事实来源 |

秘书可起草/补齐/提交获授权申请，但首发不代人审批。TG 群按钮首发只打开登录门户；正式审批由 Web/小程序/Android 的本人认证连接提交。

## 2. 合同管理

OA-07：合同字段包括 contract_no、方向 receivable/payable/none、类型、相对方、关联项目、owner、标题、原币总额、税额（如启用）、生效/到期日、续约/终止条件、付款/收款里程碑、备注、分类。相对方名称/联系人/证件资料仅保存必要字段，实际模板 Q-06/07 冻结。

合同正文工作版、审批版、签署件分别标识并绑定 file_version；合同业务修订与文件版本不能混为一张表。支持主合同/补充协议关系、关联采购与项目。相对方和金额变更不得覆盖已批准修订。

合同生命周期：`draft → pending_signature → effective → completed / terminated`。送审使用通用申请实例，审核中通过 approval_status 展示；只有最新所需修订 approved 才可 pending_signature；生效需登记签署日期与签署件（无签署件例外须专门制度）。合同尚未到生效日仍 pending_signature 或展示已签待生效信号，不能提前记 effective。

OA-08：签署后更改关键内容必须建立 amendment 修订/补充协议并重审；当前有效版本在新修订生效前继续有效。合同终止/完成需原因、权限与未结节点清单。删除草稿走软删除；已签署不得普通删除。

里程碑记录方向、应收/应付金额/币种、到期日、满足条件、已履行金额和凭证。实际收款和支出区分；只有支出进入费用/付款台账。提醒以明确日期触发，不以 AI 推断的法律解释自动生效。首发不电子签名、不自动银行扣款、不出法律结论。

## 3. 采购

OA-09：申请字段含用途/项目、物品或服务明细、数量/单位、单价、税/折扣、预计总额/币种、候选供应商、报价附件、预算引用、期望交付与经办人。是否强制多轮比价由模板决定；不得硬编码三家报价。

采购生命周期 `draft → requested → ordering → receiving → completed`，各未终态可按规则 cancelled。requested 表示送审，只有 approved 才能 ordering；rejected/returned 通过申请状态展示，需重提。采购与审批实例分别建模，不能把字符串一列同时表示两者。

OA-10：允许一申请多订单/分批收货；订单有供应商、外部单号、金额/币种、交付日。收货/验收按行记录数量、结果、经办与附件；累计合格数量不得超订购量（明确超收例外需制度）。退货是反向记录，不直接改历史收货数。付款单独记录，可分期；申请批准金额与订单差异超规则阈值重新审批。

完成需订单、收货/服务验收、差异处理和结算检查通过；已取消但实际已交付/付款的事项必须单列，不允许取消自动抹账。耐用资产编号/折旧管理不属于首发通用采购闭环。

## 4. 报销

OA-11：报销头含申请人、项目/公司费用、费用日期范围、说明、币种；明细含日期、供应方、类别、数量、单价/金额、税额（如启用）、receipt_ids、关联采购/订阅/已有费用。首发一张报销单一种币种；多币种分单，原始票据可注明原币供核验。

OCR 结果仅为候选字段，必须记录来源、置信/人工确认与修改，原始票据不可被 OCR 替代。按文件摘要、供应方/日期/金额组合发现重复候选；无票或重复必须理由和审批人可见，不把所有相同金额票据绝对判死。

OA-12：批准后进入 settlement_state `unsettled/partially_settled/settled`（由有效付款分配计算），人工经办登记支付日期、金额、方式标识、凭证与参考号；无实际支付不得 marked settled。多次支付/退款用独立记录；纠错采用冲销/反向引用，不能删除已核实付款历史。

报销涉及已存在的订阅或采购支出时关联同一实际费用，现金报销与公司先行支付区分；出现“公司已付 + 员工再报销”需异常校验，避免真实双付。具体处理规则 Q-07 冻结。

## 5. 通用异常与验收

提交期间修改正文：旧版本提交 409，保留草稿；审批人手机双击：同 Idempotency-Key 返回同结果，不产生第二决定；两个设备审批相同步骤：最多一个终态成功；审批人停用：步骤阻塞，管理员不能假冒通过；付款接口重试：永久业务去重键阻止重复。

验收须覆盖每种申请完整正常链、退回重提、拒绝、允许撤回与禁止撤回、附件失权、审批本人限制、金额规则边界、已批准内容试图覆盖，以及批准后仍未结算的准确展示。
