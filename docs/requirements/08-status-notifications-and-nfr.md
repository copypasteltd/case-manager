# 服务状态、通知与非功能需求

版本：v1.0-draft；日期：2026-10-23；关联 R-10/13、U-13/14。以下数值为候选验收目标，需 P0 实测和 Q 冻结，不是已交付性能。

## 1. 服务状态

OPS-01：维护 host、service、endpoint、owner、关联项目、探测方式、预期响应/时延阈值、维护窗口与告警接收范围。复用成熟指标/可用性工具，不从零重造采集平台；系统聚合、关联与管理事件。

服务状态 `operational/degraded/down/maintenance/unknown`。默认 60s 探测、连续 3 次失败确认 down、连续 2 次成功恢复；高时延/部分探测失败可 degraded。180s 无有效新数据必须 unknown。maintenance 为受控展示覆盖层，原始观测仍保留；不能维护结束后继续套用过期正常值。

OPS-02：状态计算保存 observation_at、received_at、source、sequence；迟到探测不覆盖新结果；单个外部可用性探测正常不证明整台机器资源健康。维护窗口、采集断流和真实故障要区分，unknown 也能告警。

OPS-03：事件 open/investigating/monitoring/resolved，含影响范围/等级、负责人、时间线、证据、恢复与复盘。恢复事件不删除失败记录；重复告警聚合同一事件。首发手工处置，秘书只读汇总与建立待办。

探测目标需专门权限和 allowlist，防止 SSRF（私网、云元数据、重定向、DNS 重绑定）；内部监控端点单独配置可信网络。外部探测与告警链路必须独立于主应用机，主机宕机仍能触达收件人。

## 2. 通知

OPS-04：站内通知为最低必需，TG 仅允许已配置渠道；邮件/平台订阅消息按实际接入决定，不默认具备平台推送资格。通知事件包括任务分配/提及、待审批/退回、合同/订阅到期、复制/备份失败、服务事件、秘书结果。

每条通知绑定 business_event_id、recipient、channel、template_version 和 dedup_key。创建 outbox 后异步投递，重试有上限/抖动/限速；用户已处理时允许合并/抑制陈旧催办。站外正文最小化，接收权限在发送时重新确认。敏感通知只给“有待办，请登录”，不通过标题泄露。

已读不等于业务已处理，已送达不等于人已阅读。投递失败不回滚已提交审批/文件操作，进入可见失败队列和告警。用户偏好不能关闭关键备份/安全告警的责任链，需另设必要收件人。

## 3. 非功能约束

| ID | 场景与候选目标 | 测量边界 |
| --- | --- | --- |
| NFR-01 | 普通 API p95 ≤500ms，错误率 <1% | 3 人基线+10 人余量；固定查询集/数据量，服务端计时；排除模型/文件传输；正确拒绝不记系统错误 |
| NFR-02 | 搜索 p95 ≤2s | 固定中文/英文/ACL 样本与规模；索引构建另计；结果正确性必须同时达标 |
| NFR-03 | 接收秘书请求 ≤2s 返回任务 ID；断线重播不重复提交 | 包含持久化受理，不包含最终推理时间；按 event sequence 校验 |
| NFR-04 | Web/Android 真实 120 GB 续传/摘要一致 | 断网、刷新/重启、凭据过期、弱网；实测 RSS/临时盘无随整文件大小线性增长 |
| NFR-05 | 普通小文件复制正常链路 p95 ≤15min | ≤100MB 候选车道；大文件按吞吐、队列、重试暴露实际风险窗口 |
| NFR-06 | 同云 PG 候选 RPO 5min/RTO 2h；跨云候选 RPO 8h/RTO 4–8h | 条件是实际产品配置和演练；6h 备份间隔还需计完成/复制耗时 |
| NFR-07 | 单节点生产候选 99.5% 月可用 | 以香港外部成功请求与明确维护规则统计；无 HA 不承诺高 SLA；30 天预算约 3.6h |
| NFR-08 | 所有未授权读取/写入阻断；无密钥入日志/模型 | 含聚合、引用、缓存、对象 URL、TG 与管理员无内容授权场景 |
| NFR-09 | 可重建应用节点，外部持久化；任务可恢复 | 重建候选 2h，不含全量对象复制；无本机唯一业务/认证恢复资料 |
| NFR-10 | UTC 时间、业务时区账期、定点金额、多币种 | 日期与时刻区分；API ISO8601 UTC；浏览器时区不更改账期 |
| NFR-11 | 长任务有进度、取消、错误恢复和可观测性 | logs/metrics/traces 的 request/run/job ID 连贯；不泄露敏感内容 |
| NFR-12 | 本地原生工具、真机；不调度虚拟化；浏览器不用标签页清理 | 开发/测试执行记录确认；不能为了测试方便启动 Docker/WSL/Android 模拟器 |

端到端香港体验单独报告 DNS/TLS、API、首屏、对象上传/下载和平台网络限制，不能用服务器 500ms 代表用户首屏速度。性能测试不能只用空库。

## 4. 可维护与可访问性

按钮可键盘操作，表单标签/错误关联明确，状态不只用颜色传达；移动端触控、返回栈、软键盘和弱网均验收。中文优先，英文文件名/正文/供应商名称兼容；首发不承诺完整双语翻译。

依据当前官网的详细视觉及无障碍约束见 [设计体系](../design/README.md)。双主题、正文/控件对比度、错误汇总、焦点、缩放、命中区与各业务状态展示按该基线实现，验收计划为VD-01—14；不改变已有TC的业务验收要求。

版本冻结 Go/Node/PG/Taro/React/RN/Codex/平台工具链并记录兼容矩阵，升级必须回归权限、上传、审批、费用与恢复。依赖与产物可追踪到源码提交和锁文件，不能在生产执行依赖 latest 的随机构建。
