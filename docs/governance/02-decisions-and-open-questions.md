## 2. 需要 P0 实测的架构假设

| 验证 | 成功证据 | 不通过时的处理 |
| --- | --- | --- |
| 香港用户到境内 API 与主存储 | 不同网络时段普通请求、下载、120 GB 上传吞吐/失败/账单样本 | 调整合法可用的网络或区域设计，记录 ADR，不先许诺 CDN 能解决全部路径 |
| Codex 服务端运行与权限隔离 | 锁定版本、正常工具调用、撤权、恶意资料、取消/重启、凭证隔离 | 停止该适配器生产放行；替代运行时需另行确认，不能冒称已实现 Codex |
| Android 大文件 | 真机可获取稳定文件句柄，不整文件入内存/复制，进程重启能补片 | 原生桥接方案调整；不把“只能前台小文件”算首发达标 |
| 双云流式复制 | 大文件中断恢复、固定源、目标摘要、出口和缓存高水位 | 调整 Worker 位置/分片/带宽；不能缩小到仅复制小附件 |
| 平台发布资格 | 两小程序真实主体/类目/审核材料与 Android 发布路径 | 提前处理外部依赖，全部平台首发要求不自动取消 |

## 3. 决策记录格式与关闭规则

每条 Q 更新：状态（open/proposed/confirmed/rejected）、确认内容、确认人、日期、证据、关联 ADR、受影响需求/配置和下一复核日。仅有开发实现不构成 Q 已确认。

重要决策记录背景、备选方案、最终选择、负面影响与回退触发。原 ADR 推荐在此细化，不重编号。尤其主云变更、PG 自建、跨云低 RPO、Runtime 更换、首发范围变更必须留下决策。

风险没有消失但采取措施时标记“已缓解”，不能标记“已解决”。放行条件用可观察证据关闭，不能用“应该没问题”。
