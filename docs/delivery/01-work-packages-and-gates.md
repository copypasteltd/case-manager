## 2. 阶段安排与估算口径

P0验证→P1底座→P2完整业务→P3大文件/AI→P4各端→P5联调首发；实际原生大文件和平台资格必须前置PoC，不等到最后才验证。移动端公共层与Web业务可并行。阶段成果允许内部试点，正式对外首发仍四端同时。

原估算155–230净工程人日，含20%风险为186–276人日；三名工程师+部分测试/产品投入约18–24周为规划区间，平台审核/资格与范围变化另计。必须在WP-01后按真实技术结论、任务分解、人力、Q确认与预算重新估算，不能把每个WP随意分摊后冒称准确报价。

## 3. Definition of Ready

一个工作项开工前：关联需求/页面、字段/状态/授权明确；Q是否影响已标识；精确请求/响应/错误与数据库不变量就绪；正常、异常、重复/冲突测试可描述；迁移/回退与外部依赖已识别。未明确费用/审批/权限的部分不能硬编码临时生产规则。

界面工作项同时遵守 [官网风格体系](../design/README.md)，准备双主题/主要尺寸/关键状态与可访问性说明。WP-02交付令牌/基础组件，领域WP交付业务组件和页面，WP-11/12落实原生/小程序适配，WP-14执行VD-01—14；风格样板不能代替产品页面完成。

## 4. Definition of Done

实现、评审、适当测试与证据、迁移/契约/文档同步、日志/指标、无秘密泄露、失败恢复、各端状态/错误处理均完成；相关TC通过且缺陷关闭。涉及云/平台/大文件/恢复的项必须有真实环境证据，mock通过不能单独算Done。

工作项状态 planned/ready/in_progress/review/testing/done/blocked；blocked写具体依赖与负责人，不笼统写“等待用户”；其余独立项继续。Done不代表全系统可发布，仍需G5。

## 5. 项目管理节奏

每周检查范围变更、Q关闭、已完成证据、下周依赖、费用/流量/AI预算、质量与风险。会议结论放docs，待办带编号/负责人/期限。出现Runtime不可控、Android大文件失败、平台资格不符等路线级问题时立即做ADR/排期调整，不积压至验收。
