# OSS/R2适配器与流式传输基础

日期：2026-10-23。关联[存储协议](03-storage-protocol.md)、[元数据规则](09-file-metadata-and-namespace.md)、[实施台账](../delivery/02-implementation-ledger.md)。源码在app/backend/internal/objectstore/。

## 1. 当前交付与明确边界

已实现原生Go适配器：初始化multipart、限定分片签名、分页ListParts、核对清单后合并、幂等终止、Head、固定来源范围读取、流式写入单片。同时提供分片布局、清单校对、固定源全内容SHA-256与单片跨端流式传输基础。

这些基础已接入[上传会话控制与封存handler](11-upload-control-and-freezing.md)及[原生执行器与用途配置](12-upload-worker-and-cloud-identities.md)，后续已有扫描/放行、正式提交、[双云执行器](16-cross-cloud-replication.md)及[下载签名/受控流](17-download-authorization-and-streaming.md)的隔离实现。默认应用仍未启用云存储；存在适配器代码不代表真实上传或双云服务已经通过验收。

## 2. 提供商及版本

固定依赖由go.mod/go.sum记录：OSS SDK V2 v1.6.1、AWS SDK S3 v1.114.5、AWS凭证模块v1.20.10；使用独立的OSS和R2实现。构造时提供明确的端点、区域、桶和凭证，不读取SDK的个人配置、共享凭证或隐式云环境身份。

阿里云采用其[官方Go V2分片接口](https://www.alibabacloud.com/help/en/oss/developer-reference/v2-multipart-upload)。R2按[官方Go示例](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-go/)使用S3客户端与auto区域；依据[兼容性表](https://developers.cloudflare.com/r2/api/s3/api/)，不依赖原生S3版本功能或UploadPartCopy中的源条件支持。

提供商文档于2026-10-23核对；固定版本从Go模块发布元数据读取并由校验和锁定。后续升级重新跑请求级检查及真实云验证，不直接跟随latest自动改变生产依赖。

## 3. Key与写入权限

真实Key由组织/会话/文件/版本/候选UUID生成。适配器拒绝文件名、相对路径、查询参数等作为Key；保留用户名称的职责属于数据库。

客户端签名只能针对draft路径下已知multipart和part number。签名默认由用例选定时长，适配器上限15分钟；不能签发候选或正式对象的客户端上传。浏览器不能手设的Host/Content-Length不作为客户端请求头返回；长度仍由签名输入和实际分片字节约束。

服务器写入能力与客户端签名能力区分。部署必须给上传、promotion、replica、cleanup配置各自最小权限身份；同一个Store接口不等于允许把一组广权限凭证分发给全部进程。当前已有上传签名/检查/生命周期、固定源校验、promotion、replica、下载签名与代理读取独立用途配置；cleanup仍待接入。不能据此认定RAM/R2策略已安装。

## 4. 分片与冻结来源

服务端候选范围为5—512MiB，默认32MiB，总大小上限120,000,000,000字节、最多10000片。120GB默认3577片。末片可小于最小片；清单必须连续、无重复、大小准确、非末片等长且有合法ETag。

ListParts每页最多1000项，返回续页标识；用例必须取完受限页数，再按会话中已固定的布局核对，不能根据客户端ack或适配器Complete的成功推断会话字节完整。Complete在提供商请求中按片号排序。

来源记录包含唯一Key、明确ETag条件、大小及可用的OSS原生版本号。ETag仅作为来源条件，不解释成SHA-256。读取带准确Range及If-Match，返回长度、Content-Range、ETag和原生版本必须相符；不符即拒绝并关闭响应体。

R2来源冻结依赖唯一Key、multipart完成后旧分片凭证失效以及服务器控制写入，不能虚构原生版本号。最终对象不可变性还依赖服务端角色、任务日志、每次候选独立ID及提交协议，适配器本身不提供跨PG/云的原子事务。

## 5. 内存与校验

HashExact使用一个256KiB显式缓冲区，读取量不超过声明大小加一，拒绝短流/长流。HashSource以32MiB范围逐段读取同一个固定源，复用256KiB缓冲区计算完整内容摘要并关闭每段响应体；不缓存整个范围或整文件。

TransferPart把准确来源范围直接交给目标单片写入，检查实际消费字节和目标回执；目标未消费完来源时不能保存“已复制”证据。它只返回单片结果，不完成multipart、不修改副本状态，也不自行标记已校验。Worker必须在有效租约和fencing token下保存回执，并在完成后独立核对目标完整SHA-256。

两端使用底层分片API，未调用可能整段缓存未知reader的高级自动上传器。SDK内部行为仍需真实120GB的RSS、临时盘和中断测试验证；256KiB是本模块的显式缓冲大小，不能写成整个进程的内存上限。

## 6. 网络与错误

构造器要求HTTPS及相应提供商域名；传输设置连接/握手/响应头超时、连接数上限，拒绝重定向。任务调用方仍须提供生命周期超时、心跳与取消，不能让后台读取无限等待。

自动SDK重试限制为一次尝试。初始化或完成请求遇到不确定网络结果时，错误标记uncertain；用例必须对账既有会话/对象，不能直接重建任务。仅根据提供商的NoSuchUpload，终止操作可视为已经完成。

公开错误仅包含受控代码、是否可重试和结果是否不确定，不保留原始请求、提供商正文或可展开异常链。设置的普通格式化和JSON序列化隐藏凭证。签名URL仍是短期敏感能力，不能进入普通日志或TG。
