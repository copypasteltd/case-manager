视觉实施必须遵守 [官网风格设计体系](../design/README.md)、[组件与交互](../design/03-components-and-patterns.md) 及 [19组页面设计配方](../design/04-page-and-cross-platform-design.md)。主题、字体、密度和可访问性来自统一令牌；不能以界面简化改变本文的能力/业务状态。样板是设计参考，不是业务完成证据。

## 2. 页面清单与状态

| PG-01 `/login` | 登录/MFA/激活/找回/平台绑定 | 限流、停用、绑定未完成；不枚举账号 |

## 3. React/Vite

使用 TypeScript strict；服务端状态用统一请求/缓存层，表单局部状态分离。菜单/按钮可按 capability 隐藏，但后端仍授权；不把全量受限数据下发后前端过滤。列表稳定分页，长列表虚拟化按实测需要引入。

统一处理 401 刷新单飞、409冲突保留草稿、422字段问题、429退避；不全局自动重试业务写请求。生成 Idempotency-Key 后保存在待提交操作中直到结果确定；用户真正新动作才换 key。

所有富文本/Markdown 输出消毒，禁任意 script/危险 URL；预览隔离 CSP/来源，不在主站执行上传 HTML。源映射/调试信息按环境控制。环境变量中能进静态包的内容一律视为公开，不能放云或模型密钥。

## 4. Taro 与原生边界

共享：DTO/金额日期格式、基础业务组件、状态码映射、查询逻辑；平台适配层：登录身份、网络/SSE替代、文件选择/预览、权限、分享/深链、上传后台、推送/订阅消息。React/Vite Web 与 Taro 不强行共用完整 UI 组件树。

微信/抖音若不支持稳定 SSE，使用 after_seq 增量轮询+退避/页面可见性暂停；仍消费同事件语义。前后台切换先同步 run 状态，不能重发 prompt 产生第二任务。

Android 大文件使用原生模块，不把 RN JS 内存作为120GB中转；上传前说明后台和系统限制，提供暂停/重试和权限修复。发布通过真机安装/升级验证与签名保管，包 ID、最低 OS、设备矩阵在 Q-05 冻结。

## 5. 兼容与前端完成标准

每个页面提供截图/录屏、接口mock（脱敏）、空/错/冲突/权限样例与真机验证记录。布局不硬编码仅一个员工名/一个币种。高风险动作二次确认必须展示具体对象/范围/金额，不用无信息的“确定吗”。

本地浏览器验证只保留正在使用的标签页，验证后关闭不用页面；不能关闭用户原有页面或为测试启动本地虚拟化环境。

Web项目详情已接入交付页签，固定版本提交、退回重提、修订历史、独立人工验收和冲突保留的实现／证据见[交付协议](42-project-deliverables-and-acceptance.md)及[页面设计](../design/15-project-deliverables-and-acceptance.md)。Taro公共页面的项目协作、固定交付与人工决定见[移动项目协议](45-mobile-project-collaboration.md)。有界实际内容读取及其设备边界见[固定内容协议](46-mobile-fixed-content-reading.md)；两小程序真机与Android完整验收仍须完成，不能用共享类型编译替代。

增量75在现有16个Taro注册页面中接入[项目立项、资料与成员管理](75-mobile-project-setup-and-members.md)：项目列表进入立项，详情进入编辑，成员页配置角色／移除与独立负责人移交。继续复用原命令、版本和授权；活动项目范围／日期只读，viewer与只读阶段关闭写入口，深链接重新鉴权。最终两小程序编译及新Android开发包已单独验证，真实平台和设备放行点保持原标准。

增量76继续在既有页面中加入[里程碑、风险与问题操作](76-mobile-project-milestones-risks-and-issues.md)：列表新建、详情编辑及独立状态确认。香港时间及微秒、实际成员、里程碑完成证据、风险转实际问题和解决说明沿用原接口约束；输入／状态草稿与真实回执分别核对，冲突和未知结果须重新读取。各端编译、H5流程和Android开发包的证据单独保存，不能替代小程序或实体设备验收。
