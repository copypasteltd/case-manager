# 上传队列、扫描审核与会话再验证

日期：2026-10-23。实现入口在 app/web、app/backend；当前覆盖 Web，不代表微信、抖音或 Android 已交付。本文补充[上传控制](11-upload-control-and-freezing.md)、[正式提交](14-file-promotion-and-commit.md)及[例外制度](15-scan-waivers-and-review.md)，沿用[官网设计体系](../design/README.md)的双主题语义令牌。

## 1. 页面与职责

| 入口 | 职责 | 不可混淆的事实 |
| --- | --- | --- |
| 资料目录的“上传文件” | 选择原文件，建立固定目标的会话 | 对象权限允许上传，不等于存储服务已配置 |
| 文件详情的“上传新内容版本” | 固定打开窗口时的基础版本 | 新原文件名保存在版本记录；业务文件名称由独立改名流程管理 |
| 全局上传入口 /uploads | 本人会话、分片传输、校验、提交、报告与终止 | 本机收到分片回执，不等于云端已对账或文件可用 |
| /scan-waivers | 本人申请与制度指定的审核任务 | 系统管理员没有自动取得内容读取或放行权限 |
| /scan-waivers/:id | 核对固定源、固定报告和制度修订，决定或取消 | 批准后继续服务端整理，不立即承诺正式文件或双云可用 |
| /storage/scan-policies | 按分类发布启用或停用的新修订 | 选定审核人不会自动给他授予对应资料范围 |

上传状态、扫描状态、正式内容和备份状态分开呈现。正式提交成功后，链接到正式文件的版本/副本记录。迁移没有新增，仍使用至 0022 的既有表。

## 2. 对象权限与列表

Folder.can_upload 由服务端依据文件上传动作、真实目录范围、项目可写状态和 Web/Android 渠道计算。File.can_update 用于新版本入口；服务端仍核对文件、目录与固定基础版。

新增 GET /uploads，state=active 或 all，默认 active；Web 使用 all 查看历史。仅返回当前组织、本人的记录。目录读取、上传或更新动作、祖先状态、固定分类与目标位置在数据库分页前过滤。已提交的记录还检查关联正式文件当前的读取权限及其当前目录祖先，不能绕过正式文件的后续分类或授权变更。游标绑定身份、授权版本、渠道和筛选范围。

取详情及写操作会重新检查当前会话、用户/组织授权版本和范围。签名返回前再次检查，退出、到期或正常旋转造成原请求会话失效时，不返回新的许可；后续请求使用正常续期后的当前会话。云端已经签发的短期许可仍有最长五分钟的撤权延迟，暂停本机传输不能收回已发出的许可。

GET /storage/upload-capabilities 返回 control_ready、reason_code、120000000000 字节上限和 48 小时会话期限。它只检查签名/对账身份、主端纪元匹配与显式容量配置，不能充当 Worker 存活、扫描引擎、云权限、目标连通性或完整链路就绪证明。缺失配置时禁用新上传并说明原因，不生成成功占位记录。

## 3. 全局队列与本机生命周期

UploadProvider 在登录后的应用层持有 File、控制器与操作状态，页面路由变化不卸载队列。退出、会话失效或应用卸载时中止本机请求并释放 File；关闭/刷新浏览器后从服务端列表找回会话，重新选择原文件。

File、文件字节、签名 URL、云回执请求头及会话凭证不写入 localStorage、IndexedDB 或持久化查询缓存。React Query 只缓存不含签名的会话/报告 DTO；注销清空应用缓存。当前未提供 Service Worker 或系统后台上传。离开页面提示仅提示本机仍有等待/传输源，不能保证设备休眠期间继续执行。

“暂停本机传输”取消当前 fetch，并保留当前浏览器内的 File 和会话；不伪造后端 paused 状态，也不停止服务端封存、摘要、扫描或复制。继续操作先云端对账。浏览器刷新后，本机暂停意图与文件引用清除；服务端会话仍按真实状态显示。

浏览器一次运行一个文件的分片传输，最多两个分片请求同时进行。其他已选择文件等待本机名额。队列服务端任务在浏览器之外执行，文件传输结束后可继续跟踪校验，必须明确确认才调用正式提交。

## 4. 原文件识别与分片传输

选择文件时拒绝零字节、非安全整数大小和超过 120,000,000,000 字节的文件。字节数使用十进制字符串传给 API；界面 GB 为十进制单位，分片 MiB 为二进制单位。

Web 源指纹格式为 web-sample-v1 加 SHA-256。输入包含 UTF-8 JSON 数组 [原文件名、字节数、lastModified]，再连接最多前 64 KiB 与不重叠的末 64 KiB；除这两个样本外不读取完整 File。它只是重新选择的辅助识别，不能证明文件中段未变，不能当作原文件完整摘要或真实性证据。用户更换名字、修改时间或样本会被拒绝；具有相同元数据和样本的不同中段仍可能通过此检查。权威 SHA-256 来自服务端固定源完整回读，正式提交窗口展示该值供核对。

流程为：检查源 → 续期会话 → ListParts 对账 → 仅签发缺失分片 → 两个有界 Blob.slice 直传 → 回报 ETag → 完整 ListParts 再对账 → 请求封存。每批签名前重新确认当前应用会话；不一次预签全文件。当前布局默认 32 MiB，120 GB 为 3577 片，末片按精确长度处理。

云端 PUT 只接受官方 OSS/R2 HTTPS 地址、正确分片号及有效短期许可；不携带应用 Cookie，不跟随重定向，不发送 Referrer。只转发允许的媒体/摘要及 OSS/R2 签名头。浏览器自动提供 Blob 长度，不尝试设置受浏览器限制的 Content-Length 或 Host。

云端响应必须为 200 且可读到 ETag。CORS 必须允许实际 Web Origin、PUT 及所需签名头，并暴露 ETag；失败时提示检查配置。错误正文不解析、不显示，签名 URL 不进入日志/错误文案。每个分片请求最长十分钟，不整文件转成 ArrayBuffer、Base64 或 Blob。

客户端只按已返回分片的精确长度更新“本次分片回执”字节，不伪装连续网络吞吐或云端确认。服务端 confirmed_parts 只取云端对账结果。最终云端缺片时停止，不能因本机进度 100% 而封存。

## 5. 结果未知、冲突与正式提交

每个上传的写请求根据动作及固定正文持有幂等键。成功确认后释放该次键，下一次同正文对账需要读取新的云状态；结果未知时保留键供同一浏览器核对，禁止自动重发业务写操作。

网络断开、超时、签名或回报失败会停止传输，保留当前会话和原文件供手动继续。继续时先对账云端；不会自动创建新会话、变更目标或改用新基础版本。刷新后服务端记录仍可发现，但本机未确认操作键不持久化，须先核对会话真实状态，不能把重新建立上传当作自动恢复。

ready 只表示候选已准备。确认提交必须发送当前会话版本、固定 SHA-256 和原基础版。基础版、名称、状态或版本冲突时保留窗口及填写内容，关闭窗口读取最新记录后重新判断。提交成功使用独立 result_file_id 关联正式文件，保留不可变上传输入的 file_id/base_version_id 语义。

正式版本与备份分开：主端验证通过和正式版本提交后，次端复制仍可能排队或失败。上传页不能显示“上传完成且两地安全”之类合并结论。

## 6. 扫描例外页面

上传队列显示原始扫描报告：结论、原因码、实际送检字节、引擎/签名库与固定源 SHA-256。unscannable 且 blocked 的上传可以发起明确例外申请，需原因及风险确认；当前制度缺失/不匹配时保留内容并显示服务端拒绝。

审核人通过 GET /scan-waivers/:id/scan-report 读取申请指向的不可变报告。该接口检查申请当前范围，按申请的 report_id 读取，重扫后也不能改成“最新报告”。普通上传详情仍限上传人，不能为了审核而给审核人开放他人的上传操作。

批准窗口固定申请版本、上传版本、报告与摘要，要求原因、风险确认和最近 MFA。拒绝也需要最近 MFA；本人只能取消申请。审批操作不能改变源、类型、制度或目标。最新报告、状态、制度修订或范围变化由后端再次核对。

政策页面仅允许 internal/project_restricted；严格受限与恶意内容不能选择放行。格式为精确 MIME、原因是受控枚举、大小明确填写、审核人从获授权的人员目录选择。没有臆造格式、阈值、默认审核人或自动启用制度。

## 7. 会话内两步再验证

新增 POST /auth/mfa/step-up，只接收六位 code，要求有效人工渠道当前会话及 Web CSRF；不适用于 Agent/TG。它只更新当前 session 的 mfa_verified_at，不轮换凭证、不产生新的登录家族、不自动提交业务表单。Me 返回可空的 mfa_verified_at，页面在九分钟时提前要求重新验证，后端仍以十分钟为最终边界。

组织锁在用户/会话锁之前，与刷新、停用和授权变更保持顺序。验证器步数仅可消费一次；账号级每十五分钟最多八次再验证尝试。错误码使用 422，不把错误动态码解释成原登录失效。没有验证器时拒绝，不能现场绕过角色和原有注册流程。

动态码消费、当前会话证明和成功审计同事务保存，审计失败全部回滚；失败动态码保存拒绝审计。动态码、验证器密钥与恢复码不进入业务事件、幂等结果或页面日志。该认证路由不使用业务幂等缓存，结果未知时先读取当前身份状态，不能自动重用动态码。

## 8. 验证与放行边界

上传客户端 8 项单元场景覆盖 120 GB 有界采样/末片计算、仅缺失片直传、最终对账、原文件不匹配、过期/跨源/危险头许可、未知回报停止、暂停与云错误脱敏。它们使用受控小内容和请求替身，不是云传输证据。

新增原生 PG 场景覆盖本人队列及游标/ACL、到期/渠道、接入配置、MFA 原会话/重放/限速/审计回滚、申请固定报告及重扫/撤权、签名/对账期间退出、分类与正式文件权限。完整结果以[后端验证快照](../quality/evidence/backend/result.json)的时间和源码摘要为准。

[上传浏览器记录](../quality/evidence/uploads/result.json)使用真实 API、当前开发账号和原生 Edge，测试队列导航/刷新、缺省接入拒绝、错误原文件、本机暂停意图、明确终止、隔离账号、制度表单中的 MFA 及错误保留，覆盖双主题五种宽度。夹具是明确命名的本地上传元数据，不创建云对象、扫描报告或成功扫描，不把显示 120 GB 记为上传通过。脚本在 finally 中关闭全部自建上下文和浏览器。

真实 OSS/R2 CORS、120 GB 弱网/长时直传、真实引擎及大二进制例外决策、正式提交/备份完整 UI 正向链、断电/恢复、平台真机仍待独立验收。Android 原生上传与两个小程序页面尚未实现，四端首发目标保持不变。
