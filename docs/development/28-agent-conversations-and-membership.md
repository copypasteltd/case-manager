# 秘书会话、成员与上下文安全版本

日期：2026-10-23；2026-10-24补充消息与任务账本。本文记录 AI-01、AI-05 和 AI-20 的会话底座，关联[秘书需求](../requirements/07-secretary-and-channels.md)、[身份权限](../requirements/02-identity-and-permissions.md)及[技能与运行时适配](27-agent-skill-packages-and-runtime-adapter.md)。会话元数据、成员管理、消息受理、任务事件及取消已有代码；运行时执行器和真实模型尚待接入，不能把会话创建或排队成功当作秘书已经执行完成。

## 1. 会话范围

| 类型 | 创建与阅读边界 | 成员管理 |
| --- | --- | --- |
| private | 仅创建人；可不关联项目，也可固定在本人参与的指定项目 | 永远只有创建人，不能增加其他人 |
| project | 必须指定项目；创建人必须是当前有权项目成员 | 独立会话成员名单，项目成员不会自动加入 |

关联项目会话继承该项目分类，不能由客户端降低。没有独立严格受限范围与授权流程时，拒绝创建 confidential 会话。项目、创建人、类型、分类与创建时间均不可变；需要改变范围时，应建立新会话并重新选择可披露资料，不能原地改标签扩大原有上下文访问。

阅读同时要求：有效用户、当前组织/用户授权版本、当前会话成员、conversation.read、分类/渠道规则，以及关联项目的当前成员与 project.read。系统管理员不能凭配置权限读取会话标题、成员或后续内容。仅知道会话 ID 也不构成访问凭证。尚未加入共享会话的人收到 404，列表和搜索不暴露其标题或存在性。

独立未绑定角色 agent_user 提供 conversation.read/create/update/manage_members 与 agent.run 动作。迁移和组织初始化只创建角色，不为现有员工自动绑定，也不启用 AI 数据处理策略。加入会话不会生成项目成员、角色绑定或其他资源授权。

## 2. 数据结构与不可变约束

| 表 | 保存内容 | 约束 |
| --- | --- | --- |
| conversations | 固定身份/范围、当前修订、乐观版本、创建与更新时间 | 当前指针须对应最新完整修订；禁止应用删除 |
| conversation_revisions | 标题、active/archived、完整声明成员数组、上下文安全版本、前序修订、作者与原因 | 仅追加；序号连续；同一基础修订只有一个后继 |
| conversation_members | 每个修订的规范化成员快照 | 仅追加；必须与该修订声明数组完全一致 |

成员名单包含创建人，总数 1—100。创建输入可包含最多 99 位其他成员，拒绝重复、无效或重复填写创建人。个人会话仅一位成员。历史成员快照不随停用、退出项目、撤销角色或会话移除而改写；可用性按当前身份和权限计算。

声明数组与规范化行由延迟约束触发器在提交时比较，防止绕过新修订向旧快照追加成员。更新/删除旧修订与成员行由权限和不可变触发器双重阻断。身份字段也由独立触发器保护，不依赖前端禁用输入框。

标题与归档变更生成新修订，context_security_version 保持。成员集合真正变化时，该值必须准确增加 1；没有变化的增加/移除返回冲突，不生成假修订。数据库同时验证前序连续、成员集合差异、安全版本和当前指针，不能任意跳版本或保存半份名单。

## 3. 事务、并发与重放

写入使用统一命令事务，顺序为组织授权锁、发起人状态/授权版本、当前业务授权、幂等记录、会话行锁与基础版本、业务修订、审计/outbox、结果。expected_version 不匹配返回 409，保留客户端未保存输入。

编辑先单独锁定会话头，再用新语句读取它指向的不可变修订。不能把这两步合成会在锁等待后重新检查头指针的 join 查询：READ COMMITTED 下，头可能已切换，而同一语句的修订快照仍旧，导致把有效会话误判为 404。独立确定性场景让编辑请求真正阻塞于头锁，再发布完整后继，验证等待者收到 409 版本冲突且不覆盖获胜修订。

成员变更取得组织独占授权锁，同时写入新成员修订、上下文安全版本和组织 authorization_version。角色/项目撤权与会话变更使用相同的组织锁顺序；其他授权读取与写入按对应共享锁排序。审计或 outbox 失败必须回滚全部成员和版本变化，不允许存在“名单已改变但旧授权仍有效”的部分提交。

详情、列表与成员候选使用同一 Repeatable Read 事务，并检查组织/用户当前授权版本；一次响应不能混用旧标题/安全版本与新成员名单。读取在准入期间遇到授权或并发变化可返回 412/409，客户端应重新查询，不能继续显示过期结果。

幂等重放前重新鉴权。创建和编辑的重放结果重新读取当前可见会话，不向已被移除成员返回旧响应中的标题或名单。成员变更回执只含会话 ID、版本、安全版本与本人是否失去访问；不能用它承载额外业务正文。非创建人可在有管理权限时移出本人，成功后清除会话详情缓存并返回列表。

分页游标绑定组织、本人、授权版本、渠道、run、类型/状态/搜索/项目筛选。成员变更提升组织授权版本，旧游标失效。搜索使用字面量匹配；% 等字符不是跨权限通配符。ACL 先过滤，再分页，不暴露隐藏条目数量或多余下一页。

## 4. API 与 Web

| 方法与路径 | 行为 |
| --- | --- |
| GET /v1/conversations | 仅当前可见列表，支持 q/type/state/project_id/cursor/limit |
| POST /v1/conversations | 创建个人或指定项目共享会话 |
| GET /v1/conversations/{id} | 当前完整元数据与成员可用性 |
| PATCH /v1/conversations/{id} | 固定基础版本下编辑标题、归档或恢复 |
| POST /v1/conversations/{id}/members | 固定基础版本下加入或移出单个成员 |
| GET /v1/conversations/{id}/member-candidates | 当前有权项目成员，排除已加入者；最多 100 项 |
| GET /v1/conversations/{id}/context-sources/{resourceType}/{resourceID} | 核对全部成员的 AI 阅读范围并返回固定来源片段，见[资料读取协议](29-agent-context-and-source-projection.md) |

写操作使用现有 CSRF、严格 Schema、Idempotency-Key、真实发起人和审计协议。Agent 身份不能反过来创建会话、改名单或修改会话范围。返回的 can_edit/can_manage_members 也不向 Agent 宣称这些能力。实际候选目录不以全公司身份列表代替；候选人在保存前再次核查。

Web 在“公司秘书”下提供列表/搜索、个人和项目会话创建、标题编辑、归档恢复、成员加入和退出。共享会话最初可仅创建人，后续通过真实候选接口选人。表单版本冲突保留输入，不自动覆盖或自动重新提交。归档会话停止成员调整；恢复不改写历史。后续已加入资料选择与共同阅读核验预览，具体实现及证据独立记录于[资料读取协议](29-agent-context-and-source-projection.md)。

界面沿用[品牌应用规范](../design/09-brand-application-and-content-style.md)的既有色彩、字体和组件，不额外引入 AI 专用渐变或装饰色。尚未接通任务时明确显示“秘书暂未启用”，不提供假消息流、假进度或预设成功回答。

## 8. 消息受理与任务账本实现

迁移 `0047_agent_runs_and_messages.sql` 增加运行配置、任务、追加消息和追加事件。应用身份不能安装运行配置；没有部署配置时 `runtime-options` 返回明确不可用，提交不生成消息或假回复。隔离测试由数据库所有者安装受控配置，仅验证受理与取消，不调用模型。

| 接口 | 已实现行为 |
| --- | --- |
| `GET /conversations/{id}/runtime-options` | 核对当前成员、AI分类许可、会话阶段及固定配置，供页面选择 |
| `POST /conversations/{id}/runs` | 固定会话修订/安全版本、调用者、配置、客户端消息UUID与最多20份资料；202只表示受理 |
| `GET /conversations/{id}/messages` | 按准确权限绑定游标读取；后来加入的成员不可读加入前的消息 |
| `GET /runs/{id}` | 原始读者与当前权限核验后的任务状态，不披露执行器私有信息 |
| `GET /runs/{id}/event-log` | 按 `after_seq` 重放有序JSON事件，含当前任务及下一位置 |
| `GET /runs/{id}/events` | 有界SSE批次，支持 `Last-Event-ID`；连接结束后可重新读取，不重启执行 |
| `POST /runs/{id}/cancel` | 当前请求者提供准确版本与原因；排队/待批准可确认取消，执行中仅记录取消请求，正式提交阶段拒绝撤销声明 |

受理将任务、原始用户消息、首条事件、审计及outbox放在同一事务中。幂等键与客户端消息UUID共同防止断线重发重复创建；相同UUID更改正文或资料返回冲突。同一会话最多一个活跃任务，组织20个、个人3个；这是当前准入上限，后续预算与执行器仍须独立限制资源。

每份资料固定业务版本、知识版本和完整来源摘要。阅读消息时重新检查依赖；变化或失权后返回隐藏占位，不能继续显示旧正文。成员变更不会扩大旧消息的声明读者。事件序号连续并与任务版本一致，数据库拒绝终态改写、缺失事件、错配范围及回退状态。

Web和第11个Taro页面均已接实际会话/成员/资料选择、消息、事件及取消接口。Web待核对请求仅在有界会话内存保留，导航后明确使用原请求核对；退出清除会话缓存。移动文字沿用15分钟有界内存草稿，恢复时不自动恢复资料选择或核实声明；请求键另行保存准确意图，禁止自动改写为另一次创建。两端遇到读取失败隐藏旧内容；任务读取失败会同时触发Web会话与消息的当前权限核验。

原生验证入口：`python app/scripts/verify_backend_batches.py --batch-size 8`、`python app/scripts/verify_web.py secretary-runs`、`python app/scripts/verify_mobile.py`、`python app/scripts/run_agent_browser.py --runs`、`python app/scripts/run_mobile_browser.py --secretary`。浏览器脚本独占5189并关闭所属上下文、服务器与隔离测试库；不能同时运行两种浏览器夹具。Taro检查为H5与编译验证，不替代小程序/Android实机。证据见[实施台账](../delivery/02-implementation-ledger.md)。
