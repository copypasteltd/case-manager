# 秘书指定文件版本正文读取

日期：2026-10-25。承接[共用执行边界](../skills/execution-boundaries.md)、[项目计划](48-secretary-project-plans.md)及[常规更新](50-secretary-routine-updates.md)，推进 GAP-04／11／12。此增量接通真实文件字节的有界读取，为后续文件修改提供来源基础；完整平台 Goal 继续执行。

## 1. 实现范围

| 编号 | 已实现能力 | 当前约束 |
| --- | --- | --- |
| FT-01 | Web／Taro 会话选择文件及准确版本，预览、继续阅读、添加引用 | 必须明确选择版本；不会默认采用最新版本或自动发送 |
| FT-02 | 从正式对象的已校验副本读取正文 | 指定文件 ID 和版本 ID；副本、存储目标、来源证据与共同授权均须成立 |
| FT-03 | UTF-8 文本、Markdown、CSV、JSON | MIME 为 `text/plain`、`text/markdown`、`text/csv`、`application/json`；1 字节至 1 MiB；拒绝非法 UTF-8 和 NUL |
| FT-04 | 完整字节验证后按字符分段 | 每次先核对完整长度与 SHA-256，再截取 Unicode 码点；默认 4000、最多 10000 字符 |
| FT-05 | 同一文件的多个正式版本共同引用 | 引用键包含版本 ID；旧版本不会被当前文件头替换，也不会被另一个版本覆盖 |
| FT-06 | `read_resource` 及可追溯工具回执 | 复用准确版本来源和真实正文；重放相同调用返回原回执，不再次下载 |
| FT-07 | 网络读取期间撤权／取消和旧元数据处理 | 读取前后分别核对；不持授权事务等待网络；缺历史文件名时明确阻断 |

暂不解析 PDF、Office、压缩包、图片或音视频，不对 120 GB 文件进行整体模型读取。空文件、超过上限的文件及人工扫描放行版本也不进入本通道。人工下载、大文件上传及正式版本管理继续使用原业务入口。文本草稿、真实 diff、新版本写入、批量整理和全文索引仍待后续实现，不能从读取回执推定已完成写入。

## 2. 员工使用流程

进入公司私密或项目会话，打开资料选择，选择文件后再选择准确正式版本。项目会话使用原项目文件范围，公司会话使用公司资料范围；最终服务器仍对每位会话参与者检查文件、会话、项目及 AI 处理许可。

预览显示版本正文、来源摘要及原始文件证据；“继续阅读”固定原版本与来源，不随当前文件头更新。员工可把同一文件的两个版本分别加入待发送资料。选择与预览仅建立待引用内容，明确发送时才创建用户消息和执行请求。

Taro 历史消息按引用的版本 ID 打开对应文件版本。页面隐藏或切换资料时中止预览请求，迟到结果不能覆盖新选择。微信／抖音的实际平台表现仍需真机验证。

## 3. HTTP 与来源语义

沿用接口，不新增平行的下载入口：

```text
GET /v1/conversations/{conversation_id}/context-sources/file/{file_id}
    ?context_security_version=1
    &version_id={exact_version_id}
    &offset=0
    &max_chars=4000
```

标识和安全版本必须来自当前可见会话、文件及正式版本。`offset` 为 Unicode 码点偏移，范围 0—1048576；越过正文长度返回参数错误。正文可能包含中文及 emoji，不能用 UTF-8 字节偏移续读。`next_offset` 为空表示到达文末。

返回沿用 `ContextView`：`type=file`、准确 `version_id`、正式版本序号 `resource_version`、原版本文件名、正文 `text`、字符范围、观察时间及 `evidence`。文件证据中的 SHA-256 绑定完整原件；`source_sha256` 则绑定受控来源投影，包含正式版本元数据及文件证据。两者含义不同，不能把投影摘要当作原件字节摘要。`context_sha256` 进一步绑定会话修订、安全版本、受众及此次字符范围。

`context_refs` 使用 `type=file`、文件 ID、准确版本 ID。服务器在受理时固化版本元数据及原件证据，不把正文复制进来源快照。重复同一版本会去重，不同版本保留；项目等可变业务对象继续遵循既有单版本约束。

## 4. 两阶段读取与事务

1. 在短授权事务内核对当前组织、发起人、会话、全体成员、分类、项目范围和准确版本。要求版本可引用、扫描结果为 `clean`，并且存在已验证副本：预期与实际 SHA-256 一致、具有验证时刻及完整来源证据、存储目标启用、专用读取身份匹配。
2. 固定来源投影摘要与内部副本指纹，然后释放事务。指纹还绑定副本记录版本、提供商、桶及准确对象来源；云定位信息不进入模型结果。
3. 使用专用 Go 读取身份执行最长 10 秒的有界对象读取。核对返回长度、ETag、适用时的对象版本 ID，再读取最多“声明长度 +1”字节。只有完整长度和 SHA-256 均一致且编码可用时才得到正文。请求取消会关闭流；所有成功／失败路径均关闭对象流。
4. 重新打开授权事务，重新检查当前会话与共同许可、运行租约及取消状态、准确版本、来源摘要和副本指纹。中途撤权、会话改变或来源改变时拒绝输出正文。最终才截取字符范围并保存预览审计或工具回执。

预览总请求预算为 15 秒；对象读取过程不占用授权事务锁。集成验证在读取钩子中以 1 秒数据库超时完成真实授权变更，再确认最终正文被拒绝，覆盖“网络读取挡住撤权”的问题。

本通道不在服务器文件系统保留正式原件或正文缓存。限定大小的字节与字符串只在受控进程内存中处理。预览审计仅记录受控摘要；正式执行工具回执可保存其有界正文及证据，继续遵循消息、回执及历史受众的访问规则。

## 5. MCP 与执行回执

现有 `read_resource` 扩展 `type=file`，条件 Schema 要求 `version_id`。`project-briefing`、`project-create`、`project-update` 三种已有受控配置可使用本读取类型，不增加原生进程可调用的工具名称。

文件读取结果包含真实片段、准确文件证据、完整 `content_sha256`、`content_size_bytes`、`verified_content=true`、来源摘要及 `untrusted_data=true`。正文是待处理资料，不能改变技能、权限、工具范围或执行身份。文件读取没有业务操作号，不能伪装为 `committed` 写入。

执行控制器在下载前后均执行运行及来源校验。最终回执与来源观察在同一短事务保存；同一工具调用键和相同参数重放返回原 JSON 结果，不重复读取，换参数则冲突。取消和租约规则沿用既有控制器，已提交业务事实也不因取消被抹去。

## 6. 专用读取身份

显式配置：

```dotenv
CP_AGENT_FILE_PROVIDERS=disabled
CP_OSS_AGENT_FILE_READER_ACCESS_KEY_ID=
CP_OSS_AGENT_FILE_READER_ACCESS_KEY_SECRET=
CP_OSS_AGENT_FILE_READER_SESSION_TOKEN=
CP_R2_AGENT_FILE_READER_ACCESS_KEY_ID=
CP_R2_AGENT_FILE_READER_ACCESS_KEY_SECRET=
CP_R2_AGENT_FILE_READER_SESSION_TOKEN=
```

启用时提供商列表为 `oss`、`r2` 或不重复的 `oss,r2`，并使用原提供商 endpoint／region／bucket 配置。每个身份只负责其正式对象读取；具体云策略及实际可达性仍需真实账户验收。

默认关闭。普通下载签名、上传、扫描或其他身份不会自动开启 AI 读取，也没有环境 SDK 身份兜底。API 与秘书 worker 分别加载显式配置；模型子进程剥离继承的 `CP_` 配置，只注入当前任务的受限凭证，不接收云密钥、数据库口令或内部对象定位。代码当前选择首个合格且已配置的副本，读取失败会明确返回失败，不宣称已经完成跨云自动切换。

## 7. 失败与旧数据

| 情况 | 返回语义 | 后续处理 |
| --- | --- | --- |
| 未选择版本、范围非法、文件／版本不匹配 | 参数错误或不可见 | 由员工重新选择准确资料 |
| `AGENT_TEXT_FORMAT_UNSUPPORTED`／`AGENT_TEXT_SIZE_UNSUPPORTED` | 当前适配范围外 | 保留原件，另提供有界文本版本或人工阅读 |
| `AGENT_TEXT_SCAN_REQUIRED` | 准确版本不是扫描通过 | 走既有扫描流程，人工放行不代替检查 |
| `AGENT_TEXT_METADATA_UNAVAILABLE` | 历史版本原文件名未知 | 核实导入元信息；不使用当前文件名冒充历史记录 |
| `AGENT_TEXT_READER_UNAVAILABLE`／`AGENT_TEXT_SOURCE_UNAVAILABLE` | 专用身份或来源证据不足 | 由运维核对配置和正式副本 |
| `AGENT_TEXT_READ_FAILED`／`AGENT_TEXT_CONTENT_INVALID` | 网络读取或原件完整性失败 | 不返回半段正文，不静默接受损坏内容 |
| `AGENT_TEXT_ENCODING_UNSUPPORTED` | 字节不是可接受的 UTF-8 文本 | 明确转换后作为新的正式版本管理 |
| 权限／会话／运行／来源在读取中变化 | 沿用既有撤权、冲突及取消错误 | 停止本次输出，重新核对当前状态 |

历史文件的创建人允许为 NULL，授权检查按未知所有者处理，不虚构当前发起人为创建人。历史原文件名 NULL 与创建人 NULL 是两种独立情况；后一项不会自动阻断所有项目授权，前一项必须明确阻断此正文读取。

## 8. 验证和剩余工作

原生集成测试 `TestAgentFileText` 使用真实上传、完整摘要、扫描、正式版本和数据库流程，云读取端为受控字节实现。覆盖两个正式版本、中文／emoji、1 MiB 边界、非法编码、NUL、不支持格式、截短／多字节／尾部损坏／ETag 不符、缺版本、错文件、旧元数据、工具重放、撤权及取消后零新增回执、共享预览及流关闭。独立配置测试确认专用身份必需、无权限兜底和重复提供商拒绝。

Web 与 Taro H5 场景验证明确选择、历史正文、固定续读、双版本引用、真实消息受理及取消。完整结果见本轮[验证说明](../quality/evidence/secretary-files/verification.md)，编译与受控字节验证不代表真实 OSS／R2、真实模型、Android 原生执行或小程序真机验收。

下一项文件功能应消费此准确版本与完整字节证据，实现受控文本草稿、真实差异、固定新内容摘要、原版本冲突检查及正式版本写入／复制流程。真实模型与原生隔离器、技能发布、TG、其他 OA 工具、真实双云容量和生产恢复继续保留在原 Goal 差异清单，不以此增量作为已完成证明。
