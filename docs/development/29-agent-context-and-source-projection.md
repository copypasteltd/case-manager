# 秘书资料读取、共同阅读范围与来源固定

日期：2026-10-23。本文记录[会话底座](28-agent-conversations-and-membership.md)之后的资料准备实现，关联[秘书需求](../requirements/07-secretary-and-channels.md)、[身份权限](../requirements/02-identity-and-permissions.md)、[知识需求](../requirements/03-projects-and-knowledge.md)及[技能适配](27-agent-skill-packages-and-runtime-adapter.md)。当前提供受控文本投影与 Web 预览，尚未提交给真实模型；不将资料预览称为任务执行或工具授权。

## 1. 读取目的与能力边界

普通员工在 Web 能看到某项业务，不代表该项资料已允许 AI 处理。秘书读取同时遵守当前业务权限、分类制度的 ai_allowed、渠道规则与会话范围。项目、任务和知识是当前支持的三类来源。

分类许可与渠道由[人工策略发布](30-classification-policy-publication.md)管理，默认不自动启用；预览接口不能替用户修改该规则。

| 来源 | 读取内容 | 固定依据 |
| --- | --- | --- |
| project | 项目名称、说明、状态 | 项目 ID、当前乐观版本、完整投影摘要 |
| task | 任务标题、正文、状态 | 任务 ID、项目范围、当前乐观版本、完整投影摘要 |
| post | 知识标题、正文、状态及引用证据 | 准确不可变修订 ID/序号、固定文件版本、完整投影摘要 |

接口不接受任意 URL、本地路径、对象键或存储凭证。文件原件不是当前文本接口的读取类型。文件引用只核对可读性、正式状态、扫描结果及固定版本，并返回安全元数据；没有下载原件、解析 120GB 文件、调用外部模型或触发业务修改。

## 2. 全部成员的共同阅读范围

一次读取按同一数据库快照依次完成：

1. 验证调用人当前身份、组织/用户授权版本与会话成员资格。
2. 验证会话 active，且调用人提交的 context_security_version 与当前一致。
3. 取得当前完整成员快照，逐人检查有效身份、conversation.read、项目成员及 project.read、当前渠道和 AI 分类许可。
4. 验证来源与会话的项目范围完全一致，且来源分类不高于会话分类。
5. 对每位成员分别检查该来源的实际阅读动作；知识还需按共同读者范围选择修订，并检查所有文件引用。
6. 在上述检查全部成功后，输出限定字符片段及来源摘要。

会话中只要存在失效或失去资料权限的成员，本次共同资料读取即被阻止。不得悄悄忽略失效成员后继续读取；管理员也不获得例外。移除成员必须走正式的成员变更事务，生成新修订与安全版本后重新准备资料。

项目会话只能读取该准确项目的项目、任务和知识。未关联项目的个人会话只能读取公司范围知识，不能借个人会话汇总所有项目。项目范围为空与项目 ID 不相同，均不能通过降低分类绕过。

全部成员校验在服务内部构造 AI 数据检查身份，外部请求不能提交 run_id、他人身份或 AI 许可开关。这里的内部标记只用于启用 AI 分类规则，不是可运行的任务身份或凭证。

## 3. 知识修订与文件证据

共享知识按共同成员中的阅读权限选择准确修订：

| 成员权限组合 | 默认可读修订 | 显式 version_id |
| --- | --- | --- |
| 每一位成员都是作者或当前有 post.write | 当前修订，包括未发布草稿 | 可选择同一知识的其他不可变修订 |
| 存在仅阅读成员 | 当前已发布修订 | 仅该准确已发布修订 |
| 尚未发布，且存在仅阅读成员 | 拒绝 | 拒绝 |

仅阅读成员不能通过 ID 猜测取得新草稿。返回的 resource_version 是实际选中修订序号，不泄露私有草稿的最新头版本。查询修订时同时绑定组织、知识 ID 和修订 ID，拒绝错用其他知识修订。

每条文件引用必须解析到准确 file_id/version_id。未固定的旧来源在本次读取中解析并固定当前正式版本；历史准确版本在仍可用、状态允许时可继续引用。每个成员都必须具有该文件的当前阅读与 AI 许可，并通过目录祖先、回收站、正式版本和 clean/waived 等既有检查。

只要任一成员无法读取任一引用，就拒绝整份衍生知识投影，避免通过摘要或正文绕过原文件权限。每份知识最多核对 20 条引用。返回的 evidence 包含名称、准确版本/序号、SHA-256、字节数、媒体类型、扫描状态与豁免依据，不包含云对象键或签名链接。

## 4. API 契约

`GET /v1/conversations/{id}/context-sources/{resourceType}/{resourceID}`

| 参数 | 约束与默认值 |
| --- | --- |
| resourceType | project、task、post |
| resourceID | 准确 UUID；进入业务比较前规范为小写 |
| context_security_version | 必填，当前会话安全版本，正整数 |
| version_id | 可选，仅 post 可用，准确知识修订 UUID |
| offset | 默认 0；0—200000；按 Unicode 字符计，不按字节计 |
| max_chars | 默认 4000；1—10000 |

成功返回 ConversationContextView：准确会话/修订/安全版本、来源类型/ID/版本、标题/状态/正文、字符范围及下一起点、来源摘要/上下文摘要、安全文件证据、untrusted_data=true 和观测时间。全部字段由同源 OpenAPI/JSON Schema 校验，客户端类型同源生成。

错误不返回隐藏资料标题、正文或成员详情。404 用于无权或不可披露来源；409 用于会话归档或上下文安全版本变化；412 用于调用人的授权版本失效；422 用于不支持的来源、修订/字符范围或引用上限。读取设置 5 秒数据库处理上限，超时不能返回部分资料。

### 摘要含义

source_sha256 覆盖本次完整来源投影：类型/ID、标题、状态、正文、分类、项目、实际资源版本/知识修订与文件证据。它不随字符分页或观测时间变化。

context_sha256 进一步绑定调用人的组织、用户、渠道、run、授权版本，会话准确修订/安全版本、当前完整成员集合以及该片段范围。相同来源的不同片段或不同会话/身份可以产生不同上下文摘要。

这两个摘要只描述观测内容。它们不是权限票据、批准凭证、工具提交回执或永久可用性保证。后续任务准入、上下文恢复和工具调用仍须重新核对当前授权、成员、安全版本与准确来源；不能凭此前预览绕过撤权。

## 5. 普通业务读取与 AI 读取的分离

项目列表、任务、里程碑、风险、问题、工作台汇总和任务依赖，以及知识列表、修订、评论读取，均按 Actor.RunID 是否存在启用 AI 数据规则。普通人工阅读继续按其业务权限；AI 身份不能复用人工模式的固定 false 参数取得数据。

对应项目/知识/评论分页统一使用 core.CursorBinding，明确包含组织、用户、渠道、run、用户/组织授权版本和业务筛选。不得直接序列化含 json:"-" 的 Actor 来构造权限游标，也不得以易混淆的拼接字符代替结构化绑定。

游标跨用户、跨渠道、跨 run、跨授权版本或从人工切换到 AI 均失效。先按完整权限和可见修订过滤，再搜索、排序与分页；工作台数量也应用同一 AI 数据许可，不能只过滤详情。

## 6. Web 与品牌应用

会话详情加入“准备给秘书的资料”，沿用[品牌应用规范](../design/09-brand-application-and-content-style.md)的灰白背景、文字层级、墨色主按钮、蓝色强调和既有表单组件。归档会话仅提示恢复后核对。

员工按资料类型及标题选择，无需输入内部 UUID。候选来自当前员工有权访问的业务列表，并限制在固定会话范围；公司知识分页中排除项目知识，可继续加载。候选可选不代表共同阅读核验已经通过。

“核对并预览”调用真实受控接口；只有成功核验后显示返回的标题、准确修订序号、正文片段和引用文件版本。正文按普通文本呈现，不执行其中 HTML、脚本、指令或外部资源。任何失败或重新选择均隐藏旧片段，不继续显示上次成功结果。

下一片段继续固定知识修订，并比较完整来源摘要；中途来源变化时要求从第一段重新核对。会话修订/成员安全版本变化使资料选择组件重新建立。该预览不累加为持久模型上下文，当前也不生成虚假消息或运行进度。
