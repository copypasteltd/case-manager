# 移动端项目协作与固定交付修订

日期：2026-10-24。状态：Taro公共页面、真实API／H5操作及两小程序编译已通过本地验证；平台真机与完整原生业务待验收。关联PM-03—08、WP-04及[四端能力矩阵](06-clients-and-pages.md)。本轮复用现有Go/PostgreSQL契约，不新增数据库迁移，不改变四端同批首发要求。

## 1. 能力与入口

| 页面 | 入口与已实现动作 |
| --- | --- |
| 项目概况 | 项目列表进入；项目范围、阶段、业务日期、任务、里程碑、风险、问题、成员、交付、文件与记录入口 |
| 项目资料 | `pages/project/index?id=…&section=…`；按项目分页查阅里程碑、风险、问题、交付，按名称搜索，查看当前成员及项目角色 |
| 里程碑／风险／问题 | `pages/detail/index?kind=…&id=…`；负责人姓名、截止时刻、说明、严重性、概率、缓解措施／处理结果；风险已发生时可进入关联问题 |
| 任务 | 当前负责人、前置任务及其真实阶段；按权限处理任务；创建评论、修改本人评论、查看不可变评论历史及分页 |
| 交付 | `pages/deliverable/index?id=…`；当前资料、准确提交修订、固定文件引用、验收结果及历史；新建、编辑、提交、退回、独立验收 |
| 新建交付 | `pages/deliverable/index?project_id=…`；项目有效成员负责人、可选未结束里程碑、名称、验收准则与原因 |
| 固定历史 | `pages/deliverable/index?id=…&revision=…`；读取指定修订，页面不提供将旧历史当作当前修订的写入口 |

项目开始／到期日期保持`YYYY-MM-DD`业务日期，不经过时区位移。任务、里程碑、评论、提交及决定的事件时刻按香港时区表达。成员姓名为当前可见姓名，不冒充提交时冻结的历史姓名。

## 2. 复用的接口契约

| 动作 | 接口 | 关键约束 |
| --- | --- | --- |
| 项目资料 | GET `/projects/{id}`、`/members`及`/milestones`、`/risks`、`/issues`、`/deliverables` | 受当前项目权限及渠道约束，列表使用服务端游标，不先取全部再在客户端过滤 |
| 创建交付 | POST `/projects/{id}/deliverables` | 负责人来自有效项目成员，里程碑可选，名称／准则／原因为必填 |
| 编辑交付 | PATCH `/deliverables/{id}` | 固定`expected_version`；仅服务端`can_edit`允许时出现 |
| 提交修订 | POST `/deliverables/{id}/submit` | 固定头版本、`expected_revision_id`、1—20个准确正式版本、说明与原因 |
| 人工决定 | POST `/deliverables/{id}/decisions` | 固定头版本、修订ID和内容摘要；真实交互会话及近期MFA，独立验收声明 |
| 当前与历史 | GET `/deliverables/{id}`、`/revisions`、`/revisions/{revision}` | 当前头与不可变修订分开；逐页读取，撤权后不沿用旧结果 |
| 任务讨论 | GET／POST `/tasks/{id}/comments`、PATCH `/comments/{id}`、GET `/comments/{id}/history` | 修改固定`expected_revision`，保留旧评论；本轮创建文字评论，修改文字时保留已有固定附件版本 |

类型直接引用生成的`@copypaste/contracts`，不手写另一套业务实体。交付协议和状态机以[固定交付与人工验收](42-project-deliverables-and-acceptance.md)为准。

## 3. 文件选择与固定依据

候选分为本项目文件与公司公共文件，支持名称搜索、文件分页及版本分页。用户先选文件，再明确选择版本；当前版本与历史版本同时标注。只允许选择当前可用且`clean`或已有扫描例外`waived`的版本，去重并限制20项。提交时服务端重新校验权限、分类、归属、扫描及可用性。

界面展示原文件名、版本序号、字节数与SHA-256，引用跳转读取同一`file_id/version_id`；不替换为“最新版本”。固定修订的名称、准则、文件和决定从该修订读取，不能取当前编辑字段补写历史。

本轮固定版本入口提供元信息查阅，不将其称为已读取文件内容。微信／抖音的实际授权内容预览、下载及普通附件上传仍须完成；Android还需要真实原生文件访问和后台传输宿主。验收页面明确要求通过可用渠道实际核实文件，元数据展示不替代人工核实。

## 4. 授权与人工确认

页面每次显示先读取当前`/me`，再读取项目／交付。隐藏页面关闭读取作用域并清空已显示业务结果；再次进入重新授权。分页及辅助查询也各有作用域，旧查询返回不能拼接到新列表，分页失败清空这组列表并提供重新读取。

交付编辑、提交、决定入口使用后端返回的`can_edit/can_submit/can_decide`。列表创建另核对全局动作、当前项目只读角色和项目阶段。任务变更与评论在项目`closing/archived/cancelled`或本人项目角色为`viewer`时只读；权限读取失败也不展示写表单。实际服务端判断仍是最终依据。

成员角色变更会提高该成员的认证版本，使旧会话失效。旧会话读取收到401后，公共会话层核对刷新结果；刷新同样失效则清空身份和业务视图，要求实际重新登录及MFA。只读能力应在新会话下重新读取，不能把旧令牌继续浏览写成权限切换成功。

通过验收需要另一名获授权人员、两个当次未勾选的核实声明、非空说明及实际MFA步骤。提交人可以退回补充，不能自验通过。退回也需要本次MFA。前端确认有效期采用9分钟，服务端独立校验自己的期限；切换页面清除前端MFA状态及验证码，验证成功不自动提交决定。

## 5. 草稿、并发与恢复

共享内存草稿仅保留白名单文字：原因、动作选择、名称、准则、说明、评论正文及负责人／里程碑选择ID。按登录代际、用户、授权版本、对象／表单种类及准确业务版本隔离；验收额外绑定修订ID和内容摘要。有效期15分钟，最多32项，总计10万字符；每字段长度受独立上限约束，超长内容拒绝保存，不静默截断。

文件选择、验证码、验证结果、核实声明及完整请求载荷不进入草稿。页面隐藏返回后只恢复仍匹配当前权限与版本的文字；文件与声明需要重新选择。变更授权、退出、换用户或整页重载均不能恢复旧草稿。

写请求由用户明确触发，不自动重放。相同在途表单意图复用幂等键；成功清理草稿并重新读取当前对象。403／404、409／412和结果未确认会锁定该表单，保留文字并要求先核对当前结果与权限。刷新后重新读取能力和版本，不把冲突前的声明或MFA带到新修订。

另设有界的会话内命令记录，与可编辑草稿分开：保存精确请求签名、原幂等键及在途／未知／成功状态，最多128项，签名和绑定合计10万字符。绑定包含登录代际、用户、授权版本及准确业务依据。页面隐藏后仍保留尚未核对的请求；用户明确以相同输入核对时复用原键，不自动发送。结果未知时禁止把同一绑定改写为另一请求；容量不足拒绝新操作，不淘汰未核对记录。可见页面收到成功回执后清理，旧页面的迟到回执不能消费新的记录。

命令记录可能包含业务请求的精确序列化内容，仅驻留有界内存，不恢复进表单、不落盘、不记录日志；认证与MFA请求不进入此记录。退出清空，整页重载不能恢复。跨重载的统一操作查询／恢复中心尚未实现；结果未知时先查阅列表及对象核对，不能把另建一条资料当作结果确认。
