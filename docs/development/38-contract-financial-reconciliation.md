# 合同节点、真实费用与资金归属协议

日期：2026-10-24。状态：本地后端及Web已实现并验证；完整后端、最终浏览器与开发运行时检查通过。依据[合同计划](26-contract-payment-schedules.md)、[唯一实际费用](35-canonical-actual-costs-and-incurred-reports.md)、[实际资金](36-payments-refunds-and-settlement.md)及[OA需求](../requirements/04-workflows-and-oa.md)。合同法律完成/终止、移动端与真实银行证据继续分别验收，本增量不代表四端系统可生产上线。

本章第10节保留0039的历史验证来源；当前完整后端见[完成／终止协议](39-contract-completion-and-termination.md)。迁移0040扩展法律阶段门禁：已完成／终止合同仍可按准确生效修订登记真实后续费用关联、财务归属与更正，所有来源／余额／权限规则继续有效，法律阶段不会因此重开。

## 1. 事实与归属

生效合同计划及节点不因对账而修改。节点归属既有规范费用或已登记资金的一部分金额，保留准确来源版本、修订、摘要和人工原因；它不新建费用、付款或银行指令。一个来源可以分配到多个节点，但全部节点的归属合计不得超过该来源金额。同一资金的费用结算和合同归属是不同维度，报表仍只计一次真实资金。

应付节点只接受已确认且关联准确生效合同的原费用，以及同币种、同范围、同往来方的实际对外付款。应收节点只接受实际收款，不生成支出费用。允许部分及超计划归属，差额单列；不能通过篡改计划金额消掉差额。

退款引用准确正向资金归属。应付退款须是原付款收到的实际退款；应收退回使用实际对外付款，固定原收款与节点。同一退款不能重复归属，不能超过该正向归属当前余额。应收退回占用实际对外付款的可分配余额，不能再用同一部分结算费用。

## 2. 修正、核对与未知

解除归属追加反向记录，不删除来源或旧记录；部分解除保留剩余金额。来源被冲销时，当前投影不再把该来源计为有效履行；历史核对仍保存当时依据。实际退款可能先登记、后归属，界面持续显示待核对退款，不能推定它与某个节点无关。

人工核对固定当前来源集合指纹、各项来源状态/准确修订、净归属金额、未归属退款摘要及凭证。即使合同或归属头版本未变，来源冲销、退款或来源版本变化也会使旧核对失效。条件是否满足、金额差额和未归属退款的影响分别确认；有差额时不能宣称已结清，人工核对也不自动完成或终止法律合同。

没有费用/资金阅读权限时对应金额为未知；不得显示零。历史来源、解除和退款仍参与当前阅读门禁。技术管理员没有自动业务权限，新增合同对账角色默认不绑定。正式命令要求实际人工会话、近期MFA、准确合同/归属版本与幂等键。

## 3. 存储与并发约束

迁移0039追加独立合同财务头、不可变操作账本和固定凭证引用。合同商业版本与财务头版本分开，财务写入不改变已批准条款。锁序为组织授权、排序后的关联项目、合同、规范费用、排序后的资金及其退款家族；反向来源固定，金额上限由数据库约束和业务层共同检查。业务、审计、发件箱和幂等回执同事务提交。

费用/资金现有冲销、退款与结算规则继续有效。应收退回的余额保留纳入资金校验，不能绕过费用分配上限。来源变化后只计算当前投影和核对有效性，不每天重写历史。读取在一致数据库快照中完成，分页绑定身份、授权、渠道和筛选。

## 4. 页面与验收

合同详情展示计划、已归属费用、已归属净收付、未归属退款、差额与条件核对；历史可查看固定依据。提供准确费用/资金选择、部分归属、退款归属、解除和人工核对。提交冲突保留输入；MFA后仍需本人明确提交。界面沿用[官网规范](../design/README.md)，深浅主题与窄屏保留币种、金额和事实名称。

验收须覆盖应收/应付、部分/超额、跨节点与并发上限、退款及原资金冲销、真实费用去重、资金余额预留、固定凭证、旧指纹、历史ACL、幂等撤权及审计回滚。具体显示、来源选择、弹窗、双主题与响应式规则见[合同节点设计](../design/11-contract-financial-reconciliation.md)。布局检查和真实业务检查分别记录，不能以截图代替数据库并发验证。

## 5. 数据模型与投影

| 对象 | 存储与关键不变量 | 读取表达 |
| --- | --- | --- |
| 生效合同计划 | 复用准确生效商业修订及`contract_milestones`；财务命令不修改计划 | 合同方向、币种、计划金额、日期和条件固定；未知计划与明确无计划分开 |
| 独立财务头 | `contract_finance_heads`以组织/合同唯一；版本从0开始，每次操作递增1；当前事件与连续账本一致 | `version`为财务头版本，`contract_version`为合同本身版本；两个均用于写入前置条件 |
| 归属及操作事实 | `contract_finance_events`保存合同/节点/生效修订、连续序号、种类、准确来源版本/修订/摘要、金额或固定核对快照、实际人工会话及原因 | 归属、退款、解除和人工核对分别展示；当前余额不覆盖原始金额 |
| 核对凭证 | `contract_finance_event_files`仅允许绑定核对事件；1—20项唯一正式文件版本 | 使用既有固定版本文件组件，保留扫描/豁免和访问限制 |
| 引用保护 | 凭证登记`file_version_references`，类型为`contract_finance_event` | 全额解除、来源冲销和旧核对失效均不删除历史引用 |
| 资金余额 | 复用`payment_records`及分配账本，增加应收退回预留计算 | `contract_return_reserved_amount`为已用于收款退回的部分，实际可分配余额扣除该值 |

账本种类为`cost`、`cash`、`refund`、`release`、`review`。前三种属于正向来源归属记录，每节点最多100条，已解除记录仍占用历史来源名额；达到上限应明确失败并走产品扩容评审，不能截断历史或复用旧记录。解除和核对追加新事件，不占用这个来源名额。数据库拒绝历史更新/删除、断序、脱离头指针及不完整事务。

`remaining_amount`表示某条原始归属扣除已解除金额后的余额，`effective_amount`还考虑来源当前是否已冲销及退款方向。退款投影为负向，解除引用准确原归属；两者都不会生成第二笔实际付款。应付当前费用与当前净付款相互独立，例如节点计划60、费用30、付款50，应显示三个不同事实，不能合并成“已付费用50”。

`outstanding_amount=max(计划−当前净收付,0)`，`excess_amount=max(当前净收付−计划,0)`；允许净收付超过计划，超额单独显示。金额使用十进制字符串，来源按币种最小单位校验，内部计算最多6位小数，不经过JavaScript浮点数累计。汇总使用报表金额类型，不能套用单笔金额上限而丢失合法合计。

## 6. 来源资格与逆向操作

| 类型 | 必须固定的业务依据 | 额度与方向 |
| --- | --- | --- |
| 应付费用 | 已确认原费用、准确当前版本/修订/摘要；既有`cost_links`指向本合同准确生效修订；币种及往来方匹配，分类不低于合同 | 全部合同/节点的费用归属余额之和不超过原费用；费用仍只发生一次 |
| 应付付款 | 已登记未冲销的实际对外付款，项目范围、往来方、币种及分类符合合同，不是员工垫付结算 | 正向资金归属合计不超过来源总额；既有费用分配是另一维度，不重复增加现金支出 |
| 应收收款 | 已登记未冲销的实际收款，其他范围条件同上 | 只形成收款归属；费用轴为不适用，不能创建支出费用 |
| 应付退款 | 已登记实际退款，`refund_of_id`固定原付款，并引用同节点准确正向`cash`归属 | 退款日期不早于原付款；归属总额不超过该退款，且不超过原正向归属当前可退余额 |
| 应收退回 | 已登记实际对外付款，引用同节点准确原收款归属 | 预留对外付款余额，不可把同一部分再分配到费用；退回总额不超过原归属余额 |
| 解除 | 固定本合同/节点的`cost`、`cash`或`refund`原事件及解除金额 | 金额严格大于0且不超过剩余归属；正向资金剩余不能低于仍有效的退回归属 |

来源版本、修订和摘要来自实际选择结果，不能仅提交来源ID后让后端静默改绑最新版本。选择器可提前筛选；数据库事务再次核验实际状态、范围、方向与上限。新增费用/资金归属还分别要求`cost.record`或`payment.record`；解除本合同归属不要求重新取得来源登记能力，但仍需全部来源阅读与合同对账权限。

有实际退款但尚未确定节点归属时，显示“有退款待核对”，并让已固定的旧核对失效。不能按比例自动推定退款落在哪个节点。收款原记录存在有效退回归属时，拒绝直接冲销原收款；应先按真实情况冲销或解除退回，再处理原收款。冲销和解除业务含义不同，不能用解除伪造银行退款。

来源费用冲销后，节点当前有效费用归属为0，原归属和原核对仍可追溯；实际资金冲销亦然。不能把来源冲销当作删除，或继续使用旧核对宣称当前履行有效。

## 7. 人工核对与固定依据

核对保存当时来源集合：归属记录、剩余及有效金额、来源当前头版本/修订/摘要/状态、原付款退款家族摘要，以及未归属退款事实。`expected_fingerprint`是数据库规范快照的32位MD5摘要，用于检测依据变化；它不是签名、秘密或授权凭证。

来源变化可能不推进合同或财务头版本，因此三个前置条件都要满足：准确合同版本、准确财务头版本、准确来源集合指纹。任一变化拒绝旧提交；不能仅刷新版本号后自动重试。当前读取通过快照指纹比较得出`unreviewed/current/stale/restricted`；新退款、退款冲销、费用冲销等能使旧记录成为`stale`，旧快照保留当时状态。

条件满足、金额差额及未归属退款三个确认项独立处理。条件满足默认不勾选；净收付与计划不等时必须明确确认差额；有待归属退款时必须确认已经核实其影响。必须提供1—20项可批准用途的准确正式凭证，禁止重复版本。核对记录不会自动改变合同法律生命周期，也不代表银行对账、会计结账或合同完成条件全部满足。

## 8. HTTP契约与错误恢复

本增量实际接入以下5项操作。机器契约扩展到208路径、264操作、409个Schema；包含其他规划接口，数量不等于全部接口已实现。

| 方法及路径 | 输入与结果 |
| --- | --- |
| `GET /v1/contracts/{id}/finance` | 当前准确合同/财务版本、计划节点、各轴可见性、当前金额/差额、核对有效性及操作能力 |
| `GET /v1/contracts/{id}/finance/events` | 可选`milestone_id`、`cursor`、`limit`；完整授权后返回固定历史、当前有效余额、固定凭证及下一页游标 |
| `POST /v1/contracts/{id}/finance/entries` | 共用版本/原因；`milestone_id`、`kind=cost/cash/refund`、准确`source_id/source_version/source_revision_id/source_content_hash`、正数`amount`；仅退款要求`source_event_id` |
| `POST /v1/contracts/{id}/finance/entries/{entry}/release` | 共用版本/原因及正数`amount`；路径固定原归属 |
| `POST /v1/contracts/{id}/finance/milestones/{milestone}/review` | 共用版本/原因、`expected_fingerprint`、三个明确布尔确认及`evidence_version_ids` |

共用写入字段为`expected_version`、`contract_version`和`reason`，请求遵循同源闭合Schema、CSRF及幂等协议。成功回执仅保存`contract_id/milestone_id/version/event_id`，重新读取详情取得当下事实，不用旧回执金额覆盖当前显示。

| 情况 | 机器错误及客户端行为 |
| --- | --- |
| 合同/财务头或来源准确版本已变 | `409 VERSION_CONFLICT`；保留输入，要求重新核对准确对象 |
| 来源集合发生外部变化 | `409 CONTRACT_FINANCE_BASIS_CHANGED`；保留原因/勾选/凭证，不自动确认新集合 |
| 合同尚未生效/项目只读 | `409 CONTRACT_NOT_EFFECTIVE` / `PROJECT_READ_ONLY`；说明当前阶段，不能通过换版本绕过 |
| 来源或退回已超额 | `409 CONTRACT_SOURCE_EXCEEDED` / `CONTRACT_RETURN_EXCEEDED` / `PAYMENT_BALANCE_EXCEEDED`；重新查询来源余额 |
| 解除超额或仍有退回 | `409 CONTRACT_RELEASE_EXCEEDED` / `CONTRACT_RETURN_STILL_LINKED`；保留输入并先处理准确反向来源 |
| 原收款仍被退回引用 | `409 PAYMENT_HAS_CONTRACT_RETURNS`；保留原资金事实，不能先冲销原收款 |
| 授权改变/MFA不足/对象不可读 | 使用既有412、MFA及404协议；撤销过期查询和能力，补MFA后仍由本人明确提交 |
| 缺凭证、精度、来源不合条件或SQL最后防线 | 使用既有字段错误/业务约束错误；不向用户输出数据库原始文本 |

列表游标绑定组织、用户、授权版本、渠道和节点筛选；换身份或筛选不能继续旧游标。读取在一致快照内核对组织/用户授权版本，权限变化返回失效信号。

## 9. 权限、事务与报表

`contract.read`只允许读取可见合同，`contract.reconcile`另行授予；预置`contract_reconciler`角色要求MFA且默认不绑定。管理员角色没有业务阅读豁免。应付费用、资金轴分别检查合同范围能力及全部历史来源当前阅读权，包括已全额解除的记录和有关退款；某轴受限时金额为`null`、可见性为`restricted`，不能显示0或开放完整历史。应收费用轴明确`not_applicable`。

正式命令拒绝AI运行身份，核对实际有效人工会话及数据库当前最近10分钟MFA，执行人和MFA时间由数据库取得。幂等回放在返回缓存前重新检查当前权限、会话及来源阅读；不能利用旧成功键绕过撤权。所有关联项目按确定顺序加锁，归档/关闭/取消项目拒绝新财务操作；组织授权锁与既有费用/资金命令共用。

应收退回的预留参与资金分配上限和当前余额；付款详情明确单列该值。现金视图继续是支出现金口径，原收款不计入支出，实际退回作为真实对外付款计一次，冲销按其生效期间反向计入。项目份额使用准确退回归属；不得把整笔资金重复计入每个关联节点。应付合同归属也不会改变既有费用结算和项目现金分摊口径。统一收入报表、外汇折算和会计结账仍需各自协议。
