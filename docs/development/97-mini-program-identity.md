# 增量97：微信、抖音小程序身份绑定与登录

本增量推进 GAP-19 的平台身份接入。员工先使用既有内部账号登录对应小程序，在账号安全页输入当前密码、获取平台身份并明确确认绑定；后续可通过该小程序的平台身份进入同一员工账号。Web、Android 可查阅、解除本人绑定。无自动注册、手机号／昵称／UnionID 合并或匿名员工账号。

公司仍保留 Web、微信、抖音和 Android 四端目标。本实现的原生 PostgreSQL、受控 HTTP 协议检查及浏览器合成演示，不能替代真实 AppID、平台凭据、香港网络、隐私审核和真机首发验收。

## 配置与信任边界

| 配置 | 用途 | 分发范围 |
| --- | --- | --- |
| `CP_WECHAT_APP_ID` / `CP_WECHAT_APP_SECRET` | 公司微信小程序服务端身份交换 | API 服务的私有环境 |
| `CP_DOUYIN_APP_ID` / `CP_DOUYIN_APP_SECRET` | 公司抖音普通小程序服务端身份交换 | API 服务的私有环境 |
| `CP_MINIAPP_IDENTITY_KEY` | Base64 编码的32字节随机专用身份摘要密钥 | API 私有环境及受控灾备密钥托管 |

默认两个平台均关闭。某平台的 AppID、Secret、专用密钥必须完整有效；部分配置使 API 启动失败，不回退到匿名或伪身份。一个部署每个平台对应一个公司 AppID；AppID 是公开配置，Secret 和专用密钥不得进入小程序、APK、Git、日志、截图或监控标签。`GET /auth/miniapps` 只发布已配置平台及 AppID。

身份摘要使用独立密钥与用途区分的 HMAC-SHA256，输入包含平台和 AppID。数据库保存摘要和绑定关系，不保存原始 code、OpenID、UnionID、平台 session_key。更换 AppSecret 时保留专用密钥；不要直接更换摘要密钥后期待原绑定自动迁移。密钥轮换须单独安排当前绑定撤销、员工重新绑定及灾备恢复方案。

平台协议：微信采用服务端 `GET https://api.weixin.qq.com/sns/jscode2session`，抖音普通小程序采用 `POST https://developer.toutiao.com/api/apps/v2/jscode2session`。后者要求 `err_no=0`、`data.openid` 与 `data.session_key`，匿名标识不能登录员工账号。参考[微信服务端说明](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)与[抖音普通小程序说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/basic-abilities/log-in/code-2-session)；本轮微信文档地址未能通过网页读取工具打开，不能将协议合成检查称为真实微信服务验收。

生产适配器固定官方 HTTPS 地址，10秒超时，不跟随重定向，最多接收32KiB响应。HTTP 测试可在测试代码注入受控 transport；业务请求和环境变量不能指定交换 URL。外部错误统一转为安全错误，不返回带凭据的 URL、原始响应或驱动诊断。

## 员工使用逻辑

1. 在公司微信／抖音小程序通过内部账号登录，进入“我的工作空间 → 我的小程序绑定”。客户端检查实际运行环境及 AppID：微信读取 `getAccountInfoSync().miniProgram.appId`；抖音读取 `tt.getEnvInfoSync().microapp.appId`（基础库至少2.21.0）。两者各自与服务端配置相符；H5、Android 和不匹配 AppID 无法获取绑定证明。
2. 输入当前内部账号密码。已设置验证器的账号，先完成最近10分钟内的两步验证。后端检查当前交互会话、账号状态、用户与组织授权版本，再调用平台交换；网络调用期间不占用业务行锁。
3. 平台 code 在网络调用前取得数据库唯一使用记录。超时、错误或响应丢失后，原 code 不能再次用于绑定或登录；用户重新操作取得新 code。
4. 成功交换后生成2分钟证明，限定组织、员工、原交互会话、平台、AppID 和两个授权版本。弹窗提示绑定当前内部账号；取消不创建绑定。确认后通过带幂等键的命令原子写入绑定、消费证明并产生审计与 outbox。
5. 以后在同一小程序选择“微信／抖音身份登录”。后端只查找已存在的有效绑定和有效员工；适用角色要求 MFA 或员工已有验证器时，继续 MFA／首次设置流程。平台身份不会绕过现有权限。
6. Web、Android 和两个小程序可查看本人的分页绑定历史并确认解绑。解绑使该绑定产生的访问凭证、所有刷新轮换及未完成 MFA 挑战失效；密码登录的独立会话不因该绑定解绑而撤销。重新绑定创建新记录，旧历史保留。

抖音环境信息采用[官方环境接口](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/api/foundation/env/get-env-info-sync)，不调用未支持抖音的 Taro 账号接口；缺少能力时明确失败，不以服务端 AppID 冒充实际运行信息。客户端在各平台开发者工具／发布工程中选择对应真实 AppID；当前没有提供公司正式发布凭据。Android 使用独立 `.rn` 适配器拒绝平台身份获取，避免将小程序登录或 Expo 扩展带入原生包。

平台 code、密码及 MFA 码只在必要请求中使用，不存入移动持久化存储。退出页面会清理密码输入并取消该页面拥有的请求。移动凭证沿用现有内存会话设计，不能据此声称已完成原生安全持久化验收。

## API 与数据模型

| 方法与路径（统一 `/v1` 前缀） | 身份要求 | 行为 |
| --- | --- | --- |
| `GET /auth/miniapps` | 公开 | 已配置平台／AppID；不含 Secret |
| `POST /auth/miniapps/login` | 单次平台 code | 既有绑定登录，返回既有 LoginResult／MFA 挑战 |
| `POST /me/miniapp-binding-proofs` | 对应小程序交互会话、当前密码；已设验证器须最近 MFA | 生成2分钟本人证明，不创建绑定 |
| `GET /me/miniapp-bindings` | 已登录本人 | 分页查看有效及已解绑历史，游标限定员工与授权版本 |
| `POST /me/miniapp-bindings` | 原证明会话、本人确认、适用最近 MFA、幂等键 | 原子消费证明并绑定 |
| `POST /me/miniapp-bindings/{id}/revoke` | 已登录本人、适用最近 MFA、expected_version、原因、幂等键 | 保留历史并使绑定会话／挑战失效 |

迁移78新增 `miniapp_code_claims`、`miniapp_binding_proofs`、`miniapp_bindings`，并给 `sessions`、`auth_challenges` 增加绑定来源外键。原77个迁移保持原始字节。有效平台身份在部署内只能对应一个员工；同一员工同一 AppID 也只能有一个有效绑定。摘要及历史不可由应用身份改写／删除，绑定只能以版本递增方式撤销。

MFA 设置、正常验证与恢复码验证都检查当前绑定并继承来源；Refresh 轮换继承同一来源。员工新增验证器后，旧的未完成MFA的平台会话即停止访问与续期，须重新登录完成验证。认证还检查平台配置是否仍有效。解绑与刷新按组织、员工、会话顺序取得锁，防止并发刷新让解绑会话复活。证明确认、幂等重放均先检查当前交互与适用 MFA；旧绑定撤销后，原绑定命令不能通过重放恢复它。

## 失败恢复与运维

- 未配置／AppID 不符：使用内部账号登录；由运维核对实际平台后台、客户端 AppID 与 API 私有配置，勿把 Secret 填入客户端构建变量。
- 平台交换超时／凭证已使用：重新由本人获取 code，不以重试旧 code 推断原交换是否成功。
- 证明过期、跨用户／会话、授权版本变化：重新核对身份并创建证明；不接管其他员工的绑定。
- 绑定或解绑响应丢失：Web 保留同一命令幂等键核对；Taro 显示结果待核对并禁止重复提交，通过刷新本人绑定列表确认存储状态。服务端已提交的命令不会重复写历史。
- 员工停用或权限变更：沿用既有认证版本与权限检查。解绑不授予、提升或恢复任何业务角色。
- code 使用记录暂不自动清理，以保留持久防重放边界；生产容量与保留策略需在后续运维周期中制定，不能直接清空后称为等价防重放。
- 平台服务因境内服务器、香港员工链路或平台限流失败时保留内部账号登录入口。服务器出口、合法域名及 HTTPS 配置需由真实环境验证。

## 验证与交付

原生测试覆盖双方协议的受控 HTTP 请求、错误及匿名响应拒绝；完整业务测试覆盖本人密码确认、两平台绑定、重复 code、证明消费、跨会话／用户／授权版本、分页游标、冲突身份、MFA 设置／验证／恢复、解绑历史及刷新竞争。页面检查使用真实本地 API 与隔离数据库，并模拟“已提交解绑但响应丢失”。

新的 Web／Taro H5 媒体展示查看、确认、取消、解绑与对账；不展示密码、MFA 秘密、平台 code 或真实业务数据。H5 不模拟 `wx.login`／`tt.login`，媒体不构成平台身份交换的真机证据。具体执行时间、源码摘要、测试数量、Android 构建／缓存范围及清理结果见[增量97验证](../quality/97-mini-program-identity-verification.md)。

真实验收仍需：公司微信／抖音 AppID 与服务端密钥、实际小程序包、香港真机、平台审核／隐私声明、服务器出口与 HTTPS 合法域名、内部成员绑定及停用演练。完整 Goal 继续 active；本增量不宣称四端生产就绪。
