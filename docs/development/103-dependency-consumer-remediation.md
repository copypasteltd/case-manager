# 增量103：构建依赖调用链修复 / Build dependency consumer remediation

[中文指南](../README.zh-CN.md) · [English guide](../README.en.md) · [验证记录](../quality/103-dependency-remediation-verification.md) · [当前范围](../delivery/04-current-scope-and-acceptance.md)

本轮推进 GAP-26。Taro 的旧模板下载和版本查询会加载旧 Git／HTTP 依赖，Metro 的图像解析仍使用旧接口。直接把新版图像库写进清单，会留下嵌套旧库，或使 `require('image-size')(...)` 失效。本轮通过公开源码的本地适配包替换调用边界，提交真实安装树和调用行为证据。

This increment advances GAP-26. Legacy Taro template/update consumers load old Git/HTTP dependencies, while Metro expects the old callable image-size API. The local adapters retain their own package identities and delegate parsing/metadata to current upstream packages. The installed tree and actual consumers are checked together; findings are not hidden by renaming a vulnerable implementation.

## 1. 实现与使用 / Implementation and use

| 编号 / ID | 内容 / Change | 约束与行为 / Behavior |
|---|---|---|
| DEP-01 | `packages/image-size-compat` | Metro／Less 保留 CommonJS 可调用接口，实际解析由 `image-size@2.0.4` 执行。支持 Buffer／Uint8Array、文件路径、回调及 `disableFS`；文件读取最多512 KiB头部并关闭句柄。不承诺未使用的完整旧版API。 |
| DEP-02 | `packages/latest-version-compat` | Taro 的 Promise／CommonJS 入口委托 `latest-version@9.0.0`，继续使用版本标签与包不存在错误。旧 package-json／got 分支移除。 |
| DEP-03 | `packages/template-download` | 保留 Taro callback 调用，支持 provider简写、直接HTTP(S)归档、Git克隆与准确修订；HTTP使用Node原生fetch，归档使用已有维护版提取器。 |
| DEP-04 | 下载边界 / Download boundary | 最多8次重定向、256 MiB压缩输入、1–120000 ms超时；拒绝非HTTP(S)归档、嵌入URL凭据及HTTPS降级，跨源剥离authorization／cookie。未知选项明确报错。 |
| DEP-05 | 临时目录 / Temporary directories | 拒绝已存在目标；先在明确目标父目录内创建独立暂存目录，成功后重命名，失败时核对所属路径并清理。面向Taro单进程开发CLI，不提供并发发布协议。 |
| DEP-06 | Git 参数 / Git arguments | 使用无shell的原生Git参数调用，禁用ext传输；拒绝选项形式的修订，经rev-parse得到准确commit后检出。仅删除经过路径核对的本次克隆 `.git`。 |
| DEP-07 | 产物来源 / Artifact provenance | Android来源摘要新增四个本地适配／提取包，除锁文件外也绑定其实际源码，防止本地包内容变化却复用旧产物证据。 |

These modules serve developer build consumers. They do not execute company payments, change business permissions or implement the AI execution isolation required by GAP-10. Existing Web, miniapp and Android business features remain in scope.

模板兼容入口支持 `clone`、`checkout`、`shallow`、`git`、`headers`、`timeout` 六个选项；callback在成功或失败后调用一次。归档去除第一层目录，空归档、未知格式和越界提取均失败。Git模板仍是开发者选择的源码；该功能不声称能隔离模板中的可执行代码。依赖适配不等于八项Skill通过真实模型验收。

## 2. 安装与复现 / Installation and reproduction

在 `app/` 使用原生Node22与已提交锁文件：

```powershell
npm ci --no-audit --no-fund
npm run test:dependency-security
npm ls image-size @copypaste/image-size-parser download-git-repo latest-version got git-clone --all
python scripts/verify_dependency_remediation_clients.py
python scripts/freeze_dependency_remediation_clients.py
$env:CP_MOBILE_BUILD_PROFILE='local'
$env:CP_MOBILE_API_ORIGIN='http://127.0.0.1:18080'
python scripts/build_android.py --google-mirror --evidence-group dependency-remediation
python scripts/inspect_android_apk.py --evidence-group dependency-remediation
python scripts/freeze_dependency_remediation_android.py
```

证据写入器遇到已有记录应先归档原尝试，不能覆盖失败。原生SDK准备见[开发指南](08-local-development.md)。不运行Docker、WSL、虚拟机、模拟器或真机；不安排网络性能测试。

The first installation retained a nested image-size1.2.1, which the installed-tree and bounded ICNS child checks detected. A general npm dedupe also failed with an optional React peer resolution conflict. Neither force nor legacy-peer flags were used. The two stale nested image-size lock locations were removed from the candidate input and the lock regenerated by standard `npm install --package-lock-only`; the committed result must then pass normal `npm ci`, actual tree validation and consumer tests. Intermediate attempts remain under the evidence directory.

本轮新增的调用检查包括：真实Metro资产尺寸／倍率／摘要，PNG／SVG、路径及回调；有界子进程中的ICNS／HEIF／JXL零长度结构；真实Taro `fetchTemplate` 入口；本地合成Git仓库、修订及参数拒绝；HTTP失败、无效归档、重定向、凭据剥离、超时与残留清理；真实CJS版本查询入口的本地合成registry及404。既有归档越界、符号链接、glob、codemod、XML和序列化检查继续保留。

## 3. 审计与剩余工作 / Audit and remaining work

完整扫描包括开发、构建、optional与peer依赖。npm按包汇总的记录包含传播关系，不等于独立CVE数量。基准102锁在本轮新扫描中仍为80项（13 high／60 moderate／7 low）；最终前后对比、安装树和逐项未完成清单见[验证记录](../quality/103-dependency-remediation-verification.md)。扫描返回1表示仍有告警，不能表述为安全门槛通过。

最终完整扫描为70项（6 high／57 moderate／7 low）。从告警集合中移出的10个包级记录为cacheable-request、download、download-git-repo、git-clone、got、http-cache-semantics、image-size、latest-version、normalize-url和package-json；没有新增告警包。Taro CLI由high转为moderate，仍属于开放记录。剩余6项high为webpack5-runner及旧HTML压缩、PostCSS、Vite、Webpack开发中间件和开发服务，逐项保留原公告和安装位置。

All unresolved package findings remain open with their original advisory chains and installation locations. Placement in a build/development dependency is not an exemption. The remaining legacy HTML minifier, old Vite/PostCSS and development-server consumers require compatible implementation changes and relevant consumer checks. GAP-26 remains active.
