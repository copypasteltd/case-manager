# 增量75：移动项目立项、资料与成员管理

微信／抖音／Android 共用的 Taro 客户端增加项目立项、准确已发布模板选择、项目资料编辑、成员角色配置／移除和负责人移交。入口接入现有16个注册页面，复用既有 Go／PostgreSQL 接口，不增加迁移或另建权限规则。全部代码位于 `app/`，验证记录位于 `docs/`。

## 1. 功能与入口

| 编号 | 功能 | 入口及行为 |
| --- | --- | --- |
| MP-01 | 新建项目 | 项目列表的“新建项目”；填写名称、类型、范围、访问范围及可选起止日期，当前本人为负责人 |
| MP-02 | 使用准确模板 | 按真实游标和搜索选择已发布记录，同时显示名称、系列标识与修订；预览目录、任务、里程碑和内容摘要 |
| MP-03 | 展示真实结果 | 新项目 ID、编号、版本、阶段及初始化情况来自原命令回执；pending／partial_failed 不写成全部完成 |
| MP-04 | 编辑项目 | 项目详情的“编辑项目资料”；固定当前项目版本，不修改项目编号、模板或访问分类 |
| MP-05 | 保留变更审批 | 草稿可编辑范围和日期，空日期明确提交null；active／on_hold只允许普通名称／类型编辑，范围与日期须按原项目变更审批实施 |
| MP-06 | 成员安排 | 项目成员页可为实际有效候选设置member／manager／viewer，或明确移除；提交固定项目版本、用户、角色／动作及原因 |
| MP-07 | 负责人移交 | 独立表单选择实际有效用户并确认；使用原负责人更新命令，新负责人为owner，原负责人保留manager，已有业务职责不自动搬移 |
| MP-08 | 只读与撤权 | viewer、closing／archived／cancelled以及无相应动作权限不显示写表单；深链接重新读取当前权限及项目角色 |
| MP-09 | 不确定结果与冲突 | 网络结果未知、无效成功回执或409／412锁定当前提交；保留输入，先重新读取实际结果，禁止自动重放或用新版本覆盖旧决定 |

新建不直接选择他人为负责人，也不隐含批量配置成员；创建后通过真实成员／移交入口分别完成。访问分类沿用普通立项已有的公司内部／项目受限选择，分类变更继续使用独立政策流程。新建项目不会代替后续业务批准、验收或结项。

## 2. 接口、版本与权限

| 动作 | 既有接口 | 固定依据 |
| --- | --- | --- |
| 新建立项 | POST `/projects` | 当前本人ID、完整资料、明确选定模板ID；服务端锁定该已发布修订并同事务初始化 |
| 选择模板 | GET `/project-templates?state=published` | 实际搜索、游标及完整内容；停用后保存冲突，不能自动改选另一修订 |
| 编辑资料 | PATCH `/projects/{id}` | 项目自身expected_version；普通表单不发送owner_id／classification／template_id |
| 当前成员 | GET `/projects/{id}/members` | 当前用户资料及memberships角色分别显示，不能以全局动作列表代替项目角色 |
| 配置候选 | GET `/projects/{id}/member-candidates` | 原项目manage_members权限；超过原100位容量显式拒绝，不截成完整目录 |
| 成员变更 | POST `/projects/{id}/members` | 当前项目版本、真实user_id、set／remove、适用角色及原因 |
| 负责人移交 | PATCH `/projects/{id}` | 独立expected_version／owner_id命令，同时要求原update与manage_members权限 |

成员变更不授予新的业务动作。本人和项目负责人不能从普通成员变更入口改动，负责人须通过独立移交处理。移除仍由原业务检查未闭环任务、里程碑、风险、问题及交付；有遗留事项时返回真实原因。成员角色变化会使其旧登录失效并推进组织授权版本，客户端重新读取本人资料及当前成员。

创建回执核对新ID、版本1、本人负责人、完整资料、业务日期、准确模板修订、项目编号、真实阶段与初始化状态。编辑回执须匹配原ID、原版本加一及本次资料，保留负责人、分类和模板；成员／移交回执分别匹配准确项目、下一版本及预期负责人。未经核对的成功响应按结果未确认处理。

## 3. 输入与恢复

日期使用有效 `YYYY-MM-DD` 业务日期，不经事件时区转换；客户端拒绝不存在的日期、非闰年2月29日及倒置范围。名称处理首尾空白，范围正文保留实际输入。错误采用现有 `MobileError` 展示具体原因，不能将本地日期校验错误显示为通用读取失败。

新增 `ProjectInput` 仅含名称、类型、范围、起止日期及分类等输入字符串。它参与原有15分钟、32项、总10万字符的共享内存草稿限额，绑定当前登录代际、本人、授权版本及准确业务版本。读写均复制白名单字段，不保留任意嵌套对象、凭据、确认标志、API结果或模板完整证据。模板选择不从文字草稿自动恢复，返回页面须重新选择与核对。

成员／负责人表单只保留输入的用户ID、动作和原因，仍以当前实际候选与项目版本复核。成功后清理对应草稿并重新读取；退出、撤权、新版本或新登录不得恢复旧授权输入。命令继续使用有界内存意图记录及原幂等键，结果未确认时不另造新请求，前端关闭或网络中断不代表服务端回滚。
