# 移动项目概览与关联业务查阅

本增量继续推进 GAP-01／03／18，代码位于 app/，文档位于 docs/。移动项目空间复用[增量69](69-project-business-overview.md)的真实授权聚合接口，补充费用、收付款、订阅、项目变更的详情与列表入口，以及项目预算修订的分页核对。原合同、采购、报销、任务、文件、知识、服务和人工审批继续进入原业务页面。

## 1. 功能约束与实现

| 编号 | 员工可以执行的操作 | 实现与边界 |
| --- | --- | --- |
| MVO-01 | 从项目资料打开项目业务概览 | 同一真实 API 返回16类当前可读记录，完整计数与最近5项分别展示；无权类别为“未核实”，不显示隐藏标题／数量 |
| MVO-02 | 核对发生支出、冲销和批准预算 | 逐币种显示原额／冲销／净发生额，保留全部十进制文本精度；实际分摊、未确认费用、付款、预测和预算分别判断 |
| MVO-03 | 从工作台或项目概览查阅实际费用 | 原费用读取授权；查看原额、实际分摊、冲销引用、当前可读结算、固定凭证及业务关联；结算不可读时不猜测余额 |
| MVO-04 | 查阅资金记录和分配流水 | 原付款权限；查看方向、原额、退款／预留／未分配金额、独立分配／释放／冲销流水；登记不代表自动银行支付 |
| MVO-05 | 查阅订阅、价格期间和已生成账期 | 原订阅权限；内部状态与供应商停费核对分开，原币价格按期间展示；没有已生成账期不表示没有订阅义务 |
| MVO-06 | 核对项目变更与预算修订 | 提案范围／日期／基线／审批计价／净变化与实际实施分开；预算列表保留草稿、批准、取代和准确来源修订；保持预算不变与明确清空有不同文案 |
| MVO-07 | 刷新、前后台切换与失败重读 | 页面隐藏释放请求作用域和概览定时器；返回重新鉴权；失败先清除旧事实，撤权后不保留标题、金额或之前的成员数据 |
| MVO-08 | 在各客户端构建中访问相同资料 | 使用现有 Taro 原生组件／Android适配层；两小程序编译与 Android 打包分别核验，H5浏览器不作为真机或平台发布证据 |

16类为：任务、里程碑、交付、风险、问题、变更、预算修订、文件、知识与日志、合同、采购、报销、实际费用、收付款、订阅、服务配置。服务 `active` 只表示配置“使用中”；必须进入原服务页核对带时间的观测、签名、新鲜度和健康状态。没有项目筛选契约的全局服务列表不伪装为本项目全部服务。

## 2. 页面和稳定引用

| 入口 | 真实路由与数据来源 | 导航约束 |
| --- | --- | --- |
| 项目概览 | `/pages/project/index?id={project_id}&section=overview`；`GET /projects/{id}` 与 `GET /projects/{id}/overview` | 项目ID、版本、快照时间及16类完整性一致后才挂载事实；页面可见期间每60秒重读，隐藏停止 |
| 费用／收付款／订阅／变更 | `/pages/finance/index?kind={cost|payment|subscription|change}&id={id}` | 类型只接受固定白名单；每项复用对应读取端点并校验准确ID，不接受任意外部路径 |
| 项目变更列表 | `/pages/project/index?id={project_id}&section=changes`；`GET /projects/{id}/changes` | 明确当前载入数量，按原游标继续读取，点击真实变更ID |
| 项目预算修订 | `/pages/project/index?id={project_id}&section=budgets&focus={budget_id}`；`GET /projects/{id}/budgets` | 原接口按页读取；选中修订未在当前页时明确提示，继续分页或重新核对，不以另一修订替代 |
| 财务资料列表 | 原列表页增加 `costs`／`payments`／`subscriptions` | 原接口支持的项目／标题筛选和游标；本轮新增查阅入口，不授予新的内容权限 |
| 固定凭证 | 原文件详情及固定版本阅读页 | 使用服务器返回的 `file_id`／`version_id`／SHA-256，不以文件当前版本替换已有凭证 |

注册页面新增 `pages/finance/index`，总计16页。项目概览、变更与预算视图作为原项目页的子组件进入两小程序与 Android 图谱；不为每个项目类别重复注册页面。原通知中的订阅账期页面增加回到订阅配置和对应实际费用的入口。

预算读取原协议没有单条预算端点，因此选中ID保留为 `focus`，当前实际页未包含时显示“尚未载入或当前不可读”。列表中的来源变更链接同时标明固定提案修订ID；打开的是该变更的当前详情，不宣称其当前修订就是旧预算的固定来源版本。费用业务关联和付款分配同样保留来源修订信息，并明确“查看当前资料”。

## 3. 金额、时间和状态

金额格式函数只对十进制字符串分组，保留负号、零和最多6位小数，拒绝科学计数、非有限值及不符合契约的文本。所有币种分别显示，金额不经过 JavaScript Number。缺金额和受限结算显示“未核实”，不能自动补零或推断已结清。

概览沿用服务端原口径：只统计本项目实际分摊，费用原额与冲销原额分别保留，再显示净发生额；草稿不计入。付款登记、合同／采购／报销批准额度、订阅预测不额外增加发生支出。批准预算按类别与期间独立核对，不据全期间发生额推算剩余额。

项目预算明细的“修订金额”可以来自草稿，只有 `approved` 表示当前批准预算。变更中 `budget_lines=null` 表示保持不变，`[]` 表示拟明确清空；审批通过仍不表示已经实施。费用和资金的冲销均可进入对应原记录，不覆盖原流水。

快照与记录更新时刻以香港时区显示到秒；业务日期使用原日期字符串，不随设备时区漂移。订阅保留自己的计费时区，供应商侧核对时刻与内部取消生效日分别展示。

## 4. 授权与生命周期

页面继续使用 `usePage`／`MobileClient`／`Scope`：读取前核验 `/me`，隐藏／刷新关闭旧请求作用域，注销清除内存凭据。读取结果不写入普通小程序存储，不持久化新的财务快照。旧请求不能在新作用域挂载结果。

概览先核对项目ID、准确版本、完整类别、计数／状态／预览及 `has_more` 的一致性。前后两次读取遇到项目版本变化时请重读，不把不同版本拼成一个已核实概览。无权类别即使错误响应附带旧计数或标题，也会拒绝挂载。

普通列表的后续页失败也隐藏已载入事实，保留明确错误和重读入口。费用详情、项目概览重读失败不会继续显示旧标题／金额；分配和账期子列表失败不会显示为业务空集。每项原记录、凭证、来源或项目跳转仍由服务器重新授权，概览读取不扩展权限。

本轮新增的是查阅与核对。原申请提交、审批、任务处理及交付验收仍由已有页面和业务命令处理；不在概览中增加变更实施、预算批准、资金登记或订阅停费动作。归档仍执行原完整结项核查和人工复盘。

## 5. 主要代码与验证

主要实现为 [project-overview.ts](../../app/mobile/src/platform/project-overview.ts)、[overview.tsx](../../app/mobile/src/pages/project/overview.tsx)、[business.tsx](../../app/mobile/src/pages/project/business.tsx)、[finance/index.tsx](../../app/mobile/src/pages/finance/index.tsx)，以及现有项目详情、工作台、列表、账期与导航层的实际入口更新。

便携逻辑新增10项测试，覆盖大额／负额／零／6位精度、香港午夜与秒、16类准确入口、服务范围、固定读取白名单、旧／外项目快照、未知与空集、隐藏事实及完整计数／分页。完整移动测试和两目标编译由 [verify_mobile.py](../../app/scripts/verify_mobile.py)执行；浏览器通过 [专用执行器](../../app/scripts/run_mobile_project_overview_browser.py)启动原生隔离数据库和真实API，再进行 Taro H5 导航、分页、授权、传输失败和撤权核对。

Android 使用既有原生工程重新生成离线业务包及开发 APK，并检查全部16个注册页面与原生适配层进入包内。不会启动 Docker、WSL、虚拟机、模拟器或实体设备。实际命令、结果、准确来源、失败尝试和清理证据见[验证记录](../quality/evidence/mobile-project-overview/verification.md)。

320像素浏览器核对发现原共享可点击行的108px设计值经Taro缩放后不足44个CSS像素，本轮改为44PX最小高度，保留原生行控件的既有高度。修正后重新执行移动测试、双目标编译、Android构建及完整浏览器链，不沿用旧UI来源的通过结果。
