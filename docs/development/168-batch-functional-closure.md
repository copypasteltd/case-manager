# 增量168：全部编号先审查，整批代码后统一验证

本轮承接167，按全部23个当前有效GAP逐项建立独立需求上下文；每个确认代码缺口再由不同作者反证。23份源码审查及9份独立反证位于[审查目录](168-audit/)。源码审查不执行或通过业务验收；未读边界分别保留。用户移出的五项继续移出，真实配置仍按“后续提供”处理。

## 执行约束

[完整代码计划](168-batch-code-plan.json)覆盖全部23项，记录12项确认代码任务及具体文件。初始计划的全部应用、消费端、回归用例、接口生成器和采集／核验工具写完，才保存首批2843文件源码快照。之后统一启动原生HTTP/PG、客户端、运行器和部署工具检查；先收集失败，再成批修复和封存，仅重跑受影响输入。计划是不可变的测试前快照，`tests_started:false`描述快照时间，实际执行以各阶段回执为准。

共用`development_wave.py --increment 168`代替继续复制逐增量测试调度器；其发布门禁核对全部编号、每个源码审查记录、全部确认任务及原始源码归档。该流程约束不能把外部未提供事实、公司制度或正式验收虚构为已完成。
