# 每轮完整开发后统一验证

本约定落实用户最新要求：每轮先完成全部未定事项中可落实的代码开发，再统一测试与调试，停止逐模块开发、测试、再开发下一模块的推进方式。

## 每轮顺序

1. **完整盘点。** 逐项检查当前全部有效编号、上轮失败、源代码TODO、需求未定事项和调用链。保留原编号；列出应用实现、接口／数据结构、Web与共享移动端、权限／审计、后台任务、部署工具及前置用例等受影响部分。
2. **一次完成代码批次。** 确认的代码缺口及全部消费者、必要回归夹具和本轮验证工具均完成后，才能开始该批次测试。不能把未写的调用方或用例包装成“待验收”。确实缺少公司制度、账号或外部配置的事项记录待提供的事实，继续完成不依赖它们的代码；不得伪造资料或结果。
3. **封存后统一检查。** 固定代码任务清单、完成状态、全部源码原始字节和摘要；检查不能倒写为代码完成证据。统一执行适合本轮变更的后端、客户端、运行器、部署及必要页面检查。
4. **收齐失败，集中修复。** 同一检查批次内先收齐结果，保留失败记录和对应源快照；归并后一次修正全部确认问题，再封存一个修复批次。只重跑实际输入变化或仍有疑问的检查；未受影响的结果按准确消费文件摘要复用。
5. **统一交付。** 更新中英指南、未完成编号表、更新记录、受影响的实际截图／录屏／GIF；核对提交内容后连同代码提交、推送。不得以源码审查、合成数据、开发包或本地通过代替正式验收。

## 完成状态

| 状态 | 含义 | 必备记录 |
| --- | --- | --- |
| 本轮代码已完成 | 已确认的完整代码批次与全部调用方写完 | 代码计划、具体路径、封存源码；不是测试通过 |
| 本轮统一检查通过 | 对应准确源码的适用检查已实际通过 | 原执行结果、失败及修复记录、明确复用和延期范围 |
| 待公司／外部验收 | 需要真实制度、服务器、服务或平台配置 | 固定原编号、具体缺少资料和后续验收步骤 |
| 已移出范围 | 用户明确取消的当前要求 | 保留原编号和范围依据，不记成测试通过 |

`app/scripts/development_wave.py`以每轮代码计划约束全部有效编号和已确认代码任务，封存所有原始源码，并阻止未完成代码任务或封存后变化的源码进入阶段检查。增量168的[测试前计划](168-batch-code-plan.json)与[开发记录](168-batch-functional-closure.md)是首个完整实例。计划中的测试状态描述封存当时；实际检查以追加回执为准。

当前范围仍遵守[范围修订99](../delivery/04-current-scope-and-acceptance.md)。不重新引入真机、网络性能／实网120GB、历史迁移／容灾或AI费用控制；不使用Docker、WSL、虚拟机或模拟器。每次页面检查结束关闭全部自建且不用的页面、上下文、浏览器及临时服务，保留用户原有进程。真实配置已由用户说明后续提供，不重复索取。
