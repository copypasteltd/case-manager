# 唯一实际费用、分摊、冲销与发生支出报表

日期：2026-10-24；范围：迁移0036、Go费用服务、Web台账与发生支出视图。依据[费用需求](../requirements/05-finance-and-subscriptions.md)、[OA需求](../requirements/04-workflows-and-oa.md)和[采购履行](34-purchase-orders-acceptance-and-returns.md)。全平台及四端首发目标继续保留。

## 1. 经济事项与事实边界

一次真实经济事项保留一个 `actual_cost_entries.id`，采购、报销及合同使用 `cost_links` 关联此ID。关联不复制金额，不生成付款，不把报销改为已结算。审批通过、订单承诺、验收、费用发生和现金支付各有独立证据。

本次提供不完整草稿、不可变修订、固定供应方/凭证、项目与公司分摊、人工确认、全额冲销、准确业务关联及原币发生支出报表。当前关联类型为批准采购、批准报销、生效应付合同。

付款/退款及分配、员工报销结算的后续实施见[资金与结算协议](36-payments-refunds-and-settlement.md)。继续实现采购差异和完成条件、订阅/预测账期、统一汇率口径、供应方/负责人报表筛选、异步导出及预算控制。Taro费用界面和Android真机仍待完成。本文不代表完整财务闭环或会计总账已交付。

## 2. 来源标识与身份

同组织永久唯一 `(org_id, source_key)`，不随幂等缓存过期释放。格式为小写命名空间、冒号和稳定业务标识；例如 `manual:UUID`。同一事项由采购和报销进入时应先查找原费用再关联。系统不会仅凭相近标题自动合并不同事项。

Web为人工新事项生成稳定UUID，同一次表单保存/重试继续使用它；可靠外部来源可填写其固定标识。来源键、创建人、所属项目、分类及记录类型创建后不可更改。来源键不能代替数据库费用ID，所有关联仍固定准确ID。

命名空间 `reversal:` 由服务器保留，人工创建拒绝使用。冲销键为 `reversal:{original_cost_id}`，同时通过唯一反向关系阻止重复冲销。

## 3. 内容与准确金额

草稿只要求有意义的标题及登记原因，其余可未知：日期、币种、金额、供应方允许null，类别可空，分摊和凭证为数组。未知不写成零、不编造日期和供应方。数组必须明确为 `[]`，不能用null替代。

确认要求：非未来的香港业务发生日；已配置币种；正金额；类别；固定供应方修订；至少一个当前可用、权限允许且通过安全检查或正式例外的凭证版本；正数分摊且合计严格等于费用金额。

金额、分摊使用十进制字符串和 `numeric(20,6)`，以已配置币种精度校验，不以JavaScript浮点计算合计。HKD/USD/CNY/EUR/GBP当前为2位，JPY为0位；数据库币种目录为实际依据。费用凭证最多20个，分摊最多100行，不同项目和公司范围各最多一行。

基础币种/汇率制度未确定，响应 `base_currency/base_amount` 为null，报表 `fx_coverage=unconfigured`。按原币分别展示；不以1:1、0或临时市场报价编造确认汇率。未来接入汇率须固定来源、日期、舍入和确认快照。

## 4. 所属项目与分摊权限

所属项目用于业务管理及对象授权；分摊项目用于归集真实成本。所属项目与分摊可以不同，创建后所属范围固定。公司分摊以 `project_id=null` 表达。

读取费用除了自身 `cost.read`，还须当前能读取全部分摊项目；任一项目不可读则整笔不可读，避免其他项目金额通过总额泄露。历史修订还检查其历史分摊范围，不能因当前修订移除敏感项目而扩大历史读取。

所属及全部分摊项目按排序锁定。写入核对项目可写、分类不降低；closing/archived/cancelled拒绝新增、修订、确认、冲销及关联。SQL约束独立核对所属和分摊项目的分类，不仅依赖界面选项。

台账 `project_id/company_only` 按分摊范围筛选，以支持报表钻取；列表每条仍显示费用完整金额，不冒充该项目分摊额。报表在所选范围下只求该分摊金额。所属范围与分摊筛选的语义须在新客户端保持一致。

## 5. 职责与人工确认

迁移及组织初始化建立以下角色，均不自动绑定用户：

| 角色 | 能力 | MFA |
| --- | --- | --- |
| cost_recorder | cost.read、cost.record：登记/修订及关联 | 草稿无需近期MFA，关联需近期MFA |
| cost_confirmer | cost.read、cost.confirm | 需要 |
| cost_reverser | cost.read、cost.reverse | 需要 |
| cost_reader | cost.read | 按组织制度 |
| finance_reporter | cost.read、report.read | 按组织制度 |

确认、冲销及新增关联要求当前人工有效会话与数据库记录的最近10分钟MFA。Agent运行身份不获人工财务事实写入权。系统管理员不自动取得业务读取/写入；费用权限也不自动授予往来方、附件和来源单据的读取权。

敏感命令在幂等命中前再次核对当前权限及实际会话MFA；不能拿旧成功结果绕过撤权。数据库事件插入触发器还检查会话归属、撤销/过期、用户状态与授权版本、准确MFA时间及新鲜度，拒绝伪造时间或他人会话。

Web身份验证只刷新证明，不自动提交确认/冲销/关联。员工仍须核对内容并点击相应业务按钮。

## 6. 修订、确认与全额冲销

写命令携带 `expected_version / revision_id / content_hash / reason`，修订还提交完整费用内容。冲突拒绝覆盖，保留填写内容，关闭后读取最新业务再决定。幂等键绑定准确请求，不因网络重试制造另一笔经济事项。

草稿修订创建新 `cost_revisions`，保留前序、内容摘要、作者和原因。确认只改变核实状态及头版本，必须仍引用准确当前修订。已确认费用不能原位更改金额、日期、分摊、凭证或供应方。

全额更正时，同一事务把原费用标为reversed，新增独立confirmed/reversal费用及其修订、分摊、文件引用和事件。新记录继承原费用的完整事实，只有发生日使用明确冲销生效日；不得早于原发生日或晚于香港当前日。原记录与冲销行都不能再次冲销。

原费用继续按原日期贡献正发生额，冲销按其日期贡献负额。例：1月发生1,000，2月冲销1,000并登记正确费用1,200，则1月1,000、2月200、累计1,200。不能同时删除原历史额并再扣冲销。

冲销是纠错事实，实际退款另行登记。未来付款分配模块接入时，必须明确检查已有结算关系，不能据本次费用冲销推断资金已退回。

## 7. 准确采购、报销及合同关联

只允许已确认且未冲销的原费用新增关联。固定来源单据、准确修订和关系：采购 `incurred_for`、报销 `reimbursed_via`、合同 `contractual_basis`。同费用/来源只关联一次，最多100项。

采购/报销须准确已批准修订，合同须准确批准且生效的应付修订；应收合同不能计作费用来源。须当前可读、币种一致、来源分类不高于费用，来源项目在费用所属或分摊范围内。

迁移0040之后，合同即使已完成／终止，也可继续按其准确批准且曾生效的应付修订关联真实后续费用；不重开法律阶段、不改写旧结束事实。当前规则与证据见[完成／终止协议](39-contract-completion-and-termination.md)。

每项来源已关联的有效confirmed原费用总额不得超过其准确批准金额。业务层先锁来源，再锁费用头；SQL插入触发器也锁来源，延期约束复核准确批准修订、金额、分类和范围。并发各300关联批准500时最多一个成功。

冲销原费用后，其有效占用释放；历史关联仍保存，不能靠删除关联改写事实。当前关联保存完整费用金额，未提供逐来源部分金额分配；需要超批准金额或差异业务时明确拒绝，继续开发制度和审批，不设置未经确认的默认容差。

来源标题按当前来源权限再投影，失权只保留固定关联标识与“当前不可查阅”，无额外入口。重放响应也重新投影当前权限，旧缓存不恢复已失权名称/文件。

## 8. 数据与数据库约束

| 表 | 作用 | 可变性 |
| --- | --- | --- |
| actual_cost_entries | 永久来源、固定管理范围、状态、当前修订及头版本 | 受限推进，禁止删除 |
| cost_revisions | 固定内容、摘要、前序、作者及原因 | 仅新增 |
| cost_allocations | 准确修订的有序公司/项目金额 | 仅新增 |
| cost_revision_files | 固定凭证版本 | 仅新增 |
| cost_links | 准确业务来源关系 | 仅新增 |
| cost_events | 每次头版本对应的不可变人工事件/MFA证明 | 仅新增 |

延期约束核对完整连续事件、头/最新修订一致、修订前序完整、事件状态转换、分摊与payload一致、文件列表一致、币种精度、确认完整性及冲销继承。当前头不能指向孤立修订，不能仅改状态绕开事件。

文件引用自动登记为 `cost_revision`，保留评估响应Schema同时支持该类别。修订/冲销后旧凭证仍受引用保护。应用数据库角色没有历史事实UPDATE/DELETE权限，数据库触发器另阻止修改；没有给应用授予迁移DDL能力。

费用头、修订、事件、审计、outbox及幂等回执同事务提交。审计失败全部回滚，原幂等键可在问题修复后重试。锁顺序与项目关闭/授权更新协调，禁止先修改成本再异步补审计。

## 9. 实际接口

以下11项操作已进入服务端，不把其他规划接口视为已可用：

| 方法 | 路径（/v1前缀） | 内容 |
| --- | --- | --- |
| GET / POST | /costs | 有界台账 / 登记草稿 |
| GET / PATCH | /costs/{id} | 当前可见事实 / 草稿完整修订 |
| POST | /costs/{id}/confirm | 确认准确当前费用 |
| POST | /costs/{id}/reverse | 全额冲销，另填effective_on |
| POST | /costs/{id}/links | 关联准确已批准业务 |
| GET | /costs/{id}/revisions | 有界历史修订 |
| GET | /costs/{id}/revisions/{revision} | 准确历史内容 |
| GET | /costs/{id}/events | 有界登记/确认/关联/冲销记录 |
| GET | /reports/expenses | 发生支出统计，kind=incurred |

台账支持标题/来源搜索、draft/confirmed/reversed及incurred组合状态、原币、类别、日期半开区间、分摊项目/公司；20条默认、100条上限。分页绑定身份、授权版本、渠道、运行及全部筛选，不接受换对象/筛选复用旧游标。

契约为[同源OpenAPI](openapi.json)，通过app/scripts生成后端嵌入Schema与共享TypeScript。费用阶段全域目录共181路径、235操作、350 Schema；后续资金阶段已扩展，当前计数见[资金协议](36-payments-refunds-and-settlement.md)。其中仍包含其他模块尚未实现的规划操作；不能由总数推算完整平台覆盖。

## 10. 报表口径与权限

`GET /reports/expenses?kind=incurred` 返回半开日期范围、Asia/Hong_Kong、as_of、原币分列的expense_amount/reversal_amount/net_amount/entry_count、未确认条数及未配置汇率状态。空日期默认当前香港月份；显式范围限1至366天，不接受只有一个边界。

报表在同一REPEATABLE READ只读快照中核对实际组织/用户授权版本、每笔费用及全部分摊项目读取权限和report.read，然后计算金额、未确认数和统计时间。关联表不进入聚合join，一费三关联仍只贡献一次。

原费用confirmed/reversed均计正发生额，reversal计负额。项目/公司筛选只取该分摊行，不把整笔费用归给每个项目。不同币种不相加，负净额如实展示。未确认条数仅包括期间内已有发生日且符合分摊筛选的草稿，未填日期草稿由台账另查。

`expected/amortized`等未接入口径返回明确409，不返回空成功报表。现金口径现已独立接入 `/reports/cash`，不能把发生支出结果改标签充当现金。当前未提供供应方/负责人筛选及导出，不用客户端拼接模拟授权汇总。

## 11. 页面、可访问性与视觉

Web提供实际费用列表/详情、草稿编辑、准确历史、追加事件、业务依据选择及月度发生支出页。来源从有权可读且符合币种/批准状态的真实列表选择，固定当前修订；不让员工手填来源UUID冒充核对。

沿用[官网风格体系](../design/README.md)：暖白/深色背景、墨色主要按钮、蓝色链接/焦点、细分割线、克制卡片和明确数字层级。金额保持准确字符串；冲销行用类型标签及负号说明，不只靠颜色。空白草稿、读取错误、失权、冲突和未配置口径均有具体文案。

表单分摊可在窄屏换行；修订历史使用明确选择的准确版本。嵌套资料选择器关闭后焦点回到仍打开的父模态。MFA刷新不替代人工确认，错误不自动清空输入，不自动重放写命令。
