**Verdict:** partial · confidence: high for the inspected source paths. One actionable code divergence, F-G02-01, requires independent refutation before implementation. This is a source review, not test execution or GAP-02 formal acceptance.

### F-G02-01 — Contract performance nodes cannot associate their task/purchase/claim work

**Normative source:** [original §5.1, line101](../../01-requirements-and-scope.md#L101) explicitly says “履约节点关联任务、采购/报销和费用记录”; [OA-07](../../requirements/04-workflows-and-oa.md#L27) also asks for contract/purchase association. This is an existing first-release scope item, not a newly invented feature or an unanswered company policy.

**What is present:** [ContractMilestone](../../../app/backend/internal/contracts/models.go#L130) stores only its fixed contract/active revision/plan identity, title/direction/currency/amount/due date/conditions. [ContractFinanceLink](../../../app/backend/internal/finance/contract_finance_models.go#L14) supports exact financial source attribution. [LinkContractFinance](../../../app/backend/internal/finance/contract_finance_mutations.go#L188) rejects all source kinds except `cost`, `cash`, `refund`; its ordinary branch resolves an actual cost or actual payment. Human financial review can attach exact files and attest conditions; it cannot select a task/purchase/claim identity.

**What is absent in the inspected source surface:** no ordinary persistent association, create/revoke/history API or four-client selector binds an active contract node to a task or a purchase/claim record. [Task.milestone_id](../../../app/backend/internal/project/models.go#L54) is a separate project milestone: [migration0002](../../../app/backend/migrations/0002_projects_knowledge.sql#L54) constrains it to `milestones(org_id,project_id,id)`, not `contract_milestones`. Spend [Create/Content](../../../app/backend/internal/spend/models.go#L43) has no performance-node identity. The contract milestone route only edits the ordinary draft's payment schedule or reads activated financial nodes ([routes](../../../app/backend/internal/httpapi/contracts.go#L48)); financial routes only expose attribution/release/review ([routes](../../../app/backend/internal/httpapi/contract_finance.go#L23)).

**Static trigger, not an executed test:** after creating a valid project task and activating a scheduled contract, a human cannot choose “this task fulfils this contract node”; there is no supported command or stored link to submit. Choosing the task in a finance entry cannot work: the `kind` allowlist rejects `task`, while a forged financial kind resolves the identifier as an actual cost/payment. A purchase/claim before any expense likewise cannot become a node reference. Free text or a shared project is not an object relation that can be traversed, rechecked or withdrawn.

**Counter-evidence retained:** one confirmed expense may already link the contract and the approved purchase/claim through `cost_links`. The finding does **not** claim that shared-expense reuse is missing, that money should be auto-created, or that the task's completion should auto-complete legal or financial obligations. It is limited to the stated performance-node relation and its ordinary UI/API/history. A correct repair must preserve independent commercial approval, actual expense/cash, human review, current visibility and original contract-node identity; company policy must not be invented to implement the relation.

### How the verdict was reached

The ordinary contract, purchase and claim journeys have executable implementations and meaningful authorization/state/revision boundaries, so `absent` would be false for GAP-02 as a whole. The explicit performance-node relation remains absent at the model, route and consumer layers, so the full requirement is `partial`. This gap can be implemented without cloud credentials, real bank access or company approval amounts. Independent code/spec refutation remains required before treating the proposed divergence as an accepted batch repair.

### Open questions and acceptance boundary

- Company contract templates, owner/approver assignments, currency/rounding/tax policy, amount thresholds, self-approval and financial exception policy still require human adoption; their missing inputs are not code defects.
- This source review did not execute any native PG case, browser flow, build, production service or real platform/cloud/model acceptance, and does not close GAP-02 or the 23-package register.
- This audit does not assert exhaustive security verification of every financial helper or latest mutable source; GAP-03/other numbered audits own their independent requirements. The paths, searches and the concrete missing surface above are the evidence for this verdict.
