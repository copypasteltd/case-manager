# 项目业务概览与财务关联（增量69）

日期：2026-10-26。推进 GAP-01／PM-03；代码保存在 `app/`，文档保存在 `docs/`。本轮接通 Go／PostgreSQL 概览接口和 Web 项目空间，继续沿用原业务模块的授权与写入协议。

## 1. 功能约束

| 编号 | 实现内容 | 必须保持的行为 |
| --- | --- | --- |
| POV-01 | 一致的项目业务快照 | `GET /v1/projects/{id}/overview` 返回项目ID／版本、快照时间、`scope=readable_records` 与16类记录；事务内校验组织／员工授权版本，并使用同一可重复读快照 |
| POV-02 | 可读记录计数与最近预览 | 每类统计全部当前可读记录及其状态，独立预览最近5项；`has_more` 只比较可读总数与预览长度，不按已加载页数估算总数 |
| POV-03 | 不可读与可读空集分开 | 没有类别读取范围且没有获准单条记录时，返回 `available=false,count=null,states=[],items=[],has_more=false`；不读取隐藏总数，不披露标题，不用零冒充已核实 |
| POV-04 | 稳定业务引用 | 预览保留实际记录ID、版本、可用的准确修订ID与更新时间；任务打开原详情，合同／采购／报销／费用／付款／订阅／文件／日志／服务进入原模块；项目内页签链接可直接访问 |
| POV-05 | 本项目实际发生支出 | 共用发生支出报表的逐笔授权谓词；按当前费用修订的 `cost_allocations` 计算本项目份额，费用与冲销逐币种求和，金额始终使用十进制字符串 |
| POV-06 | 批准预算独立呈现 | 只展示实际已实施且当前 `approved` 的协议1预算ID／修订／币种／金额；提案草稿、仅通过审批的预算、已被取代的修订不进入当前预算金额；明确的零预算保留 |
| POV-07 | 内容与服务读取边界 | 普通日志读者使用已发布修订的标题／ID；文件必须处于有效目录链；服务只展示配置名称与目录状态，健康状态在原服务详情按新鲜度核对 |
| POV-08 | 真实读取与缓存保护 | Web挂载、聚焦及每60秒重新读取，支持手动刷新；读取失败或项目ID不匹配时隐藏旧概览事实，项目读取失败不继续展示缓存项目；viewer及结束项目沿用原只读限制 |

所有数量均是调用者可读范围内的结果，不能用于证明全项目业务已经闭环；完整结项仍使用原结项核查／归档协议。单条授权需要同时满足原角色动作、作用域、分类策略及成员／例外条件，资源例外不自动授予角色动作。

## 2. 聚合范围与筛选

| 类别 | 业务来源与关联 | 概览读取规则 |
| --- | --- | --- |
| 任务／里程碑／风险／问题 | 项目ID直接关联实际业务头 | 逐条执行对应 `.read` 动作；沿用项目分类及实际创建人 |
| 交付 | 实际交付头与当前提交修订 | 按 `deliverable.read` 读取，可读旧协议记录仍保留，不伪装成已完成新协议验收 |
| 变更 | 协议1变更头及准确提案修订 | 同时具备该条 `change.read` 和本项目 `budget.read` |
| 预算修订 | 协议1预算及所属变更 | 本项目 `budget.read`；草稿另外检查该条 `change.read`；预览可包含已批准／取代历史，金额面板只列当前批准基线 |
| 文件 | 目录项目ID、有效文件头及当前文件版本 | `file.read`；文件有效且全部祖先目录有效并可到达根目录；不下载文件或声称原件已存在云端 |
| 知识与日志 | 项目ID及所选内容修订 | `post.read`；未归档；草稿只对作者／获准编辑者开放；其他读者使用已发布修订 |
| 合同／采购／报销 | 同项目、未删除业务头及当前修订 | 逐条使用原 `contract.read`／`purchase.read`／`claim.read`；这里只读取业务头，不提升为财务闭环授权 |
| 实际费用 | 当前费用修订中存在本项目分摊 | 使用 `can_read_cost` 的完整费用范围判断；不通过多条业务链接重复计费 |
| 收付款 | 实际不可变付款分配份额或合同现金归属包含本项目 | 使用 `can_read_payment`；与原付款列表的项目筛选一致，未分配付款草稿不凭头部项目ID冒充已形成现金归属 |
| 订阅 | 项目ID及当前订阅修订 | 使用 `can_read_subscription`；订阅配置／周期预测不直接变成实际发生费用 |
| 服务配置 | 服务配置的项目ID | `service.read`；配置 `active` 不表示服务健康，不复制可能过期的健康投影 |

概览只提供最近5项预览；各业务列表继续采用原游标分页。服务卡片提供实际服务详情链接，现有全局服务列表没有项目筛选时不伪造“本项目全部服务”入口。里程碑、交付、预算等仍进入原项目页签；未新增高级甘特、资源排期或跨项目组合视图。

## 3. 财务口径

发生支出是全期间的本项目实际分摊，仍需原 `report.read` 入口授权，以及每条费用的费用读取和报表读取授权。`expense_amount` 保留费用原额，`reversal_amount` 保留冲销原额，`net_amount=费用原额−冲销原额`，`entry_count` 统计实际记账条目；被冲销原费用与对应冲销都保留，不能直接删掉原费用后再减冲销。草稿单独计数，不进入金额。

不同币种分别返回，不调用汇率、不换算或相加；服务端由 PostgreSQL numeric 聚合并转文本，前端只对字符串分组，不使用 JavaScript Number 转换金额。跨项目费用只计本项目分摊份额；需要读取其他分摊范围而调用者无权时，整条费用继续按原协议隐藏，不通过汇总旁路披露。

预算按其批准期间独立列示，不把全期间发生支出减去期间预算后宣称“剩余预算”。付款、合同、采购／报销批准额度、订阅预测均不是第二份发生支出。本轮不新增现金余额、应收应付自动记账、汇率或税务规则。

## 4. 工程接口与页面

主要代码为 [overview_reads.go](../../app/backend/internal/project/overview_reads.go)、[overview_models.go](../../app/backend/internal/project/overview_models.go)、[project_incurred.go](../../app/backend/internal/finance/project_incurred.go)、[ProjectOverview.tsx](../../app/web/src/ProjectOverview.tsx) 和 [Projects.tsx](../../app/web/src/Projects.tsx)。所有表名、字段及读取动作是固定服务端片段，客户端不能指定SQL。事务锁定授权版本，不写入业务事实或新增权限。

新增一个只读端点及对应版本化契约，OpenAPI生成源为 [build_openapi.py](../../app/scripts/build_openapi.py)。无新增数据库迁移、依赖包或模型工具；既有64项迁移及实例的数据目录保持原归属。开发API在精确核验所属进程后更新，以加载新端点；不启动外部存储、模型、TG或生产服务。

Web使用现有官网风格令牌及浅／深色主题；16类卡片按宽度三／二／单列布局，财务表格限制在内部横向滚动。任务入口和页签使用URL参数，项目概览与原业务模块之间可导航。读取失败时不把已缓存数据当成当前授权事实。

## 5. 使用和授权

1. 登录本地开发前端，在“项目”打开可访问项目，再选择“项目概览”；可直接使用 `/projects/{项目ID}?tab=overview`。
2. 按卡片查看当前可读总数和最近记录；任务卡打开原任务详情，项目内卡片切到原页签，其他模块进入对应业务记录。需要后续记录时进入原模块列表继续分页。
3. 财务卡片需要原发生支出报表权限，每条费用仍需通过完整分摊范围校验。没有权限时保持未核实，不能用新增概览端点取得其他角色权限；角色配置沿用原管理员流程，不自动给全员绑定财务角色。
4. 使用“刷新概览”核对新的香港时间快照。读取失败先恢复读取，不据旧缓存作审批、归档或付款判断；需结项时进入“结项与归档”执行原完整核查。
