# 账号安全、密码恢复与设备会话

本增量落实 GAP-06，并补充 GAP-18 的账号入口。对应 IAM-01—04、WP-02。实现位于 `app/`，本说明及验证材料位于 `docs/`。完整平台目标和四端首发要求继续保留。

## 1. 已实现的用户流程

| 编号 | 使用人及入口 | 实际行为 |
| --- | --- | --- |
| SEC-01 | Web“账号安全”；移动端“我的” | 查询本人设备会话，区分当前设备、有效、到期和撤销记录，支持分页与刷新 |
| SEC-02 | 设备列表的撤销入口 | 撤销指定设备的整个刷新会话；其他设备继续工作；退出当前设备后返回登录 |
| SEC-03 | 两端“修改密码” | 核验当前密码；已配置两步验证的账号需最近10分钟内完成验证；保存后所有设备退出 |
| SEC-04 | Web“成员与授权 → 重置密码” | 具有组织级 `user.password_reset` 动作的管理员，经最近两步验证及成员版本检查，签发15分钟单用凭证 |
| SEC-05 | Web／移动端登录页“忘记密码” | 粘贴管理员交付的凭证、填写并确认新密码；成功后使用新密码重新登录 |
| SEC-06 | 两步验证确认 | 已登录的两端可重新输入验证器验证码；重置与修改密码均保留已配置验证器和剩余恢复码 |

密码重置不提供公开账号检索接口，不对任意填写的账号返回存在性信息。凭证经管理员核实员工身份后交付，系统不会声称已发邮件或群消息。邀请激活和密码重置为独立流程。

## 2. 设备会话的定义

同一次登录产生一个 `family_id`，刷新后创建的新访问／刷新凭证继续属于该会话。列表以会话为单位，不把每次凭证轮转显示为新设备。

列表返回平台、首次登录、最近凭证刷新、访问凭证到期、刷新凭证到期、撤销时间、状态和是否当前设备。当前只记录这些事实；“最近刷新”不代表员工最近一次活跃时间。平台名称取实际会话类型，不推测设备型号或地理位置。

只查询当前组织与当前用户。签名游标绑定组织、员工和身份安全版本；其他员工无法复用游标。历史记录保留，过期但未撤销的刷新会话显示到期；访问凭证暂时到期但刷新仍有效时，设备会话仍为有效。

撤销操作在同一事务中锁定组织、核验当前交互会话、锁定目标会话，并撤销该会话全部凭证。刷新、修改密码、签发或消费恢复凭证遵循一致的锁顺序。刷新先提交时，新凭证仍被撤销；撤销先提交时，刷新被拒绝。不同员工及不存在的设备统一返回不存在。

交互账号接口拒绝秘书运行身份和 Telegram 渠道。会话管理权限不经秘书工具扩大。

## 3. 密码修改与恢复约束

### 3.1 本人修改

需要有效交互会话与当前密码。新密码沿用现有 Argon2id 实现：64 MiB、3轮、并行度2；至少12个字符，UTF-8最长1024字节，新密码不能等于当前密码。已配置两步验证时，核验数据库中当前会话的最近验证时间。

成功事务更新密码摘要、增加用户 `auth_version` 与业务版本、撤销全部设备、消费旧登录挑战、撤销未使用恢复凭证，并写入审计与 Outbox。旧访问凭证立即被鉴权拒绝，旧刷新凭证不能重新换取有效会话。其他员工的身份版本不被连带修改。

错误的当前密码返回 `CURRENT_PASSWORD_INVALID`，保留本机登录。网络中断或结果未确认时不把页面状态当成功依据，应使用新密码重新登录核对。密码表单不保存到业务草稿或通用浏览器存储。

### 3.2 管理员签发

迁移0053为系统管理员增加明确的 `user.password_reset` 动作。签发仍要求当前有效交互会话、最近10分钟内两步验证、组织级动作和目标用户的准确业务版本；受邀或已停用账号不能签发。

每名员工同时最多一份未使用、未撤销的凭证。重新签发会撤销旧凭证，包括已到期但仍占待用记录的凭证。签发本身不修改密码，也不代替员工登录。

凭证采用独立HMAC域生成，绑定组织、随机重置ID、用户、身份版本与到期时间；数据库仅保存摘要。幂等回执不保存明文凭证，响应在命令提交后再次检查当前权限及凭证有效状态，再向签发人展示；过期、使用或替代后的旧回执不会重新展示可用凭证。

### 3.3 单用消费

公开消费接口只接受恢复凭证与新密码。检查凭证未使用、未撤销、未到期，目标仍有效且身份版本一致；同时复核签发人仍有效、身份版本未变，并仍拥有有效组织级重置动作。签发人改密或撤权后，其未用凭证不能继续消费。

验证与消费在组织排他锁下完成，两个并发消费仅有一个成功。消费后执行与本人改密相同的身份失效动作，同时标记本凭证已使用。已设置的MFA继续生效；重置成功不会自动登录，也不会授予业务角色。

非法、过期、被替代、已用、停用或版本失效凭证统一返回 `PASSWORD_RESET_INVALID`，不暴露具体账号状态。按来源IP和凭证摘要限速，密码修改按组织／员工限速。无效消费写入独立拒绝审计，不随失败事务回滚。

## 4. API 契约

准确字段见[OpenAPI](openapi.json)和生成的类型。新增5条路径、5项操作；当前共244条路径、307项操作、522个Schema。

| 方法与路径 | 输入及权限 | 成功结果 |
| --- | --- | --- |
| `GET /v1/me/sessions` | 有效交互会话；`cursor`、`limit` | `DeviceSession`分页 |
| `POST /v1/me/sessions/{id}/revoke` | 本人会话ID、原因、幂等标识；`id`为刷新会话ID | 会话ID、撤销时间 |
| `POST /v1/me/password` | 当前密码、新密码、幂等标识；配置MFA时需近期验证 | `changed=true`，所有设备失效 |
| `POST /v1/users/{id}/password-resets` | 目标版本、原因、幂等标识；管理员动作与近期MFA | 重置ID、用户ID、到期时间、仍有效时的凭证 |
| `POST /v1/auth/password/reset` | 单用凭证、新密码；不要求登录 | `changed=true`，不返回登录凭证 |

Cookie写操作继续检查Origin及CSRF；Bearer接口保留设备渠道限制。本人改密和当前Web会话撤销成功后，响应清除会话、刷新及CSRF三种Cookie。移动端仅在确认成功后清除内存凭证；旧请求晚到不能清除后续新登录。

## 5. 数据、审计与权限

新增 `password_resets`，保存组织／目标／签发人、双方身份版本、凭证摘要、原因、有效期及消费／撤销时间；复合外键限制同组织，部分唯一索引限制每名员工只有一份待用凭证。新增设备会话历史索引。

应用账号可读、插入和更新恢复凭证状态，无删除权限。签发、本人改密、设备撤销使用现有事务命令框架，将审计、Outbox及幂等回执一并提交。恢复消费单独提交安全审计与Outbox：审计主体为空，渠道为 `password_reset`，明确这是持有恢复凭证的操作，不伪称已登录员工或管理员代替执行。

事件包括 `auth.session_revoked`、`auth.password_changed`、`auth.password_reset_issued`、`auth.password_reset_completed`。事件／回执不含密码或明文凭证；恢复凭证仅出现在授权签发响应中。业务安全日志继续受既有只追加约束。

改密的幂等请求指纹先使用独立域HMAC保护，再进入通用命令框架；相关密钥继续位于数据库外的服务器配置。数据库集成断言同时核对回执无密码和请求摘要经过密钥保护。

## 6. 验证与运行

验证方法、实际数量及来源摘要见[本增量验证记录](../quality/evidence/account-security/verification.md)。原生后端回归覆盖并发刷新与撤销、游标归属、凭证重放／替代／过期、成员与签发人失效、MFA保留、密码变更失效、审计不泄密及交互身份边界。

Web与Taro H5操作真实隔离PostgreSQL和Go API，覆盖页面到事务结果；两套小程序完成编译。验证结束关闭所属浏览器、上下文、临时服务并删除隔离库及私有夹具。全程使用原生Windows环境，未调用Docker、WSL、虚拟机或模拟器。

## 7. 验收边界与后续

本地代码闭环不能替代微信／抖音真机、Android原生会话及正式发布验收。人工核实身份与凭证交付需要公司明确责任人及渠道；建议正式启用前验证备用管理员账号。唯一管理员已退出且忘记密码时，当前方案不能自行签发凭证；若同时丢失验证器及全部恢复码，也不能仅凭重置密码绕过MFA。独立恢复渠道及受控运维恢复机制仍须设计与验收。

GAP-06保留上述正式使用边界，GAP-18继续补齐移动业务。真实秘书运行、技能发布、TG、Android、大文件／双云、生产监控、部署与恢复等继续按[28项编号清单](../delivery/03-goal-gap-assessment.md)推进。
