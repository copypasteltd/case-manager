# 服务事件摘要与固定来源

本增量将服务状态模块接入秘书执行器，推进 GAP-12、GAP-13、GAP-15。提供 `incident-summary` 的实际只读工具及 Web / Taro 服务资料选择、历史证据回看；TG `/incident` 可进入同一持久队列。源码包保持 draft，开发环境不安装生产执行配置，不调用真实模型或发送 TG 消息。

## 员工使用链路

1. 在项目会话选择“服务状态资料”，核对共同可阅读的服务说明，加入准确资料引用。
2. 选择已安装的事件摘要执行配置并发送请求。没有有效配置时，界面继续显示真实不可用状态。
3. 执行器通过 `search_resources` 查找获授权的准确服务，通过 `read_service_summary` 读取状态证据。
4. 正式任务结果引用 `service` + `service_id` + 快照 `version_id`。消息中的“查看固定状态快照”重新核对当前共同权限后展示原始记录。
5. TG 指定话题收到 `/incident` 时，沿用绑定身份、渠道版本、请求 TTL、执行配置和容量检查，创建隔离的渠道会话与任务；结果保存在门户。

不需要新建移动端公开页面。本增量沿用现有秘书页面；微信、抖音入口共用 Taro 源码。Android 原生签名包、大文件真机上传及真实平台审核仍按原有上线门槛验收。

## 工具协议

`read_service_summary` 接受单一 JSON 对象：

```json
{"service_id":"准确服务UUID"}
```

或明确指定成对的 RFC3339 `from` / `to`。缺省读取最近 24 小时，最多 31 天，结束时间不得晚于数据库读取时间。执行准备上下文包含服务端 `server_time`，模型不得使用客户端时间猜测边界。

工具输出沿用现有回执格式：`status=succeeded`、`committed=false`、空业务写入引用、准确 `source_refs` 和 `content`。只读成功不代表修复、配置变更或发送通知。

`content` 包含：

| 字段 | 含义 |
| --- | --- |
| `report_id` | 固定快照 UUID，作为来源 `version_id` |
| `service_id` / `configuration_version` | 准确服务及读取时配置版本 |
| `captured_at` / `recheck_at` | 实际数据库评估时间及原状态建议复查时间 |
| `window` | 本次记录查询时间窗 |
| `state_as_of_capture` | 读取时状态，包含原始观测状态和维护覆盖 |
| `sources` | 监控源名称、准确修订、状态与投影时间 |
| `observations` | 签名验收后的观测事实、接收时间及载荷摘要 |
| `maintenance` | 时间窗相交的维护与取消事实 |
| `incidents` | 共同可读事件及时间窗内人工处理记录 |
| `truncated` / `updates_truncated` | 明确的条数或文本截断标志 |
| `historical_snapshot` / `untrusted_data` | 历史证据和不可信业务资料标记 |

当前状态以 `captured_at` 计算；观测按 **接收时间** 筛选。本工具不重建历史窗末状态。事件可包含窗前开始、读取时尚未解决的旧事件。维护覆盖不会抹掉原始 down / degraded / unknown 状态。

## 权限与一致性

- 复用现有 `service.read`、项目范围、分类、AI 处理政策、渠道限制及会话全体成员共同权限。
- 项目会话只读取该项目的服务；公司会话只读取公司级服务。服务列表中的可见选项仍须经过独立上下文核验。
- 跨服务事件逐一检查关联服务。任何服务不在共同范围内时，整条事件不返回；不泄露标题、正文或私密关联服务的计数。
- 快照只允许原会话中、原受众集合内的当前成员读取，且重新检查所有关联服务的当前权限。快照不是额外授权。
- 使用现有组织锁固定业务配置、维护及事件；对监控源按 ID 取得共享锁后再读取评估时间，阻止签名采集在本次捕获中途更新投影。
- 后续新观测不会改写快照，也不会将历史摘要更新成绿色。再次获取最新状态必须产生新的读取回执。
- 服务配置来源和同一服务的多个固定快照以不同版本标识进入证据集合；同一快照 ID 对应的证据若变化，仍拒绝执行。

## 内容与容量限制

| 范围 | 单次上限 |
| --- | --- |
| 主服务监控源 | 100 个；超过则明确拒绝 |
| 展示监控源 | 前 20 个，状态聚合仍覆盖全部源 |
| 观测 / 维护 | 各 20 条，降序读取，超出标记截断 |
| 事件候选 / 展示事件 | 最多检查 100 条候选、展示 10 条共同授权事件 |
| 每个事件的窗内处理记录 | 10 条，超出标记截断 |
| 说明、原因、处理正文 | 每项 500 字，超出标记文本截断 |
| 完整快照 JSON | 90,000 字节；超过明确要求缩小范围 |
| 当前任务来源总数 | 沿用现有最多 20 个固定来源限制 |

不向模型提供采集公钥、外部监控标识、原始签名载荷或签名。服务说明、事件文字均作为不可信数据，不提供 shell、SSH、网络探测或修复能力。

## 数据结构与执行边界

迁移 `0061_agent_service_reports.sql`：

- 新增 append-only `agent_service_reports`，绑定组织、任务、会话、发起人、服务、原受众和关联服务。
- 保存准确标题、配置版本、完整文本及文档摘要，防止 JSONB 重排改变历史来源正文。
- 插入须绑定正在执行的 `incident-summary` 任务；延迟约束要求同一事务中存在匹配内容、快照 ID、摘要与版本的真实工具回执。
- 应用角色仅有 SELECT / INSERT；UPDATE / DELETE 同时受数据库触发器阻止。
- 扩展只读工具回执枚举和 TG 事件配置约束，不修改历史迁移。

Go、MCP、SDK 的事件摘要工具集合一致：`read_resource`、`search_resources`、`inspect_operation`、`read_service_summary`。TG 事件执行沿用相同四项只读能力。其他写入技能仍不进入 TG 范围。部署检查展示精确工具和配置摘要，draft 包不会因此变为已发布。

## 验证与上线边界

验证记录位于[本增量证据](../quality/evidence/service-summary/verification.md)，包含原生数据库、运行时、Web、移动端构建及浏览器清理结果。

工具回执证明实际读取及准确来源，不对自然语言结论逐句作语义判定；摘要质量和覆盖范围仍须使用真实样本进行模型评测。

上线仍需提供真实服务器与云账号、模型和运行时发布配置，完成外部隔离证明、真实采集器与 TG 回调联调。真实模型、真实 TG 收发、跨云备份和 120 GB 上传未由本增量的本地验证替代。
