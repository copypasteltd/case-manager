# 文件元数据、目录与名称空间实施约束

日期：2026-10-23。关联 [文件需求](../requirements/06-files-and-search.md)、[存储协议](03-storage-protocol.md)、[权限需求](../requirements/02-identity-and-permissions.md)、[实施台账](../delivery/02-implementation-ledger.md)。

本文记录当前代码的确定性规则及完成边界；它不替代120GB直传、内容扫描、双云复制与恢复验收。

## 1. 对象与权限

- 文件、目录、内容版本分别保留稳定ID。文件改名或同范围移动只更新文件元数据版本；不重写内容版本、原文件名、摘要、对象Key。
- 新建文件和目录必须记录真实创建人；数据库拒绝更改创建人。历史创建人无法可靠追溯时保留空值，不按当前负责人补造“本人”权限。
- 每次读取、列表、历史和写入使用同一授权策略。列表在分页前过滤ACL及AI使用限制，分页凭证绑定用户、授权版本、渠道和运行；文件读取同时检查完整祖先链处于有效状态。
- 项目只读角色不能通过组织角色获得文件写入。项目进入结项核查、归档或取消后，普通目录/文件变更被阻止。
- 公司顶层目录使用公司内部分类；项目目录在项目创建时生成的资料根目录下新增。新建严格受限目录需要对象授权流程，当前入口明确拒绝，不能创建后自动扩大权限。

## 2. 名称比较与数据库互斥

当前实现候选为“保留显示名称；NFKC规范化、Unicode完整大小写折叠、再次NFKC得到比较键”。这是工程设计值，仍需按P0真实样本评审；不把候选规则当作用户已确认政策。

例如“合同Ａ.PDF”和“合同a.pdf”、“Résumé.PDF”和使用组合重音的等价写法，共用比较键。拒绝路径分隔符、控制/隐藏格式字符、平台禁用字符、点目录、尾随点/空白和CON/COM1等平台保留名。显示名称不参与真实云对象Key构造。

`storage_entries`为跨文件/目录共享的名称空间。同一父目录中，活动文件与活动子目录也不能同名。数据库唯一约束处理并发竞争；文件表和目录表各自的唯一索引不能替代这一约束。应用角色不能直接修改名称预留表；受限的触发器随元数据事务同步预留。

现有记录的比较键不由SQL猜测Unicode策略或静默改名。已有跨类型冲突会阻止迁移，应先盘点并产生明确处置记录；后续真实2TB导入必须输出规范化冲突清单。

## 3. 创建、移动、改名与锁

命令先锁组织并核对授权版本，再进入项目锁；公司资料使用组织内的事务咨询锁。所有未来上传正式提交、保留约束变更和清理任务也必须遵循相同锁顺序，避免绕过目录状态与名称互斥。

普通移动限制为相同项目和相同分类。跨项目或分类差异返回需要权限影响计划；提交未接入的计划参数会明确拒绝，不忽略计划执行普通移动。项目资料根目录不能改挂到其他目录；递归检查禁止移动到自身或后代。

写入要求准确的元数据版本和操作原因。业务行、名称预留、幂等结果、审计与outbox在同一事务提交；任一失败全部回滚。网络重试复用相同请求内容的幂等键；重放前重新鉴权。过期版本不自动覆盖。

## 4. 版本与副本呈现

内容版本包含序号、基础版、原文件名、十进制字符串字节数、SHA-256、媒体类型、来源、作者、执行者、时间、扫描和可用状态。历史未知原文件名显示未提供，不拿后来重命名的名称填充。

扫描的数据库隔离状态映射为接口“已阻断”；无法扫描与扫描通过分开。授权放行必须有放行引用。元数据查询不构成下载许可；[下载授权](17-download-authorization-and-streaming.md)重新核查固定版本、校验副本、扫描/可用性、分类与渠道。

每个OSS/R2记录独立返回提供商、状态、实际摘要、校验时间、更新时间和受控状态码。桶、真实对象Key、云源标识及原始云错误不通过普通元数据接口返回。

无副本记录时汇总为空；仅有一端不能汇总为双云已校验。两端均有匹配内容版本权威摘要的记录和校验时间，才显示已校验。状态标签与摘要证据冲突时显示失败；数据库也拒绝缺少摘要/时间的已校验记录。

## 5. 回收站与恢复

软删除只变更逻辑状态，释放活动名称预留，保留所有内容版本和副本记录。有法务保留或有效保留约束时拒绝移入回收站。恢复检查准确元数据版本、原目录有效、项目可写和名称无冲突；名称占用时整个恢复回滚。

“从回收站恢复”与“恢复历史内容”是两个操作。前者保留当前内容版本；后者必须生成新的不可变对象和内容版本，禁止回拨current指针。历史内容恢复已使用[独立异步任务](19-history-restoration.md)，复制/校验完成后由用户明确提交；旧同步入口的历史模式返回409及任务入口说明。普通软删除不触发双云硬删除。

## 6. 当前接口与验证边界

已实现目录列表/详情/创建/移动、文件列表/详情/版本记录/移动/软删除/回收站恢复。精确输入/输出见[OpenAPI](openapi.json)；尚未实现的机器契约路由不等于可调用功能。

`GET /v1/files/{id}/versions/{version}` 读取属于该组织及逻辑文件的准确历史元数据，逐次检查当前 file.read、项目成员与祖先目录权限；未知、错文件或无权版本不转而返回 current。它不受列表第一页20项限制，也不随文件后来改名替换原文件名。副本沿用当前摘要/时间证据投影，不返回桶、Key、云源或原始错误，更不构成原件下载许可。4个新增原生PG叶场景覆盖22版跨页历史、改名、错绑/未知/非法ID、无效副本证据及成员失权；固定正文导航的移动检查另见[客户端实施](31-mobile-client-foundation.md)。

原生PG隔离测试覆盖并发Unicode重名、跨文件/目录冲突、应用角色权限、创建人不可变、防环/项目边界、乐观锁与幂等、缺失/冲突副本证据、原文件名保留、回收站冲突、只读/归档、审计失败回滚以及本人范围。

浏览器脚本使用真实接口创建目录；文件详情用明确标记的本地元数据夹具。夹具不创建云对象，主端标记缺失、扫描标记无法扫描，副本为排队/失败。显示120GB数值只检查界面与契约精度，不是120GB传输测试。详情见[文件浏览器记录](../quality/evidence/files/result.json)与[后端记录](../quality/evidence/backend/result.json)。
