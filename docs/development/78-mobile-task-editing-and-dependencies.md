# 增量78：移动任务创建、资料编辑与前置依赖

本轮推进GAP-01／18，在既有16个注册页面内补齐员工手工任务操作。复用原Go／PostgreSQL命令、版本及状态约束，不增加另一套任务状态机。代码位于app/，协议与证据位于docs/。完整四端与真实环境目标继续保留。

## 1. 操作与数据

| 编号 | 入口 | 行为与约束 |
| --- | --- | --- |
| MT-01 | 项目任务列表 | 当前项目、成员与本人权限重读，20条分页、标题查询与状态筛选；可写项目且有task.create时显示新建 |
| MT-02 | 新建任务 | 名称、说明／验收标准、负责人、优先级、审核要求、开始／截止、父任务与里程碑；确认后检查真实新ID、版本1和todo状态 |
| MT-03 | 新建子任务 | 从当前可写且未结束任务进入，明确预选真实父任务；用户可核对或解除，不能将错误项目地址当作合法关联 |
| MT-04 | 编辑资料 | 使用任务自身expected_version；done／cancelled须先按原流程重开；编辑不改变实际任务阶段 |
| MT-05 | 清空与分配 | 已有开始／截止、父任务、里程碑可明确传null解除；负责人保持时不发送assignee_id，改变或清空需task.assign |
| MT-06 | 添加／移除前置 | 选择同项目当前可读任务，独立确认准确一条关系，使用后继任务版本；当前资料与实际关系回读通过后才结束操作 |
| MT-07 | 状态与循环 | 原业务阻止前置未完成时推进、依赖／父子循环、进行中新增未完成前置、已完成／取消任务修改以及结束项目写入 |
| MT-08 | 并发与未知结果 | 原有幂等键、共享有界内存、结果核对和禁止自动重放继续生效；响应不完整、关系回读不符或冲突保留输入并要求重读 |

任务创建时，不具task.assign的用户可暂不分配或选择本人；编辑时不能通过重复发送相同assignee_id制造额外分配权限需求。负责人仍必须为本项目实际有效成员；旧负责人不可用时，由有权人员重新分配。

## 2. 关联与权限

父任务及里程碑候选使用原20条服务端分页与标题查询，不能只取前100条冒充全量。新关联必须实际读取、属于当前项目且未结束；当前任务不出现在自己的父／前置候选中。原关联当前不可读时不展示越权标题，也不自动清空；保留原ID，保存仍受原业务校验。

依赖列表只表示当前可读的前置任务，空列表不能宣称不存在其他不可见关系。移除逐项读取当前前置原记录，不能按任意文本ID进行批量解除。后端依赖循环、父子循环、完整前置与子任务完成约束继续独立检查。

项目closing／archived／cancelled、本人成员角色viewer或缺少当前动作时不显示对应写入口；服务端仍是最终授权依据。成员变更使旧登录失效后需要重新登录／MFA，不能沿用旧令牌把权限变化包装为成功。

## 3. 时间、草稿与实际回执

普通日期时间输入明确解释为香港墙上时间，带时区输入按准确偏移转换。严格拒绝不存在的日历或时刻，比较保留PostgreSQL六位微秒，截止不能早于开始。留空是明确的无排期／清空，不依赖设备所在时区。

九项任务输入只保留有界文字白名单，加入原15分钟、32项、10万字符总预算；按本人、登录代际、授权版本、创建／编辑／依赖种类、实际任务版本及子任务父对象分别隔离。完整API结果、文件选择、凭据、MFA或确认声明不保存。切换关联不恢复旧授权。

任务成功结果核对实际项目、新ID或原ID、准确下一版本、状态、全文、分配、父／里程碑、优先级、审核要求及微秒时间。依赖命令只返回任务，因而额外核对原字段不变、当前可读关系和回读任务的准确版本；关系读取失败或后续并发导致版本变化时不能显示已完成。

公共useCommand允许异步回执核对；只有核对后且页面仍有效才清理输入与消费命令结果。页面隐藏、取消作用域或身份变化不自动重放在途请求。结果未知须先通过实际列表／对象核对；前端超时不代表原事务回滚。
