# 文件历史内容恢复

本协议承接 [文件需求](../requirements/06-files-and-search.md)、[正式提交](14-file-promotion-and-commit.md) 和 [双云复制](16-cross-cloud-replication.md)。恢复回收站对象与恢复历史内容是两种操作；历史恢复保留全部已有版本，产生新的物理对象、新的正式版本及准确来源，不回拨历史指针。

## 1. 固定输入与授权

创建恢复任务固定目标文件、当前文件元数据版本、当前内容版本、来源历史版本、来源已验证副本、源对象身份/摘要/大小、目录、分类、存储纪元、发起人及其授权版本、原始渠道、原因与48小时期限。任务不接受任意对象路径或调用者声称的摘要。

入口使用已有的 file.read 与 file.restore 权限。首版支持已登录的 Web、Android、微信和抖音人工会话；Agent 必须走后续受控工具协议。任务列表先验证文件读取权限，再在分页前限制发起人；只有任务本人且仍具备读取/恢复权限的用户能查询和操作任务。

首版只从当前主端的完整已验证副本读取，并复制到同一主端的新对象；主端切换或来源不可用会明确阻断。跨云恢复/主端故障切换需要专门恢复计划，不能把读取次端自动变成切换写端。

来源必须有正式可用状态、完整SHA-256、已验证副本、固定对象身份及原始扫描证据。扫描 clean 保留原报告；原本 waived 的内容必须再次核对原豁免仍在有效期、制度为当前启用版本及批准证据，保留 waived 与原引用。复制验证不冒充重新扫描，也不延长豁免有效期。仅有历史 clean 标签、但没有原报告的导入资料也被拒绝，需先通过专门导入/重新核验流程。

任务的后台授权来自发起时固定的人工主体和渠道，用户退出浏览器不会自动撤销已创建的后台工作。主体停用、授权版本变化、范围到期或渠道权限变化会阻止后续检查点；失效任务不能靠重新登录、换渠道或修改固定输入重新获得发布权。当前有效用户可重新创建任务，或在仍有对象权限时取消旧任务。

## 2. 容量、复制与提交

组织逻辑容量包含全部历史正式版本、未过期上传预留和未过期恢复预留。两种任务共用组织容量锁，禁止并发各自通过容量检查。组织容量仍由运维显式配置，不把现有2TB存量当默认额度；逻辑额度不代表两云物理费用/临时副本容量。

恢复任务经事务 Outbox 进入独立大小车道。云调用在数据库事务之外执行，沿用分片复制、已知UploadID对账、结果未知后Head核对、目标完整摘要回读和检查点。未知初始化使用新尝试Key；每次持久化回执前重核租约、固定来源、期限、授权版本、文件/项目可写性、目录和分类。

状态为 queued → copying → verifying → ready → committed；受控重试为 retry_wait，终止为 cancelled/failed。ready 仅证明候选复制和目标回读成功，不修改当前内容。用户明确提交时固定任务版本、基础内容版本及摘要；在同一事务核对候选证据、最新文件元数据/内容版本、两云目标与权限，创建新正式版本、主端验证证据、次端排队、审计及事件，再改变当前版本。

当前文件发生改名、移动、分类或内容变化均拒绝提交，不自动重定基础版。取消/过期/失败不删除旧文件或已有历史；候选及孤立分片保留可清理记录，实际清理另走保留协议。业务法律保留不禁止新增内容版本，但禁止通过恢复移除旧内容或解除保留。

## 3. 接口

- POST /files/{id}/history-restores：创建固定恢复任务。
- GET /files/{id}/history-restores：当前发起人有权任务列表，游标绑定身份和文件。
- GET /history-restores/{id}：当前任务及候选校验进度。
- POST /history-restores/{id}/commit：明确发布，生成新正式版本。
- POST /history-restores/{id}/cancel：取消且保留追踪记录。

原 /files/{id}/restore 仍用于回收站恢复；历史模式返回明确的迁移入口说明，不能继续使用同步File响应假装异步恢复已经完成。

输入输出由 [同源 OpenAPI](openapi.json) 定义。创建返回202及 HistoryRestore；显式提交返回201及 FileCommitResult。取消与读取返回实际任务。版本冲突为409，固定主体授权变化为412，任务超过48小时为410；幂等重放前仍验证当前人工会话和对象权限，不把权限检查放在缓存结果之后。

## 4. 数据、执行器与运行

[0023迁移](../../app/backend/migrations/0023_history_restores.sql)增加 file_history_restores 与传输日志的 restore 主体。来源、目标、发起人授权版本、原因和期限禁止更新；候选/结果绑定后不能替换。任务的来源、基础与结果均以同一组织、同一文件的外键绑定，不接受跨文件历史引用。

每个逻辑恢复预分配一个 planned_version_id，每次未知初始化分别创建尝试ID。目标Key采用 org/{org}/files/{file}/versions/{planned_version}/replicas/{attempt}/original；不确定尝试无法覆盖其他尝试。正式版本以 restored_from_version_id 保留准确来源，base_version_id 指向发起时的当前版；两者不可混淆。序号在文件锁内取 max(seq)+1，保留所有既有历史。

| 执行参数 | 已实现值 |
| --- | --- |
| 命令 | worker-restore-small / worker-restore-large |
| 车道 | storage.restore.small / storage.restore.large |
| 任务类型 | file.history.restore.v1 |
| 大小分界 | 不超过100,000,000字节为small，超出为large |
| 单任务截止 | small 30分钟，large 12小时；不是完成时间保证 |
| 复制/摘要 | 默认32MiB分片；完整回读按32MiB检查点和256KiB缓冲执行 |
| 租约与重试 | 沿用120秒租约、30秒心跳和最多8次受控退避 |
| 用途身份 | CP_{OSS或R2}_RESTORE_SOURCE_* 与 RESTORE_TARGET_* |

SOURCE仅需固定正式对象读取；TARGET仅需恢复候选分片创建/读写/完成与回读。实际云IAM仍需分别安装、核验路径与操作限制；变量名称不等于真实权限已配置。执行器不读取API会话/MFA、迁移或模型密钥，不继承上传、下载、正式候选、跨云复制的凭证。开发启动脚本仅传其用途变量。生产SQL专用账号与权限分拆仍待部署验收。

示例从项目根目录运行：`python app/scripts/run_backend.py worker-restore-small`。缺少显式存储或用途身份会拒绝启动；本任务未启动真实云恢复执行器。原生Linux [服务候选](../../app/deploy/native/copypaste-restore@.service)按small/large实例提供，没有安装或启用；不需要本机Docker/WSL/模拟器。

任务结束、错误码、审计、Outbox与任务完成/重试在同事务内提交。取消在项目/目录名称空间锁内复核权限，但允许只读项目的任务取消。队列耗尽修复覆盖首次尚未写入 active_job_id 的任务，防止永远显示排队。首次复制、目标冻结、候选就绪均有实际阶段事件；没有把全局上传会话当作合成恢复任务。

## 5. Web交互

文件详情的历史版本提供「恢复为新版本」，当前版无此动作；不可用/无法扫描的历史显示禁用原因。can_restore_history与can_view_history_restores由服务端对象授权产生；后者允许有权用户在归档后查看自己的任务。当前任务列表显示本人任务、来源/基础内容序号、两个独立的复制/摘要进度、原因、期限和受控错误。

创建对话框固定文件元数据版与来源版本，解释复制及后续确认；ready 卡片必须再次确认基础内容版本与摘要，才提交原始固定输入。弹窗不随后台轮询重定基础版。写入前确认会话；同一未确认请求保留幂等键，版本/权限冲突保留输入、停止自动重试。取消明确保留旧文件和候选追踪记录。超期任务不可发布，可以取消并重新发起。

使用 [设计规范](../design/README.md) 的双主题令牌、黑白主动作、既有危险描边、对话框和单列窄屏规则。恢复复制成功与正式可用、次端保护分别表达；列表不显示云桶、对象路径、固定ETag、凭证或原始错误正文。

## 6. 验证与边界

原生PG的 TestHistoryRestoration 包含13个叶场景：新版本/来源链/显式提交与双云排队、基础版冲突、审计回滚、共享容量、本人分页隔离、RPC中取消/撤权、目标损坏、已知断点/未知初始化、旧租约/首次耗尽、扫描例外及制度修订、不可变输入/归档取消、存储纪元变化。用途配置单测覆盖两云独立SOURCE/TARGET且不继承其他角色。准确的源码摘要与全量结果见 [实施台账](../delivery/02-implementation-ledger.md)。

[浏览器检查](../../app/scripts/check_history_restores.mjs)与 [结果](../quality/evidence/history-restores/result.json)覆盖五条实际API/UI链：不可用历史禁用动作、明确标记的排队元数据/双进度、双主题五宽度、移动取消保留版本、其他员工任务隔离。使用专用前缀项目/目录，准备程序只写不可用元数据，不伪造扫描报告、ready候选或成功副本；所有临时浏览器/上下文均已关闭。

这些检查不证明真实双云权限、真实120GB吞吐、生产恢复时间、真实扫描、Web就绪提交的云端联调或四端真机可用。当前还没有跨云灾难恢复、自动保留清理、失败任务人工重试命令或直接为旧导入资料补扫的完整界面；这些继续按完整需求交付。
