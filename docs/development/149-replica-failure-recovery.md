# 增量149：文件复制失败／恢复通知与固定版本入口

## 1. 实际问题与行为

原工作器已经为失败产生`replica.failed`站内通知，但人工重试排队后通知会提前不再需处理；实际校验成功只改变旧通知的实时状态，不会形成新未读恢复投递。通知入口只到文件首页，旧内容版本可能不在最近20项历史中。

本轮复用原复制工作器与通知投递机制，贯通失败→已读→人工重试→复制／校验→恢复未读→打开准确版本→单独已读。主线结构仍111，没有新增结构、费用策略或自动重试授权。全部五次冻结不变；rc.5／APK148固定业务147，149新增通知逻辑及入口在当前源码，未重新制作APK或冻结包。

## 2. 员工操作

1. 文件创建人／版本作者在具有当前普通文件读取权限的渠道收到复制失败通知；不广播给无关人员或仅具组织元数据权限的管理者。
2. 已读仅确认所见投递序号，仍保留“仍需处理”。打开资料会先重新读取通知，再核对准确版本和副本。
3. 有普通文件更新权限的人员核对失败／缺失副本并明确填写原因，使用原重试命令。Web和共享移动端均可从固定版本进入原重试流程；服务器继续核对原权限、准确修订及来源。
4. 排队、复制、等待重试及校验中均不当作恢复，已有失败通知继续需处理；工作台继续依据实际业务行核对，不依赖已读标记。
5. 实际工作器将目标字节、摘要与校验时间写为完整verified证据后，原已投递失败线程才可追加恢复投递；同一线程变为新未读。初次正常复制不会发送恢复提醒。
6. 新恢复通知打开对应文件版本和副本。历史版本与当前头独立，版本不在最近20项也可直接读取。旧失败的已读序号不能吞掉新的恢复通知。

## 3. 后端和一致性

通知类别继续使用`replica_failure`。新增消费`replica.verified`，接收人来自已有失败线程；要求该线程存在同组织、同副本的真实`replica.failed`投递引用。当前副本修订、状态、期望／实际／正式版本摘要和verified_at全部一致才候选恢复；不会凭外部payload或“已安排重试”声明成功。

临时投递候选携带事件类型和聚合修订；读取当前副本时锁定准确副本／版本并再次核对事件依据，防止查询候选后状态变化或延迟旧事件被解释为新的进展。普通收件箱读取仍显示当前事实，保持原接收人、当前用户状态、普通文件权限与祖先目录检查。停用／撤权继续隐藏内容并抑制后续恢复投递。原子投递回执、租约栅栏、不可变历史、按原事件时间去重和投递序号机制全部复用。

`queued/copying/verifying/retry_wait`表示仍待实际校验；`verified`只有完整摘要／时间证据时解除处理义务。若verified行证据不完整，则安全显示`replica_unconfirmed`并保留需核对。已退休／清理版本不作为可打开的当前通知目标。公司数据或真实云运行结果未被合成证明替代。

## 4. 接口与四端入口

| 项目 | 约定 |
| --- | --- |
| HTTP | 复用`GET /notifications`、`GET /notifications/{id}`、summary及原read命令，无新路由 |
| Target | 新增可选`version_id`／`replica_id`，文件副本通知同时提供两个准确ID；`web_path`保留安全文件基础入口 |
| Web | 共享白名单先核对基础入口，再构建`/files/{id}?version={version}&replica={replica}`；固定版本面板调用普通单版本接口并核对归属 |
| 微信／抖音／Android源码 | 使用共享白名单生成固定详情地址，核对文件／版本／副本，突出“通知对应副本”；有权限时复用原人工重试表单 |
| 兼容边界 | 旧基础通知地址继续接受；新客户端拒绝不成对ID、其他类型夹带副本ID、任意重定向及不匹配的回复。旧冻结客户端不能计为149新入口已验收 |

用户正文、对象桶／key、原始提供商诊断、凭据和复制payload不加入通知。恢复只进入原站内投递渠道；TG与其他跨渠道披露仍须各自接入和授权。

## 5. 精选验证

原生HTTP／耐久临时PG：新套件12业务子场景、1未启用浏览器钩子、1组汇总＝14条pass，另1项既有通知回归，共15条记录；钩子不是业务通过。实际合成对象存储工作器执行摘要失败和人工重试后真实字节校验，没有直接修改副本状态来伪造成功。四渠道登录使用真实会话；仅隔离测试角色明确要求MFA后真实注册验证。

Web5／共享移动5、类型及Web／微信／抖音构建通过。实际Web3项核对：恢复未读、固定版本打开、序号2已读；390／768／1440宽度无横向溢出。三PNG、2.8秒实际无声操作MP4、6秒三截图导览GIF已核对，GIF不冒充连续录屏。移动端额外UI、全量回归、新APK和真实云／生产验收继续延期。

首次后端检查在测试MFA准备阶段失败，失败报告和准确旧测试源码保留；只修正隔离测试角色策略，没有放松生产规则。新增只读来源核验模块晚于浏览器捕获，单独记录捕获时完整构建输入列表／摘要；所有实际捕获输入保持原字节，唯一后加核验模块由当前来源摘要与自身SHA独立绑定，无重录或哈希改写。

## 6. 运维和后续

沿用原notification worker部署。新增事件类型随当前后端消费者运行；对尚未消费、仍与当前副本修订一致且已有失败投递的旧verified事件，可能补齐恢复通知。原事件时间排序和版本重查继续抑制过期／重复投递。读取或恢复不授予额外文件／组织操作权，不替代真正的复制完成。
