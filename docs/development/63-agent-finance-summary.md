# 秘书月度财务摘要与固定来源

本增量推进 GAP-03、GAP-12、GAP-13，将已有订阅预测、发生支出与现金报表接入 `subscription-review` 的真实只读工具。员工可从 Web 与 Taro 秘书消息打开生成时刻的财务快照。源码包为 1.1.0 draft，尚未发布或安装生产模型配置；不开放财务写入、付款、供应商取消及 Telegram 财务执行。

## 员工使用流程

1. 进入公司会话或单个项目会话，确认成员范围。每名成员都须允许 AI 处理该分类、渠道和相关财务记录。
2. 选择已安装的订阅审阅配置，明确月份与需要的口径。没有有效配置时，界面继续显示真实不可用状态。
3. 秘书分别调用预测、发生支出或现金读取工具，不把三者混成一项总额。
4. 回复附准确的 `agent_finance_report` 来源。点击“查看固定财务快照”，重新核对当前权限后展示历史正文。
5. 后续新增费用、登记付款或生成账期，需重新生成摘要；旧快照保留原值，不作为当前余额。

沿用现有秘书页面，无新增移动公开页面。微信、抖音、Android 共用本次 Taro 业务组件；编译、H5 浏览器验证和原生真机验收分别记录。

## 工具契约

`read_finance_summary` 只接受以下字段：

```json
{"month":"2025-01","view":"actual","currency":"HKD"}
```

| 参数 | 约束 |
| --- | --- |
| month | 必填，严格 YYYY-MM，2000—2100 年，按自然月起止，结束日不包含 |
| view | 必填，forecast / actual / cash；actual 对应已有报表 kind=incurred |
| currency | 可选，三位大写代码；不提供时保留各原币种分别汇总 |
| 范围 | 由服务端会话固定，不接受额外 project_id、scope、用户身份或任意查询 |

| 会话范围 | 真实含义 |
| --- | --- |
| 项目会话 | 该项目的订阅配置及费用／付款分摊；不是整条跨项目费用金额 |
| 公司会话 | 公司分摊及公司订阅，不等于全部项目合计，也不等于所有未归集现金 |

历史 Skill 显式输入 Schema 可描述多项目需求，但本次对话执行工具只处理当前公司或单个项目范围。多项目合并需分别取得准确来源并明确分摊关系，不能传入工具未实现的聚合范围。

## 财务口径

| 口径 | 数据来源 | 必须保留的解释 |
| --- | --- | --- |
| forecast | 已存订阅账期、固定价格、启停生效规则及日历覆盖检查 | 按订阅本地自然日；缺失账期、未知价格、草稿和覆盖上限须单独说明；不能把缺失当零支出 |
| actual / incurred | 已确认费用及冲销、发生日期、项目／公司分摊 | 未确认数量单列，不能由付款或审批直接认定发生支出 |
| cash | 已登记收付、退款／更正、实际支付日期和分摊 | 与发生支出分开；不表示银行实时余额，不自动执行付款 |

复用 `finance` 原有三份报表的事务内投影。公共 HTTP 接口仍在自己的 repeatable-read 只读事务内调用相同投影；秘书在已锁定组织的执行事务中读取并保存证据。现有订阅日历、确认、退款、冲销及合同现金分配规则继续生效。

金额保持十进制字符串，原币种不合并，未配置汇率不补零、不计算虚构折算值。HKD／USD 等币种仍遵守原有币种精度校验。`report` 保留原报表字段及 `as_of`，外层记录 `captured_at`、`month`、`view`、范围、输入数量、历史与不可信数据标记。

工具只提供汇总和异常计数。逐笔缺票、重复扣费、具体供应商退款或停止收费，仍需相应明细证据；不能从汇总或内部停用状态推断。

## 共同权限与证据保护

- 以发起人的现有财务可读范围选择输入，并明确“仅含获准读取记录”，不声称完整全司总额。
- 所有当前成员须有 report.read，且能够以当前 AI／渠道策略读取每项贡献记录及关联资源；任一成员不满足时拒绝整个摘要，避免悄悄改变总额口径。
- 输入分类不得超过会话分类；沿用费用分摊项目、付款／合同关联、订阅关联费用的现有权限函数。
- 费用保存原修订，用于继续检查原分摊；同时检查当前费用修订。付款和订阅继续检查当前关联及保存修订归属。
- 财务输入 ID／修订目录仅存服务端授权目录，不进入模型正文。模型只得到汇总、计数、覆盖说明和准确快照来源。
- 历史快照限定原会话和原受众。新增成员不能自动读取旧证据；权限撤销或 AI 策略变化可以使旧正文不可读。

每次汇总最多 500 项输入；超出即失败，不截取后冒充完整汇总。沿用每次任务最多 20 个固定来源及执行配置的工具次数、时间与预算限制。

## 数据结构与执行器

迁移 `0062_agent_finance_reports.sql` 新增 append-only `agent_finance_reports`：组织、任务、会话、发起人、项目、分类、原受众、标题、准确 JSON 文本、私有输入目录和文档摘要。

三项数据库保护分别阻止 UPDATE／DELETE、绑定正在执行的 subscription-review 及准确会话范围、延迟检查同一事务的成功工具回执。回执必须匹配内容、快照 ID、摘要和来源版本。应用角色仅有 SELECT／INSERT。

Go、MCP、SDK 允许 `read_resource`、`read_finance_summary`、`inspect_operation`。`completed` 必须引用本次成功财务工具产生的准确快照；一般项目读取、其他任务回执、待处理回执、遗漏财务来源均不能证明财务审阅完成。此校验证明读取及来源，不逐句验证自然语言推理。

Web／Taro 使用现有上下文接口读取 `agent_finance_report`。界面使用固定快照类型路径，核对原摘要、会话修订和分页边界；请求中或失败时隐藏旧正文。Taro 页面隐藏或关闭时释放请求及快照状态。移动客户端允许该内部来源路径中的下划线，继续拒绝外部 URL、双斜线、片段、换行和目录跳转。

## 验证与后续边界

验证汇总见[本增量证据](../quality/evidence/finance-summary/verification.md)。原生用例实际建立订阅、账期、费用、付款与分摊，验证三口径、多币种、共同权限、缺失预测、完成回执、不可改写、原会话限制与权限撤回。浏览器使用真实接口及独立测试库，结束后关闭所属上下文和临时服务。

真实模型样本评测、正式 Skill 发布／安装、复杂逐笔差异审阅、FX／预算、多端真机、真实云存储／120 GB、TG 披露投递及生产部署仍需继续验收。完整平台 Goal 保持执行。
