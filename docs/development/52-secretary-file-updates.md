# 秘书准确文本修改、隔离草稿与正式版本提交

本增量在[准确文件正文读取](51-secretary-file-text.md)上接通单文件更新，推进GAP-04／11／12。代码位于 `app/`，文档位于 `docs/`；不调用Docker、WSL、虚拟机、模拟器或子代理。

支持员工在Web及Taro会话中明确选择现行文件版本，发送修改要求。秘书读取原件、提交有界字符编辑，Go生成真实差异和隔离草稿，现有后台完成完整性、扫描及正式候选准备，最后提交可追溯的新版本。旧版本保留。云端、真实模型和真机的正式验收仍属于完整平台Goal。

## 1. 已实现范围

| 编号 | 能力 | 当前实现及边界 |
| --- | --- | --- |
| FU-01 | 明确更新范围 | `RunCreate.file_update` 固定文件ID、基础文件版本及文件元数据修订；不得由模型改换目标 |
| FU-02 | 有界编辑 | UTF-8文本／Markdown，原文和结果各1字节至1MiB，1—64项按原文Unicode码点定位的编辑 |
| FU-03 | 格式保护 | 保留原BOM、一致的LF／CRLF以及未修改字节；拒绝混合换行、裸CR、NUL、非UTF-8、空结果及无实际变化 |
| FU-04 | 真实差异 | 服务端计算变化位置、前后长度、完整变化摘要及各1000字符以内的预览；不接受模型自报差异 |
| FU-05 | 云端隔离草稿 | 专用Go身份上传有界字节；模型看不到凭证、对象键及云上传标识 |
| FU-06 | 沿用正式文件流程 | 后台完成冻结、完整SHA-256、扫描、候选复制及完整回读；人工扫描豁免不能用于秘书提交 |
| FU-07 | 固定计划和提交 | 准确草稿、基础版及计划摘要一致才能提交；每次运行最多3份草稿、1次正式提交 |
| FU-08 | 事务和回执 | 正式版本、当前文件头、副本记录、审计、Outbox、幂等操作与工具回执同事务完成 |
| FU-09 | 两端入口 | Web／Taro明确选择、发送、实际差异与扫描状态、正式版本／操作回执及取消；选择本身不发送 |
| FU-10 | 撤权和竞争 | 网络前后重新核对当前授权与基础版本；取消、授权变化或员工先提交版本时拒绝后续写入并尝试终止本次分片 |

CSV、JSON沿用只读能力；PDF、Office、归档包、二进制、大于1MiB的文件编辑、创建新文件、移动目录、批量和跨项目操作不在本次单文件实现中。120GB上传、2TB迁移与双云实际校验仍按既定文件工作包验收。

## 2. 员工请求与权限

```json
{
  "file_update": {
    "file_id": "准确文件UUID",
    "base_version_id": "准确现行文件版本UUID",
    "expected_file_version": 7
  }
}
```

以上字段加入已有 `RunCreate`，不是独立提交接口。员工仍须选择当前可用的 `file-update` 配置并填写本次修改要求。Web／移动端先核对文件处于会话项目或公司范围、版本是现行版本、格式和容量符合编辑条件；服务端再次核对，不信任客户端结果。共享会话要求所有原始读者当前均能阅读准确基础版，后加入的成员不能获得旧请求的内容授权。

创建运行时形成不可变 `agent_file_intents`：绑定真实发送人、组织／个人授权版本、会话修订和上下文安全版本、准确文件与基础版本、文件修订、目标名称／目录／分类／格式、基础资料投影摘要及本次消息。用户消息固定引用 `agent_file_update:<run_id>` 和意图SHA-256。模型只在 `prepared_context.authorized_file_update` 中取得这一范围；没有范围时不能调用写工具。

本流程是明确、可恢复的L1更新，不新增重复人工批准。资金、权限、永久删除、批量和跨项目等授权规则继续按[秘书需求](../requirements/07-secretary-and-channels.md)及[共同边界](../skills/execution-boundaries.md)执行。

## 3. 编辑、差异与格式

`create_file_draft` 接收 `file_id`、`base_version_id` 和 `edits`，每项如下：

```json
{"start_char": 6, "end_char": 9, "text": "新计划🙂"}
```

位置按未修改原文的Unicode码点计算，起点包含、终点不包含；BOM、CR、LF各占一个码点。范围必须升序、不重叠，同一起点不能多次修改。工具参数JSON受64KiB总量约束，不能利用少量字段输入无界全文。编辑后仍须满足1MiB总量限制。

Go先读取并完整验证准确原件，再应用编辑。最长共同前缀和后缀之间的内容构成真实变化区间；这是一个完整变化区间，可能包含多个编辑之间未变化的文字。返回字段如下：

| 字段 | 含义 |
| --- | --- |
| `start_char`／`removed_chars`／`added_chars` | 实际变化区间和前后码点数 |
| `removed_sha256`／`added_sha256` | 完整前后变化内容的SHA-256 |
| `before`／`after` | 各最多1000字符的变化预览 |
| `before_complete`／`after_complete` | 预览是否覆盖对应的完整变化内容 |
| `line_ending`／`utf8_bom` | 原文的一致换行约定与BOM事实；无换行原文新增行仅使用LF |

完整草稿另有内容SHA-256和字节长度。截断预览必须明确标注，不能称为完整差异；现阶段没有差异全文分页下载入口。源码 `files/agent_text_edit.go` 保留编辑以外的原始字节，不进行隐式格式化或编码转换。

## 4. 隔离上传及后台处理

流程为“固定范围→完整原件读取→实际编辑→预约上传→隔离分片写入→后台冻结／摘要／扫描→正式候选→固定计划提交”。

每次读写网络I/O前后分别使用短授权事务，远程请求期间不持有数据库授权锁。草稿预约先落库，再进行有界网络上传，成功后重新核对运行、租约、会话、AI许可、资料指纹、文件头及存储纪元，才能记录阶段结果和工具回执。

草稿使用既有 `upload_sessions`，渠道固定为 `agent`，草稿ID等于上传会话ID。普通上传的查阅、签名和提交路径拒绝该会话；普通上传队列在分页前排除秘书草稿，不会产生被隐藏草稿占据的空页。不能通过Web／Android人工接口绕过秘书的准确范围。模型得到业务草稿ID、摘要、差异和状态；云对象键、上传标识、ETag留在私有证据中。

专用草稿身份只执行Begin／WritePart／Abort，后台生命周期身份另行完成分片、冻结来源。随后使用既有小文件校验、扫描和候选准备执行器；草稿不是正式文件，原件仍在原版本中。正式字节存放在对象存储中，应用机不保存长期正文缓存。

## 5. 计划、提交及异步边界

`propose_file_update` 由已登记的真实草稿固定计划，包含原始范围、实际差异、完整内容摘要、目标以及隔离来源摘要。调用者不能提交自己的差异、目标目录或内容摘要替代服务端证据。

`commit_file_update` 必须给出准确文件、基础版、草稿ID和计划摘要。尚未扫描通过或候选未就绪时返回 `pending`、`committed=false`；`inspect_operation` 返回当时的实际草稿状态。相同工具调用键只重放原回执，状态变化后的重试需使用新键。

正式提交复用既有 `UploadService.CommitAgentDraft`，不冒充人工渠道，不接受扫描豁免。准确基础版本、文件元数据修订、目标位置／分类、当前用户权限及扫描证据均需一致。正式版本来源为 `agent`，主副本完成验证；第二副本初始排队并继续按实际复制状态展示，不能把主存储提交等同于双云备份完成。

一次运行只能提交一份草稿，实际成功结果才能让模型输出 `completed`。正式版本和工具回执之间任一写入失败，整笔数据库事务回滚；重复提交返回同一事实，不额外新建版本。

当前不会在运行回复 `pending`、结束、取消或超时后自动续跑提交。未完成的差异仍可查看，员工须核对现行版本后明确发起新请求；不能把新的请求自动绑定到上次草稿。界面会提示已停止运行的草稿不会自动提交。跨运行草稿恢复和差异全文审核仍是后续能力。

## 6. 数据迁移及保护

[0051迁移](../../app/backend/migrations/0051_agent_file_updates.sql)新增五张只追加的表：

| 表 | 事实 |
| --- | --- |
| `agent_file_intents` | 员工发送时固定的准确范围与意图摘要 |
| `agent_file_drafts` | 有界编辑指令、实际内容摘要／长度、差异及原件指纹 |
| `agent_file_stages` | 实际隔离分片回执与来源 |
| `agent_file_proposals` | 固定草稿计划与摘要 |
| `agent_file_commits` | 实际正式版本、业务操作和原始提交结果 |

应用角色仅有SELECT／INSERT；五项不可变守卫、五项绑定守卫和三项延迟证据守卫共13项。SHA使用PostgreSQL原生 `sha256`，无需新增扩展。意图与发送消息、草稿与准确预约上传、正式结果与成功业务操作及同事务工具回执互相约束。既有工具回执和执行观察增加三种文件工具白名单。

## 7. 显式云身份配置

```dotenv
CP_AGENT_DRAFT_DRIVER=disabled
CP_OSS_ENDPOINT=
CP_OSS_REGION=
CP_OSS_BUCKET=
CP_OSS_AGENT_DRAFT_WRITER_ACCESS_KEY_ID=
CP_OSS_AGENT_DRAFT_WRITER_ACCESS_KEY_SECRET=
CP_OSS_AGENT_DRAFT_WRITER_SESSION_TOKEN=
```

只接受 `disabled`、`oss` 或 `r2`。提供商端点／区域／桶使用对应的 `CP_OSS_*` 或 `CP_R2_*` 共用定位配置，凭证则严格使用专用 `AGENT_DRAFT_WRITER` 角色。R2使用 `CP_R2_AGENT_DRAFT_WRITER_*` 凭证。默认关闭，无普通上传、下载、读取或复制身份兜底；专用身份必须与当前有效主存储目标一致。原件读取另用[独立读取身份](51-secretary-file-text.md)。API与秘书Go worker显式加载身份，模型原生子进程不继承 `CP_` 云凭证。

线上还需要既有生命周期、校验、扫描、候选和副本执行器，以及临时对象／未完成分片的云端生命周期规则。本地受控流程不能证明真实云策略、网络、容量和清理规则已部署。正常失败会尝试Abort；进程崩溃或云回执丢失的残留需要运维配置云生命周期规则兜底。应用侧物理清理尚未接通，过期检查和容量预约失效不代表云字节已经删除；详见[保留和清理边界](20-retention-and-reference-protection.md)。
