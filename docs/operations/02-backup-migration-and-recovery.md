# 备份、2 TB 迁移与灾难恢复运行手册

修订99：本文中的历史迁移、独立数据库备份／PITR、一致恢复集、密钥／主机重建、RPO／RTO和容灾演练已移出当前范围，保留为历史设计，不继续开发或要求验收。当前仍保留OSS＋R2双端存储／复制／校验、普通文件回收站／版本恢复、生产PG持久化及正常结构升级。以[当前范围](../delivery/04-current-scope-and-acceptance.md)为准。

版本：v1.0-draft；日期：2026-10-23；关联 FILE-08/13/14、NFR-05/06/09。以下为待验证运行手册；RPO/RTO 是条件化目标。

## 1. 恢复集组成

一个恢复集必须包含：DB备份/恢复点、同一一致性视图的文件引用清单、引用版本的对象存在/内容校验证据、schema/app版本、配置/Skill版本、加密格式与密钥版本引用、备份与校验完成时间。密钥原文不放同一普通备份目录；独立恢复保管必须能找到相应历史版本。

数据库包含权限、正文、审批/费用、会话、业务工具提交和审计，不能仅备份文件桶。双云最新对象镜像也不替代历史恢复集。

## 2. 逻辑备份一致性

候选每6h逻辑备份，另有托管PG PITR（候选14d）。逻辑备份使用一致性快照；为使文件引用清单与之匹配，可由协调事务导出 snapshot，pg_dump 使用该 snapshot，清单查询使用同一快照，保持导出事务有效直到参与方取得快照。实现时需评估快照持有对 vacuum/连接的影响，不能一边查清单一边用另一时刻 dump 冒充一致。

逻辑备份加密流式上传或在严格配额的加密临时文件中生成；不得依赖应用本机唯一副本。记录备份大小、摘要、开始/DB快照/完成/跨云复制/校验时间。每份备份配套当次引用清单；每日全量对象catalog是补充，不代替当次一致性清单。

pg_dump 只能作为逻辑恢复，不能作为连续 WAL/PITR 的物理 base backup。托管PITR是否跨云可用、保留/密钥/恢复区域须单独证实；同云产品恢复能力不能算作异云已备份。

## 3. 恢复目标与缺失判定

| 故障域 | 候选目标 | 必须前提 |
| --- | --- | --- |
| 应用节点损坏 | 重建≤2h，业务状态不因本机丢失 | 外部PG/存储/密钥和产物可得 |
| 同云PG逻辑故障 | RPO≤5min、RTO≤2h | 真实PITR产品、配置、历史恢复演练 |
| 主云整体不可用 | 跨云DB RPO≤8h、RTO4–8h | 6h备份+完成/复制/校验窗口持续满足，引用对象齐备 |
| 最新文件尚未副本完成 | 风险窗口=该版本最后可靠副本事实 | 大文件不套用15min；缺失版本逐条报告 |

恢复点必须同时满足：DB可恢复、该快照需要的原件/历史引用有可验证副本、配置/密钥可用。不能简单取“两个桶最后修改时间的较小值”。若最新备份含未复制对象，可选择更早完整恢复点；或经负责人接受进入明确的降级恢复，缺失标记missing并列出业务影响，绝不伪称零丢失。

增量96提供[原生盘点、映射、固定计划、上传续跑与逐项核验工具](../development/96-native-file-import.md)。以下真实规模、对象、ACL、恢复与切换验收要求保持；CLI报告不会自动批准切换或删除源原件。

## 4. 2 TB 存量迁移

1. **盘点**：只读列来源路径、size_bytes、mtime、SHA-256（分批流式）、格式、owner、项目/分类、已有权限；保留清单版本和错误。源不可访问/加密包/超120GB/同名规范化冲突单列。
2. **映射**：确认项目/目录/账号/分类；未明确归属进入仅迁移管理员可见的待归类区，不能默认全员公共。生成 source_id→file_id/version_id 映射。
3. **小批试迁**：代表性格式与120GB真文件，测试香港路径、分片/恢复/双云校验和账单；按实际有效带宽估总窗口，至少计源读取、上传、跨云和必要回读。
4. **全量分批**：固定来源快照或约定只读窗口；按批上传/正式提交/副本校验，失败断点重跑。重试用迁移source_key，不新建重复逻辑文件。
5. **增量核对**：若来源仍被编辑，二次扫描差异/最后只读窗口，固定最终源版本；不能导入到一半仍称2TB同一时点完整。
6. **核验**：原始总字节/对象数/摘要、每项映射、ACL、当前/历史、主与副本完整清单、抽样用户查找/预览；全量内容校验证据覆盖全部迁移原件，抽样业务使用是额外校验。
7. **切换**：用户验收后门户成为写入入口，来源保留约定窗口；明确新旧双写禁止。来源清理需独立确认与保留检查，不因迁移脚本成功自动删源。

清单行：`migration_batch, source_id/path, source_size/hash, org/project/folder, classification, file_id/version_id, primary_ref, replica_ref, verification_at, error, reviewer`。清单本身有权限、加密和备份。

## 5. 应用节点重建

隔离故障节点→记录最后有效job/epoch→取得冻结产物和受限配置→在核准原生环境恢复服务账号/网络→连接独立PG/存储→检查schema兼容→过期租约回收/对账→重建临时索引/缓存→验证账号、项目、审批、费用、文件引用→恢复入口。

Agent原生线程文件丢失时从业务消息/工具证据重建，不重复已提交工具；只有经过筛选归档并验证可恢复的原生状态才能承诺原样续接。

## 6. 主云灾备与单主切换

1. 宣布事件、冻结写入、记录当前epoch和最后可靠恢复点；防止旧入口继续接任务。
2. 由独立凭证/网络控制隔离旧主写身份与旧Worker，保存可审阅fence证据。仅停止进程但不能确认旧节点隔离时，不开放新主写入。
3. 在隔离恢复环境解密/恢复PG，加载对应对象catalog，逐引用核验；先以只读模式验证权限、合同签署件、费用、会话和版本。
4. 选择新主（R2候选）并完成其写/签名/上传适配验收；增加storage_epoch，所有旧session/plan/worker凭据失效或重建。不能只改一个bucket字符串就承诺可写灾备。
5. 负责人确认已知缺失/RPO与业务影响后开新主写入，监控上传/费用/告警。所有客户端先重新取capability/会话。
6. 原主恢复后作为待对账旧副本，不自动回切。按新纪元清单补齐数据、解决孤儿和冲突；再次受控切换。

正式单写灾备开放前也可只读访问副本，需标明数据时点。首期是否投入可写跨云灾备由 Q-12 冻结；至少完整演练DB+对象的只读恢复，不能用其冒称可写切换已验收。

## 7. 演练证据与保留清理

每次记录事件/演练ID、开始时刻、恢复集、理论与实际数据损失窗口、恢复各阶段时间、缺失对象、费用/权限核对、密钥可得、测试结果、责任人与改进项。演练在隔离命名空间，不向真实TG群或供应商发业务通知；恢复出的定时/支付/通知任务默认禁用，确认后再处理。

回收站90d、版本180d、备份14日/8周/12月仅候选。删除前生成dry-run依赖清单，排除current/签署/验收/hold/有效恢复集引用，批准观察后执行，逐项审计。不能先删对象再发现仍需从一年前DB恢复它。
